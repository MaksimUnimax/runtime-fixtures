# Техническое задание Seller Agents

Версия 1.0, 2026-09-14. Это обязательное целевое поведение, а не утверждение о готовой реализации.
Основание: [решения владельца](../decisions/DECISIONS.md). Статус реализации: [STATUS](../STATUS.md).
Детали UI — [UX](UX.md); протоколы и пределы согласования — [SYNC](../architecture/SYNC.md).

## Назначение и границы

Seller Agents — «ИИ-сотрудник» продавца: одно браузерное расширение даёт выбранному пользователем ИИ доступ к разрешённому чтению его кабинетов Ozon/Wildberries.
ИИ формирует команды, пользователь разрешает пакет нажатием, расширение обращается к площадке и передаёт результат в этот же диалог.
Модель и её подписку предоставляет пользователь. Сервис не хранит бизнес-отчёты в облаке и не обещает доступ к данным, которых нет в разрешённых API или правах кабинета.

Бета бесплатная с регистрацией. Сервер обеспечивает аккаунты, доступ, метаданные магазинов, совместимость, редкое согласование и администрирование. Критический путь получения данных остаётся в браузере.

## Коммерческий доступ после беты

[Согласованная политика подписки от 2026-09-24](../architecture/SUBSCRIPTION_ACCESS_POLICY.md): локальная проверка перед запросом к площадке, общее обновление примерно раз в сутки при использовании, фиксированные 72 часа после подтверждённого оплаченного срока при отсутствии достоверного ответа, немедленная остановка новых запросов при актуальном запрете. Серверные изменения подписки сохраняются сразу; общий lifecycle worker пока остаётся 30 секунд. Это целевые требования, коммерческий запуск и готовность реализации не заявлены; бесплатная бета остаётся отдельной.

## Магазины и привязки

Магазин — сущность Seller Agents с marketplace и storeId, пользовательским именем, подтверждённым providerAccountId, когда его можно достоверно получить, и состоянием проверки.
Секреты принадлежат локальному credential record; его revision меняется при замене ключа. Имя магазина не участвует в авторизации, квотах или определении кабинета.
При отсутствии надёжного API идентификации нельзя обещать автоматическое обнаружение одинаковых кабинетов: интерфейс показывает непроверенное соответствие, импорт требует выбора пользователя.

Удаление магазина завершает его локальные сессии и удаляет соответствующие секреты в текущей установке. Служебная отметка удаления передаётся другим установкам при очередном обращении; выключенный браузер нельзя удалённо очистить мгновенно.
Переименование меняет подпись, а не токен, идентичность или контекст ИИ.
Нельзя незаметно заменить кабинет под прежним storeId. Если проверка обнаружила другой кабинет — создать новый магазин и использовать явную смену привязки.

## Разрешение и исполнение пакета

Выбранный блок фиксируется при нажатии: accountId, conversationKey, storeId, bindingRevision, credentialRevision, текст/хеш блока и пакет команд.
Изменение popup после нажатия не перенаправляет уже запущенные запросы.
Обрабатываются только явные команды данного блока. Ответы, найденные в старой истории, цитатах, пользовательских сообщениях или другом диалоге, сами не исполняются.

Зависимая команда с reportId/cursor, который ещё не получен, не достраивается расширением. ИИ получает промежуточный результат и формирует следующий явный пакет.
Один разрешённый API envelope выполняет максимум один бизнес-запрос; локальный HELP — ноль. Сетевые служебные действия авторизации учитываются отдельно.
Ожидание локального разрешённого окна квоты перед первым запросом допустимо. После полученной сетевой ошибки/429 повтор требует новой команды пользователя.

Ошибка параметров отдельного элемента возвращается в его результате; последующие независимые корректные элементы могут продолжаться. Потеря авторизации сервиса, несовпадение магазина, смена сессии или Finish останавливают остаток.
Проверки безопасности и схемы выполняются до сети. При неоднозначной форме блока показывается ошибка разбора, без угадывания команды.
Смешанный блок HELP/API допустим при сохранении порядка. Нельзя прежним запретом HELP отменить принятое поведение актуального runtime.

## Доставка и остановка

Ответ содержит источник, магазин, операцию, время/период при наличии, полноту, данные или ошибку. Эти метаданные не заменяют пользовательское подтверждение правильного магазина.
Большой ответ передаётся файлом поддерживаемым адаптером, без молчаливого обрезания. Оригинальное имя сохраняется. Недоступность загрузки явно показывается; ссылка только на локальный объект не считается доставкой данных в ИИ.

Доставка может повторно использовать уже полученный локальный результат в пределах TTL без нового обращения к площадке.
Успешная запись файла подтверждается завершением транзакции хранилища. Потеря ответа после отправки запроса или неоднозначная доставка имеют состояние UNKNOWN, а не автоматически SUCCESS/RETRY.
Finish прекращает будущие действия. Уже принятый площадкой запрос нельзя отменить задним числом; уже отправленное сообщение ИИ может остаться в истории.
Остановка не удаляет ключи или пользовательский диалог.

## Безопасность и нецелевые функции

Команды не содержат секреты, произвольные HTTP-адреса, заголовки авторизации или исполняемый код. Контент страницы и вывод ИИ недоверенные.
Read-only определяется бизнес-эффектом операции, а не HTTP-методом. Политика персональных данных и прав проверяется кодом.
Нет редактирования цен, ставок, карточек; собственного LLM-инференса; хранения бизнес-контекста на сервере; облачного архива; автоматических многошаговых задач; команды «обойти ограничения».
Истечение/отзыв доступа сервиса и политика временной автономности описаны в [контрактах](../architecture/CONTRACTS.md), без запроса сервера на каждое действие.

## Изменение спецификации

Детали экранов и внешние API неизбежно уточняются по проверкам. Чтобы не переписывать проект заново, фиксируются границы, ID требований и переходы, а внешние неизвестные — в [OPEN_ITEMS](../decisions/OPEN_ITEMS.md).
Изменение принятой механики требует отдельного решения; исправление реализации под существующее требование нового продуктового согласования не требует.
