# Что подготовить владельцу

Актуальное уточнение: [ответы и решения владельца 2026-09-23](OWNER_DECISIONS_2026-09-23.md). При расхождении прежних вопросов/планов с этой записью применяется запись владельца.

Владелец не программист. Уже полученные ответы не запрашивать повторно. Для серверного ввода давать одну готовую команду и последовательные понятные подсказки; SFTP, правка JSON/SQL и настройка прав не являются обязанностью владельца. Адрес почты и наличие устройств не являются паролями; их можно сообщить обычным текстом. Токены, пароли, OTP, cookies, файлы ключей и исходные коммерческие отчёты в чат с ИИ не присылать.

## 1. Серверный Telegram

На Easyscript подготовлен каталог `/root/octoport-owner-intake` с правами 0700 и пустой файл `telegram.env` с правами 0600. Он находится вне Git, не подключён к сервисам и не меняет текущие A/B/C. Токен и binding уже предоставлены и проверены; текущий статус см. в записи решений владельца. Не вводить токен повторно без причины.

Файл содержит только три поля:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_OPERATOR_IDS=
TELEGRAM_NOTIFICATION_CHAT_IDS=
```

Порядок:

1. Создать своего бота через официальный `@BotFather`, либо выбрать уже созданного, который не обслуживается другой системой. Скопировать токен в свой менеджер паролей.
2. Открыть собственную приватную SSH/веб-консоль сервера и выполнить `python3 /root/octoport-owner-intake/fill_telegram.py`. Скрипт попросит токен скрытым вводом и сохранит в этот файл. Не запускать ввод секретов через чат/RDC-команды, которые видны модели. Альтернатива — изменить этот же файл через своё SFTP-подключение с сохранением прав 0600.
3. Указать числовой Telegram user ID администратора и chat ID доставки, если они известны. Это не `@username`, не телефон и не IP. Несколько ID разделяются запятыми. Личный ID положительный, ID группы может быть отрицательным.
4. Если ID неизвестны — оставить их пустыми, сообщить «токен внесён, ID нужны». После согласования короткого окна C получит только метаданные твоего сообщения **своему** боту и поможет подтвердить ID. Не привязывать первого случайного отправителя автоматически, не пользоваться сторонними ботами, которым нужен токен. Существующий polling нельзя дублировать вторым потребителем.
5. Самостоятельно открыть своего бота и нажать Start. Для группового назначения потребуются добавление бота и разрешение писать; поддержку тем не предполагать без проверки текущего кода.
6. Сообщить только «токен внесён; личный чат/группа; готов к проверке». C проверит наличие/формат без вывода значений, перенесёт настройки в выбранное защищённое окружение сервиса, проверит права и реальную доставку в согласованное окно. Факт заполнения файла не означает работающий мониторинг.

Скрипт ничего не отправляет Telegram, не запускает сервис, не читает старое значение в вывод и не спрашивает пароль Telegram. Последующий запуск бота и тестовое уведомление должны иметь указанный адресат/цель; текущая подготовка сама их не отправляет. После установки секретов C удаляет ненужную staging-копию по безопасной процедуре, оставляя единственный рабочий secret и запись статуса без значения. Ротация токена делает старый недействительным; это отдельное действие владельца при необходимости.

Если нет личного доступа к консоли/SFTP, сообщить это отдельно. Сначала решается доступ владельца к своему серверу; отправка токена в чат не является запасным методом.

## 2. Почта

Постоянный администратор и текущая стадия переноса: [OWNER_ACCESS.md](OWNER_ACCESS.md). В Octoport нет постоянного пароля: штатный вход через код почты.

Нужен один email, который ты можешь открыть во время проверки. B ждёт именно его. Второй тестовый email/алиас пригодится для проверки изоляции аккаунтов; ящик у другого провайдера дополнительно проверяет доставляемость.

Личный пароль от почты, app password и сам OTP разработчикам не нужны. Код вводится тобой в реальный портал. В отчёт попадают время доставки, «вход выполнен»/«письмо в спаме» и безопасный код ошибки. Если нужно исследовать заголовки письма, сначала исключаются адреса/идентификаторы, не нужные для конкретной причины.

SMTP_HOST/PORT/FROM/ENVELOPE_FROM уже заполнены в проверенном owner-test env; используется локальный почтовый транспорт. Пустые SMTP_USERNAME/PASSWORD при этой схеме сами по себе не ошибка. Нового почтового провайдера сейчас не заказываем.

## 3. Marketplace keys и реальные данные

| Что | Куда вводить | Для чего |
|---|---|---|
| Ozon Seller Client ID/API key | В карточку Ozon в установленном расширении | Продажи, товары, остатки, поставки, финансы |
| Ozon Performance credentials | В Performance-секцию того же магазина | Кампании, расходы, ДРР, часть юнит-экономики |
| WB token | В карточку WB в расширении | Доступные категории, подтверждённые при проверке |
| Ключ второго реального кабинета | В отдельную карточку | Реальная межмагазинная изоляция |
| Себестоимость/внешние расходы | В локальный выбранный файл для конкретного анализа | Полная прибыль; без него можно считать лишь явно ограниченный вклад |
| Старые выгрузки поиска | Локальные файлы владельца, когда нужен CAP-25 | Межмесячное сравнение; не серверный архив Octoport |

Не передавать эти ключи в серверный Telegram env. При серверном browser testing владелец сначала разрешает отдельный профиль/кабинет и сам вводит ключи в UI. Нельзя использовать чужие магазины, переносить личные сессии без разрешения или коммитить raw данные как fixtures. Синтетические fixtures и обезличенные примеры разработчики готовят сами.

От владельца не нужен список всех SKU/кампаний: расширение должно получать его через доступные API. Нужны только данные, которых API не знает, и независимые контрольные итоги для сверки.

### Готовые JSON — ввод через терминал

В своей консоли сервера запусти:

```bash
python3 /root/octoport-owner-intake/fill_marketplace_json.py
```

1. Открой JSON Ozon в обычном текстовом редакторе (например, Блокноте), выдели всё и скопируй.
2. Дождись подсказки Ozon и вставь содержимое в терминал. Ввод скрыт — отсутствие текста нормально.
3. Нажми Enter, напиши КОНЕЦ на новой строке и нажми Enter. После проверки введи ДА, чтобы сохранить.
4. Повтори те же действия с JSON Wildberries.
5. Сообщи только «JSON внесены». Значения токенов в чат не нужны.

Для пропуска шага введи КОНЕЦ без JSON. Ctrl+C отменяет текущий шаг; ранее подтверждённый файл сохраняется. Ошибка JSON не заменяет прежний файл. Скрипт поддерживает многострочные и длинные однострочные JSON до 2 МиБ, сохраняет исходный UTF-8 текст с правами 0600, ничего не отправляет в сеть и не активирует ключи. Если Performance находится в отдельном экспорте, сообщи об этом: не объединяй файлы вручную и не перезаписывай им экспорт Seller.

Исходник: `docs/product/readiness/fill_marketplace_json.py`, проверка скрытого ввода/отмены/прав: `docs/product/readiness/test_fill_marketplace_json.py`. Корректный JSON не означает совместимость importer или действующий API token; это отдельная проверка A/контроллера в разрешённом профиле.

## 4. Аккаунты ИИ и устройства

Указать доступные ChatGPT Standard/Work и Alice, браузеры/ОС, наличие Mac/Safari и второго устройства. Вход/2FA выполняется человеком в отдельном тестовом профиле. Пароли/cookies не передаются как файл через чат и не включаются в Git/evidence.

Одного входа навсегда недостаточно: сессия может истечь, сайт может потребовать CAPTCHA/2FA, лимит подписки может исчерпаться. Это отдельные повторные запросы с продолжением независимой работы. Обход защит не включается в план.

## 5. Исходная анкета — ответы уже зафиксированы, повторно не запрашивать

Можно ответить коротко, оставляя «не знаю» там, где нужен наш разбор:

1. Основной тестовый email: ___. Второй email/алиас есть: да/нет.
2. Telegram: бот уже есть/нужно создать; доставка мне лично/в группу; свой доступ к консоли или SFTP есть/нет. Сам токен не указывать.
3. Есть Ozon Seller: да/нет; Performance: да/нет; WB: да/нет; второй реальный магазин какой площадки: ___. Есть ли ограничения на отправку этих данных выбранному ИИ: ___.
4. Для проверок доступны ChatGPT Standard/Work/Alice: ___. Можно ли использовать отдельные тестовые профили на сервере: да/нет/только часть — какая.
5. Твои ОС/браузеры: ___. Есть Mac/Safari или доступный тестер: ___. Если нет: организуем среду или явно переносим Safari на отдельную волну?
6. Есть закрытый месяц с продажами, расходами рекламы и возвратами: ___. Часовой пояс учёта: ___. Себестоимость/внешние расходы есть в таблице: да/нет. Нужно ли в первом релизе обещать полную прибыль или пока только вклад после расходов площадки?
7. Publisher accounts Google/Mozilla/Opera/Apple уже есть: ___. Кто будет издателем и какой публичный support email: ___. Документы личности присылать только самому магазину при регистрации.
8. Сколько первых тестеров допускаем и какие окна удобны для ручной проверки: ___. Хранилище резервной копии вне этого сервера уже есть: да/нет/не знаю.

Это сбор фактов и нескольких продуктовых решений, не просьба владельцу выбирать схемы БД, API endpoints, миграции или способы синхронизации.
