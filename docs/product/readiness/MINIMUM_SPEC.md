# Детализированное ТЗ минимального Octoport

Актуальное уточнение: [ответы и решения владельца 2026-09-23](OWNER_DECISIONS_2026-09-23.md). При расхождении прежних вопросов/планов с этой записью применяется запись владельца.

Версия детализации: 2026-09-23. Нормативная основа — `docs/product/SPEC.md`, `UX.md`, `ADMIN_AND_WEB.md`, `docs/architecture/CONTRACTS.md`, `SYNC.md`, `docs/decisions/DECISIONS.md`. Идентификаторы SA-* сохраняются. Этот документ конкретизирует проверяемый результат, не объявляет функции реализованными. Неизвестные операции WB и решения владельца вынесены в отдельные gates; техническая проверка API — работа разработчиков.

## 1. Минимальный продукт и границы

Octoport — одно расширение для чтения разрешённых данных магазинов Ozon/WB из диалога выбранного пользователем ИИ. Пользователь имеет свой аккаунт ИИ; расширение не покупает вызовы модели и не использует API модели вместо web-интерфейса. Бесплатная зарегистрированная бета, backend аккаунтов/доступа/совместимости, минимальный портал, админка, поддержка и мониторинг входят в продукт.

Минимальные AI-поверхности: ChatGPT Standard, ChatGPT Work, Alice. Standard и Work проверяются отдельно. Мониторинг восьми AI-провайдеров не является поддержкой восьми провайдеров расширением. Новые ИИ включаются после адаптера и своей приёмки.

Сохраняется требование Chrome, Opera, Yandex, Firefox, Safari/macOS. Релиз канала разрешён только при доказательстве именно этого браузера. Перенос Safari на следующую волну — явное продуктовое решение владельца, не тихая правка списка ради PASS. Конкретные минимальные версии фиксирует release manifest после проверки; не писать выдуманные версии в ТЗ.

В бете нет оплаты, изменения цен/остатков/карточек/ставок, управления рекламными кампаниями, ответов покупателям, облачного архива бизнес-отчётов, общего кабинета сотрудников или собственного LLM API. Рекомендация по карточке — текст/файл для человека, не автоматическое редактирование карточки.

## 2. Карта пользовательского пути

| Этап | Действие пользователя | Обязательный результат | При отказе |
|---|---|---|---|
| Установка | Выбирает свой браузер и ставит проверенный пакет | Видны версия/источник/реальная совместимость | Инструкция для конкретного браузера; нет обещания неподтверждённого |
| Вход | Вводит email и полученный код в портале | Действующая сессия и подтверждённая установка | Различены неверный/истёкший код, лимит, доставка и закрытая регистрация |
| Добавление магазина | Выбирает Ozon/WB, вводит локальные реквизиты | Карточка магазина с именем и отдельными состояниями доступов | Сеть, отказ прав и доказанное истечение не смешаны |
| Подключение диалога | Сам открывает поддерживаемый ИИ, выбирает магазин, Start | Один текущий binding и стартовая инструкция | Неподдерживаемая поверхность/истёкшая authority объяснены |
| Вопрос | Задаёт деловой вопрос обычным текстом | ИИ выбирает известные возможности/HELP, формирует явный блок | Нет угадывания произвольных endpoint или просьбы человеку написать API |
| Чтение | Нажимает кнопку выбранного блока | Последовательное выполнение зафиксированного пакета | Ошибка конкретного элемента не скрывает остальные результаты |
| Отчёт | Получает текст/файл в том же диалоге | Видны магазин, период, источник, полнота; файл действительно доставлен | Нет ложного успеха по одному blob URL/отсутствующему attachment |
| Анализ | Получает ответ ИИ | Факты отделены от гипотез, суммы воспроизводимы | Неполные/недоступные данные не становятся нулями |
| Продолжение | Разрешает следующий явный блок | Новая страница/status/download исполняется осознанно | Нет скрытых повторов, polling, pagination или fanout |
| Завершение | Finish | Очередь/наблюдение остановлены, поздние callbacks отсечены | Уже ушедший запрос нельзя обещать отменить у площадки |

Термин Work означает рабочую сессию с локальной authority и устойчивым состоянием. Он не возвращает удалённую из продукта бесконтрольную автоработу ИИ. Автономность при недоступности control server не разрешает новые команды без предусмотренного пользовательского действия.

## 3. Экранные состояния и действия

### Popup — SA-UX-01, SA-SHOP-01..04, SA-AI-01

Сверху аккаунт Octoport и состояние доступа. Затем переключатель Ozon слева / WB справа, список магазинов выбранной площадки, добавление/переименование/проверка/удаление. Текущая привязка активного диалога показана отдельно от будущего выбора пользователя. Выбор другого пункта не переключает выполняемый пакет.

| Состояние | Видимые действия | Что запрещено |
|---|---|---|
| Не вошёл | Войти, объяснение device activation | Показывать ключи другого аккаунта или выполнять команды |
| Нет магазинов | Добавить, импортировать, получить с активного устройства | Ложное «ключи восстановятся с сервера» |
| Неизвестная страница/ИИ | Название причины, список поддерживаемых поверхностей | Вставка токенов/команд в произвольную страницу |
| Диалог не подключён | Выбор магазина, Начать работу | Подхватывать команды старой истории |
| Активен | Имя текущего магазина, Show/Hide, Finish, явная смена | Незаметная смена при движении переключателя |
| Пакет выполняется | Понятный прогресс/ожидание квоты, Finish | Второй запрос по повторному клику |
| Временный offline | Статус ограниченного автономного допуска и ожидающего sync | Маскировать известный revoke как сетевой сбой |
| Истёк допуск/отозвано | Обновить доступ/войти, объяснение | Новое чтение API вопреки authority |
| Результат не доставлен | Причина, допустимое повторение доставки локального результата | Повторять бизнес-запрос для имитации восстановления доставки |

Клавиатура, фокус, читаемые подписи и состояния не только цветом; проверка реальной ширины popup и масштабирования. Не добавляется вторая панель выбора магазина на странице ИИ. Закрытие popup не означает Finish.

### Магазин

- Имя по умолчанию Ozon 1/WB 1 с возможностью переименования; стабильный storeId не зависит от имени.
- Ozon Seller Client ID/API key и Performance credentials относятся к одному магазину и проверяются раздельно. Отсутствие Performance не выключает Seller.
- WB показывает подтверждённые категории/границы доступа. Декодированное содержимое токена само по себе не доказывает действительность/доступность метода.
- Операция «Проверить» не изменяет бизнес-данные. Привилегии определяются по фактам, не по одному 401/403.
- Подтверждённый другой кабинет при замене ключа требует новой сущности/явного выбора; нельзя сменить кабинет под старой активной привязкой.
- Удаление предупреждает о локальных сессиях и удаляет ключи текущей установки. Выключенный другой браузер не обещается очистить мгновенно.

### Смена диалога/магазина — SA-WORK-01..03

Start разрешён в существующем диалоге, но baseline отсекает старые команды. Повторный Start той же активной сессии идемпотентен. Ветка/новый conversation identity требует отдельного Start.

При явной смене показывается предупреждение: старые данные остаются в истории ИИ и могут влиять на ответы. Старая сессия завершается, создаются новый bindingRevision/workSession и новая инструкция. Поздний результат старой привязки не доставляется под новой. Установки и диалоги не склеиваются по названию вкладки.

## 4. Разрешение запросов и восстановление — SA-CMD-01..03, SA-QUOTA-01

На клик фиксируются account, conversation, store, credential revision, binding revision и полный выбранный блок. Команды только из разрешённого текущего assistant-блока; цитата, пользовательский текст, старая история и посторонняя вкладка не являются разрешением.

Одна явная бизнес-команда допускает не более одного соответствующего физического запроса; HELP не вызывает площадку. Классификация чтения идёт по эффекту операции: POST создания отчёта может быть разрешённым чтением, а GET сам по себе не доказательство безопасности. Служебная авторизация транспорта проверяется отдельно и не скрывает дополнительные бизнес-запросы.

Если следующий шаг зависит от нового cursor/reportId, ИИ получает результат и формирует следующий явный блок. Расширение не подставляет скрытую цепочку запросов. Batch из независимых команд допустим при сохранении учёта каждого элемента.

| Событие | Требуемое поведение и проверка |
|---|---|
| Неизвестная/disabled операция, неверный тип/период/пустой selector | Локальный отказ, 0 бизнес-запросов, runtime возвращается в рабочее состояние |
| 429 | Показать подтверждённую задержку; никаких скрытых повторов/бурстов; не провоцировать live 429 ради теста |
| Ответ потерян после отправки | UNKNOWN с возможной выполненностью; нет автоматического replay |
| Ошибка доставки уже полученного файла | Повторить только допустимую доставку локальных байтов до TTL; 0 новых provider-запросов |
| MV3 worker остановлен/браузер перезапущен | Восстановить зафиксированное состояние либо честно отменить незавершённый этап; не сообщать фиктивный SUCCESS |
| Finish/rebind/revoke/смена аккаунта | Late callbacks и старые разрешения больше не имеют authority |
| Лимит API одного кабинета | Общий бюджет внутри установки, независимо от переименования/числа вкладок |
| Два браузера без связи | Принята ограниченная независимость; не обещать exactly-once между установками |

## 5. Результаты, файлы и приватность — SA-DATA-01..02

Каждый результат содержит безопасную идентификацию площадки/магазина, операцию, период/часовой пояс, время получения, completeness/continuation и понятную ошибку при неполноте. Источник, дата и единицы метрик должны позволять проверить ответ ИИ.

Табличный результат не обрезается молча ради размера сообщения. Большой результат передаётся поддерживаемым файлом; частичный результат явно сообщает границу и следующий допустимый шаг. Успешное создание файла отдельно от его attachment/delivery acceptance.

Максимум один час — технический локальный буфер результатов расширения. Это не обещание удалить файл, который пользователь скачал, или сообщения из истории стороннего ИИ. Сервер Octoport не хранит отчёты/содержимое диалогов/ключи маркетплейса как архив. Диагностика не собирает сырой DOM, cookies, отчёты, OTP, токены и полный текст ответа модели.

CAP-25 исторически описывает накопление поисковой истории. В текущем продукте это **выгрузки, которыми управляет владелец у себя**, а не новый серверный или постоянный extension-архив. Анализ прошлых месяцев требует выбранных пользователем предыдущих файлов. Архив в продукте — отдельное будущее решение.

## 6. Ключи, аккаунт и перенос — SA-AUTH-01, SA-KEY-01..02

Ключи хранятся локально с изоляцией по аккаунту Octoport. Выход предлагает оставить для следующего входа или удалить. Другой аккаунт их не получает. Утрата почтовой сессии/восстановление аккаунта не восстанавливает потерянные marketplace keys.

Получатель инициирует перенос и подтверждает его. Источник должен быть включён, авторизован в том же аккаунте и иметь магазины; второго подтверждения на источнике нет. Серверный relay ограничен TTL/размером/квотами и передаёт защищённый payload, не служит постоянным хранилищем. A02+B03 принимаются совместно: остановка worker, таймаут, отзыв, повтор/ack и restart relay не создают ложного успеха или повторного применения.

Экспорт — один защищённый паролем файл всех магазинов текущего аккаунта. Пароль остаётся у пользователя. Импорт проверяет формат, показывает конфликт без секретов и требует явного выбора; совпадение имени не разрешает перезапись другого кабинета. Импорт не запускает старые команды и не переносит активную исполнительную привязку.

## 7. Backend, портал и админка

| Область | Минимум | Приёмка |
|---|---|---|
| Email OTP | Реальная доставка + ограничения/сроки/идемпотентность; различение mail/provider/product failure | Unit/PG/race и одна реальная цепочка через приложение; OTP только у владельца |
| Bootstrap | Подписанный v2 с account UUID для текущего клиента, сохранение v1 по контракту | Настоящая опубликованная совместимая цепочка; установленное расширение проверяет подпись |
| Авторизация | Атомарная refresh rotation, один refresh flight, отзыв устройства | Межаккаунтные отрицательные сценарии; expiry/offline grace строго по policy |
| Бесплатная бета | Новые регистрации по квоте, существующие входят; оплата/коммерческий device cap не подмешиваются | Race последнего места, повтор регистрации, закрытие набора без блокировки старых |
| Портал | Вход, активация, перечень установок, отзыв, установка/поддержка | Человек понимает браузер/ОС/последнее обращение; нет ложного online |
| Админка | Owner/Operations/Beta operator/Support в рамках принятых прав | Проверка права на каждом API, аудит, усиленная admin auth перед production |
| Диагностика | Добровольный просмотр пакета перед отправкой; correlationId/error/version | Отказ/отзыв согласия не ломает полезную работу; нет raw secret/data |
| Эксплуатация | Service user, лимиты ресурсов, pinned artifact, backup/restore/rollback | Реальная PostgreSQL и приложение после восстановления, не JSON-only rehearsal |

Активный backend snapshot не доказывает готовность catalog/profile compatibility. Найденный конфликт control_plane_v1/v2 — техническая задача B/C; email владельца его не исправляет.

## 8. Мониторинг и Telegram — SA-OBS-01

Мониторинг API/DOM выявляет изменение, формирует минимальное доказательство и уведомляет оператора. Решение/patch проверяет специалист; автоматическая публикация кода запрещена. Profile/config выбирает встроенные в пакет возможности, не доставляет удалённый исполняемый код.

No-session проверки публичных поверхностей возможны без личных аккаунтов. Authenticated composer/file/Work Health требуют отдельно разрешённого тестового профиля, фиксированного безопасного диалога и корректной обработки CAPTCHA/2FA/истечения сессии. Ни импорт личных cookies, ни обход защиты сайта не являются методом мониторинга.

Telegram: отдельный токен, user allowlist, список chat destinations, работающий service wiring, авторизация команд, dedup/retry/caps и privacy-safe уведомления. Критерий: владелец получает одну тестовую тревогу и восстановление, видит понятный сервис/симптом/действие; неавторизованный отправитель не получает операторские права. Создание функции sendMessage не закрывает этот gate.

При недоступной серверу официальной WB-документации допускается утверждённый ручной путь: видимый браузер владельца → официальный сайт → один `WB_OPENAPI_BUNDLE_V1` с 13 YAML → одно вложение боту → серверная проверка 13/13/источника/размера. Не просить 13 загрузок, ввод request_id и терминал. Пока бот не готов, этот путь не объявляется доступным.

## 9. Бизнес-возможности и применимость WB

Базовый список — все 45 строк [BUSINESS_SCENARIOS.tsv](BUSINESS_SCENARIOS.tsv), сгруппированные в продажи, запасы/логистику, ассортимент, цены/акции, возвраты, финансы, рекламу, SEO и межисточниковый анализ. Резервные STD-21..28 сохранены отдельно; они частично перекрываются по смыслу с CAP, но не удаляются.

Для каждого WB-сценария A/C заполняют: официальный version/hash, точные операции и read-effect, token class/category, схема идентификаторов, метрики и единицы, предел периода/страницы, quota, nullable/omission semantics, fixture и live evidence. Пока эта связка не проверена, колонка `API_MAPPING_REQUIRED` честно остаётся открытой. Количество методов в старом registry не заменяет функциональную приёмку.

Обязательные правила интерпретации:

1. Заказы, продажи, выкупы, возвраты, начисления и выплаты — разные показатели; нельзя переносить названия Ozon на поля WB без определения.
2. SKU/product_id/offer_id и nmID/chrtID/артикул/размер — разные ключи и уровни агрегирования. Таблица соединений проверяется до бизнес-вывода.
3. Склад продавца и склад площадки, FBW/FBS и Ozon FBO — не синонимы; статусы поставок адаптируются по WB.
4. Нулевой расход/остаток допустим только при доказанной полноте; отсутствие строки, 403 и неподготовленный отчёт не равны нулю.
5. ДРР — явно указанные расходы рекламы / сопоставимая выручка; метрики атрибуции рекламного API нельзя складывать с теми же продажами повторно.
6. Вклад после расходов площадки не называется чистой прибылью. Для полной прибыли нужны себестоимость, внешние расходы, учёт налогов и понятные правила распределения. Неполное покрытие расходов блокирует полное утверждение CAP-24.
7. Гипотеза причины падения не объявляется доказанной причинностью. Данные конкурентов, позиции и частоты не выдумываются из своей карточки.
8. Поисковая выгрузка CAP-25 проверяет уникальность бизнес-ключей и реальные ограничения сортировки/страниц; `page_count` не доказательство полного уникального набора.

Если у WB нет аналога конкретной Ozon метрики, можно принять корректный отказ как `PASS_BOUNDARY` по безопасности. Это **не** `PASS_FEATURE` для полноценной функции. Сокращение обещанного функционала требует видимой записи и решения, а не переименования неудачи.

## 10. Условия выпуска

Минимальный релиз требует: точную сборку/версию/хеш; закрытые критические security/data-loss/no-replay дефекты; актуальные контракты и миграции; реальные proofs заявленных браузеров/ИИ; явные результаты бизнес-сценариев; установленную mail/TG цепочку; восстановление БД/приложения; рабочую поддержку/privacy/инструкцию; готовый доступ ревьюера и разрешение владельца.

Пустой API catalog, отсутствующий bot token, неизвестный WB token policy, отсутствие Safari proof или непроверенная смысловая функция не превращаются в PASS успешной сборкой/CI. При разрешённой владельцем ограниченной волне публикации неподтверждённые каналы/возможности не рекламируются как доступные.

Цель по производительности задаётся измеримыми границами: нет сетевого control-вызова на каждую обычную команду/доставку, нет скрытого provider fanout, очереди/TTL/размеры ограничены, тяжёлые сценарии не блокируют UI без статуса. Числовые p95/квоты/TTL берутся из принятой policy и замеров exact RC; произвольные «всё за 2 секунды» не добавляются.
