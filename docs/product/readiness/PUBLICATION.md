# Магазины расширений и участие владельца

Проверено по официальным страницам 2026-09-23. Условия аккаунта, доступность оплаты/регистрации по региону и требования dashboard уточняются в настоящем аккаунте владельца. Не обещать фиксированный срок модерации.

## Когда начинаем

**Сейчас:** аккаунты издателя, подтверждение email/2FA/личности, имя издателя, support/privacy контакты и доступ к целевым устройствам. Это может занять внешнее календарное время и не должно впервые выясняться в день готовности кода.

**После устойчивого RC:** собрать точные браузерные пакеты, проверить содержимое/подпись/идентификаторы, подготовить listing, разрешения, privacy, screenshots, инструкцию тестирования и доступ ревьюера. Установка unpacked/developer build не равна подписанному магазинному пакету.

**После C06 и решения владельца:** подать готовый кандидат на review; отдельно зафиксировать режим публикации. Подготовка черновика/пакета не означает разрешение публично выпустить продукт. Нельзя подать неработающую заглушку только ради «занять очередь».

## Различия каналов

| Канал | Владелец | Разработчики | Граница |
|---|---|---|---|
| Chrome Web Store | Собственный Google publisher account, подтверждения/2FA, разовый registration fee по dashboard | ZIP, разрешения/приватность, описание/изображения, тестовая инструкция и доступ | При Submit for Review выбрать нужный режим. Документация допускает отложить публикацию после approval; есть 30-дневное окно, после него draft |
| Mozilla AMO / Firefox | Mozilla account с подтверждённой почтой | Пакет, необходимые исходники/инструкция сборки для reviewer, signing, listed/unlisted route | Подпись нужна для обычного Firefox release/beta, включая самостоятельную unlisted-раздачу; developer temporary install не заменяет её |
| Opera Add-ons | Opera publisher account, принятие условий | Upload, категория/лицензия/описание/иконки/screenshots/support page, совместимость | Проверить текущий процесс фактического выпуска после принятия; не обещать тот же defer-switch, что в Chrome |
| Yandex Browser | Отдельного выдуманного Yandex publisher account не требуется | Проверить конкретный пакет и маршрут установки | Официально используются совместимые расширения из Chrome/Opera каталогов; Yandex runtime всё равно имеет отдельный тест |
| Safari / App Store | Apple Account/2FA, индивидуальное или организационное enrollment, membership, App Store Connect | Safari-пакет, разрешения, карточка, тестовый путь/TestFlight, реальные runtime proofs | У Apple есть web packager без локального Mac/Xcode; его ограничения проверяются на нашем ZIP. Реальный Safari/macOS тест остаётся обязательным |

Apple указывает 99 USD за год Developer Program с региональными различиями; фактическая сумма/доступность в аккаунте владельца может отличаться. Для организации нужны соответствующие юридические данные/полномочия и, где применимо, D-U-N-S. Не просить владельца присылать документы личности в этот чат: они подаются самому Apple/магазину.

## Что нужно от владельца до review

1. Публичное имя и тип издателя, контролируемая почта, доступ к подтверждениям/оплате, выбранные страны распространения.
2. Контакт поддержки и privacy/deletion запросов; подтверждение фактов о владельце продукта для текста политики. Техническое описание обработки составляют разработчики по реальному коду.
3. Явное решение о первой волне: сохраняем весь заявленный browser scope либо публикуем подтверждённые каналы по мере готовности с открытыми ограничениями. Последнее не считается полной приёмкой оставшихся браузеров.
4. Подтверждение готовой карточки/ограничений и разрешение Submit/Publish. Действия с реальной производственной средой имеют отдельный exact-artifact план.

## Что готовит C без участия владельца в программировании

- Один проверенный artifact на канал: version, package hash, source SHA, contract/migration/profile compatibility, production endpoints и доверенные ключи из авторитетного input.
- Стабильная идентичность расширения/пакета и допустимые origins/device activation для магазинной сборки; developer ID не должен случайно остаться единственным разрешённым.
- Обоснование каждого permission/host permission и минимальный набор. Удалённый config не подменяет запрещённый remotely hosted executable code в Manifest V3.
- Честная privacy policy: локальные ключи; transient encrypted transfer; отправка выбранных отчётов стороннему ИИ по действию пользователя; account/device metadata; diagnostics; сроки; удаление/контакты. «Мы вообще ничего не передаём» неверно.
- Минимальные HTTPS страницы установки/поддержки/privacy и работающий portal login. Полный маркетинговый сайт/SEO не нужен для их подготовки.
- Безопасный reviewer путь. Если требуется вход, один демонстрационный аккаунт и синтетические данные через нормальный auth flow; никаких ключей владельца, доступа к его почте, постоянного универсального OTP или отключения авторизации ради review. C/B должны доказать, что ревьюер сможет сам завершить предоставленную инструкцию.
- Инструкция воспроизводимой сборки/исходники для магазина, когда требуются; clean install/update и минимальный smoke именно подписанного/выданного пакета.
- Подготовленный ответ модерации с фактами и проверками, без автоматической отправки от имени владельца без разрешения.

## Эксплуатация после публикации

Модерация может попросить уточнение или отклонить пакет; аккаунт может потребовать повторную проверку, membership — продление. UI ИИ и API меняются; понадобятся новые подписанные версии и иногда новые runtime/смысловые проверки. Ротация marketplace token или вход в AI-профиль остаются действиями владельца. Эти зависимости стоят в реестре, а не исчезают после первой подготовки.

Публикация в store и deployment backend — разные операции. При сбое необходимо понимать, можно ли отозвать/приостановить распространение, отключить несовместимую возможность существующей policy и восстановить backend. Нельзя обещать мгновенно откатить уже установленное у всех пользователей расширение.
