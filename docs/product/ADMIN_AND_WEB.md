# Аккаунты, сайт, админка и статистика

## Аккаунты

Сохраняем существующий passwordless email OTP и разделение пользователь / аккаунт / устройство.
В бете один владелец аккаунта; приглашения команды, должности сотрудников и общий корпоративный кабинет пока не создаются.
Ограничения OTP, повторной отправки, перебора и session rotation — техническая защита, не коммерческий лимит установок.
Первичная активация расширения использует принятый серверный device flow через авторизованный портал. Подтверждение активации не является дополнительным подтверждением переноса ключей в исходном браузере.

Портал показывает установки: понятное имя браузера/ОС, дата активации, последнее известное обращение, отзыв доступа. Не обещает точное online-состояние без постоянных соединений.
Отзыв применяется при следующем успешном обращении и ограничивается сроком автономного допуска; мгновенная блокировка выключенного устройства не гарантируется.
Восстановление доступа через подтверждённую почту не восстанавливает локально утраченные ключи: нужен активный источник либо файл.

## Минимальный сайт перед бетой

- Краткое описание «ИИ-сотрудник», поддерживаемых подтверждённых сценариев и требования собственного аккаунта ИИ.
- Регистрация/вход, состояние набора, активация расширения и управление установками.
- Установка по браузеру, видимые ограничения версии/ОС/ИИ, начало работы.
- Обратная связь с добровольным безопасным диагностическим пакетом.
- Понятная информация о данных: ключи локальны, исключение — согласованный перенос; результаты направляются выбранному ИИ.

Подробные воронки, публичное ценообразование и монетизация отдельно после MVP.
Минимальная страница установки нужна до приглашения беты; её нельзя откладывать на момент после публикации расширения.
Сайт не содержит универсальную командную консоль для магазинов и не становится хранилищем отчётов.

## Роли администратора

| Роль | Разрешено | Ограничение |
|---|---|---|
| Owner | Пользователи, роли, набор беты, эксплуатация, выпуск конфигурации | Чувствительные изменения с усиленной проверкой и аудитом |
| Operations | Состояние сервисов/установок, диагностика, подготовка профилей | Публикация профиля только при отдельном праве |
| Beta operator | Просмотр набора и изменение квоты | Выдаётся явно; не подразумевает доступ к ролям |
| Support | Поиск аккаунта, статус доступа и безопасные ошибки | Не видит ключи, содержимое отчётов и диалогов |
| Billing | Будущие платежные операции по отдельным правам | В бесплатной бете интерфейс платежей не активируется |

Права проверяются сервером для каждого действия, скрытие кнопки не защита. Административная сессия отдельна от клиентской; перед production требуется усиленная авторизация администраторов.
Нельзя давать ИИ административный токен со всеми правами. Будущий admin-AI ограничен разрешёнными действиями и явным подтверждением чувствительных изменений.

### Индивидуальные деревья подсказок ИИ

Администратор выбирает запись реестра ИИ, отдельно редактирует дерево подсказок и ответов и сохраняет черновик. Клиенты получают только отдельно проверенную опубликованную версию. Применяются существующие RBAC, CSRF и транзакционные проверки полномочий; новые права не выдаются. Полный контракт версий, конфликтов параллельного редактирования и подписанной доставки — [Per-AI hint and answer trees](../architecture/SYNC.md#per-ai-hint-and-answer-trees). Это согласованное требование, а не отметка готовности админки.

## Данные админки

Известные магазины: storeId, площадка, пользовательское имя, подтверждённый кабинет при наличии, наличие отдельных реквизитов в установках, последний известный результат проверки.
Количество магазинов считается по стабильным идентификаторам, а не числу сохранённых токенов/установок.
Активность: зарегистрированные, впервые подключившие магазин, впервые получившие результат, вернувшиеся пользователи; агрегаты успехов/ошибок и время поддержки.
Точные финансовые показатели продавцов, запросы к ИИ, сырые ответы API и файлы не собираются.

Расширение копит ограниченные счётчики событий локально и передаёт пачкой при служебном обращении. Повторная отправка не удваивает счётчики; потеря телеметрии не блокирует полезную работу.
Метрики поясняют задержку обновления и ограниченность наблюдения. «Нет событий» не равно «пользователь точно не работал».

## Обращения поддержки

Обращение содержит версию/канал/браузер/ОС/ИИ, код ошибки и согласованный обезличенный correlationId.
Диагностический экспорт предварительно показывает содержимое. Не включать секреты, cookies, полный DOM, текст диалога, исходные файлы или параметры с персональными данными.
Support различает ошибку расширения, ограничения API, ошибку доставки и ответ самой модели. Ошибки модели не выдаются за подтверждённые данные магазина.
