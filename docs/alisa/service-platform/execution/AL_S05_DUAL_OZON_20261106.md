# S05 · два доступа Ozon в форме добавления магазина

**SOURCE_CANDIDATE_NOT_INSTALLED.** По замечанию владельца Performance раньше был доступен только в карточке уже созданного магазина. Теперь форма добавления Ozon сразу показывает два отдельных блока: Seller API и необязательный Performance API для рекламы. У обоих свои Client ID и секрет. У WB остаётся один токен. Backend уже хранит раздельные SELLER/PERFORMANCE revisions одного store UUID; его API/schema/vault этой правкой не меняются.

Обе рекламные строки можно оставить пустыми. Частичная пара останавливает отправку и показывает, что нужно заполнить обе строки. После отправки секреты сбрасываются из DOM до первого await и не сохраняются в React state. Новый магазин создаётся одним прежним create command с Seller, затем Performance сохраняется прежним credential command именно в этот UUID с текущей revision. Только после сохранения обоих начинаются последовательные раздельные проверки; revision обновляется по каждому ответу. Ошибка Seller не препятствует сохранению рекламного секрета.

Это два отдельных серверных сохранения, не новая атомарная API операция. Если второе сохранение не подтвердилось, форма явно сообщает, что магазин уже создан, и предлагает проверить его карточку перед повтором; автоматических повторов create/check нет. Успех обоих сохранений не выдаётся при частичной ошибке. Рекламу по-прежнему можно добавить или заменить из существующей карточки.

Browser qualification проверяет обе пары в одной форме, запрет частичных рекламных данных без создания магазина, два раздельных канала одного UUID, Seller-only вариант, сохранность/проверку Performance при отклонении Seller, отдельный injected second-save failure, отсутствие секретов в формах/API и прежние WB/session/tenant/replacement сценарии. Synthetic peer не доказывает реальную привязку Ozon. Performance IDENTITY_NOT_VERIFIED и прежний Seller binding gate сохраняются; этот UI patch не включает их фиктивно.

Текущая установленная версия до этой правки — web d991, API6098; [предыдущий отчёт](AL_S05_SESSION_EXPIRY_20261106.md). Перед включением нужны точные CI/package и независимый source review. Установка меняет только web component на основном https://alisa.octoport.ru/app/stores; перенос админки/Identity, миграции и импорт чужих ключей не входят в задачу.
