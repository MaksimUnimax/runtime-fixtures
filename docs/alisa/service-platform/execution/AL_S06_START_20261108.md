## Ближайшая реализация и проверка

Сначала изучить контракт уже работающего native OAuth и его реально загруженную настройку, затем определить минимальный мост между подтверждённым клиентским кабинетом и отдельным skill grant. Не просить новое приложение или новый клиент, не проверив существующий. Одинаковая почта, подпись магазина или совпавшее имя не являются разрешением на автоматическое объединение аккаунтов.

Кабинет должен показывать статус подключения Алисы, голосовую приватность, отзыв и повторную привязку. Авторизацию навыка и браузерный OIDC нельзя смешивать: token/refresh должны отдавать протокольный JSON, а действующие grants лабораторного навыка сохраняться. Приёмка включает настоящую консоль Диалогов, возврат в тот же аккаунт, refresh, unlink/relink, сохранение срока доступа и изоляцию чужого tenant. Поддельный клиент и mocked API не заменяют этот результат.

## Реализованный кандидат

В рабочую ветку сохранены исходники установленного сайта `917600ca66cd6afaaf906ec468078cbd6eaba083` из git bundle с Easyscript: себестоимость, каталог товаров и 30-дневная сессия. Чужая рабочая копия не менялась. Исправление прямого входа Identity и квалифицированная native-привязка Ozon остаются в объединении. Эта интеграция исходников не означает, что остальные текущие обновления native/Station или админки уже попали в пакет: их preimage нужно сверить отдельно перед установкой.

Добавлено приложение `alice_link` с отдельными additive-таблицами. OAuthlib 4.0.1 выполняет протокол authorization_code/refresh/revoke; браузерный OIDC не заменяется. Согласие связано с конкретной WebSession и проверяется вместе с Customer, Tenant, Membership и security revision. После входа анонимный запрос связывается один раз до показа согласия. Код одноразовый, живёт 120 секунд; access — 600 секунд, refresh — 14 дней. При refresh сохраняется один refresh и зашифрованный ответ для повтора в течение 30 секунд; проверка истечения и отзыва выполняется до возврата ответа. Unlink отзывает семейства и ожидающие согласия. Голосовая приватность включена по умолчанию и изолирована между аккаунтами.

Новые маршруты сайта: `/app/alice`, `/app/alice/connect`, `/alice/oauth/authorize`, `/alice/oauth/token`, `/alice/oauth/refresh`, `/alice/oauth/revoke`, `/alice/platform/webhook`. Старые `/oauth/*` и `/alice/webhook` лабораторной связки не меняются. Новый webhook сообщает только о привязке; финансовые результаты остаются в AL-S07. `user_id` Яндекса не является основанием доступа. Один лишь успешный token exchange ещё не даёт статус CONNECTED: требуется валидный запрос навыка.

Включение требует `ALISA_ALICE_LINK_ENABLED=1` на web/platform, существующих skill client ID/secret и skill ID только на platform и отдельного `ALISA_ALICE_DATA_KEYS`. Значения не опубликованы. По умолчанию функция выключена. Потребность в новом приложении Ozon или новых ключах магазина не вводится. Анонимные согласия ограничены 60 в минуту и 5000 в сутки; действующий account cleanup очищает истёкшие согласия и короткие зашифрованные retry-ответы конечными порциями.

Предварительное независимое review запросило фиксацию WebSession, разделение service-секретов, строгий S256 challenge и лимит анонимных запросов. Исправления внесены; окончательный вердикт ещё не получен. Быстрые проверки используют настоящий OAuthlib/Django на отдельной SQLite, без сети. PostgreSQL-прогон дополнительно проверяет одноразовый эффект при одновременном обмене кода, одинаковый retry-ответ при одновременном refresh, гонку refresh/unlink, сохранение ключей магазина и подаренного доступа. Browser-прогон использует пакет, настоящий локальный IdP с паролем и письмом, раздельные аккаунты и HTTPS. В нём граница брокера Яндекса перехватывается; это не выдаётся за настоящую консоль Диалогов.

Первый общий локальный прогон остановился на отсутствующем `jsonschema` в scratch-зависимостях: 73 проверки прошли, одна не запустилась. Архитектурная граница и специализированные OAuth-проверки прошли. В CI исходного кандидата `7ce8e7c8366f1bf4835e51a8373f3d1ccf70b2ae` locked build, runtime, staff, access, stores и packaged PostgreSQL/browser прошли. Все 22 проверки AL-S06 на отдельном PostgreSQL, включая конкурентные запросы и неизменность ключей/подаренного доступа, прошли без пропусков. Полный Identity/browser остановился до входа на ошибке порядка инициализации списка секретов в самом новом harness (`UnboundLocalError`, строка 109); она исправлена. Полный повтор ещё не завершён.

После окончательного review добавлена блокировка самой WebSession до повторной проверки сессии: обычный UPDATE logout использует ту же блокировку, поэтому завершившийся первым logout не позволяет последующему consent выдать код. Новый PG interleaving-тест проверяет реальное ожидание row lock через `pg_blocking_pids`. Очистка истёкших Alice-envelope теперь вызывается и при выключенном admission-флаге; отдельный PG-тест вызывает действующий `accounts_cleanup` с флагом OFF. Для token/refresh/webhook внутренний timeout сокращён до 3,5 секунды, чтобы оставить время внешнему транспорту; browser-прогон измеряет refresh, но не заменяет измерения настоящего Яндекса.

Повторная read-only сверка установленного API обнаружила чужие более свежие изменения staff session в `alisa-staff-session-r1-20261108`; они принадлежат параллельной работе с админкой. Их файлы и режим работы этой задачей не меняются. Перед установкой AL-S06 необходим overlay только web и новых platform-путей с сохранением этих точных активных staff-файлов. Текущий native/Station также обновляется другим исполнителем и не подлежит откату из пакета AL-S06. Запас диска на Алисе находится близко к установленному пределу 3 GiB; установка не должна пересекать этот предел.

Первичные протокольные источники: [настройка сервера Яндекса](https://yandex.ru/dev/dialogs/alice/doc/ru/auth/create-server), [порядок авторизации навыка](https://yandex.ru/dev/dialogs/alice/doc/ru/auth/how-it-works), [OAuthlib RequestValidator](https://oauthlib.readthedocs.io/en/latest/oauth2/validator.html). Callback фиксирован: `https://social.yandex.net/broker/redirect`; token/refresh возвращают JSON без OIDC-redirect.

**Действия владельца:** сейчас не требуются. **Следующий шаг AL-S06:** полный locked CI и независимое review точного кандидата; затем сверка активных параллельных изменений перед установкой. Текущая лабораторная связка продолжает работать отдельно.
