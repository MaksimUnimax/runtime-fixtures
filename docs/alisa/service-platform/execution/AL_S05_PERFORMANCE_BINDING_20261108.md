# AL-S05: рекламный доступ Ozon — актуальное состояние

Исправление установлено на https://alisa.octoport.ru/ и использует обе уже работающие серверные пары ключей. Новое приложение Ozon, OAuth-регистрация или новые ключи не нужны. Прежний запрос этих действий был ошибочным и отменён; [PR 401](https://github.com/MaksimUnimax/runtime-fixtures/pull/401) закрыт как superseded.

Seller и Performance проверены с реальными ключами через работающий checker. Для существующей квалифицированной пары Performance возвращает CONNECTED с явным происхождением NATIVE_OWNER_CONFIGURED_PAIR; это не выдаётся за provider-issued crosswalk. Неизвестная пара остаётся непроверенной.

Установлен конечный обработчик повторного запуска checker: при неизменённом квалифицированном источнике обновляются только process generation и производный MAC. Другие ключи, scope, изменения разрешений и квалификаций автоматически не принимаются. Native core, web, identity, admin и клиентская БД этой установкой не менялись.

[Полный результат и ручные шаги](AL_S05_NATIVE_PAIR_20261108.md). [PR 402](https://github.com/MaksimUnimax/runtime-fixtures/pull/402). Код и пакет прошли CI; реальные setup-check Seller/Performance и защита границ прошли отдельно. Owner-переход карточки, рекламные отчёты, финансовый и голосовой путь пока не заявлены. Общая AL-S05 остаётся открытой в этих границах.

**Действия владельца:** заново вводить ключи не нужно. Для обновления старого сохранённого результата открыть [Мои магазины](https://alisa.octoport.ru/app/stores), нажать «Обновить список», затем «Проверить новый ключ» в «Реклама Ozon». Ожидается «Текущий ключ, версия 1: Подключение подтверждено».

**Следующий шаг:** обычный пользовательский переход карточки и оставшиеся реальные сценарии AL-S05; следующий блок roadmap — AL-S06. Чужая активная матрица и RuntimePort не входят в эту поставку.
