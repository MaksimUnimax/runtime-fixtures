# AL-S05: подтверждение связи рекламы Ozon с магазином

## Что сделано

Пакет исправлений входа **AL-S02** установлен и проверен: [результат](AUTH_NAVIGATION_20261108.md). Это не закрывает весь AL-S05.

По **AL-S05** Seller и Performance сохраняются отдельно в одной карточке. Настоящая пара Performance успешно получает токен, но не возвращает доказательства общего кабинета с сохранённым Seller-доступом. Предыдущий минимальный живой probe и границы вывода сохранены в [исследовании](AL_S05_OZON_IDENTITY_RESEARCH_20261106.json) и [безопасном receipt](s05-real-keys-20261108/performance-identity-probe.json).

Дополнительно проверен конкретный предполагаемый способ сопоставления: числовой префикс существующего Performance Client ID **не совпадает** с Seller Client-Id владельца. В отчёт записаны только булевы значения, без самих идентификаторов или секретов. Значит, разбор префикса не решает этот реальный случай. Новых запросов к API с ключами и изменений файлов credentials не было.

В официальном [анонсе Ozon от 6 апреля 2026](https://dev.ozon.ru/news/691-Performance-API-Optimizatsiia-kontrolia-dostupov-cherez-OAuth/) описан общий OAuth-доступ к двум API с выбранными разрешениями, включая роль для чтения. Это кандидат для полноценного подключения, а не доказательство принадлежности уже сохранённой старой пары ключей. В [официальном описании OAuth](https://dev.ozon.ru/start/450-Protsess-OAuth-avtorizatsii-dlia-dostupa-k-Ozon-Seller-API/) `sub` имеет разный смысл для `authorization_code` и `client_credentials`; подменять один другим нельзя.

Полный точный контракт Performance пока не получен. Публичная страница не даёт читаемого описания в поисковом fetch. Прямая ограниченная загрузка официального Swagger с разрешённого сервера возвращает HTTP 307 и `text/html` вместо JSON; результат сохранён в followup исследования. URL подтверждён существующим registry API Watch. Обход challenge, смена идентичности браузера или перебор адресов не выполнялись.

Работающая версия сайта, ключи, Seller-подключение, статусы карточки и конфигурация не менялись. Реклама не объявляется подключённой по одному факту получения токена. Новая регистрация приложения Ozon пока не запрашивается: сначала нужен точный поддерживаемый контракт.

## Действия владельца

Нужен только общедоступный файл описания API — без токенов, паролей и cookies.

1. В обычном браузере открыть [официальный Performance Swagger JSON](https://docs.ozon.ru/api/performance/swagger.json).
   Ожидаемый результат: скачивание JSON или его отображение в браузере. В файле должны быть `openapi` либо `swagger` и раздел `paths`.
2. Если JSON отображается как текст, сохранить его через Ctrl+S под именем `ozon-performance-swagger.json`.
   Ожидаемый результат: файл JSON с описаниями методов, а не HTML-страница.
3. Прикрепить этот файл в текущий диалог.
   Ожидаемый результат: доступен официальный контракт для проверки способов привязки и реализации. Никакие живые ключи повторно отправлять не нужно.

Если вместо JSON остаётся проверка доступа/страница ошибки, зафиксировать её текст; не выдавать HTML за Swagger. Этот внешний вход блокирует доказанную реализацию привязки, а не уже работающие Seller и вход.
