# Проверка реальных ключей магазинов · 8 ноября 2026

На https://alisa.octoport.ru/app/stores установлено исправление проверки ключей. Seller Ozon и WB проверены реальными ключами через установленный platform adapter, защищённый Unix socket и действующую службу проверки. Это не приёмка финансового отчёта, голосового сценария или действий в браузерной сессии владельца.

## Что исправлено

Seller возвращал `IDENTITY_NOT_VERIFIED` даже после HTTP 200: существующий флаг квалификации привязки Client-Id/API-key оставался выключенным. Реальная правильная пара дала HTTP 200 со строгой схемой company; замена Client-Id и отдельно API-key дала по HTTP 401. После независимого review включён существующий `--seller-binding-qualified`. Каноническое внутреннее имя остаётся `ozon:client:<normalized Client-Id>`; оно не переименовано в provider seller_id.

Performance принимал client_credentials, но прежний код безусловно возвращал `IDENTITY_NOT_VERIFIED`. Теперь строго проверяются access_token, Bearer и положительный целый expires_in. Правильный ответ даёт `AUTHENTICATED_UNLINKED`: рекламный ключ принят, связь с этим Seller-кабинетом не доказана. Новый ключ остаётся PENDING, verified_identity не присваивается, финансовые/рекламные отчёты не запускаются. Некорректный HTTP 200 не превращается в успешную проверку.

В карточке появился явный текст «Ozon принял рекламный ключ. Связь с этим магазином ещё не подтверждена; рекламные отчёты пока недоступны». Из общего footer удалено устаревшее безусловное утверждение о невозможности подключения магазинов.

Сохранённые владельцем обе пары в единственной карточке «Кровь и Песок» совпали с исходными серверными ключами; в доказательства записаны только булевы результаты сравнения. Ключи не импортировались в другие аккаунты и не попадали в Git, отчёты, вывод или аргументы процессов.

## Ресурсы и сохранность

В собственной неактивной b8-версии объединены 118 побайтно одинаковых файлов зависимостей после проверки owner/mode/xattrs/hash/nlink и активных inode. Пути, содержимое и архивы сохранены; удалено 0 путей, затронуто 0 активных inode. План был 67 379 200 байт, прирост свободного места в этом запуске — 67 366 912 байт; посторонние изменения свободного места не приписаны этому действию. Исходные метаданные сохранены приватно. Неуспешный 9b-plan и неисполненный c866-plan оставлены как история, без мутаций. Успешный PLAN_ONLY ранней c866-версии имел exit 1; интерфейс исправлен на явные plan/apply с exit 0 для завершённого плана.

Финальный readback: 3 378 135 040 свободных байт при обязательном резерве 3 221 225 472; 513 046 inode. Существующие конфигурации входа, почты, vault и назначения администраторов сохранены. Миграций и прямых записей в клиентские строки БД не было.

## Что остаётся открытым

Последний read-only просмотр реальной карточки показывает обе прежние PENDING revision 1 с историческим `IDENTITY_NOT_VERIFIED`: никакие статусы в БД вручную не менялись. Владельцу нужно обновить страницу и нажать «Проверить новый ключ» отдельно у Seller и рекламы. Повторно вводить ключи не нужно. Ожидаемый Seller — «Подключение подтверждено»; Performance — явное сообщение о принятом ключе и неподтверждённой связи.

Нет приёмки реального owner browser / authenticated BFF mutation. Нет доказательства связи legacy Performance client_credentials с тем же Seller-кабинетом; успешный token endpoint не заменяет такое доказательство. Полное подключение рекламы требует официальной привязки кабинета/Ozon OAuth с согласием продавца. Общий platform health по-прежнему сообщает `RUNTIME_NOT_CONNECTED` для аналитического report gateway; клиентский финансовый/голосовой сценарий этим исправлением не объявлен работающим.

Точные безопасные доказательства, процедуры и CI receipts находятся в [s05-real-keys-20261108](s05-real-keys-20261108/). Секреты и приватные download URLs туда не включены.
