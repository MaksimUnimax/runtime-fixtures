# Основной адрес сайта Алисы — alisa.octoport.ru

Прямая команда владельца 5 ноября 2026: сайт должен открываться на https://alisa.octoport.ru/, а не на техническом alisa-stage. DNS и действующий сертификат уже покрывают оба имени; на основном имени обнаружена инфраструктурная заглушка.

Переключается основной browser origin текущего принятого приложения: сайт, кабинет, canonical и callback. Для текущей среды это явный ALISA_CANONICAL_SITE_ENABLED=1, с точным доменом и прежним закреплённым issuer https://id-stage.octoport.ru. Эта команда меняет внешний адрес действующего приложения; не создаёт новую prod-БД и не копирует тестовые данные в production. Внутреннее имя конфигурации stage само по себе не является адресом пользователя. Полное разделение новой production-среды по исходной v0.5 остаётся отдельным инфраструктурным результатом.

Issuer, person, subject, client ID, секреты и продуктовые аккаунты сохраняются. В существующем OIDC-клиенте адрес нового callback добавляется явно, без wildcard, смены secret и нового pairwise subject. Старый callback сохраняется в реестре для обратимой настройки; frontend канонического origin его не выбирает.

Старый browser origin перенаправляет GET/HEAD на основной. Старый /auth/callback не переносит code/state в новый origin: предлагает начать свежий вход. Старый POST не переигрывается автоматически. ACL и Basic auth инженерных маршрутов сохраняются; admin/id-stage/lab не перенаправляются и не меняют учётные записи.

До закрытия: точный source/пакет и независимый обзор; регрессия OIDC/BFF; nginx -t; проверяемый HTTPS; обычные страницы на основном имени, старые redirects, регистрационная форма и реальный вход в прежний кабинет с кодом из Gmail. Подготовка этого документа ещё не доказывает установку.
