# AL-S16: установлен отдельный Swagger Watch

На Алисе работает отдельная служба получения и сравнения официальных Swagger Ozon/WB по аналогии с API Watch Октопорта. Она использует общий код acquisition/registry/inventory/diff, проверяет только публичные API-документы и не запускает мониторинг ИИ. Это выполненное раннее поручение по AL-S16 для поддержки AL-S05; полные шаги роадмапа остаются открытыми.

| Источник | Проверенный установленный результат |
| --- | --- |
| Wildberries | 13/13 документов автоматически загружены и проверены, 309 операций |
| Ozon Seller | Официальная загрузка возвращает HTTP 307 вместо JSON; документа пока нет |
| Ozon Performance | Официальная загрузка возвращает HTTP 307; переданный владельцем документ сохранён после review: 47 путей, 48 операций |

Периодический запуск включён: 6 часов; заблокированные Ozon источники повторяются не чаще 24 часов. Снимки и изменения сохраняются с SHA256; последняя исправная версия сохраняется при сбое. Документ владельца отмечен OWNER_SUPPLIED_REVIEWED и не получает ложную дату автоматической загрузки. Ни ключи магазинов, ни клиентская БД, ни матрица этим процессом не используются. Новая схема не меняет автоматически работающий код интеграций.

Source `7cbe3059a83677aeb42a086898a48067918f16a2` прошёл все три профильные CI: Swagger(shared148 + product16), документация, полная платформа. Установленный пакет и units совпали с контрольными суммами CI. Реальный завершённый watcher exit0, timer enabled, status active. Четыре прежних readiness остаются READY; действующие pointers, процессы и настройки приложений сохранены. [Полный ход, CI, ограничения и исправления](swagger-watch-20261108/PROGRESS.md), [проверка установленного результата](swagger-watch-20261108/installed-verification.json), [независимый review receipts](swagger-watch-20261108/installed-independent-review.json), [PR400](https://github.com/MaksimUnimax/runtime-fixtures/pull/400).

В ходе установки устранены ошибки прав каталогов и ожидания nginx reload. Первый сбор остановился из-за 117,6 МБ заново созданных временных APT indices. После независимой проверки удалены только два восстанавливаемых бинарных cache-файла; исходные lists и установленная база пакетов сохранены, генерация этих cache-файлов отключена обратимой настройкой. Повторный сбор WB прошёл. Ни резерв 3 GiB, ни квоты не уменьшались.

## Действия владельца

Для продолжения работы не требуются. Необязательная проверка руками:

1. Открыть [статус Swagger](https://alisa.octoport.ru/health/swagger). Ожидается JSON с `product_id: alisa_market`, `scope: PUBLIC_OPENAPI_DOCUMENTS_ONLY`, `llm_monitoring: false`.
2. Найти `WILDBERRIES` в `families`. Сразу после успешного сбора `expected_documents`, `available_documents`, `fresh_documents` равны 13; `complete: true`.
3. Найти документ `OZON_PERFORMANCE`. Ожидается `last_good.origin: OWNER_SUPPLIED_REVIEWED`, `operations: 48`, `fresh: false`. У обоих Ozon `outcome: OPERATOR_SOURCE_REQUIRED`, `http_status: 307`; общий `status: DEGRADED` относится к неполному покрытию Swagger Ozon.
4. Обновить страницу. Меняется `generated_at`, возраст автоматически загруженных документов растёт; простое открытие страницы не запрашивает кабинет магазина и не запускает финансовые отчёты. Если источник позже обновится или устареет, статус покажет текущее состояние.

HTTP503 у этой страницы соответствует DEGRADED мониторинга документов. Работоспособность сайта проверяется отдельными readiness; в установленной проверке все четыре READY. Подтверждение рекламы в карточке магазина этой службой не добавлено.
