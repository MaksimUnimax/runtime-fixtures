Scope: stores models/migration/service, dedicated encrypted vault, customer BFF/UI, strict RT-CHECK client contract, focused PostgreSQL/socket/browser qualification. Новые таблицы принадлежат alisa_market и tenant. Секрет вводится только владельцем этого кабинета; из расширения/старого runtime он не импортируется. Setup разрешён без оплаченного периода.

Store UUID неизменен; название и голосовой псевдоним не являются идентичностью площадки. Provider identity принимается только из проверенного RT-CHECK. Подтверждённый дубликат ограничен одним tenant/provider; сведения другого tenant не раскрываются. Seller/WB и Performance имеют отдельные revisions/status. Новый ключ сначала pending; активная ревизия переключается только после проверки того же кабинета и CAS. Отключение/удаление отзывает pending/active secrets и увеличивает revision. API не возвращает secret, ciphertext, identity fingerprint или secret_ref.

Vault использует отдельные platform-only ключи Fernet, отдельно от Identity/BFF. В encrypted envelope закреплены environment/product/tenant/store/kind/revision. Ciphertext хранится только в отдельной vault table; credential metadata содержит ссылку. Старые секреты при замене очищаются, ревизии и safe audit сохраняются. Dedicated keyring подаётся приватным конфигом; без него capability закрыта.

Mutation UUID и payload digest привязаны к customer/tenant/action; повтор возвращает сохранённый безопасный результат, изменённое тело — conflict. Validation claim сохраняется до внешнего вызова, HTTP/IPC выполняется вне DB transaction, итог применяется только при текущих customer security/store/credential revisions. Прерванный check не становится CONNECTED и не повторяется автоматически. Новый явный check допускается после срока предыдущей попытки.
