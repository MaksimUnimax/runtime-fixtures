## Использование клиентской границы

`RuntimeClient` получает путь/UID доверенного сервиса, все ожидаемые current_versions и настоящий платформенный Authorizer. `prepare(operation)` возвращает свежий утверждённый контекст; `current(context, operation)` повторно проверяет действующие права. Оба метода обязательны. Контекст не принимается из запроса браузера. Caller задаёт исходные UUID request/logical/trace; клиент не создаёт другой ID после потери ответа.

Операции: current_versions, capabilities, submit utterance, status(job_ref), read_result(job_ref), cancel(job_ref, request_id). Submit receipt означает ACCEPTED. Для неоднозначного submit/cancel RuntimeFailure содержит `outcome=UNKNOWN`, `retryable=False`: вызывающий код сохраняет прежний UUID и не считает это доказанным отказом или разрешением нового расчёта. До независимой приёмки текущая платформенная DisconnectedRuntime и рабочая связка навыка сохраняются.
