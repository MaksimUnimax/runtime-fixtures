## Что теперь исполняется в проверенном пакете

Отдельные admin OIDC client, host-only cookie, key, BFF и service authority. Успешный штатный TOTP/recovery event привязан к одному authorization request и фактическому одноразовому библиотечному code; затем подписанные MFA claims проверяет реальный BFF. Старый MFA label, наличие настроенного фактора, другой flow и повтор code не выдают доступ. Первый фактор passwordless-пользователя требует свежего native email-code login.

В браузере пройдены настройка TOTP, native step-up для recovery codes, новый TOTP для входа, OWNER, два реальных клиента S02, отдельные заявки, карточка, локальная блокировка/разблокировка и сохранение global identity. Назначен ADMIN только с users.read; его прямая команда блокировки отклонена backend. Отзыв staff закрыл два независимо вошедших браузера. Подмены missing/stale/type/acr MFA claims отклонены реальным BFF. Аудит и logout проверены без контактов/секретов в журнале.

Native core дополнительно проверил конкурирующие одинаковые commands с одним эффектом/revision, изменённый payload под тем же UUID, последний OWNER, чужой product scope, свежесть MFA, права runtime на append-only audit и очистку только собственных staff payload.
