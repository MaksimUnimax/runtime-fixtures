## Реализовано в исходниках

- Отдельные admin OIDC client, host-only cookie, session key, BFF и service authority. State/nonce/PKCE/issuer/audience/signature проверяет pinned OIDC library; ID token дополнительно требует согласованные подписанные native MFA claims.
- Успешный штатный `authenticator_used` TOTP/recovery event привязан к текущему authorization request; evidence помещается в тот же зашифрованный cache record, что и фактический библиотечный code. При выпуске code browser evidence потребляется. Старые authentication labels, наличие фактора, другой flow и повтор code не заменяют новый native event.
- Закрыта особенность pinned библиотеки: первый фактор passwordless-пользователя можно настроить только после свежего native email-code login (300секунд), а не по старой identity session. Собственной проверки OTP/подписи нет.
- Flow/session API, текущие server permissions/revisions, именованные OWNER/ADMIN, защищённый bootstrap/последний OWNER, UUID command receipts с fingerprint. Повтор команды проверяет актуальные права, другой payload под тем же UUID получает конфликт.
- Реальные read/command routes для клиентов, отдельных заявок, staff, сессий и безопасного аудита. UI содержит поиск, карточку, локальную блокировку/разблокировку, назначение ограниченного ADMIN, отзыв staff и сессии. Публикация каталога/возвраты/деньги не объявляются реализованными.
- Очистка стирает свои истёкшие/отозванные staff payload и сохраняет другой product scope. Readiness учитывает staff schema. В source nginx-example admin callback query исключён из access log; live nginx не менялся.
