# AL-S02: вход сразу через форму, без промежуточного подтверждения

Владелец сообщил, что Seller и Performance ключи подтверждены в кабинете после [исправления AL-S05](AL_S05_NATIVE_PAIR_20261108.md). Это owner-reported результат; он не заменяет ещё не выполненную приёмку рекламных отчётов. Продолжение по roadmap — AL-S06 после исправления текущего замечания входа.

## Замечание и результат изменения

При действующем Identity-входе и отсутствующей сессии сайта пользователь видел страницу «Подтвердите вход в кабинет» с единственной кнопкой, после которой всё равно открывалась форма. По прямому указанию владельца этот лишний шаг убран из клиентского пути.

Проверенный customer OAuth target сразу открывает штатную форму электронной почты и пароля. GET сохраняет текущий Identity-вход. Только защищённый CSRF POST этой формы завершает старый SSO и передаёт введённые реквизиты в native allauth LoginView. Пароль, свежий код из письма, rate limits, PKCE, подписи, state/nonce и разграничение клиентов сохраняются. Старые success-сообщения не показываются. Административная MFA и повторное подтверждение настроек безопасности идут по прежнему маршруту.

Пять изменённых исходников независимо проверены: [review](direct-login-20261108/source-review.json), [дополнительная проверка реального browser-сценария](direct-login-20261108/source-review-r2.json). Добавлены проверки прямой формы, сохранения SSO на GET, отказов CSRF/чужого target без logout, неверного пароля без отправки кода и без повторного использования SSO, обязательного свежего почтового кода, возврата в тот же аккаунт и того же OAuth target. В браузере второй собственный клиент теряет только cookie сайта, затем проходит пароль и доставленный код без промежуточного клика; проверяется сохранение tenant и количества клиентов.

**Статус:** SOURCE_REVIEWED; CI и установка ещё не выполнены. В текущий момент новая версия на сайте не заявлена.
