# Общая учётная запись и проверка реальной почты — 2026-11-05

## Требование владельца

Клиенты и администраторы у Алисы и Октопорта — одни и те же люди. Разные кабинеты до объединения не должны превращаться в две независимые постоянные регистрации. Общая учётная запись не означает автоматическое предоставление прав второго продукта.

## Проверенные основания

- [IDENTITY_AND_UNIFICATION.md](../v0.5/IDENTITY_AND_UNIFICATION.md), разделы 1, 3, 5: целевой identity issuer — id.octoport.ru; сначала потребитель Алиса, затем подключается Октопорт. Person, локальный пользователь и организация — разные сущности.
- [MERGE_ROADMAP.md](../v0.5/MERGE_ROADMAP.md): AL-M01 — адаптер входа Октопорта; AL-M02 — подтверждённая связь существующих аккаунтов; AL-M04 — общая админка с продуктовыми правами. Физическое слияние БД не является обязательным результатом.
- На Easyscript действующий Octoport использует собственные OTP request/verify и локальные users / user_identities / accounts / admin_principals. Нынешний вход не является готовым OIDC issuer для прямого подключения Алисы.
- Сейчас новые identity-записи Алисы не читают и не изменяют клиентов и администраторов Octoport. Совпадение email не является разрешением на объединение.

## Что изменяет эта правка

Закрывает технический путь AL-S02 для явно приглашённой реальной почты: native identity code → существующая почтовая служба Octoport → почтовый ящик → OIDC callback → собственный кабинет. Это тот же будущий общий identity, а не дополнительный временный провайдер.

Приглашения задаются одинаковым ALISA_REAL_LOGIN_RECIPIENTS в private identity/platform config (до 20 адресов, stage only). В identity требуется абсолютный путь ALISA_REAL_SMTP_PASSWORD_FILE к закрытому файлу пароля. Используется выделенный служебный SMTP-доступ к mail.octoport.ru:25, обязательный STARTTLS с проверкой сертификата, no-reply@octoport.ru. Секреты и адреса приглашённых в Git не сохраняются. Web получает только ALISA_REAL_LOGIN_ENABLED=1 для правдивого текста.

Без этой настройки действует прежний synthetic-only режим. example.invalid остаётся во внутреннем SMTP sink; тестовая заявка /join также не открывается для реальных адресов. Код не выдаёт магазины, платежи или права Octoport.

Исходящее письмо шифруется в outbox и очищается после отправки/истечения срока. Сбой до SMTP DATA допускает ограниченный повтор. Неопределённый исход передачи или потерянный процесс не вызывает автоматическую повторную отправку; интерфейс предлагает проверить почту и запросить новый код.

## Граница приёмки

Исходная правка не доказывает установку, доставку в Gmail или готовность AL-M01–M04. Для закрытия реальной почты нужны точная установленная версия, письмо в контролируемом ящике, подтверждение кода, повторный вход в тот же кабинет и проверка приватности. Отдельный итоговый receipt фиксирует фактический результат.

Следующий шаг общей регистрации — AL-M01 на совместимом кандидате Octoport: новый вход должен открыть существующий local account/device без пересоздания. Затем AL-M02 подтверждает контроль обеих старых записей. Переносить общие таблицы или автоматически сливать людей по почте эта правка не разрешает.
