# AL-S07: задания и закрытое соединение платформы с ядром

09.11.2026. **INSTALLED_CLOSED_BOUNDARY_VERIFIED**. Пользовательский live-проход Алиса → отчёт → кабинет остаётся NOT_RUN: в платформе отсутствуют AccessGrant/AccessLedger и AliceLink. Действующая native/Station-связка сохранена. Права, подарки, пользовательские сессии и OAuth-связи ради тестов не создавались.

Поставка: [PR411](https://github.com/MaksimUnimax/runtime-fixtures/pull/411), поверх принятого RuntimePort [PR410](https://github.com/MaksimUnimax/runtime-fixtures/pull/410).

## Установленное поведение

- `/app/queries`: выбор подтверждённого магазина, отправка вопроса, список и карточка, чтение сохранённого отчёта, отмена.
- `/api/v1/queries`, `/{id}`, `/{id}/result`, `/{id}/cancel`: браузерный BFF с текущей WebSession, проверкой Host/Origin и no-store.
- Платформа хранит только квитанции: ID, store scope, hash вопроса, ссылку на runtime и состояния. Вопрос, отчёт, bearer и execution ticket в Query не сохраняются.
- Неопределённый submit сохраняет исходный ID. Только явное восстановление с тем же ID и точным исходным вопросом может повторить отправку. Обычное открытие, статус и повтор webhook расчёт не запускают.
- Голосовой ID включает владельца, tenant и беседу. Отмена с вложенным runtime UNKNOWN не объявляется завершённой.
- После блокирующих OAuth/privacy-проверок неперсистентный DeliveryGuard проверяет исходный контекст, действующие права, Query TTL и runtime TTL под delivery-транзакцией.
- `PROVIDER_REFUSAL` обозначает пояснение об ограничении доступа. Точный отрицательный TEMPLATE_NOT_FOUND envelope текущего шаблонного ядра нормализуется в `UNSUPPORTED_QUERY`; ни один из них не считается первым полезным отчётом.
- Квитанции закрываются через сутки независимо от очистки. `queries_cleanup` включён в существующую account-cleanup службу; нового таймера нет. Нативный семидневный учёт фактических вызовов модели сохранён.

## Граница исполнения

Один существующий Engine, Worker и SQLite ядра. Платформенный authority обслуживается отдельным приватным HTTP-пулом на Unix socket: публичный синхронный worker не ждёт проверки прав от самого себя. Нового вычислителя или очереди нет.

Сокеты проверяют UID и права каталогов. Выделенный служебный секрет не является ключом площадки или модели. Проверяются nonce, HMAC, audience, текущие revisions и явно закреплённые версии. TCP fallback, доверия первому handshake, вывода tenant/store из UUID, email или названия нет.

Привязка подготовлена по существующему root-controlled `NATIVE_OWNER_CONFIGURED_PAIR`: совпали публичные tenant/store и подтверждённая Seller identity, а также native account/store/credential binding. Реальные идентификаторы и конфигурация остаются в закрытых серверных файлах.

## Совместимость текущего ядра и systemd

Во время работы другой поток установил `alisa-template-only-r2-20261109`. Старый R4 поверх него не устанавливался. Новый native release `alisa-template-only-r2-s07-acl-r2-20261109` сохраняет все его исходники; изменены только `runtime_port_service.py` и его тесты, обновлены манифесты. Шаблонный режим, Premium-классификатор, модельный ответ, промпты и прежняя Station-связка сохранены.

Первое включение выявило совместимость с настоящим systemd LoadCredential: маска 0440 представляет ACL, у owning group доступа нет, конкретному UID службы разрешено чтение. Проверка теперь принимает только точную такую ACL-форму на read-only mount под root-owned `/run/credentials/<unit>/`, без `..`, дополнительных UID/group/world прав или writable родителей. Обычная owner-only форма сохранена.

Первая попытка автоматически вернула конфигурацию, unit-файлы и web pointer. Новая пустая таблица Query сохранена. Повторное включение прошло; rollback-данные и история первой попытки оставлены в закрытом серверном каталоге. Увеличения цепочки `zzzz` override-файлов не было: пути native/retention обновлены в существующих последних fragments, новые boundary-настройки имеют отдельные обычные имена.

Платформенная сборка сохраняет параллельные изменения `staff/policy.py` и `staff/views.py`: продлённую сессию и восстановление прерванного входа. Зависимости переиспользованы; новые download/browser caches на сервер не устанавливались.
