## Единый путь клиента, не набор кнопок

До 02 /login объясняет состояние и ведёт к заявке. С 02 он запускает реальный OIDC-путь до /app. С 05 существует /app/stores. С 06 — /app/alice. С 07 — /app/queries и готовый result до TTL. С 11 — каталог. Покупка/история только с 20; реальные продажи с 24. Для гостя не рисовать чужие цифры и «живые» картинки из фиктивных магазинов.

Новая админка использует собственный origin и отдельный OIDC client. Её рабочие экраны — Next.js, общие компоненты pinned. Отсутствующая функция не выглядит активной; hidden button не является authorization. Уже введённые права проверяются прямым запросом backend. Будущие команды проверяются только после своего появления.

## UX обязательных состояний

Пустой аккаунт, нет доступа, оплата в ожидании, неверные права магазина, timeout источника, неопределённый исход, истёкший результат, недоступный backend, ожидание приглашения — отдельные объяснения и действия. Нельзя выдавать сетевую ошибку за неверный ключ или нулевую выручку.

Формы опасных действий: цель, область product/tenant, основание, preview эффекта, подтверждение, idempotency receipt. Для частичного возврата — отдельный access_effect. Поддержка не получает secret/impersonation по умолчанию.

## Будущий общий интерфейс

Одно identity, профиль, выбор product/account и навигация; отдельные API. Админ видит вкладки только с нужными product scopes. Разные организации не смешиваются. Свою главную не удалять сразу при появлении общего ЛК: судьба SEO/кампаний решается в AL-M05.
