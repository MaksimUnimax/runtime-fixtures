# Проверка зависимостей v0.5

Основная последовательность **00–24**, без перенумерации прежних 01–24. Каждый consumed capability производится раньше. Для теста разрешены возможности собственной поставки, но не будущей. Проверка аннотаций не доказывает весь естественный язык — проведена и авторская смысловая сверка.

| Ранее | Исправление |
|---|---|
| Техническая основа спрятана в сайте | AL-S00 имеет конечный технический E2E и 18 сценариев |
| ENV мог требовать уже созданный выпуск/CI | Только инфраструктура; приложения/CI/миграции результат 00 |
| Схема квитанции не принимала AL-V04 | Разрешены AL-S00 и существующие новые test IDs, есть positive/negative fixtures |
| Runtime/identity границы не привязаны к каталогам | SOURCE_LAYOUT, владельцы БД, adapter и защищённые пути |
| Неясно что сдаёт первый исполнитель | START_HERE, EXECUTOR_BRIEF, FOUNDATION_00, команды и evidence |

168 прежних сценариев сохранены по ID, действиям и ожидаемым результатам. 18 foundation cases добавлены отдельно. Ранние техпробы не требуют login/публикации/магазина. AL-S02 получает уже существующий identity shell, но полный OIDC доказывает сам. AL-S05/07 по-прежнему требуют конкретных контрактов ядра, а не завершения всей матрицы. Будущее объединение AL-M не входит в зависимости 00–24.

Никакой функции не назначен ACCEPTED, продуктовых тестов этой документационной работой не выполнено.
