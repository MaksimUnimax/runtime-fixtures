# Исполнение и приёмка v0.5

## 1. Единая очередь

ENV-00 → AL-S00 → 01–24. ENV проверяет инфраструктуру; 00 создаёт технический каркас; 01 строит свою главную/воронку; 02 — регистрацию вместе с ЛК. Отложенные AL-M не нужны для запуска Алисы.

## 2. Что считается поставкой

Один ответственный доводит результат полностью. Для 00 это исполняемая инженерная вертикаль и выпуск, для 01–24 — предметная возможность через все нужные слои. Таблица без API, API без экрана или кнопка без эффекта не закрывают функцию. Базовые технические границы после 00 используются, а не переизобретаются в каждом шаге.

## 3. Начало

Прочитать карточку/модули/тесты, подтвердить входы, pinned source/artifact, владельца путей и внешние разрешения. Проверить source diff и действующие locks. Время и факт старта записать. Никакого самовольного назначения A/B/C и остановки работы матрицы.

## 4. Передача

Commit, artifact SHA256, installed version, migration heads, адреса, роли, exact demo, ожидаемые значения и safe evidence. Тестировщик не пишет отсутствующий UI, deploy script или business logic. Источники секретов указываются ссылкой на закрытое хранилище, не самими секретами.

## 5. Приёмка

NOT_STARTED → IN_PROGRESS → READY_FOR_QA → ACCEPTED_FOR_DECLARED_SCOPE. REWORK/BLOCKED имеют причину и необходимые действия. Набор документационных проверок — отдельный результат. Принятый локальный scope с открытым live этапом не разрешает внешний выпуск.

Проверяются позитивный путь, прямые запрещённые обращения, повтор, границы данных и ошибки. Screenshots подкрепляются фактическими эффектами. Fake payment не является платежом провайдера; text/tts не доказывает звук Станции. После изменения сборки повторить затронутую регрессию; прежний PASS не переносить автоматически.

## 6. Безопасность по первому потребителю

Технические роли/secrets/default-deny — 00. Tenant isolation — вместе с ЛК. Шифрование — с ключами. Полномочия/replay/TTL — с первым отчётом. Идемпотентность денег — с первой оплатой. Поздний recovery/dashboard не разрешает ранние небезопасные функции.

## 7. Параллельность

Основной порядок однозначен. Другие исполнители могут готовить disjoint изменения при известных входах; это не разрешение принимать будущую функцию до зависимостей. Матрица независима. Один владелец runtime adapter; никаких одновременных некоординированных изменений transport/registry.

## 8. Публикация

В Git попадают исходники/контракты/очищенные evidence, не живые БД, токены или финансовые ответы. Запись подтверждается commit и readback. Рабочие данные не хранятся в чате. Коммерческий выпуск, DNS, реальные оплаты и массовые уведомления — отдельные разрешённые операции.
