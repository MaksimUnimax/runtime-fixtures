# Документы маркетплейсов по шаблонам · 09.11.2026

Прямое изменение владельца: в ЛК хранить документы и ответы API маркетплейсов по использованным шаблонам **48 часов**. Изменение входит в AL-S07/AL-S10 и дополняет AL-R024: короткий TTL голосового ответа сохраняется, для документов действует отдельный срок.

## Поведение

- Таблица «Отчёты»: название использованного шаблона, магазин, время получения, окончание хранения и ссылки «Скачать».
- Один запуск шаблона может содержать несколько файлов/страниц API. Файлы группируются по запуску. Составной шаблон получает документы всех своих шагов. При объединении запросов ответ относится только к шаблонам, чьи доверенные шаги используют этот API.
- Название, ID, версия и hash каталога фиксируются из принятого template selection и доверенного каталога. Новые шаблоны и их зависимости автоматически используют общий путь; отдельных веток по ID шаблона или методу API нет.
- Готовый документ площадки сохраняется байт в байт. Обычный структурированный ответ API преобразуется в самостоятельный HTML-документ с таблицами/списками и экранированными значениями; при большом объёме, глубокой структуре или разреженных таблицах заранее выбирается полный JSON-документ без потери полей и квадратичного расширения. Ответ модели не подменяет данные API.
- Сохраняются фактически полученные успешные ответы, в том числе если итоговая генерация модели позднее завершилась ошибкой. 401/403/429 и модельные запросы не превращаются в отчёты. Авторизационные ответы, ключи, signed download URL и текст исходного вопроса в архив не записываются.
- Срок каждого файла: received_at + 172800 секунд. Открытие, скачивание и повторная доставка не продлевают срок и не обращаются повторно к площадке/модели. Старые уже удалённые данные не восстанавливаются запросом к площадке.

## Хранение и доступ

Документы принадлежат существующему runtime, в отдельном приватном хранилище файлов рядом с его БД; это не новая очередь и не исполнитель. Payload шифруется AES-GCM небольшими блоками. Метаданные и данные удаляет существующий независимый retention timer. После expires_at выдача закрыта даже при задержке очистки. Короткий TTL jobs/квитанций не удаляет действующий 48-часовой архив.

RuntimePort расширяется read-only операциями list_reports/read_report. Веб получает только безопасные метаданные и проверенные блоки файла через текущую WebSession и authority. Проверяются текущие владелец/tenant, точная root-controlled привязка магазина, доступ к сервису, ключи и source deny всех сохранённых зависимостей, включая авторизацию API. Для прежней Station-связки используется та же явная привязка native account/store, без сопоставления по email/названию. Смена версии каталога не делает прежний документ чужим; сохранённое название шаблона не переписывается.

Скачивание идёт с attachment, no-store, nosniff и безопасным именем. HTML не выполняется в origin кабинета. Блоки повторно проверяют текущий доступ и TTL; отзыв во время скачивания останавливает последующую выдачу. Истечение доступа и отзыв ключа не обходятся сохранённым файлом.

При обычной публикации любого нового template/core release обновляются явно закреплённые versions/bindings RuntimePort. Это обязательная часть существующего rollout, а не регистрация шаблона в архиваторе и не доверие первому handshake. Старые документы читаются под текущими правами без запуска прежнего job.

При откате вычислителя сохраняется совместимая новая версия существующей retention-службы до очистки последнего документа. Откат не оставляет 48-часовые payload без независимого уборщика.

Хранилище имеет явный технический бюджет, сохраняет 3072 МиБ свободного диска, не вытесняет действующие документы раньше 48 часов. Нехватка места отображается как ошибка сохранения; она не вызывает повтор API и не выдаётся за наличие файла. Новых фоновых служб/таймеров и download/browser caches нет.

## Обязательная проверка

1. Шаблон, добавленный только в каталог, появляется с собственным именем и файлами без изменения архиватора. Составной шаблон и несколько API-страниц сохраняют правильную связь.
2. Реальные binary bytes, JSON/object/list/scalar/empty, Unicode/Decimal и HTML-инъекции; файлы не содержат ключей/URL/модельных сообщений.
3. Один API вызов → сохранение → многократные скачивания без новых API/модельных вызовов и продления TTL.
4. 48h−1s доступен; 48h закрыт; очистка удаляет metadata+payload. Архив переживает короткий TTL и удаление job/квитанции.
5. Чужой tenant/actor/store/file, новый ключ, source deny, отсутствие доступа, смена session и отзыв в середине скачивания получают отказ.
6. Дедупликация фактического ответа, отмена до позднего ответа, restart и отказ места/целостности без повторного API.
7. Настоящие PostgreSQL authority + Unix RuntimePort + BFF/browser download на синтетических данных. Авторская проверка отдельно от независимого review; live owner отдельно от обеих.

Статус реализации и проверки фиксируется в execution receipt; сам этот документ не заявляет установленную/live готовность.
