# Публикация полного пакета в GitHub

**Фактический статус этой поставки: НЕ ОПУБЛИКОВАНО.** В текущем наборе доступных инструментов GitHub и удалённого сервера есть чтение, но нет действий записи/запуска Git. Отсутствие write-действия не является утверждением об отсутствии прав у владельца репозитория. Commit не выдумывается. Последняя прочитанная база ветки `alisa`: `3227a7dd37d166894cfccac4b07bfd2b791b2cc0`; исполнитель публикации обязан получить новую базу.

## Куда

Репозиторий `MaksimUnimax/runtime-fixtures`, ветка `alisa`, новый каталог `docs/alisa/service-platform/v0.5/`. Публикуются все файлы распакованного комплекта, включая Word, исходники Markdown, JSON, инструкции, безопасные исторические документы и MANIFEST. Рабочий код сервиса и предыдущие каталоги не меняются. Секреты не должны появиться в публичном Git.

## Проверка и отправка с компьютера с разрешённым Git

Распаковать ZIP в отдельную папку. Нужны Python 3.10+ для утилит, Git и штатная уже настроенная авторизация GitHub. Для проверки документации дополнительно PyYAML/jsonschema; установка выполняется в отдельном venv. Не вставлять токен в URL, документ или командную строку. Сначала настроить свои `git user.name`/`user.email` обычным способом — помощник не подставляет чужое авторство.

Из корня распакованного пакета:

```sh
python tools/verify_manifest.py
python tools/publish_docs.py --clone-dir /absolute/new/alisa-docs-v05
```

Второй вызов по умолчанию **только проверяет локальный пакет** и печатает план, не клонирует и не отправляет. Выбрать новый, ещё не существующий каталог вне пакета; на Windows использовать свой абсолютный путь.

Для реальной публикации:

```sh
python tools/publish_docs.py --clone-dir /absolute/new/alisa-docs-v05 --execute --push --receipt /absolute/new/alisa-docs-v05-publication.json
```

Скрипт создаёт новый clone ветки `alisa`; проверяет manifest; отказывается перезаписывать существующую v0.5; добавляет только новый каталог документации; создаёт commit от настроенного автора; до push заново проверяет HEAD; выполняет обычный push без force; проверяет, что удалённая ветка содержит commit и точное дерево файлов пакета. Квитанция сохраняется вне исходного пакета.

## Что делать при остановке

Если ветка изменилась, commit остался только в новом локальном clone. Это не публикация. Не force-push и не перезаписывать работу матрицы; перечитать изменения и повторить согласованный docs-only перенос с новой базы. Если целевой каталог уже существует — сравнить версии и hashes, не заменять автоматически.

Если push прошёл, но readback не подтвердился, считать результат НЕПОДТВЕРЖДЁННЫМ до отдельного чтения GitHub. Для передачи владельцу нужны `PUSHED_AND_VERIFIED`, commit и ссылка из фактической квитанции, а не просто сообщение команды commit.

Утилита проверена локально в режиме dry-run и на отказных условиях. Настоящий push этим пакетом не выполнен. Изменять `data/STATUS.json` ради галочки не нужно: факт публикации записывается отдельной квитанцией, исходный переданный пакет остаётся неизменным.
