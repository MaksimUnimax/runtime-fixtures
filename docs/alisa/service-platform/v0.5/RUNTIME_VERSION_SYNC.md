# Совместимый выпуск ядра и соединение кабинета

10.11.2026. Продолжение AL-S07 и REPORT_ARCHIVE_48H. Причина: bundle_hash включает исходники и каталог, поэтому обновление подсказок/шаблонов меняет hash. Если root-пины платформы остаются прежними, кабинет корректно закрывает соединение с CATALOG_INCOMPATIBLE, хотя архив и текущая Station-связь исправны. Ручная сверка после каждого выпуска заменяется конечным шагом публикации/запуска.

`products/alisa/infra/runtime_versions_sync.py` — конечная утилита администратора выпуска, не новый исполнитель, очередь или таймер. Она:

1. Проверяет root-владение, закрытость на запись, отсутствие symlinks, release namespace, artifact/source identity и каждый checksum локального immutable manifest. Полный набор файлов выпуска должен совпадать с manifest, включая корневые JSON/JSON.GZ, вложенные данные и будущие форматы; недекларированные файлы запрещены; состояние повторно проверяется после расчёта. Разрешены hardlinks неизменяемых файлов между root-owned выпусками: права записи относятся к общему inode, checksum и повторная проверка обязательны. Конфигурация и пины по-прежнему требуют единственную ссылку.
2. Вычисляет дескриптор существующим runtime_port.current_versions **как nobody**, без групп, с пустым окружением, без CREDENTIALS_DIRECTORY, секретов и запроса к listener. CPU, размер вывода и время расчёта ограничены; root не импортирует код ядра.
3. Сравнивает весь дескриптор с закреплённым. Автоматически допустимо менять только catalog_bundle_hash. Версия протокола, schema hash, registry hash, projection, language, port_build и catalog_release_id требуют явного квалифицированного выпуска.
4. Под существующей общей `/run/lock/alisa-stage-rollout.lock` атомарно заменяет runtime-versions.json, сохраняя owner/group/mode. Grants, bindings, ключи, сессии, OAuth и бизнес-задания не меняются.

Это публикация по проверенному локальному исходнику, **не trust-on-first-handshake**. Manifest и root-owned release заранее допускает автор выпуска по прежним правилам review/qualification. Утилита не заменяет такое допущение, не принимает source из сети и не разрешает неподтверждённый contract upgrade.

## Включение

После проверки source/package скопировать утилиту в `/usr/local/libexec/alisa/runtime_versions_sync.py` (root:root,0755; родители root-owned, без групповой/общей записи). Drop-in `products/alisa/infra/systemd/alice-market-runtime-versions.conf` подключается к существующей alice-market.service. Её WorkingDirectory указывает на принятый immutable release.

ExecStartPre выполняет конечную root-проверку до Worker; код-дескриптор исполняется с правами nobody. Префиксы `-+` ограничены этой командой; защиты основного worker не меняются. Документация systemd255: https://www.freedesktop.org/software/systemd/man/255/systemd.service.html (ExecStart/таблица префиксов).

При несовместимости/ошибке/занятой общей блокировке пины сохраняются, в journal появляется BLOCKED с закрытым кодом причины. Проверка не прерывает прежнюю Station-связь: основной worker запускается, а платформа продолжает закрывать неподтверждённое соединение. Контракт не смягчается ради успешного запуска.

Если installer уже удерживает общую блокировку, он вызывает утилиту **до restart** с `--lock-fd FD` и передаёт тот же открытый descriptor через `pass_fds`. FD проверяется по inode общей блокировки. Это предотвращает ожидание своей блокировки через systemd; занятый pre-start hook не ждёт installer. При совместимом rollback старый hash вычисляется из выбранного старого кода тем же способом; данные/задания не воспроизводятся.

Для проверки без записи:

```sh
cd /opt/alice-market/releases/ПРИНЯТЫЙ_ВЫПУСК
/usr/bin/python3 -I -B /usr/local/libexec/alisa/runtime_versions_sync.py --check
```

Допустимые ответы: UNCHANGED, UPDATE_REQUIRED, DISABLED. BLOCKED не содержит конфигурацию/исключение/секреты. UPDATE_REQUIRED при --check не изменяет файл. Этот шаг не создаёт новый бесплатный период доступа и не снимает проверки текущего пользователя при скачивании.

## Критерии проверки

- Совместимое изменение каталога обновляет только hash; повтор ничего не записывает.
- Contract/schema/registry/language/projection/build/catalog binding change сохраняет прежние пины.
- Подмена checksum, любой лишний файл, в том числе корневой каталог JSON или вложенный файл нового формата, symlink, групповая запись, изменённые manifest/source/config и занятая блокировка не публикуют новый hash.
- Режим/owner/group конфигурации сохраняются, частичного JSON не видно.
- Реальный systemd pre-start под User=nobody и ProtectSystem/ProtectHome подтверждает root-публикацию; ошибка сохраняет основной service path и прежние пины.
- Расчёт выполняется как nobody, не получает окружение службы/магазинов и не обращается к API/модели. Установленный readback выполняется отдельно от source/synthetic qualification.

В disposable GitHub-hosted CI каталог `/opt` может быть доступен runner на запись. Только явный `--disposable-github-runner` (проверяет оба штатных признака hosted CI и отсутствие установленной alice-market.service) временно приводит метаданные этого каталога к production-предусловию root:root/0755; затем восстанавливает исходные uid/gid/mode. Production helper такого переключателя не имеет, проверка доверия не ослабляется. Qualification сохраняет безопасные метаданные до проверки и факт восстановления.

Первичная причина отсутствия доступа реального клиента остаётся отдельной: отсутствие выданного service grant, не дефект хранилища или основание выдать срок автоматически. Следующий функциональный этап roadmap — AL-S08; шаблоны/матрица остаются параллельному потоку.
