# Формирование ответа моделью и дополнительная инструкция администратора

Дата: 09.11.2026. Основание: прямое уточнение владельца в текущем диалоге.
Статус: ТРЕБОВАНИЕ ЗАФИКСИРОВАНО; реализация и установка этим документом не подтверждаются.

## Что изменено относительно прежней документации

REPORT_v0.1.0.md, §2.11, предусматривал основной речевой ответ без модели, а дополнительный модельный вызов — только для нетипичного объяснения. В универсальном read-пути дополнительно появилась зависимость ответа от модельных finish/facts и выражений. Эти правила формирования конечного аналитического ответа заменяются данным требованием.

Новый обязательный путь: исходный вопрос пользователя → получение относящихся к нему данных API → передача вопроса и данных модели → обычный текст модели → доставка пользователю и на колонку.

Этот документ не разрешает модели менять production-матрицы, credentials, права или выполнять произвольный код. Он не заменяет отдельную работу над пониманием и планированием запроса.

## Вход модели, формирующей ответ

Обязательные составляющие:
1. Исходный вопрос пользователя. Не подменять его пересказом, названием шаблона или внутренней командой.
2. Данные, полученные от API для этого задания, с различимостью источников. Не заменять их заранее написанным серверным ответом; не подставлять данные другого задания. Не выдавать ограниченный образец массива за полный набор.
3. Только при непустой настройке — дополнительная инструкция администратора.

Наличие структуры в исходном ответе API не означает требования такого же формата от модели. Для конечного ответа нет обязательного JSON, DSL, finish/facts, списка разрешённых выражений или инструмента finish.

При пустой дополнительной инструкции третья составляющая отсутствует полностью: не добавляются пустое сообщение, поле с пустой строкой, заголовок-заглушка или текст «инструкция отсутствует».

## Настройка в админке

Переменная: answer_extra_instruction.
Название поля: «Дополнительная инструкция модели для ответа».
Форма: необязательное многострочное текстовое поле в общих настройках Алисы, доступное администратору OWNER продукта alisa_market.
Начальное значение: пустая строка; текущему владельцу никаких текстов автоматически не добавлять.

Администратор может сохранить текст, перечитать его после перезагрузки страницы, изменить и полностью очистить.
Текст сохраняется на сервере, а не только в браузере.
Строка из одних пробелов и переводов строк считается пустой.
При непустом значении содержание и переводы строк сохраняются; инструкция передаётся отдельно от вопроса пользователя.
Настройка не доступна для изменения из обычного кабинета клиента.
Сохраняется защита от перезаписи более новой настройки устаревшей формой.

Для начавшейся генерации фиксируется использованная инструкция. Транспортный повтор использует то же значение.
Изменение настройки применяется к следующей начинающейся генерации и не изменяет уже сохранённый ответ.

## Выход модели и доставка

Обычный текст модели является аналитическим ответом. Сервер не требует от неё программу обработки данных и не преобразует её ответ в собственную сводку.
Не добавляются проверки содержания ответа на соответствие JSON/DSL, обязательным полям, названиям функций или шаблону фразы.
Разделение длинного текста на страницы для канала доставки допускается без переписывания содержания.

Один пользовательский запрос остаётся одним заданием.
После получения данных ошибка генерации ответа не запускает заново уже выполненные обращения к маркетплейсам.
Полученный ответ сохраняется; повтор доставки, чтение «дальше» и повтор callback не создают новую генерацию.
Проверки доступа к данным и доставка только владельцу сохраняются.
Нет тихого переключения на серверный «запасной» аналитический ответ.

Все фактические обращения к модели для формирования ответа, включая повторы и неудачные попытки, входят в метрику «Обращения к модели на запрос за 7 дней». Отдельные бессрочные журналы вопросов, ответов и инструкций ради этой метрики не создаются.

## Сквозная проверка перед заявлением о готовности

- Пустое поле: исходный вопрос и API-данные доходят до модели; дополнительной инструкции в отправке нет.
- Непустое поле: текст сохраняется через админку и попадает в следующую генерацию.
- Очистка поля: следующая отправка снова не содержит дополнительной инструкции.
- Перезапуск страницы и службы: настройка сохраняется.
- Обычный текст, абзацы и знаки пунктуации в ответе не вызывают ошибку формата.
- Временная ошибка модели: повтор относится к формированию ответа в том же задании; успешные API-чтения не повторяются.
- Готовый ответ и повтор доставки: нет повторной генерации и нового аналитического задания.
- Отзыв доступа и попытка изменения настройки обычным клиентом не раскрывают данные и не меняют настройку.
- Реальные вопросы об акциях, простой запрос и составной запрос проходят целиком до доставки; отдельно фиксируются исходный вопрос, время, число API/модельных обращений и наблюдаемый результат.
- Статусы «описано», «реализовано», «проверено», «установлено» фиксируются отдельно. Этот документ подтверждает только первый статус.


## Дополнение владельца: три редактируемых промпта и обработка отказов

Все три поля доступны OWNER в общей админке голосовых ответов и сохраняются на сервере одной версией:

| Переменная | Назначение | Начальное значение |
|---|---|---|
| `request_planning_prompt` | Задача первого модельного разбора запроса и выбора шаблонов | «Разбери запрос пользователя и подбери нужные шаблоны для получения данных, необходимых для ответа. Сохрани все условия исходного вопроса.» |
| `answer_prompt` | Задача финального формирования ответа | «Ответь на вопрос пользователя, используя эти данные.» |
| `answer_extra_instruction` | Дополнительное уточнение для экспериментов владельца | Пусто; компонент отсутствует в отправке |

Первый промпт фиксируется при первом модельном планировании задания. Если готовый шаблон однозначно выбран сервером, дополнительный платный вызов для повторного выбора не добавляется. Техническое описание допустимых действий сбора остаётся частью существующего планировщика. В универсальном пути окончание сбора отделено от написания ответа: планировщик не составляет `facts/expr` для озвучивания. Эта правка не объявляет старое планирование свободным от структурированных команд.

Финальный промпт и дополнительное уточнение фиксируются непосредственно перед первой генерацией ответа; транспортные повторы используют тот же снимок. Вопрос пользователя и все разрешённые API-данные прикладываются отдельно. Промпты не получают права менять подключение, разрешения, исполняемый код или адреса API.

### Правило реакции на ошибки API

Сначала общий обработчик классифицирует полученный отказ и применяет известное автоматическое решение. Модели не передаётся ошибка, которую сервер сейчас устраняет сам.

| Событие | Реакция |
|---|---|
| HTTP 429 | Сохраняет задание, учитывает Retry-After, ждёт и повторяет тот же допустимый запрос. Не вызывает модель для объяснения 429. |
| HTTP 408, 425, 500, 502, 503, 504 | Повтор безопасного чтения с увеличивающейся задержкой. Уже завершённые стадии не запускаются заново. |
| Потеря соединения/тайм-аут безопасного чтения; повреждённая транспортная оболочка | Та же политика повторов. Реальные модельные попытки считаются даже при ошибке. |
| Требуется временный токен предусмотренного источника | Существующий транспорт получает/обновляет токен по зарегистрированной зависимости; токен не попадает в промпт или журнал метрики. |
| Подтверждённое требование подписки Ozon | Автоматически не покупает подписку и не повторяет отказ. Передаёт модели безопасное пояснение с точным подтверждённым названием: Premium, Plus, Pro, Lite либо «Управление отзывами». Обычный 403 не объявляется Premium. |
| Нерешаемый отказ параметров, прав, ресурса или неизвестный HTTP-отказ | Передаёт модели исходный вопрос и безопасные сведения: источник, операция, HTTP-статус, подтверждённая причина. Если причина не установлена, прямо указывает это; не придумывает объяснение. |
| Отзыв доступа владельца/магазина или отмена задания | Останавливает работу и выдачу данных; модель не используется для обхода запрета. |

Ответ модели на нерешаемый отказ — обычный текст, без обязательного JSON-подтверждения. Причина API-отказа и стадия формирования пояснения сохраняются вместе с квитанцией попытки. Повтор доставки не запускает новый API-запрос. После отказа 401/403 в модельный контекст пояснения не включаются ранее полученные бизнес-данные закрытого источника. Владелец и текущая ревизия доступа проверяются перед генерацией и выдачей.

Ограничение: автоматический повтор не гарантирует, что внешний сервис восстановится. Нельзя обещать отсутствие любых ошибок; проверяется сохранность задания, правильная классификация и отсутствие лишних обращений к модели.
