# Ozon: способы оплаты в октябрьских реализациях 2026

Статус: **источники квалифицированы на живых данных вне навыка; runtime и матрица не изменены**. Это исследование и описание общей операции для последующей регистрации в матрице, а не новый обходной обработчик речевой фразы.

## Цель и выборка

Владелец попросил установить, сколько продаж оплачено Ozon Картой и сколько другими способами, чтобы понимать ориентир цены. Использован весь ассортимент прежней октябрьской выборки; ни один SKU не исключён.

Целевая выборка — положительные товарные строки реализации по дате начисления 01–31.10.2026. Метаданные отправлений соединены с начислениями и месячной реализацией по posting_number/unit_number и SKU. Получение метаданных за часть сентября необходимо из-за заказов, созданных до октября. Все выгруженные отправления не объявляются октябрьскими продажами.

## Получение и проверки

Новых бизнес-HTTP к Ozon: **14**, все 200. WB: 0; DeepSeek: 0; сообщений в консоль Алисы: 0. Использованы уже сохранённые финансовые ответы: их повторных запросов нет.

- POST /v3/posting/fbo/list: 6 страниц октября и 5 страниц 09–30 сентября.
- POST /v4/posting/fbs/list: 2 страницы октября и 1 страница 09–30 сентября.
- Каждый запрос limit=100, sort_dir=asc, with.analytics_data=true, with.financial_data=false. FBO также translit=false.
- Первая страница с cursor=""; следующие используют возвращённый cursor. Каждая из четырёх последовательностей завершилась has_next=false. Пустой/повторный cursor при has_next=true блокирует сбор.
- 1177 уникальных отправлений в метаданных. Все 575 целевых товарных строк найдены; неизвестных меток, пропусков и дублей 0. Все целевые отправления имеют статус delivered.
- Количество и сумма каждой строки сверены с месячной реализацией; компоненты денег сверены с начислениями. Все 575 проверок пройдены. Новые суммы и товарные результаты переданы владельцу приватно.
- Проверены равенства общей, дневной и SKU-группировок. Количество в строках с двумя единицами учтено без повторного умножения суммы sale_price.

## Точная семантика способа оплаты

Основной признак: analytics_data.payment_type_group_name из данных отправления. Точная метка «Ozon Банк» выделена отдельно. Другие наблюдаемые значения сохранены: «Банковская карта», «Система Быстрых Платежей», «Кредитная карта», «SberPay», «Озон Счет Рассрочка МКК», «Баланс средств».

Группа остальных меток не переименована в «карта другого банка»: тип эмитента кредитной карты и собственно факт использования карты для баланса/рассрочки не выводятся из её названия. Результат — достоверное разделение по метке Ozon, а не предположение о банковском инструменте за каждой иной меткой.

bank_coinvestment присутствует и у части реализаций с иной меткой оплаты. Он не используется для определения карты. coinvestment нового источника сверён с суммой bank_coinvestment + pick_up_point_coinvestment + stars в месячном отчёте; это агрегат разных механизмов.

Средняя цена = SUM(покупательская сумма строки) / SUM(quantity). Разница средних групп не объявляется размером скидки на одну и ту же покупку. Альтернативная цена той же покупки без карты в источнике отсутствует. Прежняя смешанная граница цены не переносится автоматически на сегмент Ozon Карты.

## Ошибки и ограничения для патча

- **OZPAY-001:** источник начислений не содержит payment_type_group_name. Для разбивки требуется общий источник метаданных и проверяемое соединение; нельзя выдумывать метку из цены.
- **OZPAY-002:** bank_coinvestment не равен признаку Ozon Карты. Ошибочная классификация по наличию выплаты предотвращена.
- **OZPAY-003:** будущие/пустые неизвестные метки должны давать unknown с видимым покрытием, а не автоматически попадать в группу без карты.
- **OZPAY-004:** разница средних групп не является дополнительной скидкой на идентичную покупку. Для этого нужны сопоставимые исторические цены предложения с/без карты, а не только суммы совершённых реализаций.
- Предотвращены подмена даты начисления датой заказа, добавление нецелевых/отменённых заказов в реализации и двойной учёт количества.
- Прямое чтение страницы docs.ozon.ru/api/seller/ вернуло HTTPError; официальное объявление версий и реальные ответы действующих методов проверены. У бизнес-запросов ошибок нет.
- Первый вывод закрытой проекции был слишком объёмным для рабочего вывода и усечён. Для сборки отчёта повторно прочитан сокращённый результат без товарных строк; повторных HTTP к Ozon не было.

## Интеграция в сервис

[Спецификация операции](../runtime/v0.10/candidates/OZON_PAYMENT_METHODS_CASE.json) — кандидат для общей матрицы. Требуются зарегистрированные источники метаданных FBO/FBS, ключи соединения, признак способа оплаты, правила unknown/полноты, группировка day/SKU/payment_type и общие агрегаты. Отдельный обработчик этой фразы или месяца не предлагается. Денежные вычисления выполняет проверяемый код; DeepSeek может только составить разрешённый план. Публичный Git не содержит сырых ответов, номеров заказов/отправлений, цен, сумм, credential headers и токенов.
