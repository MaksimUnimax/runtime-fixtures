## Независимые проверки арифметики

- ДРР по каждой площадке: 100 × ad_spend / ordered_revenue.
- Доля расходов Ozon: 100 × (finance_storage_cost + finance_logistics_cost + finance_acquiring_cost) / finance_sales.
- Балансовое равенство: opening_balance + accrued + payments = closing_balance, с сохранением знаков выплат.
- Значения для пересчёта взяты из полученных в этой же сессии отчётов; исходные суммы и финансовые ответы в публичный документ не переносятся.
- Сходство заказанной суммы с прежней контрольной точкой не заменяет сверку с кабинетом. Проверена арифметика, а не независимая правильность классификации каждого поля внешнего API.

## Наблюдавшиеся задержки

1. Первый Ozon Orders вернул настоящий HTTP 429. Worker отложил тот же job; консоль сообщила ожидание 69 секунд. После предусмотренного интервала источник дал 200, оба маркетплейса вошли в полный READY. Отдельный новый расчёт ради повтора не создавался.
2. При последнем чтении результата один browser locator wait превысил дедлайн. До повторного действия прочитана текущая область чата: ответ уже пришёл, дата и показатели верны. Дополнительный расчёт и повторная отправка вопроса не выполнялись. Это сбой ожидания браузерного инструмента, не доказанный сбой webhook.
3. В очистке серверного окружения один сухой прогон остановила защитная проверка списка пакетов: разбор имени захватил перевод строки. Парсер исправлен до выполнения purge, повторно подтверждена область только ранее добавленных пакетов.

Новый UNKNOWN этим тестовым прогоном не создавался. Ранее существовавший UNKNOWN не сбрасывался и не повторялся.

## Перенос тестирования и удаление серверного браузера

Условие владельца: после подтверждения облачного варианта удалить созданный серверный браузер. Условие выполнено настоящими ответами всех семи сценариев.

Удалены Chromium и его серверная трансляция: пять desktop-служб, профиль и отдельный пользователь, VNC/WebSocket, nginx include/snippet и маршрут, дополнительный browser swap 2 ГБ, восемь добавленных browser/platform Snap-пакетов и 127 добавленных APT-пакетов с их остаточными конфигурациями. Два исходных auto-mark восстановлены. Предшествующий системный snapd и другие исходные пакеты не удалялись; системные обновления не откатывались.

Кэш установки удаляется адресно по конкретным digest из исходного Snap install и списку 127 пакетов из APT history; глобальный autoremove не использовался. Подробная квитанция — final-cache-cleanup.json.

После основной очистки: четыре службы аналитики и три timers active; nginx -t успешен; /healthz HTTP 200; SQLite quick_check=ok; старый маршрут трансляции HTTP 404; слушают только штатные публичные 22/80/443 и внутренний 8765. Контроль после окончательной очистки сохраняется отдельно. Облачная консоль остаётся рабочим интерфейсом дальнейших тестов.
