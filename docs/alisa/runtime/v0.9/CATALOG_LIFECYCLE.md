# Обновление библиотеки после релиза 0.9

## Что меняется независимо

Речевой синоним/набор — `speech_catalog.json`: ссылается на имеющийся показатель или формулу. Это ускоритель P1 без HTTP и вычислительного кода.

Новая формула на известных данных — `expression_catalog.json`: вложенное выражение и стабильный ID; допускает ссылки на другие формулы. P2 может построить то же дерево без именованного шаблона. Не требуется новая ветка в Python.

Новый источник/поле/гранулярность — registry и адаптер, официальный контракт, проверки прав/полноты/валюты, разрешённый live-canary, qualification. Отсутствующие себестоимость или API нельзя создать одной записью формулы.

Новый оператор — новая версия языка и тесты. Текущие: add/subtract/divide/percent/relative_change/per_day/minimum/maximum. Произвольный JOIN строк/TOP SKU не маскируется под скалярную операцию.

## Пример только JSON

В formulas каталога выражений:

```json
"three_costs": {
  "label": "хранение, логистика и эквайринг",
  "expr": {"op":"add","args":[
    {"metric":"finance_storage_cost"},
    {"metric":"finance_logistics_cost"},
    {"metric":"finance_acquiring_cost"}
  ]}
},
"three_cost_share": {
  "label": "доля трёх расходов в финансовых продажах",
  "expr": {"op":"percent","args":[
    {"template":"three_costs"},{"metric":"finance_sales"}
  ]}
}
```

В phrases речевого каталога необязательно добавить:

```json
"three_cost_share": ["доля трех затрат"]
```

В установленном live-примере эти две именованные формулы намеренно НЕ зарегистрированы: DeepSeek собрал аналогичное выражение самостоятельно. Отдельный тест добавляет их и фразу в чистую копию, запускает новый процесс, подтверждает P1 и неизменность SHA256 всех Python-файлов. Так проверена возможность развития библиотеки без изменения ядра, а не просто заявлена.

## Порядок выпуска

1. Создать отдельную копию каталога/release, не редактировать активный процесс по месту.
2. Изменить version, стабильный ID, определение/формулу и короткую метку. Синонимы нормализованы: нижний регистр, ё→е, без двойных пробелов и концевой пунктуации.
3. Выполнить `python3 -B catalog_check.py --expressions expression_catalog.json --speech speech_catalog.json`, затем `python3 -B run_checks.py`.
4. Для новой формулы добавить независимые числовые ожидания, нулевой знаменатель, площадку/валюту/область, exact-cache и version-pin; для синонима — полную фразу без потерянных условий.
5. Новые источники квалифицировать отдельно. Новая формула на прежних полях требует малого разрешённого реального сценария; не подменять статус адаптера принудительным PASS.
6. Перед переключением проверить активную версию, locks/queue, backup и rollback. Переключать отдельный runtime, не менять OAuth/ключи без причины.
7. Проверить build, хеши, ledger и реальный итог; записать UTC и границы доказанного.

## Что происходит с уже поставленными заданиями

Каталог и разрешённые магазины закреплены при приёме до P2. Развёрнутый граф хранится вместе с языком, каталогом, source registry и форматом ответа. Новая формула меняет ключ нового задания, но не переинтерпретирует старый граф. Несовместимое изменение языка/формата/source registry для ещё не разобранного P2 даёт явный PENDING_PLAN_VERSION_CHANGED до модели.

Удаление пользовательской формулы закрывает новые запросы к ней; прежний принятый граф сохраняет своё определение при действующих правах/TTL. Шесть стандартных совместимых формул обязательны для текущего language-release; удаление требует миграции. Старые финансовые результаты не склеиваются и не извлекаются частично.

## Ресурсы отдельно от семантики

resource_limits.json управляет локальным бюджетом модели: daily_calls=20 — именно скользящие 24 часа в ledger, min_interval_seconds=2. Ограничения валидируются, ключей здесь нет. Бюджет не изменяет финансовый смысл и не управляется моделью. Неизвестный исход учитывается и не повторяется автоматически. Лимиты провайдера остаются отдельным контрактом.

## Условие автономности

«Новый шаблон без правки Python» не означает «без тестов и выпуска версии». Автоматическое свободное редактирование production нейросетью не вводится. Для незнакомой фразы сначала используется общий язык известных данных; если не хватает источника, операции или однозначной области — конкретное уточнение/отказ, а не фиктивный результат.
