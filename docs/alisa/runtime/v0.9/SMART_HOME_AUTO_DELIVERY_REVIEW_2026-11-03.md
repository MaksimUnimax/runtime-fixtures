# Автоматическая выдача отчёта через «Дом с Алисой»: восстановление исходного плана и решение по матрице 0.9

Дата пересмотра: 03.11.2026. Область: отдельный проект «Октопорт маркет», ветка alisa. Статус: **архитектура и подтверждённые контракты; физический IoT→Станция→приватный навык пока NOT VERIFIED**. Изменения в рабочем webhook или OAuth этим документом не выполняются.

## Откуда восстановлено, и что было решением
Источники внутри принадлежащего владельцу контекстного архива ALISA_COMPLETE_CONTEXT_HANDOFF_2026-11-03(1).zip: prior-materials/AUTOANSWER_REPORT.md (от 02.11.2026), docs/01_HISTORY.md, docs/02_OWNER_DECISIONS.md, docs/03_PRODUCT_AND_ARCHITECTURE.md, docs/04_USER_JOURNEY.md, docs/05_YANDEX_DIALOGS_AND_OAUTH.md, docs/09_QA_MATRIX.md, docs/10_NEXT_STEPS.md. В docs/02 автоозвучка была обозначена **ПРЕДЛОЖЕНО**, не как уже технически принятая функция; владелец 03.11.2026 вновь указал на неё как на целевой вариант после текущей схемы.

Исходная цель: человек задаёт один запрос голосом; наш сервер принимает постоянное задание, выполняет API Ozon/WB и расчёт; по готовности **сам инициирует** выдачу через выбранную колонку. Команда «результат» — резерв/отладка, не обязательная реплика в целевом UX. Ответ JSON обычного навыка должен полностью прийти за 4,5 секунды; долгую работу делает worker. Старые сроки в секундах — примеры, не гарантия платформы.

## Документированный возможный транспорт
1. В пользовательском приложении «Дом с Алисой» создаётся сценарий на конкретную Станцию. Действие: «Произвольное действие: ответить на вопрос или выполнить команду» с **фиксированной** фразой обращения к навыку «Октопорт маркет», например «Попроси Октопорт маркет прочитать ожидающий отчёт». В API старта сценария нет параметра с динамическим текстом; цифры не передавать через действие.
2. Отдельное OAuth-приложение Яндекса (не account-linking нашего навыка) получает по согласию пользователя iot:view для чтения списка сценариев и iot:control для их запуска. Токен привязки навыка нельзя использовать в IoT API.
3. Сервер сохраняет разрешённый scenario_id и связь account/профиль/колонка/канал. Не использовать произвольный сценарий, выбранный LLM. Доступ iot:control шире запуска одного сценария, поэтому ограничение должно обеспечивать наше приложение.
4. После перевода отчёта в READY и фиксации события доставки worker запускает **POST https://api.iot.yandex.net/v1.0/scenarios/{scenario_id}/actions**. Статус ok подтверждает приём запроса на запуск сценария, **не** то, что колонка заговорила.
5. Сценарий инициирует команду Алисе; при успешном переходе в наш обычный навык открывается **новый** запрос с отдельным бюджетом 4,5 секунды. Навык перепроверяет связанную учётную запись, разрешённый канал и конкретный ожидающий готовый отчёт; читает сохранённый text/tts без повторного DeepSeek или Ozon/WB.
6. Выдачу фиксировать отдельно от отправки POST. Не выводить чужой финансовый отчёт, «последний отчёт в системе» или данные другого устройства. При нескольких готовых заданиях — явная серверная очередь/маршрутизация.
7. Окно времени, режим «тихо», отключённые сценарии, занятая/оффлайн колонка, отзыв IoT доступа, дубль callback, тайм-аут POST с неизвестным исходом — обязательные отдельные состояния. Не повторять неидемпотентный запуск слепо. До подтверждения пользователем доставку считать лишь попыткой, не услышанным ответом.

Документация проверена 03.11.2026:
- Яндекс API запуска сценария: https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-scenario
- Яндекс IoT scopes/методы: https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol
- Список сценариев: https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-user-info — ScenarioObject сообщает id/name/is_active, не целевое действие/устройство.
- UI создания действия-команды Станции: https://inclusion.yandex.ru/tutorials/smart-home-with-alice-ios-part3
- Обычный навык **не** начинает беседу сам: https://yandex.ru/dev/dialogs/alice/doc/ru/activation
- Тайм-аут обычного webhook: https://yandex.ru/dev/dialogs/alice/doc/ru/response

**Не подтверждено**: официальный гарантированный переход из серверно запущенного пользовательского сценария в наш приватный обычный навык именно на выбранной модели Станции, сохранение OAuth-контекста при этом, реальный звук, модерационные условия. До аппаратного испытания утверждение «автоозвучка уже работает» запрещено. В архивах прежней команды не найдено фактической IoT-связки/POST/звукозаписи; тесты были синтетическими.

## Отдельные этапы испытания
A. Настоящая Станция и согласие пользователя на отдельное IoT OAuth. Создать сценарий в приложении вручную; безопасная фраза без денег.
B. Получить список сценариев; закрепить ID конкретного созданного сценария с проверкой владельца.
C. Запустить сценарий через POST, подтвердить реально услышанную безвредную фразу на **нужной** Станции. Одного status:ok недостаточно.
D. Заменить действие на фиксированную команду приватному навыку; убедиться в новом реальном запросе webhook с корректной учётной записью. Если переход не работает — не объявлять путь подтверждённым.
E. Долгий тестовый отчёт READY, единичный запуск, произнесённая готовая сводка **без второго запроса пользователя**, соблюдение прав и отсутствие новых provider/LLM вызовов при выдаче.
F. Музыка, другой пользователь, время «Не беспокоить», offline, неизвестный исход, два отчёта/две колонки, отмена/ручное чтение прежде автоответа, revoke, тайм-аут.

## Какова реальная полнота матрицы 0.9
Версия 0.9 build5: 42 зарегистрированных показателя (не все поддержаны на обеих площадках), 8 формул в expression_catalog.json (6 прежних и 2 демонстрационные вложенные), 44 группы речевых метрик и 16 bundles в speech_catalog.json. P1 применяет существующие фразы; P2 через DeepSeek может построить вложенный AST из зарегистрированных примитивов и 8 операторов add/subtract/divide/percent/relative_change/per_day/minimum/maximum. Это **не** поддержка любого вопроса. Действуют ограничения источников/гранулярности/периода/площадки/права/валюты. Чистая прибыль без себестоимости, произвольный JOIN/TOP/SKU, оконные ряды, причинность и недоступные API не поддерживаются.
Установленный v0.9 проверен на двух настоящих составных запросах Ozon с P2/DeepSeek + API; это не тест точности всех будущих русских формулировок. В Console именно build5 пользовательская приёмка ещё не получена.

### Добавление шаблонов после релиза
- **Новая фраза/синоним/набор**: изменить speech_catalog.json, пройти проверку коллизий и регрессию.
- **Новая формула из существующих показателей**: изменить expression_catalog.json, проверить типы/циклы/ноль/единицы/период/платформы и реальное read-only canary. Python ядра не меняется.
- **Новый показатель/поле/источник API**: реестр, проверенный адаптер, контракт/права/пагинация/валюта и live qualification; невозможно одной JSON-формулой.
- **Новый оператор**: новая версия языка вычислений и тестов.
- **Новые вопросы не превращаются автоматически в постоянные шаблоны**. P2 может разобрать новую комбинацию на лету, но «самообучающаяся публикация шаблона» не реализована. Если позже добавлять процесс предложений из обезличенных нераспознанных запросов, он должен требовать review и версионированного выпуска; никаких автоправок production моделью.

## Как тестировать сейчас
Без физической Станции можно тестировать авторизацию, канонический план, P1/P2, реальный API, READY и сохранённый text/tts через Яндекс Диалоги. Команда «результат» в текущей реализации — инструмент readback и резерв для длинного отчёта; **не** финальная архитектура. Факт полноценного серверного автообращения к Станции не подтверждать консольным тестом. Отдельно проверить на реальной Станции IoT-путь.
