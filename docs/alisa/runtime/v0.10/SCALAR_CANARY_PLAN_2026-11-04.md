# План ограниченной сетевой проверки scalar matrix r3

04.11.2026. Продолжение ADR-006, не переключение навыка. Общая миграция девяти семейств написана; локальные 777 проверок пройдены. 06:34:51 UTC новый общий декодер и прежний build8 дали равные запросы, значения, валюты, строки и полноту на одних сохранённых ответах восьми семейств. Исходного месячного тела Ozon orders не найдено; этот пробел не называется закрытым повторным чтением.

## Разрешённая следующая проверка

Владелец ранее разрешил реальные read-only Ozon/WB запросы. Запустить отдельную короткоживущую проверку НЕ от root, с теми же systemd credential references и ограничениями, что у действующего сервиса. Основной runtime, OAuth, матрица и live-конфигурация остаются без изменения. Проверить девять уже подключённых в действующем build8 семейств новым источниковым интерпретатором; новые endpoint не добавляются. Октябрь 2026 — для периодных данных; текущий момент — для snapshot. Никакой новой подписки, правки товаров/цен/рекламы.

Допуск только READ_ONLY_CANARY, отдельно для точных новых registry/scalar hashes. Он основан на неизменных квалифицированных старых контрактах, полном offline-наборе и новой дифференциальной проверке. Это разрешение на испытание нового кода, НЕ заранее объявленный LIVE_VERIFIED и НЕ автоматическая замена qualifications действующего сервиса.

## Ограничения исполнения

- Максимум 16 физических вызовов всего, не более 150 секунд активной проверки; ожидание квоты ограничено, HTTP 429/неизвестный исход не повторяются этим runner автоматически.
- Общий ledger и rates действующего кабинета используются до каждого обращения. Отдельное test-job сразу RUNNING с собственным owner/lease: не попадает в очередь старого worker, не меняет pointers/slots/inbox пользователя. При обрыве остаётся UNKNOWN после lease и не повторяется.
- Текущие access/source revisions, enabled/active scope проверяются перед каждым обращением. Qualification требуемого data-source проверяется до grant.
- Ключи и рекламный token только в закрытой transport boundary. Grant учитывается отдельно; token не записывается в job/result/progress/лог.
- После завершения runner не создаёт пользовательский READY и не отправляет финансовые данные в чужую сессию: техническое задание закрывается CANCELLED с явным кодом результата теста, payload очищается; компактный ledger удаляется действующей retention по сроку.
- Итоговая квитанция содержит операцию, безопасные параметры периода, HTTP, время, полноту, число строк/показателей и hash версии; без сумм, товаров, внешних токенов и сырых ответов. Число PASS не выдумывается при отказах/лимитах.
- Временная проверка не является приёмкой в консоли Диалогов или на Станции. Отдельная установка по-прежнему требует проверенного релиза и readback.

Если штатный вызов отклонён, фиксировать сообщение, сверить параметры и факт исполнения по TOOL_FAILURE_RUNBOOK. Не переносить отклонённое действие в обходной транспорт. Независимые разрешённые тесты/документация продолжаются.
