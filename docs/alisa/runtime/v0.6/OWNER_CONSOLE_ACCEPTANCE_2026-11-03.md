# Пользовательская приёмка через консоль Яндекс Диалогов — 03.11.2026

## Новое прямое доказательство

Владелец прислал текст реальной консоли приватного навыка «Октопорт маркет» после развёртывания matrix 0.6 / web r3. Это закрывает прежний пункт «пользовательский проход после переключения ещё не наблюдался» в DEPLOY_ACCEPTANCE_2026-11-03.md. Старую запись следует читать как историческую границу до этого сообщения, а не текущий блокер.

Подтверждено пользовательским протоколом:
1. `диагностика аналитики` сообщила matrix 0.6 и включённый read-only маршрут.
2. `сводка заказов за октябрь 2026 на озоне и вайлдберриз` вернула реальный сохранённый отчёт по обеим площадкам.
3. `результат` вернула тот же отчёт с тем же временем получения 2026-11-03 07:48 UTC.
4. Свободная фраза «Сколько было заказано товаров и на какую сумму за октябрь 2026 на Озоне и Вайлдберриз?» была принята как задание; последующее `результат` вернуло тот же отчёт.
5. `ДРР за октябрь на Озоне` вернула явный отказ от ещё не подключённого показателя. text и tts в присланном Response совпадают, end_session=false.

Это подтверждение настоящего платформенного пользовательского чтения отчёта и отсутствия подмены ДРР заказами. Протокол сам по себе не измеряет количество новых HTTP/LLM-вызовов: одинаковый timestamp согласуется с exact-cache, но для строгого вывода о расходах нужны серверные счётчики. Предыдущее серверное доказательство разбора DeepSeek и алиасинга описано в DEPLOY_ACCEPTANCE; не превращать его в новый замер.

## Сохраняющиеся ограничения

Ozon не подтвердил в этом ответе код валюты; ответ корректно не называет его сумму RUB. Код RUB для WB получен из предыдущего API-ответа. Кабинетная сверка цифр, физический звук Станции, ДРР/расходы/прибыль/выкупы/остатки и товарные фильтры этим тестом не подтверждены.

Финансовые суммы, user_id/application_id/session_id и полный Request в публичный Git не переносятся. В присланном Request присутствует access_token; его значение исключено из документа и кода. Не использовать его для воспроизведения пользовательской сессии. Этот документ не утверждает отзыв или проверку срока действия токена.

## Обязательное правило по отказам инструмента

Владелец повторно потребовал: при отказе сначала читать точное сообщение и контекст, проверять аргументы, применять уже подтверждённый корректный штатный способ и продолжать разрешённую работу. Опубликованный порядок: [TOOL_FAILURE_RUNBOOK.md](../../TOOL_FAILURE_RUNBOOK.md).

Отказ до исполнения не является HTTP-ошибкой площадки или доказательством неисправности ключей. Известный случай 03.11.2026 07:27:44–07:27:45 UTC: повтор проверенного вызова существующего read-only probe через штатный RDC завершился exit code 0, три API-ответа HTTP 200; квитанция прочитана отдельно. Конкретный триггер предыдущего отказа инструмент не раскрыл. Не обещать универсальное снятие блокировок и не обходить защиту.

## Следующая обнаруженная работа

При независимом локальном продолжении воспроизведён дефект v0.6: P0-команды обходят inbox-дедупликацию. Поздний повтор того же сообщения «отмени отчёт» может отменить следующее задание, на которое уже переместился указатель. Аналогично повтор чтения может вернуть другой отчёт. Требуется атомарная квитанция P0 вместе с изменением состояния, проверка изменённого replay, текущих прав и TTL. Это дефект обработки доставки сообщений, не дефект ключей и не причина объявлять предыдущую пользовательскую выдачу неуспешной.
