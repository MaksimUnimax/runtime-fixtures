# RT-JOB-R02.3: RuntimePort на актуальном ядре

Дата: 09.11.2026. Статус: SOURCE_CANDIDATE_NOT_INSTALLED. Это продолжение платформенных PR405/PR407, а не установка старого R01 поверх работающего сервиса.

## Исходная версия и владение

Пакет `rt_job_r02/` перенесён на code-only снимок установленного `alisa-answer-model-r4-20261109`. Исходный engine SHA256: `d2c16334a81c7e12a5af8440f37d75b2d18d91c7c2454f6eccc14cbef8db354f`; архив исходных 127 файлов: `123cbdb8232c69f45e7a2cb47872d75bff4fa9586016cf1e50e90cd86c53d8c0`. Реальная конфигурация, БД, ключи и пользовательские данные в снимок не входят.

`SOURCE_SNAPSHOT.json` сохраняет хеши 127 исходных файлов. `CURRENT_CORE_MANIFEST.json` закрепляет 141 файл кандидата. Сохранены новый этап ответа модели, три настройки промптов, классификация/восстановление запросов и прежние тесты установленного ядра. Порт использует существующий этап ответа в той же очереди: original question передаётся через штатный ContextVar, а scope проверяется перед поздним dispatch и публикацией `complete_answer`. Объяснение отказа площадки 401/403 требует актуального платформенного владельца и подтверждённой квитанции отказа; прежние данные для него удаляются. Это разрешение на объяснение ошибки, не на повторное чтение источника.

`BASE_INSTALLED_MANIFEST.json` сохранён побайтно как историческая метаинформация первоначального native пакета: текущую базу определяет свежий `SOURCE_SNAPSHOT.json`, а не название старого пути в этой квитанции.
Работа выполнена в отдельной ветке и копии. Активные пути автора матрицы/обработчика, работающие службы, native OAuth и Станция не менялись. Перед установкой нужно сверить свежий runtime: новый выпуск другого автора требует согласованного переноса delta, а не замены его файлов этим snapshot.

## Поведение

RuntimePort использует тот же configured Engine, Worker и SQLite, что native ingress. Дополнительный Unix listener обслуживает только платформенный контракт. Второго worker, очереди или модели identity нет. Feature выключена без явной настройки; `--check` проверяет форму без чтения credential и сетевых вызовов.

Execution guard переносится через готовый scalar/program, P2 с исправлением ответа модели, таблицы, dataset и универсальные чтения. Ветвь отказа typed compiler сохраняет guard при переходе к universal read. Проверки актуального scope выполняются перед фактической отправкой, в позднем callback HTTP/CSV dispatch, при публикации и выдаче. При смене mapping между последними verify/resolve сохранённый результат не выдаётся. Ticket и исходный bearer не записываются в jobs/receipts.

Модель продолжает использовать действующие model_recovery/request_recovery, CSV, единый журнал calls и окно model_usage в семь дней. Предотвращённая до dispatch попытка не считается оплаченным вызовом. Прежние суточные и количественные ограничения R01 не возвращаются; сохраняется реальная ёмкость хранилища и ограничения размера протокола.

Каждый public ref регистрирует отдельного читателя `rt_…` в существующем reader_state. Submit/status/read не перемещают голосовые указатели и не меняют чужие page/delivered. Cancel A сохраняет B; отмена последнего читателя может остановить общее задание. Состояние отменённого ref остаётся CANCELLED, даже если общий отчёт готов для B. References и receipts включены в bounded retention с защитой активных alias-chain; недельная очистка model_usage сохранена.

## Закрытый authority consumer

`PlatformAuthorityClient` вызывает настоящий `/internal/runtime/authority` через отдельно настроенный Unix HTTP socket. Проверяются владельцы/режимы пути, отсутствие symlink, SO_PEERCRED, общий deadline, Content-Length, пределы headers/body и строгий JSON. Reply должен иметь действительные nonce, product/schema, HMAC и точную форму claims/scope. Redirect, DNS/TCP, unsigned fallback, локальный permissive mapping и автоматические повторы отсутствуют. Подписанные dependency failures сохраняют свой код.

Платформа должна отдельно обслуживать этот Unix socket своей принятой версией authority. Этот пакет не открывает ей TCP-порт и не активирует route. Credential выделен только этой паре сервисов и передаётся через systemd credentials; модельный или магазинный credential отклоняется конфигурацией.

## Явная настройка после совместной приёмки

Пример формы, а не готовые имена служб/магазинов:

```json
{
  "runtime_port": {
    "enabled": true,
    "socket": "/run/alisa-runtime/runtime-port.sock",
    "allowed_user": "platform-service",
    "service_id": "qualified-platform",
    "catalog_release_id": "qualified-current-catalog",
    "authority_socket": "/run/alisa-platform/authority.sock",
    "authority_user": "platform-service",
    "authority_credential": "runtime-authority"
  }
}
```

Оператор заранее создаёт доверенный каталог listener и отдельный credential. Имена пользователей должны соответствовать настоящим OS UID. Платформа настраивает весь ожидаемый `current_versions` из принятого пакета; запоминать произвольную первую версию нельзя. Bundle hash закрепляет текущие core modules, каталоги и read-policy data; task schema остаётся прежней pinned v1. Настройка listener читается при запуске; изменения требуют штатного перезапуска. Права продукта и mapping проверяются заново при каждом обращении.

Реальные public/native mappings не выводятся из совпавшего UUID, email или названия. Они требуют подтверждённых идентичностей и revisions существующих ключей. Новые магазинные ключи и приложение Ozon для этого переноса не нужны.

## Проверки и граница приёмки

Неизменённая новая база и кандидат проверяются отдельно. Неизменённая база прошла 1675 проверок. Полная квалификация включает root dataset suites, прежние контрактные сценарии RuntimePort, native answer/recovery tests и 16 новых сценариев границы порта с ответом модели. Итоговые JSON содержат фактически выполненное число проверок, отсутствие skipped/external network attempts и хеш манифеста; исходники сверяются до и после.

PostgreSQL квалификация сохраняет 43 authority checks и расширяет current-core roundtrip до 11 сценариев. Новый проход получает обычный ответ модели в той же очереди и читает один job_ref через WebSession и Alice OAuth без повторного provider/model вызова. Используются production consumer, настоящий Django signer/authority RPC, Unix HTTP, listener, очередь SQLite и worker; provider/model синтетические. Тестовая БД, роли и контейнер удаляются после прогона.
Независимое review, source CI и авторская квалификация фиксируются раздельно. Этот этап не доказывает переключение настоящего навыка, показ отчёта в UI кабинета, фактический звук Станции или live provider/Yandex acceptance. Эти проходы выполняются после согласованной установки принятого current-core source и подтверждённой mapping-конфигурации.


## Совместимость plain answer с платформой

Только страницы ответа допускают штатные LF/CR/TAB; текст запроса, идентификаторы и прочие строки сохраняют прежний строгий валидатор. NUL, ESC и некорректный UTF-8 отклоняются. Содержимое страниц не переформатируется. Проверки клиента расширены до 29; PostgreSQL 43+11 прошёл после исправления переноса строк.

При независимом R7 review обнаружены оставшиеся старые копии `http_transport.py` и `table_analytics.py`. Оба восстановлены побайтно из свежего native snapshot: native model_source/model_answer/COLLECTION_SYSTEM, classified model_response и ветка stage_answer для таблицы сохранены. Точный diff с 125 исходными файлами теперь ограничен девятью перечисленными модулями: восемь прежних port integration modules плюс provider_failure для guard текущего владельца. Отдельный тест проходит 5000 строк через табличную пагинацию к ответу модели при запрещённом voice renderer. Результат предыдущего неуспешного прогона сохраняется в evidence, исправленная версия проходит новый прогон.


## Объединение R4 с портом

Основа сверена с 24 runtime source hashes коммита `10a625949a3bb144487d75f5b7d4af389bb7e8cb`. Это более поздний источник, чем прежний paid-model-result-r4 manifest b511…; его историческая квитанция не выдаётся за hash текущего снимка. Сохранены classifier, отрицательный model_result, запрет повторения отказанного API, отбрасывание прежних данных, FAILED TTL 900 секунд, восстановление запросов, админские промпты и действующий timeout транспорта. Параметры не преобразуются, предполагаемые типы из текста ошибок не выводятся. Новых шаблонов и нового lifecycle подписок нет.

RuntimePort `read_result` возвращает result_kind=DATA либо PROVIDER_REFUSAL. Для подтверждённого отрицательного объекта сохраняется полный model_result с ok=false, data=null и retryable=false. READY в последнем случае означает готовое пояснение. Платформенный клиент проверяет схему, разрешённые tier id/name, источник provider_response, hash, размеры и отсутствие данных; metadata не расширяет доступ. Проверка metadata выполняется до последней авторизации и TTL. Legacy-ответ без новых полей остаётся допустимым для прежнего клиента. Task schema v1 не менялась, port build обновлён до R02.3.

Конфликты разрешены по функциям: engine сохраняет R4 stored explanation и PAYLOAD_TTL вместе с платформенным guard; runtime сохраняет max_request_seconds+10 и корректное закрытие только собственных sockets. Все прочие native файлы и тесты скопированы из R4 побайтно. Только девять native модулей содержат delta порта.
