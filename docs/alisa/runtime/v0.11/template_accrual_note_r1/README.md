# Пояснение «начислено Ozon» в шаблоне

По замечанию владельца 09.11.2026 обновляются только notes и версия B08.finance_accrued (1 → 2). База: alisa-model-token-cost-r1-20261109; SHA256 исходного каталога зафиксирован в template_patch.json. Полное сравнение JSON подтверждает неизменность остальных 84 шаблонов, операций, параметров и привязок данных.

Источник величины: POST /v1/finance/balance → total.accrued.value. Это исходный итог начислений за выбранный финансовый период. Выплаты берутся отдельным показателем из total.payments, остаток — из total.closing_balance; они не подменяют друг друга.

Пояснение передаётся обычным уже установленным механизмом template_context вместе с исходными разрешёнными данными API, в том числе через составной шаблон, использующий B08.finance_accrued. Глобальные промпты и обработчик ответа не меняются. Количество модельных этапов — два. Конкретный состав финансовых операций модель описывает только в соответствии с полученным ответом API. Пояснение не утверждает факт банковского перевода, прибыль, полную расшифровку всех удержаний или совпадение даты начисления с датой заказа.

Сумма и содержание голосового ответа предыдущего прогона приняты владельцем; ясность формулировки требует этого пояснения. Предыдущий запуск без задания отдельно зафиксирован как сбой до создания аналитического задания. Повтор того же вопроса прошёл без изменения рабочего кода: 5,95 с, два модельных вызова. Точная сторона первого сбоя по сохранённым метаданным не доказана; отсутствие события успешного webhook само по себе не исключает незафиксированный ранний HTTP 500. Содержимое финансового ответа не публикуется в открытом пакете.

Два запроса детализации удержаний WB/Ozon внесены только в план после простых. Текущая правка их не реализует и не включает в исполняемый каталог.
