# Выкупы WB: дата события и дата заказа

10 ноября 2026 запрос «Сколько товаров выкупили на Вайлдберриз восьмого ноября?» ошибочно направлен моделью в `B04.buyout_units_cohort`. Этот шаблон считает выкупы **из заказов выбранного периода** и вернул ноль. Для выкупов, совершившихся в указанную дату независимо от даты оформления заказа, в каталоге уже есть `B02.wb_events` с осью `event_date` и метрикой `event_buyout_units`.

Уточнение по распоряжению владельца помещено только в `purpose` двух существующих шаблонов, версии 1 → 2:

* `B02.wb_events`: «Фактические продажи (выкупы) WB по дате события, независимо от даты оформления заказа. Количество и сумма продаж; возвраты отдельно.»
* `B04.buyout_units_cohort`: «Выкупы из заказов WB, оформленных в выбранный период (когорта заказов). Только для вопроса, сколько из заказанных тогда товаров выкупили; не для выкупов по дате события.»

Серверных классификаторов ключевых слов, новых шаблонов, преобразования параметров и примечаний для озвучивания нет. Расчёты, источники и права не изменяются. Полный каталог восстанавливается применением двух записей `template_patch.json` к каталогу релиза `alisa-wb-sales-purpose-v5-20261110` с проверкой SHA256.

Фактический повтор выбора в DeepSeek и озвучка требуют отдельного согласованного прогона после команды владельца; текущий STOP сохраняется. Установочная проверка: 76 проверок шаблонов, сверка активной базы и её манифеста, два `purpose` и две версии как единственная дельта, отсутствие активного задания/доставки, отдельный релиз без редактирования исходного.

Отдельное наблюдение по стоимости: запрос с неправильным `B04` передал итоговой модели 60 482 входных токена с нулём попаданий в кэш; это объясняет его высокий расход сверх обычного выбора. Оптимизация кэша DeepSeek ведётся другим исполнителем.
