10 ноября 2026. Реализован код оптимизации штатного DeepSeek prefix cache. Рабочий сервис, данные шаблонов и голосовые тесты этой работой не менялись. Публикация кандидата не является командой немедленно перезапустить ядро.

Основной patch: [CACHE_CODE.patch](CACHE_CODE.patch). SHA256 `f9c07625e9d3ae80a6c53abe980e2f53ea0ca9833174e0500d45d875492dd175`, Git blob `03a6836a0a5c256c477cba4f3f9f395027c3091f`. Полный пакет с тестами и helper находится в `/root/alice-lab-evidence/prefix-cache-20261110/`; итоговая квитанция пакета — PACKAGE_RECEIPT.json.

## Состав изменения

Восемь файлов: engine.py, model_usage.py, runtime.py, новый selector_policy.py, template_catalog.py, template_protocol.py, template_runtime.py, новый tests/test_selector_prefix_cache.py. JSON-каталог, purpose/notes, источники, расчёты, model_answer, HTTPTransport, retry-политика, RuntimePort и Station не редактируются.

Два layout: legacy_v1 воспроизводит старый payload; catalog_prefix_v2 ставит общие поля85шаблонов и input_contract до индивидуального контекста. available_stores вынесен в хвост. Хеши, даты сборки, случайныеID и меняющийся номер каталога НЕ стоят перед общей частью. Метаданные отдельно от messages.

purpose участвует в выборе. notes и notes-only version не участвуют. Содержимое берётся из текущего каталога, не из дополнительного вручную обновляемого справочника. Системные инструкции/роли/модель/temperature/thinking/JSON-контракт сохраняются.

Обычный успешный вопрос по-прежнему имеет два модельных вызова; template_verify не возвращён. Cache miss не является ошибкой и не запускает повтор. Повторы только по существующей политике временных ошибок с тем же подготовленным payload. Текущие права проверяются заново. Кэш ответов, Redis, прогрев по таймеру и квоты не добавлены.

## Политика и включение

Без нового ключа конфигурации используется исходное поведение:

```json
{"selector_prompt":{"layout":"legacy_v1","isolation":"legacy_none"}}
```

После согласованной установки и контрольной проверки рекомендуемая конфигурация для новых заданий:

```json
{"selector_prompt":{"layout":"catalog_prefix_v2","isolation":"tenant_v1"}}
```

Это добавление только одного server-owned поля в существующую конфигурацию, не полная замена файла. tenant_v1 передаёт стабильный непрозрачный user_id, выведенный из авторизованной области клиента; он находится вне messages. A/B использует тот же user_id в обеих ветках. Финальный model_answer этой поставкой не меняет свою политику изоляции.

Выбор layout/isolation сохраняется в draft при приёме задания. Старое задание без поля — legacy_v1. Уже отправленный body сохраняется с hash в progress и повторяется побайтово. Смена default не переписывает принятые задания. Это поддержка двух форматов внутри одной сборки, НЕ поддержка одновременно исполняемых разных версий каталога.

Первоначальная база: selector-terminology-r1 /7f5af81dc6567f2ad30fb319adf4a528ad31eaad. Затем сохранены параллельные изменения WB sales purpose v5 /2e24ff30fc59dbf85d2817b09a8876fd5b8113c5 и WB buyout-date v2 /67a65d14feed9279040bbd936a958b5816c6b681.

Последний подготовленный кандидат: `/dev/shm/alisa-prefix-cache-20261110/candidate-latest`, база `alisa-wb-buyout-date-v2-20261110`. Точные контрольные суммы в LATEST_REBASE.json и FINAL_READBACK.json. Если ядро успело обновиться, нужно пересобрать кандидата, а не заменять его старым каталогом.

`prepare_candidate.py` из пакета копирует актуальный base в отдельную директорию и применяет только восемь проверенных code-overrides из code-bundle. Каждый изменяемый исходный файл сверяется по ожидаемому SHA. Изменение чужим агентом затронутого кода приводит к CODE_REBASE_REQUIRED, а не к перезаписи. Обновления template_catalog.json и других защищённых данных копируются из актуальной базы без подмены. Скрипт запрещает выход внутри /opt/alice-market и не устанавливает службы.

Пример подготовки отдельной копии, не развёртывание:

```sh
python3 -B prepare_candidate.py --base /opt/alice-market/releases/<ACTUAL_CURRENT_RELEASE> --output /dev/shm/alisa-cache-reviewed-candidate --bundle ./code-bundle
python3 -B run_offline.py --candidate /dev/shm/alisa-cache-reviewed-candidate --evidence /dev/shm/alisa-cache-reviewed-evidence
```

Сначала проверить настоящий ExecStart, не угадывать ACTUAL_CURRENT_RELEASE. После изменения видимого purpose/input_contract нужен контроль затронутых вопросов на новой общей для обеих веток версии. Новые платные A/B не запускаются автоматически этими двумя командами.

## Установка: только согласованный промежуток

Ответственный за развёртывание получает от тестера границу после расчёта, автоматической доставки и ожидаемого продолжения. Пустая QUEUED/RUNNING сама по себе недостаточна. Под `/run/lock/alisa-market-config.lock` повторно проверяются база, manifest, текущие шаблоны и отсутствие нового принятого задания; готовый пакет устанавливается по штатной схеме нового immutable release.

NativeRuntimePort включён и связывает guards с Python bundle: его проверки нельзя отключить ради установки. Согласовать совместимость платформенных pins/current-authority. Не запускать второй Worker на общей productionDB и не обещать zero-downtime без отсутствующего listener-handoff. Никакой установки в середине текущего голосового сценария.

Внутренний ledger получает только дополнительную nullable колонку calls.model_context. Миграция идемпотентна. Старые квитанции не переименовываются в известный этап; неизвестная стоимость не ноль. Те же семь дней хранения; очистка строки удаляет метаданные. Существующая очередь неподдержанных вопросов сохраняет свою политику.

`model_usage.summary()` дополнен cache_by_stage. `stage_summary(..., rates_by_model=...)` считает взвешенную долю кэша и стоимость по переданным датированным ставкам. Самостоятельного получения тарифов, жёстко зашитой цены и нового frontend-экрана нет. Для отчёта тестера доступны stage,layout,hit/miss/output/полнотаusage; добавлять их к вопросу/ответу/времени/числувызовов/стоимости.

Возврат: для новых заданий вернуть layout legacy_v1, сохранив выбранную политику изоляции. Не откатывать весь каталог к старой версии. Уже принятые задания не переписывать и не исполнять повторно только из-за смены layout.
