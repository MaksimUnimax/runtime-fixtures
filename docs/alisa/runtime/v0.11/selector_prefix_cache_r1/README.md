## Активная policy

```json
{
  "selector_prompt": {
    "layout": "catalog_prefix_v2",
    "isolation": "tenant_v1"
  }
}
```

Каталог и входная схема идут до вопроса/даты/магазинов/доступности. Меняющиеся hash/version/time не ставятся перед каталогом. purpose участвует в выборе, notes — только в итоговом ответе. tenant_v1 использует непрозрачный стабильный user_id внеmessages, основанный на авторизованной области; final-answer policy не меняется.

Выбор layout закреплён в новом draft, точный подготовленный payload сохраняется для предусмотренных технических повторов. Старый draft без policy —legacy_v1. Смена настройки меняет только новые задания. Это два формата внутри одной сборки, не одновременная работа разных версий каталога.

Cache miss не запускает повтор; дополнительного template_verify, платного прогрева, Redis, responsecache или квот нет. Нормальный успешный сценарий остаётся двумя вызовами модели. Права/currentauthority проверяются заново; недоступность шаблона не обходится кэшем.
