## Реализованная цепь

`qualified cohort + cost candidates → CostSourceSelector → проверенный expense-envelope → прежние ScenarioBindings/ReportContracts/OwnerInputs → две таблицы`.

Правила компонентов, сценарные количества, методы денежных оценок и приоритеты описаны в cost_selection_catalog.json. Общий Python не содержит ветвей по Ozon/WB/названию фразы. Для строки выбирается matched actual; если источник квалифицированно недоступен — разрешённая оценка API, затем разрешённый официальный тариф. Отсутствующая запись не равна доказанному UNAVAILABLE, тем более нулю.

Заданы комиссия, прямая доставка, эквайринг и обратная перевозка. Комиссия принимает явный percent и явную цену продавца; эквайринг — прямую amount, не процент из отношения цен. Интервальная оценка использует (minimum+maximum)/2 только для настоящего диапазона. Фактическая корректировка может быть отрицательной при разрешённой политике; оценки неотрицательны.

Unknown cancellation stage не создаёт обязательного ручного подтверждения физической передачи: разрешённая conservative return estimate принимается как оценка. Это не отменяет проверки подлинности/пригодности самого тарифа. Отсутствие документа о передаче или возврате не становится доказанным нулём.

## Факт и оценка не смешиваются под одной меткой

Каждая выбранная строка сохраняет component/line/candidate/expense keys и basis. Суммы разделены на ACTUAL_MATCHED, API_TARIFF_ESTIMATE, OFFICIAL_TARIFF_ESTIMATE. Ноль неиспользованного основания — нулевой вклад выбранных строк этого основания, **не утверждение об отсутствии всех реальных списаний**. Будущий текст/таблица должны сохранять это различие.

Селектор не добавляет рекламу CPO вторично и не генерирует расходы периода. Реклама/хранение/controls приходят отдельным проверенным envelope. При отсутствии рекламы либо контроля пересечений прежний gate возвращает BLOCKED; итог обеих таблиц не публикуется как пригодный. Неуказанные COGS/tax/own costs остаются omissions. Сам модуль не устанавливает их в0.

## Исправленная граница адаптера

Первоначальный adapter доверял внешнему selection-словарю с совпавшим pin, но не проверял изменённые суммы/основания. Теперь execute-граница повторяет детерминированный выбор по тем же источникам/политике, сверяет весь результат и текущие разрешения, а также подтверждает retained expenses. Hash не является полномочием; verifier не берётся из пользовательского JSON. Без него, при отзыве, просрочке или подмене — отказ.

check_pin(action=read) проверяет неизменность inputs/policy/code и допуск без повторного расчёта. Код/хеш адаптера включён в normalization identity. ScenarioBindings и OwnerInputs не переписаны; их арифметика и сохранённые162теста неизменны.
