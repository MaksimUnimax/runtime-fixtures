# Выбор шаблона выкупов WB по дате события

По прямому указанию владельца после разбора simple-42 уточнены только purpose/version трёх шаблонов. Это подсказки выбора для DeepSeek; notes озвучки сохранены.

- **B02.wb_events**: Фактические выкупы (продажи) WB по дате выкупа, независимо от даты заказа: количество и сумма. Для выкупов за дату без явного условия «из заказов, оформленных…».
- **B04.buyout_units_cohort**: Количество выкупов из заказов WB. Только при явном условии «из заказов, оформленных за период». Обычные выкупы за дату — B02.wb_events.
- **B04.buyout_revenue_cohort**: Сумма выкупов из заказов WB. Только при явном условии о дате оформления заказа. Обычная сумма выкупов за дату — B02.wb_events.

База: alisa-wb-returns-brief-20261110 / 7c3d6397db718f9b1772d0432b8b88bd146a9bc8. Все исполняемые файлы, расчёты, API и прочие записи сохранены, вместе с кэшем и упаковкой.

46 адресных проверок текущего каталога PASS; 0 failures/errors/skips. Независимое review назначения и установщика: без блокирующих замечаний. Повторного платного A/B и прогрева нет.

Важно для исполнителя тестов: запрос владельца о выкупах за дату нельзя заменять вопросом «из заказов, оформленных за дату». В simple-42 исполнитель задал другой вопрос; модель выбрала соответствующий B04, исходные ответы обоих API проверены; точные клиентские значения оставлены только в закрытом серверном BUYOUT_ZERO_RAW_API_RECHECK_20261110.json. Эта правка уточняет будущий выбор, но не объявляет прошлую формулировку исполнителя ошибкой модели и не даёт гарантии безошибочности LLM.

Пользовательские вопросы и параметры не переписываются сервером. Исполнитель сохраняет исходный смысл вопроса в сценарии теста. Для дальнейшей работы использовать новую установленную базу после квитанции rollout.
