# Упаковка полного входа итоговой модели, версия 1

По прямому поручению владельца от 10.11.2026: внедрить передачу имён полей один раз, с порогом 10 000 символов и простым сравнением длины. Этот документ уточняет исследование `DEEPSEEK_LOSSLESS_INPUT_COMPRESSION_OPTIONS_2026-11-10.md`: рабочий путь не считает токены и не выбирает между несколькими кодеками.

## Реализация

`model_input_encoding.py` получает уже собранные данные API. Если компактный исходный JSON короче 10 000 Unicode-символов, возвращает прежнее сообщение. Начиная с 10 000 символов описывает каждую форму объекта один раз в `schemas`, затем передаёт все значения объектов в том же порядке полей. Вложенные объекты кодируются таким же способом. Сравнивается длина полного сообщения, включая инструкцию и заголовки. При отсутствии уменьшения возвращается исходное сообщение.

Примитивные значения не преобразуются: строка остаётся строкой, число числом; `null`, отсутствие поля, пустые объекты/массивы, повторные записи и порядок элементов сохраняются. Названия полей сортируются так же, как в существующем `canonical_json`. Все исходные объекты кодируются, поэтому исходные поля `@`, `v`, `schemas` не конфликтуют со служебными именами. Это описание структуры; типов из текста код не выводит, записей по смыслу не отбирает и расчётов не выполняет.

Упаковка не создаёт постоянного словаря товаров, ссылок на внешние данные, новой таблицы БД или дополнительных модельных вызовов. Временное представление строится в памяти для отправляемого сообщения. В существующем `jobs.progress` сохраняется только номер версии преобразования `_answer_input_encoding` вместе со снимком промптов, до первой отправки. Данные API уже находятся в существующем задании и повторно в упакованном виде не сохраняются.

`model_answer.messages()` применяет кодек к сообщению с данными. Исходный вопрос, уточнения и редактируемые промпты сохраняются. Выбор шаблонов, обработка API-ошибок/429/Premium, транспорт, реальный учёт попыток и токенов продолжают работать через прежний путь. Каталоги шаблонов не входят в дельту.

Версия 1 фиксирована: порог, инструкция, порядок схем и правила сравнения относятся к этой версии. При изменении формата нужна новая версия с сохранением старого преобразователя для начатых заданий. Старый снимок промптов без `_answer_input_encoding` использует прежний JSON. Для повторов кодек заново строит то же сообщение из сохранённых данных. При переполнении рекурсии упаковки используется уже сериализованный исходник.

## Проверки

- 60 прицельных проверок: полный ответ, отмена/доступ, 429/503, Premium, два источника и выбранные примечания, повтор после перезапуска, фактический учёт попыток, старое начатое задание.
- Полный прогон предыдущей базы `alisa-wb-buyout-date-v2-20261110` с изменением: **1992 проверки PASS**, ошибок/пропусков/попыток внешней сети нет.
- На объединённой базе `alisa-selector-prefix-cache-r3-20261110` прошли **103 прицельные проверки** кэша, упаковки, очереди и ответа, затем **2035 проверок полного прогона**, без ошибок, пропусков и попыток внешней сети.
- Три отдельные проверки установщика прошли: заявка до переключения, заявка после запуска новой версии, откат при пустой очереди.
- Независимое ревью кодека и подключения: PASS. Проверено 500 случайных JSON-деревьев с восстановлением идентичного `canonical_json` и детерминированностью после сохранения/загрузки.
- Два реальных вызова DeepSeek на одинаковом синтетическом составном вопросе, без колонки и без запросов к маркетплейсам. Оба ответа верны по всем 12 числовым значениям: WB/Ozon, продажи/возвраты, суммы/единицы/число записей, выбранная дата и повторная одинаковая запись.

| Контрольный итоговый вызов | Длина сообщения с данными | Входные токены API | Выходные токены API, включая reasoning | Время |
|---|---:|---:|---:|---:|
| Исходное представление | 11 059 | 3 400 | 892 | 5,51 с |
| Упаковка v1 | 8 595 | 3 117 | 831 | 4,89 с |

В этом примере вход сократился на **8,32%**. Это фактический `usage`, а не офлайн-токенизация. Два вызова являются сравнительной проверкой перед установкой; рабочий запрос не отправляется в модель дважды ради выбора формата.

Расчёт стоимости контрольных вызовов: 0,17299 ₽ и 0,15990 ₽, всего около 0,33289 ₽, при проверенных ранее пиковых ставках $0,30/$1,20 за миллион входных/выходных токенов и курсе 82,7536 ₽/$ из текущей серии отчётов. Это пересчёт по usage, не отдельная банковская квитанция. Вызовы выполнены в 03:43 UTC, попаданий в кэш не было. Снижение выходных токенов и времени на одном примере нельзя приписывать только упаковке.

Прежние 39% были офлайн-оценкой на большой HTML-копии другого отчёта. Порог по символам не гарантирует одинаковую экономию токенов на любой структуре. Реальный расход продолжает учитываться штатно по ответу провайдера.

## Установка и соседние изменения

База установки: `/opt/alice-market/releases/alisa-selector-prefix-cache-r3-20261110`, source `b87c1de8ac34b44f5061b67ae94d133b24d273e6`. Цель: `/opt/alice-market/releases/alisa-input-packing-v1-20261110`.

Во время подготовки агент кэша обновил ядро. Первая попытка установки остановилась на `ACTIVE_BASE_CHANGED`, до каких-либо изменений службы. Упаковка перенесена поверх свежей базы кэша; `model_answer.py` и `http_transport.py` в обеих базах совпадали. Повторный полный прогон подтвердил объединённую версию: 2035 PASS. Изменения кэша и его текущая конфигурация сохраняются.

Три файла дельты: `model_answer.py`, новый `model_input_encoding.py`, новый `tests/test_model_input_encoding.py`. До установки сверяются все хеши текущей базы и кандидата с полным прогоном. Установка выполняется под существующим `/run/lock/alisa-market-config.lock`, при пустой очереди и отсутствии активной доставки, в отдельный каталог; исходный релиз сохраняется. Программный policy guard проверяется до переключения службы.

При ревью установщика найдено и исправлено окно: новая заявка могла появиться между проверкой очереди и остановкой службы, и неудачный откат оставлял бы службу остановленной. Теперь при занятой очереди служба возобновляется на текущей настроенной версии; откат откладывается. Последующий откат на релиз без кодека разрешён после завершения заданий v1 или с сохранением поддержки кодека.

Агент кэша должен брать свежую установленную базу. Общая затрагиваемая точка — `model_answer.py`; готовый файл из старого релиза нельзя накладывать целиком поверх этого изменения. Транспорт, настройки кэша, учёт стоимости и каталоги эта дельта не изменяет. Проверки колонки остаются остановленными по поручению владельца.

Файлы `qualification_review.json`, `live_results.json` и `verification.json` содержат только синтетический контроль и агрегированные результаты. Исходных данных магазинов и секретов в пакете нет.
