# AL S11 каталог действующих вопросов

SOURCE-кандидат. В рабочую установку не включён. Новых параметров экономики,
коэффициентов и изменений текущих шаблонов в этом изменении нет.

Клиент выбирает свой магазин, ищет вопрос и видит смысл, ось даты, единицы,
условия и версию. Готовит редактируемый вопрос в существующей форме, сохраняя
выбранный магазин; открытие карточки/формы ничего не исполняет. Для магазина,
которого ещё нет на загруженной странице, форма требует явного выбора.

Владелец админки читает метрики, зарегистрированные источники и зависимости
того же установленного каталога. Используется действующее разрешение
staff.manage, без добавления прав другим сотрудникам. Редактора/publish нет.

Данные поступают от конкретного RuntimePort с текущими PID/versions. Черновики
из репозитория не читаются. Секреты, notes, промпты и params API не выдаются.
Клиентский допуск проверяется локальной компиляцией действующего шаблона
для одного магазина и простого периода, с текущими проверками полномочий.
Это не обещание наличия данных/платной подписки у API: они проверяются при
настоящем запросе и отражены ограничением интерфейса.

Поиск/фильтр выполняются до dry compile; страница содержит максимум 10 карточек,
имеет continuation и общий предел времени 1,25 секунды между компиляциями.
Общий IPC timeout не увеличивается. Просмотр не создаёт job, не вызывает модель
или marketplace transport. Права не кэшируются между пользователями/запросами.

Интеграция в будущий принятый выпуск: добавить question_catalog_extension.py
рядом с текущим runtime, вызвать install() после существующих dispatch overlays.
Frozen rt_job_r02 и task schema не меняются; предыдущий dispatch сохраняется.
Платформа и оба UI включаются ALISA_QUESTION_CATALOG_ENABLED=1 только после
совместимой установки endpoint и обновления штатного versions pin. Пока флаг
по умолчанию выключен. Устаревшая версия/неизвестный endpoint закрываются
ошибкой, а не показывают заготовленный список как действующий.

Перед включением: новая сверка текущего manifest и active jobs, точная
квалификация кандидата поверх свежего ядра, объединение параллельных изменений,
CI и браузерная/установленная приёмка. Прежний успешный CI PR420 не переносится
на этот кандидат. Живая приёмка уточнений на колонке остаётся отдельным этапом.

Focused qualification: PYTHONPATH должен включать текущий квалифицированный
runtime, его tests, этот каталог, platform/src и tests/question_catalog;
python -B -m unittest test_catalog. CI дополнительно проверяет совместимость
с неизменяемой основой rt_job_r02. test_draft.mjs выполняет проверки выбора
магазина из настоящего TypeScript helper, без модели/маркетплейса.
