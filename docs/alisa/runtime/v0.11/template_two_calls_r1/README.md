# Два модельных обращения на поддержанный запрос

Причина трёх отправок в прослушанном WB-задании: template_select → template_verify → model_answer. Все три получилиHTTP200; ошибок/повторов не было.

По прямому требованию владельца отдельный сетевой template_verify удалён из общего исполнения. Новый порядок: template_select → существующая локальная compile_selection и проверка доступа → API → model_answer. Шаблоны, состав источников, промпты ответа и их настройки не меняются. Составной запрос также делает два модельных вызова в обычном успешном пути.

Старый сохранённый verify-checkpoint перекомпилируется теми же локальными проверками. План, digest и progress записываются одной транзакцией. Права/current-authority, квалификация источников, запрет универсального обхода, отказ при неподдержанном составе и сохранение входа модели сохранены.

selection_verified остаётся совместимым внутренним признаком успешной локальной компиляции, а не утверждением дополнительной независимой модельной проверки. Смысловое покрытие вопроса теперь выбирает первая модель; приёмка идёт по одному реальному запросу с комментарием владельца.

Все реальные попытки, включая сетевые повторы, считаются честно. Старые задания с 3 обращениями не переписываются; модельная ошибка/повтор может дать больше 2 попыток. Без подходящего шаблона по принятому пилоту остаётся один выбор и точный отказ.

База установки: alisa-retry20-r1-20261109; общая пауза 42920 секунд и последние ACL сохраняются. Код добавлен как overlay к полной фактически установленной базе. Голосовой запрос при изменении кода не запускается: следующий прогон требует комментария владельца.
