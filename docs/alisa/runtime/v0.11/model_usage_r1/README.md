# Алиса: обращения к модели на запрос за 7 дней

Статистика считает попытки HTTP-отправки к модели в общем транспорте. Старый журнал регистрировал резервирование до подготовки сети и удалял вызовы примерно через 25 часов, поэтому простой COUNT не давал нужной метрики.

## Формула и границы

- Числитель: записи единого журнала calls с source=model:* и dispatched в последние 604800 секунд. Включаются успешные, неудачные и неопределённые попытки, повторы и вызовы исправления формата.
- Знаменатель: принятые аналитические запросы за тот же интервал. Точный повтор request_id не добавляется; разные запросы, присоединившиеся к расчёту или получившие кеш, добавляются. Управляющие реплики и непринятые уточнения исключены.
- Это отношение двух потоков в одном временном окне, а не ретроспективная когорта только завершённых запросов. Если работают старые задания, их новые попытки входят в числитель; при нулевом знаменателе среднее отсутствует, а не равно нулю.
- Учёт начинается после установки, без восстановления вымышленных семидневных данных. Каждый старт консервативно сбрасывает подтверждение непрерывного покрытия, сохраняя имеющиеся суммы. UI показывает начало сбора, последний запуск и неполное покрытие.
- Это попытки на границе отправки, не банковский счёт провайдера. Квитанция SQLite и сетевой write не атомарны; при обрыве фактическое списание может быть неизвестно.

## Архитектура

Один журнал, очередь, транспорт и механизм восстановления сохранены. Отметка dispatched ставится один раз непосредственно перед первым HTTP send, после pool admission, DNS, TCP и TLS. Локальная ошибка ключа и ожидание занятого пула не становятся вызовами модели. Новый request counter фиксируется в той же транзакции, что принятие запроса. Никаких новых лимитов платной модели или отдельных обработчиков под конкретную фразу нет.

Общий обработчик восстановления существовал до этой задачи: он возвращает ошибки JSON/схемы/выражения модели на исправление, сохраняет исходный вопрос и успешные этапы, повторяет допустимые чтения после временных HTTP/сетевых отказов, учитывает Retry-After. Ошибки прав доступа остаются явными. Метрика учитывает стоимость этих повторов; она не добавляет сетевых повторов.

## Доступ и хранение

Новая секция находится на /admin/station/. Действие model_usage доступно staff OWNER продукта alisa_market; пользовательский endpoint его отвергает. IPC сохраняет SO_PEERCRED. Наружу возвращаются только агрегаты.

В counter нет текста вопросов, ответов, токенов или идентификаторов клиентов; идентичность запроса — необратимый digest. Новые поля calls не содержат тело ответа. Семидневный cutoff чтения точный. Физическая очистка выполняется существующим минутным таймером и при запуске runtime; без batch LIMIT для модельных записей. При остановленном сервере немедленная очистка невозможна. Основной журнал других провайдеров сохраняет прежние правила. Не архивировать рабочую БД/таблицы учёта ради доказательств; сохранять только код и обезличенные агрегаты. При откате приложения оставить новый retention активным, иначе старый код удалит модельную историю через 25 часов.

## Проверки исходника

На серверной копии с сохранёнными read_surface/universal_reads supply-read-r5: runtime 1332/1332, dataset 87/87, Station 43/43. Включены 7 новых проверок: реальный loopback HTTP 503→200, локальный отказ до сети, занятый пул, кеш/повтор/управляющая команда, 2501 просроченная запись активного задания, совместимость схемы, повторное подтверждение покрытия после старта. Внесённые сбои не направлялись в реальные API.

Независимое source review не нашло блокеров. Первое ревью нашло раннюю отметку до pool admission и ограниченную пакетную очистку; оба замечания исправлены и проверены повторно.

Серверные и синтетические проверки не доказывают физически слышимый звук на колонке. Установленный readback, реальные запросы и ограничения физической приёмки публикуются отдельным отчётом.

## Найденный реальный сбой CSV

Сложный свободный запрос дошёл до Ozon Performance. Провайдер вернул HTTP200 и CSV с разделителем `;`; старый DictReader использовал `,`, создавал None-ключи из лишних ячеек, sanitize бросал TypeError, а Worker ошибочно обозначал полученный ответ как UNKNOWN/UNEXPECTED_TRANSPORT_OUTCOME. Модель выбрала допустимый метод; причина была в нашем общем адаптере.

Новый csv_transport.py проверяет фиксированные правила quoting и все допустимые разделители потоковым проходом; выбирает только однозначный вариант либо использует явно объявленный response_csv_delimiter. Неоднозначность, дубли/пустые заголовки и разная ширина строк дают известную ошибку с HTTP200, без автоматического повтора. Пробелы, ведущие нули, десятичные запятые и кавычки сохраняются; редактирование чувствительных полей остаётся. Исправление не зависит от текста вопроса или имени метода. Реальный повторный разбор:908строк,16колонок,108987байт,HTTP200.

Ревью сначала выявило недопустимое влияние Sniffer на значения и неоднозначный выбор разделителя. Sniffer полностью удалён; добавлены отдельные регрессии. Все21прицельная проверка метрики и CSV прошли; полный итог публикуется в итоговом отчёте.

## Финальное объединение

Параллельный исполнитель установил read-completion-r2 с защищённым чтением файлов, отдельными правами WB и очисткой private payloads. Эти изменения сохранены целиком. Для финальной сборки применяется только список OVERLAY.json поверх полной установленной базы; остальные исходники в этом каталоге являются более ранними срезами. Старые repository/retention/local_gateway поверх новой базы не накладывать.
