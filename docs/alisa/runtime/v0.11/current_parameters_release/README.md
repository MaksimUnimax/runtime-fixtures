14 ноября 2026. Владелец повторно подтвердил параллельного агента. Его S11 source d4eb0ccf установлен отдельно; эта поставка строится поверх точных S11 platform/native/web manifests и не заменяет его admin/cookie-правки. Общая блокировка `/run/lock/alisa-stage-rollout.lock` и повторные readback/CAS обязательны.

## Состав и граница

Application source `1d572aebf6b05b88ae5c233ae4313284add03e45`. Зашифрованная доставка, ранее запрошенная через review-карточку, уже выполнена: payload на Alisa проверен по SHA, временная публикация удалена. Старые статусы «ожидается Run» более не актуальны.

`build_candidate.py` создаёт только отдельные immutable releases, не меняет live selectors/services/DB. В payload обнаружены два расхождения с поздним состоянием проекта: отсутствовал S11 runtime-каталог и старый donor protocol терял свежий абзац точного dataset-подсчёта. Они устранены точными supplement: сохраняются весь live protocol и S11 service overlay, добавляются только parameter-правила. Все86старых template-определений неизменны, добавлены2коэффициента. Native PIN и descriptor проверены как nobody без секретов/сети; изменяется только catalog_bundle_hash.

`migration_guard.py` допускает ровно owner_data.0002_current_parameter_only, без новых grants. Миграция и проверки схемы/прав/сохранности owner_data находятся в одной транзакции. При rollback приложения добавочная таблица и текущие значения не удаляются. `migration.py` использует точный существующий helper миграционной идентичности; не печатает закрытую конфигурацию.

`activate.py --check` читает manifests, активные selectors, очереди, доставку колонке, роли и план миграции. `--apply` под общим flock ещё раз проверяет всё, останавливает admission web/platform/native, проверяет race, применяет добавочную миграцию, включает точные parameter-флаги, синхронизирует native версии/поколение существующей owner-пары и запускает прежние службы на новых immutable-копиях. Сессии/права/привязки не создаются. Admin, identity, station и SMTP не перезапускаются.

Rollback не перезаписывает третьего автора. Восстановление каждой службы зависит от успешного восстановления/чтения её selectors/config/flags и daemon-reload, native дополнительно от version-sync. Ошибка чтения или записи квитанции не прерывает безопасное восстановление независимых служб; конфликтные элементы помечаются для внимания. Файлы открываются как regular через lstat + O_NOFOLLOW/O_NONBLOCK + fstat dev/inode, поэтому symlink/FIFO не трактуется как отсутствующий управляемый файл.
