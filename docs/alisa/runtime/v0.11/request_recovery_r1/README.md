# Восстановление запросов и выдачи на колонку — 8 ноября 2026

Проверяемый результат: один пользовательский вопрос должен пройти выбор метода, получение данных, расчёт и выдачу. Временный отказ внешнего сервиса сохраняет то же задание. Реальные ограничения доступа и отсутствие необходимых данных не заменяются выдуманным ответом.

## Найденные причины и исправления

1. HTTP 500/502/503/504/408/425 обрывали задание. Теперь все разрешённые чтения и вызовы модели используют общую обработку повторов; сохраняются исходный вопрос, магазин, период и уже завершённые этапы.
2. Потеря соединения/таймаут оставляли задание UNKNOWN. Разрешённые чтения продолжаются после паузы с проверкой прав.
3. 429 без Retry-After откладывал только одно задание. Теперь пауза действует на общий источник, остальные задания не создают повторный поток отказов. Retry-After соблюдается; фиксированного числа попыток нет.
4. Повреждённое тело ответа 429 могло скрыть сам статус. Статус и заголовок ожидания сохраняются независимо от тела временной ошибки. Для 400/401/403 тело сохраняется: оно нужно проверке подключения магазина.
5. Исправление ответа DeepSeek было только в свободном выборе методов. Теперь составной расчёт P2 также возвращает модели ошибки JSON, схемы и её выражения. Каталог, вопрос, условия и права не подменяются.
6. Повтор вопроса мог присоединяться к FAILED навсегда. Новый вопрос создаёт новую попытку; повтор того же request_id сохраняет прежнюю квитанцию.
7. После перезапуска разрешённое чтение могло застрять на истёкшем lease. Перед обращением сохраняется признак допустимого повтора; старый исполнитель после восстановления не может записать результат.
8. Таймаут второго чтения состояния колонки переводил готовое задание в ручную выдачу. Теперь автоматическая выдача продолжается.
9. При недоступности Station IPC техническая команда доставки могла уйти в нейросеть. Клиент распознаёт такие команды и не запускает по ним расчёт; идемпотентные обращения повторяются.
10. Поздние before/after старого вопроса могли заменить новый. Сохранены квитанции before, ticket для after и порядок сообщений внутри беседы.
11. Принятый Яндексом запуск без callback навсегда оставался accepted_waiting_skill. Теперь проверяется callback; повтор использует тот же одноразовый код, проверяет актуальное задание и права, увеличивает паузу до 300 секунд. После callback повторы прекращаются.
12. Сбой обновления существующего сценария до запуска требовал переподключения. Такое обновление повторяется безопасно. Неизвестный исход фактического запуска физической команды не объявляется успешной озвучкой.

## Проверки

- Первичный полный серверный прогон: 1171/1171.
- Внесение временных сбоев: шаблон, составной P2, свободный вопрос про акции, общий 429, таймаут, ошибка JSON, новый вопрос после FAILED, рестарт, отмена и отзыв прав.
- Station: реальные обработчики с подменой внешнего Яндекса; поздние сообщения, потерянный ответ IPC, отсутствие callback, второй запрос, отключение auto, возврат ответа в новую сессию.
- Независимое ревью нашло четыре дополнительных обрыва; все исправлены, повторное ревью без новых блокеров.
- Итог интеграции с параллельным business-read-r1, установка и живые запросы записываются ниже после завершения.

## Архитектура добавления шаблонов

Общие повторы находятся в request_recovery.py и Worker._call. Шаблоны описывают источники, параметры, преобразование и вычисления; они не реализуют собственные сетевые повторы. Свободный выбор методов использует тот же транспорт, журнал обращений и очередь.

Это позволяет добавлять совместимые шаблоны данными матрицы. Новый принципиально иной протокол источника всё ещё требует общего адаптера и проверки — обещание «любой будущий API без изменения кода» не даётся.

## Границы доказательства

Потерянный ответ на запуск аналитического отчёта может вызвать повторную генерацию отчёта у провайдера; бизнес-данные магазина не изменяются. Успешный HTTP запуска сценария не доказывает слышимый звук. Окончательная проверка физического произнесения остаётся на колонке.

Админка: https://alisa-admin.octoport.ru/admin/station/
Подключённая колонка: https://alisa.octoport.ru/app/station/

Проверка владельцем: «Сводка заказов за вчера на Озоне», затем «В каких акциях участвуют мои товары на Озоне». Дождаться автоматического ответа. Затем задать новый вопрос во время ожидания первого и убедиться, что старый ответ не подменяет новый.
