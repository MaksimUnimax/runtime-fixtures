# OAuth/WAL и отказ автоматической выдачи

Инцидент simple-21 от 09.11.2026: OAuth refresh успешно завершился, финансовое задание было принято и рассчитано, но служба Station четыре раза вернула voice_revoked. Регистрация автоответа не произошла, а клиент скрыл отказ и вернул ручную инструкцию «Скажите: результат». Долгий текст/комментарии шаблонов к этому отказу доставки не относятся; ядро и его установленная selected-notes версия этим пакетом не меняются.

Проверка token_active ловила любой sqlite3.Error и возвращала False. Поэтому действительный отзыв доступа не отличался от невозможности прочитать базу. На отдельной базе под непривилегированным пользователем воспроизведён механизм: SQLite WAL без служебных файлов, каталог и база только для чтения → SQLITE_READONLY_DIRECTORY, старый код → ложный voice_revoked. С открытым соединением основного OAuth-сервиса тот же читатель принимает действующий токен. Исходное исключение инцидента не было сохранено старым кодом; конкретный SQLite-код первого live-отказа ретроспективно не доказан. Проверенный дефект и восстановленная последовательность отражены отдельно.

Исправление состоит из трёх частей:
1. Основной OAuth/webhook-сервис держит одно соединение с базой на весь срок службы веб-процесса. Полностью завершённый SELECT инициализирует WAL-файлы; соединение не удерживает старую транзакцию/снимок доступа. Это охватывает не только запрос навыка, но и последующие фоновые проверки и callback.
2. Station по-прежнему проверяет токен в режиме mode=ro. Отсутствующий, просроченный, отозванный токен и другой пользователь дают False. Ошибка SQLite даёт отдельный voice_auth_unavailable с кодом SQLite в журнале без токенов и пользовательских данных. При временной недоступности фоновое задание сохраняется для повторной проверки.
3. Клиент больше не включает ручной режим молча при ошибке интеграции. Ошибка до приёма запроса не запускает платное задание. Ошибка после приёма явно сообщает о проблеме подключения автоответа и не повторяет аналитический запрос. Явно отозванный доступ не ретраится. Ручной режим при явном отключении автоответа владельцем остаётся прежним.

Права на OAuth-базу для Station не расширяются. Сроки токенов, ключи, состояние соединения колонки и настройки выдачи не переписываются. Проверка свежего токена и следующего отзыва доступа выполняется по актуальной базе; разрешения не кэшируются в соединении-держателе WAL.

Тесты выполняются под alice-lab, а не root: воспроизведение read-only WAL, действующий/просроченный/отозванный токен, новый токен → webhook → регистрация задания → фоновый tick → callback с тем же ответом → отзыв доступа. Отдельно проверены нулевая аналитика при отказе before, ровно одно задание при сбое after, отсутствие команды «результат» в ошибочном fallback и прежние сценарии доставки. Нет платных вызовов в технических тестах.

Архитектурно ресурс SQLite/WAL принадлежит основному писателю OAuth и живёт столько же, сколько сервис. Доставка остаётся читателем. Ошибка доступности и доказанный отказ авторизации — разные исходы. Ни перевод текста ошибки, ни увеличение срока токена, ни разрешение доступа без проверки не используются.
