# Текущие коэффициенты R4: штатный Worker и проверенная запись

14 ноября 2026. **EXISTING_WORKER_SOURCE_FLOW_VERIFIED_NOT_DEPLOYED**.

## Сделано

Два производителя из R3 подключены к реальному исполнителю шаблонов в изолированной копии действующего ядра. Выбор DeepSeek → зарегистрированный шаблон kind=parameter → текущий Worker._call → общий ledger/транспорт/Retry-After → проверенный числовой результат → итоговый ответ. Для сохранения используется отдельное проверенное намерение владельца, не JSON-команда модели. Нового сервиса, очереди, клиента API или универсального fallback нет.

Штатный путь обрабатывает создание отчёта отправлений, ожидание готовности, получение защищённого файла, все страницы возвратов, финансовые окна и пограничные отправления. Курсор берётся из фактического ответа; пустая незавершённая страница или повтор курсора не признаются полным сбором. CSV разбирается с обязательными колонками и без передачи персональных колонок модели.

Промежуточные нормализованные данные зашифрованы в состоянии текущего задания с привязкой к tenant/job/fragment/release. Номера отправлений заменены scoped HMAC. Проверка результата связана с событиями RECEIVED/HTTP200 того же задания, параметрами, хешами ответов и действующими правами. Только поле complete=true не является доказательством. После успешного завершения данные сбора и временные ссылки очищаются из текущего пути; история числовых параметров не создаётся. При ошибке/отмене действует уже существующий срок очистки незавершённых задач, а не новый архив сборок.

## Найденный разрыв итогового ответа

Первый сквозной тест показал: вычисление завершалось, но model_answer отправлял модели только notes шаблона и пустой responses — число результата не доходило. Исправлены template_runtime/model_answer: проверенный compact parameter_context передаётся с числом, единицей, периодом, датами, pending и подтверждённым saved. Сырые годовые строки, ключи и разрешение на запись в этот контекст не попадают. Это не дополнительный вызов модели.

## Сквозная проверка записи

Проверен настоящий Worker/SQLite вместе с настоящим платформенным сервисом/Django/PostgreSQL на синтетических ответах маркетплейса и модели. Единственная текущая запись получает рассчитанное число, даты и основание; ответ saved=true появляется после commit. Одновременная ручная правка остаётся победившей. Прямая подмена моделью режима replace без серверного разрешения отклоняется до API.

Специально прервано исполнение сразу ПОСЛЕ commit PostgreSQL, до окончания шага Worker. Перезапуск восстановил то же задание, не повторил сбор, не создал вторую запись и не увеличил revision повторно. Повтор использовал прежнюю команду и идемпотентную квитанцию без старого числа.

**Граница доказательства:** в этих тестах AdmittedWebIntent — тестовый адаптер уже разрешённой команды существующей WebSession. Это НЕ внедрённый production/voice authorizer и НЕ повышение reports:read до записи. Реальный IPC/job-intent для ЛК и колонки ещё нужно подключить. OAuth, аккаунты, привязки и права не менялись.
