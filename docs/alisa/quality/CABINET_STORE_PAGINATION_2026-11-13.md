# AL-S09 — страницы магазинов в форме отчёта

Статус: INSTALLED_TECHNICAL_CHECKS_PASS, PR418, source `1c9512728d2582bb87c21f7a5c4ae49fba22e3c4`. Это продолжение установленного автоподключения
магазинов PR417, source `592cc8bb`, и ранее установленной формы PR415.

Форма задания получала только первые 50 карточек. Магазин за пределами этой
страницы нельзя было выбрать. Если первые 50 карточек отключены, форма предлагала
подключить новый магазин, хотя подходящий уже был на следующей странице.

Добавлена явная кнопка «Показать ещё магазины» через существующий авторизованный
BFF и подписанный cursor API списка. Каждое нажатие загружает одну страницу;
доступна и страница после пустой по подходящим магазинам части списка. Загруженные
карточки объединяются по ID. Текущий выбор и введённый вопрос сохраняются; новые
карточки не выбираются автоматически. «Выбрать все в списке» действует на уже
загруженные карточки. Незагруженные страницы не считаются выбранными.

Пока идёт загрузка, форма не отправляет отчёт. При ошибке HTTP, неверной структуре
страницы или повторении cursor список, вопрос и выбор сохраняются для явного
повтора. Состав уже отправленного UNKNOWN/recover задания остаётся прежним;
подгрузка и выбор до подтверждения отправки заблокированы. Чтение списка не
создаёт задание и не обращается к модели или маркетплейсу.

Добавочный browser fixture использует настоящие PostgreSQL, BFF и три страницы с
подписанными cursor. В первых 50 карточках нет подходящих; следующие страницы
содержат 55 активных подтверждённых карточек. Проверяются выбор магазина на
поздней странице, UNKNOWN и явный recover с тем же ID/вопросом/набором, запрет
подгрузки во время UNKNOWN, ошибки HTTP/структуры/cursor без сброса формы, перенос
выбора и текста через страницу и полный выбранный список из загруженных страниц.
Только POST создания отчёта перехватывается браузерным fixture; настоящего
исполнения этих многомагазинных расчётов он не доказывает.

Реальные расчёты и скачивание документов проверяются прежним отдельным сценарием
до добавления дополнительных fixture-карточек. Новый сценарий не заменяет эти
проверки и не меняет область исходного запроса. Все его карточки удаляются при
закрытии собственной одноразовой тестовой БД.

Изменение относится к web-компоненту: миграции, ключи, права, native и серверный
выбор последнего магазина не меняются. Полнота семантических уточнений S09 и
LIVE_OWNER остаются отдельной приёмкой.

Независимое ревью R60/R61/R62 одобрило исходники, R63 — web-only установку с повторным использованием неизменного окружения. Полный CI43380221803 SUCCESS, включая прежние скачивание/feedback, выбор трёх магазинов и три страницы карточек; docs CI43380221920 SUCCESS. Прошли 209 PostgreSQL-проверок общей связки и 1968 проверок current-core без пропусков и внешних вызовов. Предыдущие прогоны выявили проблемы точных Playwright-locator для служебного alert и controlled textarea; исправлены только тестовые обращения, ожидаемые значения и проверки не ослаблялись. Установщик проверен шестью offline-сценариями отказа/отката.

## Установка и сохранение рабочей версии

Установлен `alisa-cabinet-pages-1c9512728d2582bb`. SHA256 исходного квалифицированного tar:
`d2999603cf5d30d8d65eae7ce8f370a37f60d32f8629b0ded964315898606c9f`.
SHA256 установленного web-manifest:
`07040de43b1b067052b83a9a397c0cc0f823186ba1eb84bbffee981545ff2b2c`.
Все 2261 файла сверены после переключения. Переданы только 36 изменённых файлов
(278138 байт, gzip 23303 байта); 2225 неизменных файлов используют hardlink.
Сборка и установка зависимостей на Алисе не выполнялись.

Первая подготовка остановилась на RESOURCE_RESERVE и удалила только свой
неактивный кандидат: hardlink-копия `.venv` всё равно создавала 3491 каталог.
После исправления APP/.venv ссылается точно на неизменное окружение сохранённой
базы `alisa-cabinet-multi-store-b481fbe9480ef13e`; исходные lock-хеши совпадают.
Эту базу необходимо сохранять вместе с окружением, пока новый кабинет от неё
зависит. Она также остаётся версией для отката. Точный путь ссылки проверяется
перед активацией; подмена блокирует переключение. Порог 3 GiB / 200000 свободных
inode не снижался. После установки оставалось 3232333824 байта / 445887 inode.

Перезапущена только `alisa-web@stage.service`. Остальные восемь служб сохранили
PID/WorkingDirectory и состояние active. Readiness 200 показывает новый release;
фактический рабочий каталог процесса соответствует ему. Публичный список
магазинов без сессии возвращает 401; страницы заданий и документов перенаправляют
на вход (307). Живые ключи, grants, OAuth, задачи и пользовательские сессии не
создавались и не менялись. Проверка авторизованного владельца на установленной
сборке не выполнялась; функциональная браузерная проверка относится к точному
квалифицированному пакету и одноразовой БД CI.

Ручная приёмка: при числе карточек больше 50 открыть «Задания», ввести вопрос,
выбрать магазин и нажать «Показать ещё магазины». Выбор и текст должны остаться;
следующая страница должна дать доступ к следующим подходящим карточкам.

приёмка корректного многомагазинного ответа.
