## Изменение

Один серверный parameter_periods.resolve определяет диапазон. Подготовка возвращает подписанный period_reference на 180 секунд, связанный с сессией, tenant/владельцем, магазином/ревизией/проверенной идентичностью, активными credential revisions/check state, параметром, областью, исходным period request, режимом и хешами определений/производителей.

Запуск с reference проверяет подпись и текущую привязку, затем использует именно подготовленный период. Reference не заменяет действующие проверки владельца, SKU, подтверждения, entitlement, deadline, revision и повторной авторизации перед записью. Он не даёт права записи и не хранится как прежнее значение/паспорт. Повтор уже принятого command_id возвращает прежний исход до проверки срока reference; recover использует существующий Query.

Новый клиент автоматически готовит период перед прямым запуском, если подходящей подготовки нет. Подготовленный reference передаётся через действующий BFF. Изменение формы не позволяет повторно использовать preparation другого набора полей; опоздавший ответ подготовки не становится актуальным для новой формы. BFF допускает только необязательную строку reference на start и сохраняет прежнюю строгую схему прочих действий.

Старый клиент без reference сохраняет прежнее разрешение полного/default или явного диапазона. Клиентские actual/available_from/short_history не принимаются. Это переходная совместимость; привязку показанной подготовки гарантирует новый клиент с reference.

## Доработки независимого review

Первый выполненный static review вернул NEEDS_FIX: смена формы во время ожидающей подготовки могла отправить старый набор полей; подпись reference проверялась после runtime readiness; проверка приватности default fixture root была неявной. Гонка формы воспроизведена на прежнем скомпилированном компоненте: после смены режима во время удержанного prepare отправился один start. Добавлены отдельные случаи смены формы во время prepare и во время fresh read, guard до каждой точки отправки и явная проверка default root.

Reference теперь проверяется до readiness и повторно после неё, после прежней проверки уже принятого command_id. Старый клиент разрешает период один раз на start. Обновляемый технический reference, как SKU proof, исключён из семантического command hash; новое представление той же подготовки возвращает прежний Query, не новый job. Новые тесты проверяют неверную/истёкшую строку до любых runtime calls, истечение во время readiness и отсутствие reference в continuation. Повторное независимое review V3 PASS; финальный collection35 и UI12 PASS. Подтверждение начала истории остаётся отдельным незакрытым производителем.
