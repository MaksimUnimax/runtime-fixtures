# OWNER-DEFAULT-R1 — пункт 1 владельца

8 ноября 2026. Владелец поручил сделать общую себестоимость магазина, индивидуальные исключения и автоматический выбор товаров без ручного поиска SKU. Отдельно зафиксировано: сайт развивается и как сервис аналитики, не только как вспомогательная настройка голосовой Алисы.

## Поведение

Общая себестоимость — явное утверждённое значение на интервал дат для всех товаров, включая будущие. Индивидуальное исключение перекрывает её только в свои даты. Явный ноль и NOT_PROVIDED в исключении не заменяются общей ценой; вне покрытых интервалов остаётся пропуск. Прежние значения не перезаписываются без подтверждения. Никаких r9/default250.

В форме две отдельные кнопки: «Добавить общую себестоимость» и «Добавить исключение для товара». Для общей цены товары не выбираются. Исключение выбирается по названию и артикулу из каталога подключённого магазина; ID подставляется программно. Сохранены галочка, revision, lost-ACK recovery и защита второй вкладки. Налог и собственные расходы за период не меняют семантику.

## Технические границы

Default объявлен в JSON-каталоге owner inputs; общий resolver выбирает индивидуальные интервалы перед default. Матрица не размножает цену в тысячи строк и не создаёт список SKU, нужный только для общей цены. Новые source-проверенные товары наследуют общее правило.

Выбор товаров — read-only справочная операция в существующем ограниченном peer-checked Unix IPC проверки магазина. Используется тот же bounded shared HTTP, фиксированные Ozon/WB endpoints, без retry/произвольных URL. Это не финансовый расчёт и не выдаётся за запрос через аналитическую очередь. Платформа проверяет текущую сессию/магазин/credential до и после IO, ограничивает запросы по проверенному аккаунту и подписывает cursor. Ключи не попадают в браузер/файлы; сетевой вызов выполняется вне DB-транзакции. PERFORMANCE для просмотра каталога не нужен. Каталог не записывает себестоимости.

Ozon: страницы product/list и product/info/list, сопоставление product_id→SKU без подмены product_id вместо SKU. WB: активные карточки content/v2/get/cards/list. Неполный/невалидный ответ не превращается в пустой успешный каталог. Поиск — среди загруженных страниц; следующая страница явно дочитывается.
