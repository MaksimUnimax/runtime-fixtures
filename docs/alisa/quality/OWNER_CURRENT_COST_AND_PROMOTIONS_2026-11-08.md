# Текущая себестоимость без дат и причина отказа голосового запроса об акциях

8 ноября 2026. Прямая команда владельца: себестоимость — одна текущая цифра, без предполагаемой даты её будущего изменения. Отдельно — разобраться с запросом с колонки об участии в акциях и ошибочным требованием дат.

**Установлено:** web/platform `alisa-cbe03c9ddd121f2d`; аналитический runtime `alisa-runtime-promotions-r1-20261108`. **Не подключено:** источник действительного участия товаров в акциях. Две границы нельзя смешивать: устранено неправильное уточнение периода, но список участников пока недоступен.

## Себестоимость: исправлено требование, а не только сообщение

Требование обязательной будущей даты было ошибкой проектирования предыдущей формы. Теперь при выборе магазина сразу показано пустое поле общей себестоимости за единицу. Для cost нет календарей, даты начала/окончания и переключателя «Сумма известна». Владелец вводит число и явно сохраняет; оно используется до следующего изменения владельцем. Исключение для конкретного товара также содержит текущую сумму без дат; товар выбирается по названию/артикулу.

Это не маскировка дат в интерфейсе. В сохранённых фактах `unit_cost.period = null`. Общий проверяющий модуль разрешает такую форму только по явной политике `allow_current` для соответствующего поля. При расчёте используется сохранённая текущая сумма, без придуманного бесконечного календарного интервала. Версия принятых входов и актуальные права по-прежнему проверяются. Два текущих значения для одного товара/общего правила не выбираются произвольно, а отвергаются.

Индивидуальное текущее значение важнее общего. Явный ноль или явно неизвестная себестоимость исключения не подменяется общей суммой. Нет автоматического r9/250, расчётного значения из цены продажи или присвоения суммы исполнителем. Текущая цифра — настройка для нового расчёта, не доказательство исторической себестоимости; ранее принятый расчёт не меняется задним числом.

Налог и собственные расходы являются необязательными дополнительными строками. Они не мешают сохранить одну себестоимость. Для добавленной суммы за период сохраняется её фактический период; месячная сумма не превращается в дневную или в постоянный расход.

Старые записи не мигрировались и не переутверждались автоматически. Один старый cost показывается в черновике новой формы; разные старые суммы одного товара не выбираются по догадке — поле оставляется неизвестным с пояснением. Только явное новое сохранение создаёт текущую утверждённую версию.

- 07:04:39.074028 UTC — FAILED / LLM_CLARIFY.

**Точные исходные реплики уже недоступны:** штатный PAYLOAD_TTL900секунд очистил содержимое dialogue receipts, pending и draft. Сохранились время/состояние/код ошибки. Поэтому нельзя дословно восстановить разговор или безусловно приписать каждому из двух отказов конкретную фразу владельца. Этот предел доказанного сохранён.

На точном старом установленном коде отдельно воспроизведено:

| Проверяемая фраза, не транскрипт пользователя | Старый результат |

| В каких акциях участвуют мои товары на Озоне | PERIOD_REQUIRED |

Причина: в действующей матрице/источниках нет отчёта об участии в скидочных акциях, но общий разбор периода выполнялся до определения этой недостающей функции. После ввода периода модель не могла сопоставить вопрос поддерживаемому показателю. WB advertising/promotion endpoint относится к рекламным кампаниям и не является доказательством участия в скидочных акциях.

## Исправление голосового маршрута

В информационный каталог добавлена ограниченная таблица известных неподключённых тем. Общая проверка выполняется до обработки периода, включая dataset/table пути, но после проверки доступа и с сохранением запрета изменений/секретов. Она распознаёт тему акций и возвращает `PROMOTION_PARTICIPATION_NOT_ENABLED`, не создаёт финансовое задание и не тратит модельный вызов.

Ответ установленной версии:

> Понял вопрос об участии товаров в акциях. Этот источник ещё не подключён к навыку, поэтому список участников сейчас получить не могу. Для проверки текущего участия даты не нужны. Это недостающая функция сервиса, а не ошибка вашего вопроса; продажами или рекламными кампаниями её не заменяю.

Фильтр использует целые слова, не срабатывает на «транзакции» и не трактует название товара/бренда «Акция» в кавычках как отдельный запрос. Настоящие периодные запросы заказов не потеряли свою логику. Это не новый источник акций, не фиктивный пустой список и не утверждение «вы не участвуете».

Добавлена только техническая запись `dialogue_outcome`: безопасный код ошибки и признак уточнения. В неё не пишутся реплика, пользователь/сессия, суммы или ключи. Срок хранения финансовых payload не продлевался. Теперь причина ошибки остаётся видна после очистки содержимого.
