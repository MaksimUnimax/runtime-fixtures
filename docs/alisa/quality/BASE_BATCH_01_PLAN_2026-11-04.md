## Содержание прохода

1. Один машинно-проверяемый каталог всех B01–B16/S01–S03: точные атомарные величины, источники, фразы, площадки, временные оси и ограничения. Покрыть все 36 уже доступных исходных scalar metrics; не считать новые синонимы новыми API или новыми реализованными семействами.
2. Пакетно подключить голосовые формулировки всех поддержанных простых величин и сводок. Снимок не подменяет исторический период, одно финансовое основание не заменяет другое, недоступный разрез не отбрасывается. Всё совместимое — через JSON каталоги.
3. B05/SRC-OZON-ACCRUAL: проверить исходные CASE/первичный контракт и выразимость в общем DSL; интегрировать максимально доступную часть без специального endpoint-specific decoder. Новые поля/методы без qualification не включать в live автоматически. Неполученные источники B13/B16/S02/S03 и Ozon event отмечать BLOCKED, а не фиктивно READY.
4. H00 — общий информационный маршрут с вариантами «что умеешь/можешь/какую информацию…». Не вызывает LLM/marketplace, не создаёт финансовое задание, не сбрасывает ожидающее уточнение и не скрывает настоящую команду внутри смешанной фразы. Короткий ответ перечисляет доступные возможности, а юнит-экономику называет планируемой до данных себестоимости и полного расчёта.
5. C-UE01 — обязательный составной шаблон юнит-экономики: зависимости/явная база и непересекающиеся расходы/себестоимость/налоги, статус PLANNED_DEPENDENCIES, не текущая возможность. Не выводить прибыль из финансовых начислений без условий.
6. Генерируемый пакет тестеру по всем базовым ID, включая блокирующие случаи: точный запрос и версия, ожидаемый смысл, пустые actual_response/first_response_ms/job_ready_ms/total_ms/API counts, результат NOT_RUN. Наблюдения тестер сохраняет в существующий quality/inbox и RUNS, не в новый независимый реестр.

## Приёмка

Старые 846 тестов без ослабления. Пакетные тесты каждой метрики и сводки, простых/составных refs, help variants и mixed-request negatives, разрешения/отсутствие API для help, сохранение периода/TTL и exact replay. Зафиксировать количество именно независимых executable вариантов и отдельно families/фразы/blocked entries. Один общий примитив можно расширить с отдельными negative tests; новые обработчики для названий шаблонов запрещены.

Установка только отдельным release после source hashes/lock/активных задач; действующая платформа/настройки вне scope. Если новая часть требует неготовую authority, поставка остаётся отдельным интеграционным кандидатом; доступные legacy voice-шаблоны и H00 допускаются независимо после проверки. Статус нельзя вычислять по одному наличию записи в каталоге. После проверки публикуются источник/код/тесты/пакет; final обязательно содержит конкретный следующий шаг.
