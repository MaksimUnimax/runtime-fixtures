## Подтверждённые причины

N06: period_from_text допускает только YYYY-MM-DD, тогда как request.command Яндекса содержит YYYY - MM - DD. original_utterance не является основанием обходить штатную нормализацию. Расширить только грамматику явно заданного диапазона «с ... по ...»: пробелы вокруг ASCII-дефиса, проверка реального календаря и прежних границ. Не склеивать произвольные числа/артикулы глобальным replace, не трогать строки в кавычках и фильтры. Нет даты — прежнее уточнение, не догадка.

N08: dataset parser для общего временного разбора подставляет scalar snapshot phrase; HISTORICAL_SNAPSHOT возникает раньше построения dataset-плана и наследует текст про остатки/баланс. Передавать в общий formatter безопасный reference выбранного dataset, не сырой пользовательский текст. Подпись берётся только из ограниченного словаря ошибок/матрицы. История цен остаётся запрещённой, но называется правильный тип набора и следующий шаг «сейчас» либо нужный исторический источник.

N09/OZCP-001: ранний общий фильтровый guard советует WB до установления подходящего источника. Заменить универсальной подсказкой о неподдержанном условии выбранного набора; не предлагать смену площадки, не отбрасывать фильтр. Прежний legacy OZCP-001 сохраняет свой ID. Валидные существующие WB numeric/brand filters не ломать.
