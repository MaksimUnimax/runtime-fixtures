## Управление магазинами

Магазин принадлежит рабочему пространству владельца. Ozon и WB — отдельные карточки; Seller и Performance одного Ozon — два вида ключей одной карточки. Название и голосовой псевдоним редактируются в «Мои магазины». Дубли подтверждённого кабинета одной площадки в одном пространстве отклоняются; одинаковые названия не означают один магазин.

Добавление сохраняет ключ зашифрованным как ожидающий проверки, затем отдельная проверка подтверждает кабинет площадки. Таймаут не равен неверному ключу. Новый ключ заменяет прежний действующий только после подтверждения того же кабинета. Рекламная авторизация сама по себе не доказывает связь рекламы с Seller-кабинетом.

Отключение магазина отзывает и стирает сохранённые ключи. Повторное включение карточки не восстанавливает ключи: их необходимо заново сохранить и проверить. Удаление помечает карточку DELETED, скрывает её и освобождает идентификатор кабинета после отзыва ключей; служебная история не удаляется физически вместе с карточкой. Можно отдельно отозвать Seller, Performance или WB-ключ. Отзыв препятствует последующей выдаче данных, включая сохранённые документы.

## Путь запроса

1. Кабинет использует вход владельца, голосовой путь — привязку Алисы. До отправки проверяются владелец, действующий доступ, выбранные магазины, подтверждённые ключи и служебная привязка.
2. В кабинете владелец выбирает магазины флажками. Голосовой backend использует последний выбранный магазин; при первом выборе, недоступности текущего или неоднозначной явной смене предлагает уточнение. Упоминание площадки ограничивает кандидатов этой площадкой. Уточнение не является новым бизнес-запросом. Фиксируются исходный вопрос, ID и состав; новый магазин не добавляется задним числом.
3. Исполнитель фиксирует исходный вопрос, дату, часовой пояс, доступные магазины и версию каталога. Сейчас timezone в этом пути Europe/Moscow. Повтор с прежним ID не означает новый расчёт.
4. Модель выбора получает вопрос и каталог: ID, purpose, вид, площадки, параметры, зависимости, показатели и доступность шаблонов по магазинам. notes для озвучки не входят в каталог выбора. Префикс каталога может кэшироваться; кэш не заменяет проверку доступа.
5. Модель возвращает план из зарегистрированных шаблонов с магазином и параметрами каждого вызова. Запрос может потребовать несколько шаблонов и магазинов. Произвольный API/URL/SQL/Python на этой стадии модель не задаёт.
6. Сервер проверяет структуру плана, полноту покрытия вопроса, наличие шаблонов, разрешённые магазины, даты, фильтры, совместимость источника и доступ. Составные шаблоны разворачиваются в зависимости; совместимые обращения группируются. Универсальный fallback в обход каталога выключен.
7. Проверенные инструкции матрицы задают операции API, параметры, страницы, поля и расчёты. Обработка выполняется по магазинам с повторными проверками прав. Ошибка подписки площадки не расширяет доступ; модель получает подтверждённую причину. 429 остаётся в механизме ожидания/повторов API.
8. Ответы API и данные выполненных шаблонов передаются существующей итоговой стадии вместе с исходным вопросом и notes выбранных шаблонов. Код также предусматривает изолированный расчётный путь для больших ответов при включённой опции; фиксированное число модельных вызовов из наличия двух стадий не следует.
9. Итог сохраняется для чтения; перед выдачей повторно проверяются права. Повторное чтение сохранённого результата само по себе не вызывает маркетплейс или новый расчёт. Несовместимые показатели нельзя подменять или произвольно объединять; полная продуктовая приёмка S09 ещё открыта.
10. Архив API автоматически связывает полученные ответы с выбранным шаблоном, его версией, магазином и источником. Исходный документ сохраняется как файл, обычный ответ оформляется как документ. Хранение 48 часов от сохранения, скачивание срок не продлевает. Добавление шаблона в проверенный выпуск не требует отдельного списка шаблонов в архиваторе.

Если модель явно не нашла зарегистрированного шаблона, пользователь получает «Извините, данный запрос не поддерживается», а случай попадает в существующий закрытый журнал для последующей разработки. Ошибка выполнения шаблона и отказ площадки — отдельные причины, их нельзя выдавать за отсутствие шаблона.

Источники: `stores/{models,service}.py`, `runtime_adapter/{bindings,authority}.py`, web `app/stores` и `app/queries`, установленный native `template_catalog.py`, `template_runtime.py`, `engine.py`, `model_answer.py`, `model_program.py`, а также общий `report_archive.py`. Секреты, клиентские данные, grants и привязки при сверке не менялись.
