## 2. Причина и общий механизм исправления

**Выбор/страницы.** Старый tenant pointer и jobs.page были общими для бесед одного аккаунта. Добавлен `reader_state.py`: выбор задания определяется tenant+conversation, курсор — tenant+conversation+job_ref. Сам финансовый result остаётся общим неизменяемым payload; копия отчёта на каждую беседу не создаётся. Новый разговор не наследует tenant pointer. Внутренние request IDs также разделены по conversation, внешние receipt/replay контракты сохранены.

**Отмена.** Отмена действует на текущую подписку беседы. Для разных jobs отменяется только свой job. Если canonical job разделяется с другой беседой/alias/legacy ingress, текущая беседа отключается, но общий worker продолжает работу для остальных. При отмене последнего подписчика QUEUED/RUNNING останавливается. Это исключает влияние отмены A на B. Состояние и курсор переживают перезапуск; повтор одного сообщения не двигает страницу дважды.

**Legacy.** Вход без conversation имеет отдельный legacy reader. Явное чтение по ранее авторизованному job ID сохраняется, не меняя выбранное другое задание. Named dialogue не получает эту fallback-возможность. Граница аккаунтов и source-revocation проверяются по прежним правилам.

**Decimal.** До fixed-point format проверяются finite, коэффициент, scale, exponent и прогнозируемый размер строки. Ограничения:<=80 цифр коэффициента,<=100 символов fixed text, |value|<=1e18; входной оператор decimal допускает scale<=32, общие промежуточные helpers —<=64. Огромный exponent у нуля также отвергается. Корректные ставки1e-10 и дробные результаты сохраняются, скрытого округления нет. Матрица получает NUMBER_RANGE/ошибку источника вместо разматывания гигантской строки.

После уже известного ответа провайдера MatrixError классифицируется как детерминированный FAILED, а не сетевой UNKNOWN. Настоящий NETWORK_OUTCOME_UNKNOWN сохраняет прежнюю блокировку автоматического повтора. Числовые пределы — защитный контракт, не обещание поддержать произвольную точность любого нового источника.

**Даты.** Цельный интервал с двумя названиями месяцев разбирается до одиночных месяцев. Поддержаны один/два/отсутствующий год, декабрь→январь, ISO с пробелами и обычные даты. Будущие, обратные, несуществующие и >365 дней по-прежнему отвергаются. Текст в кавычках не становится датой запроса. На обоих исходных B05/PAY вопросах интервал31.10–04.11 создаёт ровно5 дневных задач первой стадии; это проверка плана, не новый месячный live-прогон.

Все изменения относятся к общему механизму. Каталоги источников, финансовые формулы, dataset определения, допуски, токены и квоты не менялись. S03/C-UE01 кандидаты в этот hotfix не включались.
