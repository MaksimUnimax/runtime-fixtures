## Реализуемый путь

Форма `/app/owner-inputs` и ссылка из карточки магазина. Поля SKU, интервалы себестоимости, суммы налога/собственных расходов за точный период. Ноль, неизвестное значение и исключение налога владельцем различаются. Нет default250, готового налогового процента или месячного prorating. Подтверждение каждой версии — явная галочка и команда.

Браузерный API использует прежние session cookie и Host/Origin проверки BFF. Неизвестные действия/поля и повторяющиеся JSON keys отвергаются. Подтверждение не подставляется BFF за пользователя. В localStorage только непрозрачный ID команды, магазин, revision и deadline; денежные черновики/секреты туда не записываются.

Источник получает bounded deadline и status исходной команды. Потеря ответа или reload не запускают новое изменение. Web Lock сериализует вкладки, expected_revision предотвращает перезапись устаревшим черновиком. Истёкшая неподтверждённая команда может быть освобождена только после проверки статуса под штатными блокировками платформы.

Служебная проверка прав — отдельный read-only endpoint на фиксированном loopback адресе с отдельным сервисным ключом. Платформа выдаёт ограниченный подписанный execution ticket после действующей сессии; runtime не получает browser token или пароль БД. Ticket не заменяет текущие права: обработчик перечитывает текущую сессию, approval, store/credential/access revisions. Ответ привязан к одноразовому request_id и проверяется MAC. Произвольные URLs, редиректы и автоматические повторы не допускаются; используется прежний bounded shared HTTP.

## Проверка и выпуск

Точный Node24.22.1 загружен с официального nodejs.org и сверен с опубликованным SHA256; системный Node других проектов не заменялся. UI: сборка, model/strictJSON checks, настоящий headless Chromium и реальный Next BFF с искусственными платформенными ответами. Backend: настоящий Django/PostgreSQL в disposable cluster, существующие owner-source tests плюс command recovery и loopback RPC; provider replies искусственные. Проверки отдельных слоёв не объявляются входом реального владельца или полной production приёмкой.

До установочного решения — проверить результаты, целостность текущих releases, доступный диск, совместимость последних platform/web изменений и возможность безопасной доставки. Не менять SSH/MFA/системные защиты ради передачи артефактов. Никакие реальные суммы не утверждать автоматически.

В итоговом отчёте явно разделить: реализовано, реально проверено, установлено/не установлено, какие действия действительно доступны владельцу по рабочим ссылкам. Независимый verdict не присваивать авторским тестам.
