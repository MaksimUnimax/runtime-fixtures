## 4. Что продолжено в реализации

Через существующий общий исполнитель подключены:

1. fbs_posting_list — список отправлений FBS;
2. fbs_unfulfilled_list — необработанные отправления FBS;
3. posting_fbs_get — подробности конкретного отправления;
4. rfbs_returns_list — список возвратов rFBS;
5. rfbs_returns_get — подробности возврата rFBS;
6. conditional_cancellation_list — запросы на отмену.

Раньше эти read-операции целиком блокировались из-за возможных данных покупателей. Теперь объявленная в JSON политика оставляет бизнес-идентификаторы, количества, статусы, точные суммы/валюты, даты источника и курсоры. **ФИО, адреса, телефоны, свободный текст и неописанные поля исключаются до возврата транспорта в Worker, записи результата в очередь и передачи модели.** Это не выдача полного персонального ответа.

По умолчанию неизвестное поле удаляется; неизвестная непустая структура не превращается в «пустой результат» или ноль. Не производится поиск подходящих по имени полей внутри чужого customer/recipient объекта. Составные цены сохраняют amount и currency, без округления/конвертации/угадывания валюты. Артикулы продавца допускают кириллицу, пробелы и деловые знаки, но не управляющие символы/контактные значения. Удалено ошибочное ожидание object у неструктурированного additional_data: его целиком исключает политика.

Оригинальные request builders/параметры/фиксированные origins/READ-семантика и права магазина сохранены. Не добавлен отдельный обработчик вопроса, второй HTTP-клиент или очередь. Отсутствие шаблона не мешает работе через этот слой. Полный personal-mode для остальных47операций этим изменением не реализован.
