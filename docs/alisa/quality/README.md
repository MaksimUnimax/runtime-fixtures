## Исправления общего механизма

1. JSON-каталог теперь содержит scope/response fields/related methods и применимость по наблюдаемому типу объекта. Generic context_rules отклоняют обычный SKU-метод для известной автоакции **доHTTP**, предлагают корректный read-метод и сохраняют полученные данные. Нет отдельного Python-обработчика под фразу.
2. Декларативная нормализация списка ID и общие params_expr берут настоящие ID из полного предыдущего ответа. Проверки происхождения/магазина/числового диапазона не ослаблены. Нельзя подставлять примерные ID или дефолт0.
3. Сравнение timezone-aware timestamps и общий вывод статуса по явно полученным датам отделяют текущие и будущие записи. Пользовательские даты не запрашиваются; costбездат не меняется.
4. Ошибка JSON модели после API больше не обязана обрывать готовые исходные данные: strict-формат исправляется повторным модельным шагом **без повторного API-чтения**. Невалидные примеры инструкции исправлены. Rawmodeloutput/токены не логируются; same-state no-progress остаётся ошибкой, а не числовой квотой.

Реальные промежуточные HTTP422, READ_IDENTIFIER_NOT_PROVEN/READ_NO_PROGRESS и INVALID_JSON сохранены. Неуспешные jobs не переписывались в READY. В R3 реальные форматные ошибки WB/Ozon были исправлены с сохранением их read-ответов. Финальный R4 проверен новыми запросами. Один поздно прочитанный промежуточный отчёт корректно expired; TTL ради тестов не увеличивался.

Голосовой текст ещё подробный, в отдельных полях есть технические статусы/консервативная coverage-оговорка. Следующая UI/voice доработка — краткость, а не подмена этой приёмки заявлением о полном совершенстве интерфейса.
