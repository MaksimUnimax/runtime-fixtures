**Четыре403:** три FBP-list метода с общей причиной доступа и posting_marks с указанием недостаточности разрешений метода. **Один400:** статус экземпляров с настоящим posting_number; причина пока не установлена. **ТриNOT_RUN:** FBP-get методы без реального supply_id из успешных списков. ### B2B: пустой период не подменяется

HTTP200 первоначально приводил к локальному отказу из-за неполно описанной структуры. Безопасный журнал формы значения доказал пустую строку date_from, а не неправильный часовой пояс. Для B2B теперь явно разрешено сохранить исходные пустые/null date_from/date_to с `source_period_status=MISSING`.

Общий renderer добавляет предупреждение, что источник не указал период и данные не являются подтверждённым итогом за запрошенный месяц. Это проверено в сохранённом READY-ответе. Даты не выдумываются из запроса; invoices=[] не становится утверждением «продаж не было». Числовая/периодная приёмка отчёта остаётся открытой. Старые FAILED-квитанции сохранены.

### Что установлено по Ozon403

Http_transport раньше отбрасывал пояснение уже полученной ошибки. Теперь сохраняются только фиксированная причина, HTTP, hash/длина тела; сырой текст/секреты/персональные значения не логируются.

`question_count` вернул403 с указанием требования платной подписки. Официальные материалы Ozon указывают Premium Plus для API вопросов/ответов и отзывов; наличие этой подписки у аккаунта не прочитано и не изменено. `review_count` остался общим403 — причину другого метода нельзя автоматически переносить на него. `posting_marks` указал недостаточность прав; точное имя роли неизвестно.

Конечный классификатор требует явной формулировки необходимости, а не простого упоминания активного тарифа. Denied ledger не обнулялся, блокировки прежних методов не снимались, ключи/тариф не подменялись. Ошибка анализа тела не превращает полученный403 в сетевой UNKNOWN или blind retry.
