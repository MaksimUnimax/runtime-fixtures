## Последний проход: S03 → сценарный расчёт C-UE01

[Приёмка S03_SCENARIO_BINDINGS_R01](S03_SCENARIO_BINDINGS_R01_ACCEPTANCE_2026-11-05.md), [код и контракт](../runtime/v0.11/scenario_bindings_r01/README.md).

**Готов отдельный offline-кандидат вычислительной интеграции**, использующий прежние OwnerInputs, matrix_core и ReportContracts без их изменения. JSON задаёт два сценария: контрфактическое выполнение исходной когорты без отмен и расчёт оставшихся единиц с фактическими исключениями. Себестоимость выбирается по товару и квалифицированной дате строки; отменённые единицы не дают выручку и COGS. Физическая unit cost сохраняется, распределение на исходно заказанную единицу выводится отдельно.

Суммы, стоимость на единицу, проценты, знаменатели и источники выводятся явно. Fact, API/official tariff estimate и period allocation не смешиваются. Нулевые знаменатели дают null. Отсутствующие owner inputs перечисляются как пропуски, неполная COGS не выдаётся за полную. Реклама, полнота расходов и контроль двойного учёта обязательны. Контрольные суммы не становятся дополнительными затратами.

Immutable pin включает hashes исходных фактов, политик и кода. Execute/read повторно проверяют права. Read-check не пересчитывает формулы. Модуль не хранит диалогов, не вызывает API и не создаёт собственного issuer/worker.

Marketplace/DeepSeek вызовов в проходе 0; старый полный runtime-набор не выдаётся за заново выполненный.
