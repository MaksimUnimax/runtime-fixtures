Начинать каждый сеанс здесь. Репозиторий `MaksimUnimax/runtime-fixtures`, ветка `alisa`; единый центр `docs/alisa/quality/`.

## Требование владельца — без дальнейшей переинтерпретации

Развиваем голосовую Алису **и полноценный веб-сервис аналитики**. **Себестоимость — одна текущая сумма за единицу, без даты начала и предполагаемой даты будущего изменения.** Скрипт использует сохранённую цифру, пока владелец её не изменит. Для исключения товара также текущая сумма без дат. Не возвращать требование обязательных дат или скрытый диапазон от0001до9999.

Предыдущая инструкция о будущих обязательных датах была неверной для этого сценария и отменена. Подробная старая история сохраняется в предыдущих commits, но не является текущим требованием.

## Текущая точка — CURRENT-COST / PROMOTION-DIAGNOSIS, 8 ноября 2026

[Приёмка, доказательства и ограничения](OWNER_CURRENT_COST_AND_PROMOTIONS_2026-11-08.md).

**CURRENT_COST_NO_DATES_ACTIVE / PROMOTION_DATE_GUARD_ACTIVE / OWNER_RETEST_PENDING.**

https://alisa.octoport.ru/app/owner-inputs — при выборе магазина сразу одна пустая общая сумма. Нет календарей и переключателя «Сумма известна» у себестоимости. Исключение добавляется только при необходимости; товар выбирается из каталога по названию/артикулу. В браузер/API не передаются ключи магазина.

В backend сохраняется `unit_cost.period=null`, а не выдуманные даты. Это явно разрешённая каталогом форма текущего значения. Общий resolver сохраняет права, snapshot/version и приоритет индивидуального значения. Ноль и пропуск не заменяются друг другом или общей суммой. Старое принятое задание не пересчитывается с новой версией незаметно.

Налог/собственные расходы — необязательные дополнительные строки. Их фактические периоды не требуются для сохранения одной себестоимости. Старые разные cost values не угадываются; новая форма предлагает подтвердить текущую цифру. Никакие реальные значения или approval исполнитель не назначал.

### Почему колонка требовала даты для акций

В действующей матрице **нет источника участия товаров в скидочных акциях**. Раньше общий parser спрашивал период до выявления этой недостающей возможности. После даты вопрос уходил в P2, где отсутствующий показатель не разрешался.

В техническом журнале сохранились два FAILED/LLM_CLARIFY07:03/07:04UTC и HTTP200 модельных вызовов; webhook в соответствующем интервале отвечал200. Однако точные реплики уже очищены по существующему15-минутному retention. Нельзя выдавать проверочные формулировки за восстановленный транскрипт владельца или безусловно связать каждый FAILED с его конкретной фразой.

На старой установленной версии воспроизведены «В каких акциях участвуют мои товары на Озоне», «Покажи участие в акциях», «Какие акции сейчас на Озоне»: PERIOD_REQUIRED. Установлен исправленный общий guard известных неподключённых тем перед period/dataset/table обработкой. Сохраняются auth/sensitive/read-only guards. Кавычки названий и «транзакции» не считаются акциями.

Теперь ответ прямо сообщает: источник участия в акциях ещё не подключён, для текущего участия даты не нужны, это недостающая функция сервиса. Финансовый job/model-вызов для такого вопроса не создаётся. **Это исправление ошибочного уточнения, а не подключение списка участников и не ответ «вы не участвуете».**

Добавлен только технический dialogue_outcome с кодом ошибки/признаком уточнения, без пользовательской реплики, идентификаторов, сумм и ключей. Финансовый retention не расширен.

## Действия владельца перед следующим шагом

Открыть https://alisa.octoport.ru/app/owner-inputs после обновления страницы, выбрать магазин, ввести **только текущую сумму** общей себестоимости, подтвердить и сохранить. Ожидаются версияN>0 и та же сумма после перечитывания; дат для себестоимости нет. При несохранённом черновике сначала сохранить сумму для себя. Исключения — только при реальной необходимости.

По акциям сейчас ожидается честное объяснение неподключённого источника без требования периода, не список участников. Просить владельца угадывать дату ради этого вопроса запрещено.

**Следующий шаг:** принять сохранение одной суммы; отдельная недостающая реализация — источник действительного участия в акциях, только после её проверки можно обещать список участников. История предыдущей контрольной точки: commit b4b53b973ecb473ae312d65fdf8b448b1ba85733.
