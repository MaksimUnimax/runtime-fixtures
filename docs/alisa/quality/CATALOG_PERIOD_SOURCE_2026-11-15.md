# Выбор периода в каталоге: исходники и изолированная проверка · 15.11.2026

**Подготовлено исправление отсутствующего выбора периода AL-S11. Сборка и настоящий Next.js в изолированном Chromium прошли. Изменение ещё не получило независимое ревью и не установлено на Alisa; AL-T09-01 остаётся PARTIAL.**

## Поведение

В каталоге появились «Вчера», «Последние 7 полных дней» и «Свои даты». Для своих дат показаны начало и окончание; неправильный, обратный или будущий диапазон блокирует ссылку подготовки обычного вопроса. Выбранный период виден в примере фразы и переносится вместе с выбранным магазином. Отдельный запуск задания остаётся на странице формы.

Сервер передаёт московскую календарную дату, поэтому семь полных дней заканчиваются вчера независимо от часового пояса машины. Снимки сохраняют «сейчас». Даты отчёта не подменяют отдельный период коэффициента; справка без периода не получает «за вчера». Ограничение длины вопроса сохраняет выбранные даты. Площадка показана по выбранному своему магазину; доступ и ключи не создаются.

| Production build | Next build --webpack и TypeScript PASS на копии с неизменёнными зависимостями |

Это SOURCE/изолированная проверка на синтетических магазинах и loopback API. Рабочая БД, ключи, сессии, внешние API и колонка не использовались. Нельзя записывать это как установленную пользовательскую приёмку.

Первый браузерный прогон столкнулся с двумя role=alert: правильным сообщением о диапазоне и служебным Next route announcer. Уточнён только locator внутри fieldset; отказ сохранён. Первый build после dev получил дубли generated route types из общего одноразового .next. Удалён только собственный временный generated output; clean build прошёл. Продуктовые проверки ради прохождения не отключались; первые логи сохранены.

## Границы и следующий шаг

Изменены только три файла каталога и три файла его тестов. Backend, identity, native, доступ, данные и R15 не менялись. Техническое отображение единицы currency остаётся отдельным открытым замечанием. Переключение площадки подтверждено на синтетическом WB, не на новом магазине владельца.

Независимое ревью ещё не получено. Действующие правила AGENTS.md требуют его для собственного кода; CODEX.md не разрешает запускать нового помощника без отдельного допуска. Самопроверка и CI не называются независимым ревью. До этого условия рабочая установка не переключается.

Следующий шаг: независимое ревью точного коммита и CI; затем отдельная совместимая web-only поставка с проверкой отката и приёмка в сохранённом Cloud Browser. Остальные службы, R5 и текущие сессии должны сохраниться. Четыре UNKNOWN и прежний GIFT не повторять.
