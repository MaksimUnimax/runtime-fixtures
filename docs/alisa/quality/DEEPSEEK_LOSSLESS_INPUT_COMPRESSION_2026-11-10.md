# Передача полного ответа API модели с меньшим числом токенов

Дата: 10.11.2026. Это исследование формата, не изменение работающего сервиса. Голосовые проверки остановлены владельцем и не возобновлялись.

## Исходное положение

`model_answer.messages()` передаёт исходный вопрос и `canonical_json(api_data)` целиком. `capture_api_answer()` записывает в `api_data` все полученные данные API, а также операцию, магазин, параметры, время и идентификатор квитанции. `canonical_json()` уже использует компактный JSON без пробелов; ещё одно удаление пробелов экономии почти не даст.

В ошибочном запросе о выкупах WB ответ API был 185 519 байт, итоговый вызов модели получил 60 482 входных токена и стоил 1,52735 ₽ по действовавшему пиковому тарифу. Отчёт хранится в закрытом архиве владельца; исходный `jobs.progress` после истечения задания очищен. Архив представляет API-ответ в HTML и при отображении превращает числовые и другие типы в текст.

## Обратимые варианты

1. **Короткие имена полей + словарь в начале.** Каждое поле заменяется стабильным в пределах сообщения коротким кодом (`a`, `b`…), полный список соответствий передаётся вместе с данными. Вложенность, строки, числа, null, отсутствие поля и порядок массивов сохраняются. Модель продолжает читать JSON-объекты и использует словарь для расшифровки имени поля.
2. **Схемы объектов + массивы значений.** Для каждой встреченной формы объекта передаются имена полей один раз, а сами объекты представлены идентификатором формы и полным массивом значений. Это универсальное структурное преобразование для любых шаблонов и площадок. Оно не вычисляет метрики, не ищет нужные записи и не отбирает информацию.

Обе схемы проверены программным восстановлением исходной структуры. Дополнительно проверены вложенные объекты, разные типы, null и отсутствие поля в одной из строк. Доказана обратимость структуры данных, **не доказана** точность ответа DeepSeek на новом формате.

## Офлайн-замер

Из 48-часового архива владельца извлечена HTML-копия того же отчёта с проверкой доступа. Из неё восстановлена форма и текст всех значений; типы оригинального JSON по HTML уже нельзя восстановить. Оценка токенов сделана официальным демонстрационным токенизатором DeepSeek V4 на этой копии, без сетевого вызова модели. Поэтому числа ниже — оценка относительного эффекта, не квитанция DeepSeek для изменённого реального вызова.

| Представление архивной копии | Байт текста | Оценка токенов | Изменение к JSON |
|---|---:|---:|---:|
| Компактный JSON | 201 534 | 60 455 | база |
| JSON с короткими именами и словарём | 99 722 | 45 288 | −25,09% |
| Схемы полей и массивы значений | 77 623 | 36 857 | −39,03% |
| gzip → base64 | 7 968 | 5 525 | −90,86% формально, для модели непригодно |

В архивной копии 10 129 повторений имён полей и только 64 разных имени. Это объясняет выигрыш от передачи имён один раз. Базовая оценка 60 455 близка к фактическим 60 482 входным токенам итогового вызова, но это не делает измерения вариантов фактической биллинговой квитанцией.

При неизменных выходе и тарифе, если реальный запрос получил бы те же относительные числа, экономия за счёт входа составила бы ориентировочно 0,38 ₽ для словаря и 0,59 ₽ для схем на этом дорогом случае. Не экстраполировать эти числа на короткие отчёты и весь поток: схема, число строк, повторяемость полей и кэш различаются.

## Почему остальные способы не подходят к задаче

- gzip, zstd, бинарный MessagePack или base64 сохраняют байты, но текстовая модель не получает доступных ей фактов после такой упаковки. Внешний распаковщик вернёт распакованный текст в контекст и потратит его токены. Надёжность «умственной» распаковки модели нельзя считать установленной.
- DeepSeek Files API поддерживает загрузку изображений, а текстовые файлы как вход модели не поддерживаются. Изображение таблицы ограничит токены, но после масштабирования/OCR нельзя гарантировать сохранность всех чисел и полей.
- Встроенный кэш DeepSeek уменьшает цену совпавшего префикса, но `prompt_tokens` такого вызова всё равно учитывает весь вход. Это другая, параллельная оптимизация.

## Рекомендация

Обновление: [дополнительные замеры и оценка внедрения](DEEPSEEK_LOSSLESS_INPUT_COMPRESSION_OPTIONS_2026-11-10.md) уточняют эту предварительную рекомендацию. Схемы полей и словарь повторяющихся объектов дают больший выигрыш; правильность ответов модели для всех новых представлений ещё требует отдельной проверки.

Сначала проверить вариант с короткими именами полей на фиксированном наборе реальных вопросов без колонки: он проще для чтения моделью. Затем сравнить формат со схемами. Замерять по `usage.prompt_tokens`, цене итогового вызова, числу ошибок и правильности ответов на одних и тех же данных. Особенно проверять суммы, даты, отрицательные значения, null, вложенные записи и составные вопросы. Сборщик должен работать с любым JSON-ответом API и восстанавливать его целиком; отдельный шаблон не кодируется вручную. В работающий сервис формат пока не установлен.
