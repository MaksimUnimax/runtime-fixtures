## Известные препятствия — не обходить

Последняя read-only проверка tenant с сохранённой себестоимостью: `AccessLedger отсутствует`, `AccessGrant=0`, `NOT_PROVISIONED`, не EXPIRED. Это внутренний доступ Алиса Маркет, не Ozon Premium. Каталог/запуск коэффициента законно блокируются текущим gate. **Не выдавать доступ, не менять сроки/роли, не создавать новый аккаунт или перепривязку ради PASS.** При том же результате отметить зависимые сценарии BLOCKED; доступные проверки продолжить.

Отдельно найдено: установленный `catalog.views.customer` ещё не принимает `kind=parameter`, хотя reader/ядро/UI поддерживают его. Явный фильтр может дать INVALID_PAYLOAD. Исправление/проверка этого места уже в участке тестера каталога; разработчик коэффициентов его параллельно не редактирует.

Health `runtime=RUNTIME_NOT_CONNECTED` — старый literal foundation.ready; фактический metadata IPC ранее прошёл. Это не достаточное доказательство отказа соединения.

## План браузерной приёмки

Перед началом: подтвердить нужный кабинет и магазин «Кровь и Песок · OZON», не по совпадению имени другой сессии; зафиксировать исходное число/отсутствие и область. **Не перезаписывать реальную бизнес-настройку искусственным числом ради теста.** Изменяющие сценарии выполнять на уже разрешённом тестовом магазине/параметре либо при конкретно согласованном пользователем новом значении. Не создавать новый доступ/магазин ради теста. Ручной ноль не подменять действующим коэффициентом бизнеса.

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| CP-01 | Открыть коэффициенты из текущего кабинета | Та же сессия, выбранный магазин; без повторной привязки и лишних дат |
| CP-02 | Прочитать текущее значение и обновить страницу | Число/даты те же, нет нового collection job, API/модель-производитель не вызваны |
| CP-03 | Ручной ввод разрешённого числа | Одна текущая величина; 8,5% означает 0.085, не 8.5 в долях; ручному вводу не нужны статистические даты |
| CP-04 | Явный ноль на разрешённой тестовой цели | Ноль сохраняется, не превращается в «нет значения» и не запускает сбор |
| CP-05 | Ручная замена рассчитанного числа | Старое расчётное основание/даты очищены; показана дата ручного изменения |
| CP-06 | Общий коэффициент и выбранный из каталога SKU | Индивидуальный приоритет; без исключения наследуется общее; изменение общего не стирает исключение |
| CP-07 | «Использовать общее значение» на разрешённом исключении | Собственное число удалено, применяется текущее общее, не ноль и не старая копия |
| CP-08 | Открыть расчёт и выбрать период до запуска | Год по умолчанию; полгода/свои даты меняются до команды; это период коэффициента, не период дневного отчёта |
| CP-09 | «Только показать» | Расчётный результат есть, сохранённое число/даты не меняются; saved не утверждается |
| CP-10 | «Рассчитать и заменить» | После проверки данных заменено ровно одно текущее число; дата расчёта, дата источников и статистический период подписаны отдельно |
| CP-11 | Повтор/refresh при ожидании, потеря ответа | То же Query/job/намерение, без второго сбора/записи; браузер предлагает проверить исход, не отправляет новый запрос вслепую |
| CP-12 | Отмена до commit | Поздняя запись запрещена, прежнее число остаётся; уже отправленный внешний запрос не выдаётся за физически остановленный |
| CP-13 | Отмена после commit | Честное «уже сохранено», без скрытого отката числа |
| CP-14 | Ручное изменение во время сборки, только на тестовой цели | Поздний расчёт не затирает правку; конфликт понятен, не молчаливый успех |
| CP-15 | Старый готовый результат после нового значения | Помечен superseded, не показан как нынешний коэффициент |
| CP-16 | Ошибка/неполный источник/неверный диапазон | Нет ложного нуля или saved, прежнее число/даты сохранены; точная причина зафиксирована |
| CP-17 | Чужой Origin/неавторизованный API | Отказ без раскрытия данных; не менять права или подбирать чужие реальные IDs |
| CP-18 | Узкая ширина и длинные подписи | Нет горизонтального переполнения, кнопки/селекты доступны |
| CP-19 | Вход/каталог/подготовка вопроса после просмотра коэффициентов | Чужая работа не сломана; подготовка вопроса не запускает отчёт; коэффициенту не добавляется «за вчера» |

Реальные годовые сборы не дублировать между вкладками. Сначала доступные чтения/валидация, затем один разрешённый preview и один согласованный save. Критические killpoints/restart/отзыв прав выполнять только в изолированном стенде, **не выключать Worker или службы в живой браузерной приёмке**. Ни разработчик, ни тестер не должны подменять NOT_PROVISIONED созданием grant.

## Что не включено в текущую приёмку как готовое

Голосовая запись, saved-value зависимости в составной юнит-экономике, live-доказательство короткой истории и детальная расчётная доставка SKU ещё открыты. Общую среднюю нельзя выдавать за индивидуальную доставку SKU. Прежняя историческая сверка 993/7761 и 791884.33/7793 — контроль старых данных, не эталон результата на сегодняшнем периоде и не число для ручного заполнения.

## Формат результата тестера

Один журнал: время/релиз, CP-ID, магазин/область без секретов, исходное состояние, точные действия, ожидаемое/фактическое, PASS/FAIL/BLOCKED/NOT_RUN, видимый текст/скриншот, request/query ID, время ответа, количество вызовов selector/final-answer/provider и фактическая стоимость если доступна. Для BLOCKED — точная причина и зависимые сценарии. Не выдумывать счётчики по документации; недоступную метрику пометить неизвестной. Cookie, OTP, пароли, API-токены и персональные поля не публиковать.

Результаты сохранять в своём отчёте и дать ссылку в PR421. Приёмка браузера/голоса отличается от прежних синтетических тестов; старые PASS не переносить в новый журнал без исполнения.
