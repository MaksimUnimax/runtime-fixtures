## 3. S03: законченный общий модуль входных данных

Создан `owner_inputs.py` и декларативный `owner_input_catalog.json`. Подготовлены три вида входов: себестоимость физической единицы с датами действия; налоговая сумма за точный период либо явное исключение; собственные расходы за точный период. Это не три новых исполнимых голосовых шаблона и не готовая C-UE01. Нет отдельной ветки по названию поля/площадке/фразе.

Значения не зашиты. Число250 используется только в synthetic fixture; отсутствующая себестоимость не становится250,0 или API net_price. VALUE, EXCLUDED_BY_OWNER и NOT_PROVIDED различаются. Явно введённый0 допускается как значение; null не0. Налоговое исключение не означает нулевую ставку.

При изменении цены себестоимости внутри периода возвращаются отдельные интервалы. Пропуски сохраняются. Пересечения/дубли, чужой scope/entity, другая валюта, несовместимые даты и неверные типы отклоняются. Месячные собственные расходы не делятся на дни автоматически: PERIOD_ALLOCATION_REQUIRED. Цена физической единицы не переименовывается в COGS/ordered_units; необходимые количества и их даты обязан подать будущий составной план.

Факты закрепляются immutable pin: content hash+revision+catalog hash+normalized request hash. Новая версия не меняет смысл уже принятого задания. На resolve/execute/read заново требуется доверенный callback authority; JSON/hash не дают полномочий сами. Отсутствие authority, false, truthy1 или исключение блокируют использование. Свой issuer/UI/платформенное хранилище не создавались.

Модуль stateless: без HTTP/SQL/фоновых задач и записей диалога. Ограничения данного каталога: snapshot<=1МиБ,2000записей,366дней запроса,1024сегмента. Авторизационный snapshot<=24часов — это не команда удалять бизнес-историю себестоимости в платформе. Возвращается RESOLVED/RESOLVED_WITH_OMISSIONS, не финансовый runtime READY.
