# Клиентский каталог и вход · 14 ноября 2026

Статус: SOURCE_CANDIDATE. Установка и приёмка этого изменения ещё не выполнены. Рабочую сессию владельца в Cloud Browser сохраняем; приёмка не требует выходить из неё.

Реальный вход владельца по паролю и email-коду прошёл без аутентификатора. Из-за истёкшей попытки исполнитель ранее ушёл в общий IdP-вход без клиентского next и ошибочно запросил TOTP. Правильный клиентский поток уже реализован и сохраняется; TOTP админки не меняется.

На правильном кабинете подтверждено: «Кровь и Песок · OZON», поиск «продаж» — ACCESS_REQUIRED. Read-only проверка показала NOT_PROVISIONED и отсутствие истории grants. Общая metadata-проверка установленного каталога этого пользовательского пути не доказывала.

## Изменение поведения

Обычный вход больше не содержит двух повторных checkbox service/privacy. Native signup по-прежнему получает настоящие согласия. IDP передаёт подписанные версии и исходное время native receipts; BFF проверяет их после проверки подписи/issuer/audience/nonce/PKCE. Платформа не выдумывает согласия и не переписывает существующие записи при входе. Новый локальный аккаунт без подтверждённой регистрации не создаётся. Старый открытый login-form с настоящей парой on/on принимается для совместимости, но эта пара не превращается в фиктивные записи.

Клиент с действующей сессией и своим ACTIVE-магазином, которому ещё ни разу не выдавался доступ, получает опубликованный каталог для предварительного просмотра. Все карточки помечены UNAVAILABLE; ответ имеет preview_only=true. Поиск и страницы используют те же published description/id/kind/platform. Метрики и технические источники staff metadata в ответ не переходят. Можно подготовить вопрос в форме; это не отправляет расчёт.

История любого гранта — будущего, истёкшего или отозванного — сохраняет прежний контроль доступа. Revoked scoped reads, чужой/отключённый магазин, отзыв сессии или изменение магазина во время чтения продолжают отказывать. Рабочие RPC, выдача execution ticket, Query/Worker и права на данные не ослабляются. Новые grants, счета и задания при просмотре не создаются. Неподдержанная конфигурация/версия не превращается в пустой успешный каталог.

Фильтр parameter принимается backend так же, как существующим кабинетом и ядром R5. Ложная постоянная фраза о проверенном допуске убрана; интерфейс показывает фактический режим.

## Проверка и поставка

Проверки покрывают native metadata без jobs/model/provider calls, только собственный магазин, NOT_PROVISIONED без выдачи гранта, отзыв сессии во время preview, прежний отказ после отзыва гранта, поиск/пустой результат/пагинацию и отсутствие staff sources/metrics. Дополнительно — настоящий IDP/BFF/PG путь в изолированном GitHub root job, реальные native signup receipts и их исходное время. Локальный полный qualifier отказал в запуске на постоянном сервере по GITHUB_ACTIONS guard; guard не обходили. Синтетические БД и процессы удалены. Полный прогон назначен CI.

Поставка изменяет согласованную тройку web/platform HTTP/identity. Перед сменой platform/identity customer web останавливается и дренируется; запускается только после проверки совместимой тройки. Rollback использует тот же порядок. Это закрывает замечание независимого review о mixed-version sign-ins. Ключи, accounts/security revisions, живые сессии, R5-параметры, native runtime и его authority остаются в своих действующих границах. Миграций у изменения нет.

Независимый source/installer review, точные CI и owner browser checks должны быть завершены до объявления установленного результата. Сессия владельца закреплена в Cloud Browser; не заменять её сохранённой серверной сессией другого кабинета.
