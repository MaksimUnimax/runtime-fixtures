квалифицированный исходник `592cc8bb006a4991a876c875cd497701791a5593`.
Основа платформы — установленный `alisa-store-default-a6d5e19a87577d87` из PR416.

## Поведение

- Успешная проверка ключа в кабинете автоматически создаёт служебную привязку
  магазина к исполнителю. Ручное добавление магазина в конфигурацию не требуется.
- Ozon работает с Seller API; рекламные методы используют отдельно проверенный
  Performance API. WB использует свой проверенный ключ.
- Новая подтверждённая версия ключа подхватывается автоматически. Непроверенный
  или отклонённый ключ не заменяет рабочую версию. Прежний ключ отзывается и его
  шифротекст удаляется штатной логикой после успешной замены.
- Выдача ключа выполняется на одно принятое обращение через существующий закрытый
  Unix RPC. Владелец, магазин, права и версия проверяются повторно; перед отправкой
  API выполняется последняя проверка доступа. Ключ не сохраняется в файлах ядра,
  задании, ответе кабинета или контексте модели.
- Добавление другого магазина не меняет область ранее выбранного магазина.
  Последний явно выбранный магазин остаётся по умолчанию до явной смены.
- Документы API по шаблонам сохраняются прежним общим архиватором на 48 часов.
  Повторное скачивание не вызывает API/модель и не продлевает срок хранения.
- Удалённая история привязок не расходует технический предел активных ссылок.
  Проверки особых источников и отдельного сервисного токена WB не обходятся.

До включения новой функции прежние операторские привязки продолжают работать.
Автоматическое создание выполняется при успешной штатной проверке магазина;
нового публичного метода получения ключей нет.

## Состав и совместимость

`stores.0002_runtime_bindings` добавляет две таблицы только со служебными ссылками.
Ключи остаются в существующем зашифрованном хранилище. Прежние миграции выбора
магазина, вход, 30-дневная сессия админки и связь Станции сохраняются.

Замороженное `docs/alisa/runtime/v0.11/rt_job_r02` не менялось. Отдельный builder
создаёт overlay: три интеграционных файла и один новый модуль. Базовый выпуск
проверяется по всем хешам; неизвестный изменившийся контекст останавливает сборку.
Параллельная версия `alisa-request-reliability-r1-20261113`, исходник
`65fba692b3b76715c39db21961cef2b99f4ddc45`, включается без замены её Engine,
runtime, учёта вызовов и программного ответа.

Текущий выпуск имеет полный проверенный package manifest, но его старый
`CURRENT_CORE_MANIFEST` не обновлён параллельным изменением. Для квалификации
составлен полный наблюдённый manifest из проверенного package manifest; живой
базовый выпуск не редактируется.

## Установка

Подготовлен конечный установщик с блокировкой существующего rollout-lock,
проверкой полной базы, отдельными выпусками через hardlink, резервом 3 GiB и
200000 inode, узкой миграцией и аварийным откатом. Нового сервиса, таймера,
управляющего runner или очереди нет. После перезапуска native проверяется прежняя
пара владельца и обновляется её привязка только к новой генерации процесса;
пара, ключи и права не меняются.

Установочная приёмка на момент этой записи ещё не завершена. Статус LIVE_OWNER —
NOT_PERFORMED: тестовые сессии владельца, периоды доступа, OAuth-связи и запросы к
платным моделям/маркетплейсам в живой системе не создаются. Итог установки и
технических проверок фиксируется после применения.
