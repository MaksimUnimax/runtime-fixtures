# Физическая передача, приёмка и доступ к юнитэкономике Ozon
Проверено5 ноября2026. Run20261105-TESTER-7fb84c1e. Исправление исследовательского расчёта, не установленный runtime-патч.

## Физическая передача не следует из названия ship
[Официальный справочник ошибок](https://dev.ozon.ru/community/25): POSTING_ALREADY_SHIPPED поясняется как «Заказ уже собран». Это доказывает различие терминов сборки и физической перевозки, но не устанавливает точное внутреннее условие каждого cancellation-флага.
[Официальное объяснение статусов](https://dev.ozon.ru/community/368-V-puti-k-ot-klienta/): awaiting_deliver/posting_transferring_to_delivery отделён от приёмки, движения к городу/ПВЗ и других этапов. Завершённую физическую приёмку нельзя выводить только из готовности к отгрузке.
Точное правило присвоения cancelled_after_ship в backend Ozon НЕ НАЙДЕНО. Запрещено объявлять его безусловным доказательством физической передачи либо без отдельного источника переопределять как универсальное «после сборки».

## Разбор исправления
Владелец подтвердил, что выбранный FBS-товар не сдавался Ozon. Приватный скриншот сопоставлен с выбранным заказом. Свежий get повторно вернул cancelled_after_ship=true при незаполненных delivering_date/pickup_code_verified_at/received_at_sorting_center/tariffication_fact. Returns не содержит выбранных отмен, а их accruals пусты. Последние два обстоятельства сами по себе не доказывают отсутствие расходов; нулевая применимость физической перевозки в этом случае основана на подтверждении владельца.
Убрать из прогноза для этого FBS-товара неоказанные прямую перевозку, обратную перевозку, доставку до пункта и обработку физической сдачи. Реальные деньги по рекламе, банку и другим услугам сохраняются с действительными сторно. Если позже источник покажет противоречащий расход, сохранить проводку и расследовать расхождение.
FBO-отмена остаётся с неизвестной стадией. Решение по одному FBS-товару не обнуляет логистику всех отмен.

Отдельный публичный метод готовой таблицы НЕ НАЙДЕН. Это результат поиска, не доказательство полного отсутствия API.

[Документация Seller API](https://docs.ozon.ru/api/seller/) и [справка вкладки](https://seller-edu.ozon.ru/finances-documents/additional-information/unit-ekonomika) не дали читаемого текста при открытии; закрытые определения не приписываются прочитанным источникам.

## Средние и неполнота
При отсутствии готового UE-метода использовать существующие квалифицированные начисления и количества. Если отдельной денежной статьи пока нет, допустима средняя по сопоставимой полной выборке подтверждённых услуг той же схемы, с явным периодом/числителем/знаменателем; при отсутствии такой выборки — разрешённая владельцем середина официального тарифа. Не использовать неизвестную вероятность передачи как50%. Отсутствующая применимость услуги обозначается unknown; отсутствие фактических денег не равно нулю.
Среднее по реализации кабинета нельзя незаметно подставлять в показатель по заказанным единицам. Нужна сверка определения периода, количества и расходов. Сохраняются правила отмен/возвратов/CPO из предыдущего исследования.
