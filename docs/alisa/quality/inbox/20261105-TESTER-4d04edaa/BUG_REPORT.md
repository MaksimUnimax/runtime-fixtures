# DS03 — NUMBER_RANGE теряется при декодировании источника

Статус: REPRODUCED. Severity: P2 (оценка тестера). Точная сборка: 20261105-v010-conversation-safety-r1. Это не доказательство появления ошибки именно в этом выпуске.

Искусственный успешный HTTP с `price.price = "1e-10000"` проходит настоящий Worker. Ожидание переданного пакета: FAILED / NUMBER_RANGE, result отсутствует, автоматического повтора нет. Факт: FAILED / TABLE_RESPONSE_SCHEMA, result отсутствует, один fake HTTP даже после продвижения искусственных часов и второго worker.step(). UNKNOWN не возникает.

Ответ на «результат»: «Полный отчёт не получен; точная причина пока не установлена. Частичные суммы не выдаю. Нужно проверить сохранённое задание и доступность источников; повтор автоматически не запускаю.» Причина неверного числового значения известна декодеру, но теряется для объяснения.

Точка потери: matrix_sources.py::_read перехватывает MatrixError вместе с ошибками структуры и заменяет код на TABLE_RESPONSE_SCHEMA. Авторский test_bad_provider_is_failed_after_known_http проверяет только FAILED и отсутствие WORKER_INTERNAL_UNKNOWN, поэтому 78/78 этот контрактный разрыв не обнаруживают.

Воспроизведение: independent_isolated.py / DS03; подробная квитанция DS03_CODE_MISMATCH.json. Только temporary SQLite и fake transport; production ответы и настройки не подменялись. Нет дубликата этого смысла в прочитанном BUGS.json; исторический OZCP-004 не переписан.

Следующий шаг: сохранить доказанную числовую причину в общем source decoder и дать объяснение с причиной и следующим шагом; добавить точный тест кода и фразы, затем передать новый exact build для адресного retest. Runtime тестером не исправлялся.

Отдельное наблюдение: один пустой ответ консоли Яндекса при чтении страницы. Команда не появилась в gateway receipts и не сдвинула курсор; источник сбоя не установлен. После одного повторного чтения ответ получен. Это не объявлено ошибкой бизнес-расчёта.
