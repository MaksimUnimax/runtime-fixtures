# WB: отдельный показ отмен, возвратов и обратных перевозок

Ревизия r2. Исправление исследовательского отчёта, не установка runtime.

В финансовой детализации дня есть обратные перевозки по старым отменённым заказам. Они были описаны в финансовом контроле, но отсутствовали отдельной строкой в краткой таблице владельцу. Нулевая строка по новым выбранным заказам без этого пояснения создавала ошибочное впечатление, что у магазина вообще нет возвратных расходов.

Обязательные строки шаблона: количество отмен выбранных заказов; подтверждённые возвраты после выкупа; прямая доставка выбранных заказов; обратная перевозка выбранных заказов; возврат продавцу при наличии. Отдельно показывать все обратные перевозки, начисленные за финансовый день, и число совпадений с исходными заказами.

Точная выборка обратной финансовой перевозки: POST /api/finance/v1/sales-reports/detailed, sellerOperName=Доставка, deliveryAmount=0, returnAmount>0. Сумма затрат — deliveryService; количество перевозок — сумма returnAmount. Связь с исходной заказанной штукой — точный srid. Не считать quantity=0 нулём стоимости услуги. Проверять смысл события отдельно: такой транспорт не равен автоматически возврату товара после выкупа.

deliveryServiceSum финансового дня уже включает прямые и обратные перевозки. В итог повторно обратную сумму не прибавлять. Старые заказы не становятся частью выбранного нового набора из-за совпадения дня списания. Если нужен режим распределения всех расходов дня на новые заказы, он должен быть явно выбран/обозначен с единым правилом включения расходов; не называть распределение фактическим начислением по этим заказам.
