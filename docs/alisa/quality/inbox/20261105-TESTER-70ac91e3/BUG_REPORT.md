## QA-20261105-TESTER-70ac9201 — ACCEPTANCE_RULE: пустой ответ без объяснения запрещён

Источник: прямая команда владельца 05.11.2026. State NEW, Severity UNSET. Связь: существующий OZCP-003 (непонятный технический ответ вместо объяснения), QA-20261105-TESTER-70ac9103, C-UE01/B12. Это обязательный контракт ответа; новый LIVE_DIALOGS дефект в этом прогоне не воспроизводился.

**Требование:** сервис не должен отдавать пользователю пустой ответ, голый null/пустую таблицу, один технический код или молча считать недоступную рекламу нулём. При отказе/невозможности расчёта всегда сообщать причину, затронутый источник/показатель, что не удалось рассчитать и конкретное действие для устранения. Известную причину возвращать точно; неизвестную не выдумывать.

Для HTTP 200 с пустыми rows причина не всегда является ошибкой: подтверждённое отсутствие операций оформляется как OK/VERIFIED_ZERO с основанием. Если ноль не подтверждён — DATA_UNAVAILABLE/EMPTY_RESPONSE_UNEXPLAINED: «Источник вернул пустой отчёт. Причина пока не подтверждена. Расход на рекламу не установлен, полную юнитэкономику рассчитать нельзя. Следующий шаг: проверить охват рекламных инструментов, кабинет и параметры отчёта».

Нормализованный error/result contract: status; reason_code; human_message; affected_source/metrics; retryable; next_action; safe request/result reference; as_of/completeness. HTTP/status и latency остаются в техническом журнале, секреты не выводятся. Для таймаута с неизвестным исходом не советовать повторять исходную операцию автоматически: сначала установить состояние.

Отрицательные сценарии приёмки: нет/неверные credentials (AUTH), запрет scope/permission, 429/quota, недоступность/timeout/UNKNOWN outcome, неподдержанный метод/рекламный инструмент, некорректный формат, неполная пагинация, пустой отчёт с неизвестной причиной, подтверждённый истинный ноль. В каждом случае непустое понятное сообщение и причина либо честное «причина не установлена». Разрешённые частичные данные помечены; обязательная реклама блокирует финал C-UE01.

Исправление и закрытие: автор возвращает commit/catalog/package hash и тесты; затем независимый retest точной версии через Диалоги. Добавление этой записи не означает, что поведение уже исправлено.
