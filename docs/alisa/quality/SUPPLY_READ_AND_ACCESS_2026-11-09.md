## Исправленный B2B-сценарий

Первый успешный HTTP200 не проходил нашу проекцию: не учитывалась обёртка date_from/date_to/invoices. После её добавления проверка даты тоже отказала. Безопасный журнал формы значения — только тип, длина и маска, без фактического текста/чисел — показал **строку длины0** в date_from. Предыдущие предположения о календарном формате не объявлены причиной после получения этого доказательства.

Для этого конкретного профиля теперь явно разрешено сохранить пустое/null поле периода без подстановки даты из запроса. Метаданные ответа содержат:

`source_period_status=MISSING`, `blank_calendar_fields=[date_from,date_to]`.

Общий renderer по этому признаку добавляет: **«Источник не указал период в ответе. Полученные данные нельзя считать подтверждённым итогом за запрошенный период.»** Это не отдельный шаблон B2B, а общая реакция на явный признак качества источника.

Пустой invoices сохранён как реально полученный пустой массив. Не сделан вывод «за октябрь продаж не было», не вычислена нулевая выручка, период не заполнен скрыто. Полноценная числовая приёмка месячного B2B-отчёта остаётся открытой, хотя чтение перестало падать. Неизвестные реквизиты покупателей и свободный текст по-прежнему исключаются до очереди/модели.

Все предыдущие FAILED-квитанции сохранены. Прогоны R2/R3/R4 не переписаны в PASS; конечный R5 — отдельное новое задание после изменения проверяемого кода.

Реальные диагностические обращения через ту же очередь:
