# Обязательный мини-отчёт каждого прохода

Поручение владельца от 05.11.2026: в конце каждого прохода сообщать, сколько реализовано, сколько осталось, что выполнялось сейчас, что сделано за проход, **что делаем дальше и какая следующая цель**. Следующий шаг и его измеримый результат писать раздельно.

Использовать `CATALOG_PROGRESS_CURRENT.json`, проверенный по конкретной сборке, её допускам и отдельному кандидату. Не копировать старые числа из предыдущего ответа. Единица счёта — объявленное определение показателя, сводки, формулы, табличного представления или H00. Синонимы, сочетания площадок, API-запросы, тесты и типы входных данных владельца не увеличивают число исполнимых шаблонов. Согласованные 16 бизнес-семейств и 3 служебных блока — отдельная классификация.

| Поле | Что писать |
|---|---|
| Реализовано | Число определений, включая проверенный неустановленный кандидат |
| Включено | Число определений в действующей конфигурации; это не обещание независимой числовой приёмки |
| Осталось | Готовые определения без допуска плюс именованные функциональные пробелы вне счётчика; остаток кандидата не равен всему будущему объёму |
| Сделано за проход | Только фактически выполненные изменения и проверки; новые определения, включения и квалификация уже написанного разделяются |
| Что выполнялось сейчас | Конкретный блок и его статус, без обещания фоновой работы |
| Что делаем дальше | Следующее конкретное действие, его область и точная зависимость/блокер |
| Следующая цель | Наблюдаемый результат и критерий завершения следующего этапа: что должно заработать, где и чем это будет подтверждено |

Не ограничиваться фразой «продолжить разработку». Например: шаг — подключить producer нормализованных источников к готовому S03-сценарному контракту; цель — две таблицы C-UE01 на свежем реальном периоде через существующий worker, с источниками каждой суммы и дальнейшей независимой приёмкой. Не выдавать эту цель за выполненную до доказательств.

Числа текущего состояния намеренно не дублируются здесь: они хранятся в машинном реестре и подтверждаются актуальным readback. Историческая точка Q01 была 82/69/13; после установки девяти определений — 82/78/4. Эти исторические значения не являются правилом для последующего прохода.

Готовый общий модуль входных данных S03 и offline-сценарный калькулятор не означают, что включены S03 или C-UE01. Три поля каталога owner inputs или две расчетные таблицы не превращаются в новые готовые голосовые отчёты без их источников/маршрута/допуска. Поддержанное подмножество семейства не означает полное покрытие всех площадок и временных осей.

Новые, включённые и только проверенные возможности считать отдельно. Повторный запуск тех же тестов не увеличивает число уникальных тестов. Старый полный набор не заявлять выполненным заново только потому, что текущие хеши совпали.

Исходные VERIFIED/PARTIAL/SKIP сохраняют свою проверенную версию и область. Исполнитель не закрывает внешние числовые PARTIAL собственным совпадением декодера с тем же API без соответствующего нового вердикта. Число зелёных unit-тестов не заменяет внешнюю или числовую приёмку.
