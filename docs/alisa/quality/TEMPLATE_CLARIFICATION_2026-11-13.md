# AL-S09 — уточнение исходного запроса по шаблону

Статус: IMPLEMENTING / NOT_INSTALLED. Продолжение установленного PR418; новая
рабочая ветка `feat/alisa-template-clarification-20261113`. Рабочие сервисы пока
не менялись. Параллельные изменения ядра сохраняются отдельным точным расширением.

Планировщик получает третий закрытый ответ `clarify`, рядом с `plan` и
`unsupported`. Если подходящий зарегистрированный шаблон есть, но недостаёт
периода, смысла показателя, оси или другого обязательного условия, модель задаёт
один короткий вопрос. Никакого списка конкретных шаблонов или парсера бизнес-фраз
для уточнений нет. Новые шаблоны используют тот же путь. Для snapshot/справки
период не требуется автоматически. Отсутствие самого шаблона остаётся отдельным
отказом с прежним сообщением.

Во время уточнения выполняется только существующая модель выбора. API площадки,
финальный ответ модели и создание документов не запускаются. RuntimePort выдаёт
состояние NEEDS_INPUT и результат CLARIFICATION; это вопрос, не бизнес-отчёт.
Ответ продолжает тот же native job, public query ID и runtime ref. Исходный
вопрос, дата/часовой пояс, полный набор магазинов и права закреплены. Уточнения
добавляются отдельно и видны модели выбора и итоговой модели.

Продолжение требует текущие права, тот же logical ID, точную версию вопроса и
отдельный ID отправки. Изменение ответа под прежним ID или ответ на устаревшую
версию отклоняется. Не меняется результат другого читателя; продолжение запрещено
для разделяемого задания и после любого обращения к API площадки. Стандартная
очередь получает новый порядок FIFO для продолжения. Нового worker/таймера нет.
Не более четырёх уточнений; срок ограничен прежним коротким TTL ответа.

Платформа хранит только хеш/ID/результат последней отправки уточнения и метаданные
исходных магазинов. Для этого добавляется JSON-поле continuation в Query;
questions/answers в него не входят. При UNKNOWN новая отправка запрещена,
разрешён явный повтор исходных ID/версии/ответа. Чтение состояния может подтвердить
ранее потерянную квитанцию, но ничего не отправляет повторно.

Кабинет показывает вопрос и поле ответа в карточке существующего задания.
Неопределённая отправка сохраняет ответ в открытой странице до явного повтора.
Голосовой канал использует закрытый зашифрованный VoiceDialogue. Неопределённый
ответ можно повторить фразой «повтори отправку». Другой диалог не получает этот
контекст. При смене магазина сначала нужно завершить или отменить уточнение;
сохранённый магазин для следующих обычных запросов остаётся отдельной настройкой.

Доработка существующего продуктового журнала сохраняет один эпизод от
NEEDS_CLARIFICATION до READY; повтор и polling не увеличивают спрос. В журнале
только переход состояния и непрозрачные идентификаторы, без вопроса или ответа.
SQLite получает совместимые дополнительные столбцы input_pending; старые строки
сохраняются. Это не новый журнал ошибок.

Исходный frozen rt_job_r02 не изменяется. Расширение проверяет manifest всей базы,
единственность каждого заменяемого фрагмента и выдаёт новый manifest. Прежнее
расширение автоподключения магазинов сохраняется; текущая установленная версия
ядра отдельно проверяется перед возможной подготовкой и установкой.

Проверки на момент записи: 13 новых native-сценариев и три проверки границы
сборки прошли локально. Общая регрессия расширенного ядра, PostgreSQL/OAuth/Unix,
собранный браузер и независимое ревью ещё не завершены. LIVE_OWNER не выполнен.
