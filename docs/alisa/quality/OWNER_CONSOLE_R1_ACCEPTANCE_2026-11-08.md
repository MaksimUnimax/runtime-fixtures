## Что установлено

Пользовательская страница https://alisa.octoport.ru/app/owner-inputs и ссылка «Себестоимость и расходы» в карточке магазина https://alisa.octoport.ru/app/stores . Без сессии обе страницы направляют на /login; используются прежние вход и session cookie.

Форма принимает числовой marketplace SKU, себестоимость единицы с интервалом действия, налог и собственные расходы за точный период. Сумма известна / не указана / явно исключаю налог — разные состояния. Суммы вводятся точными десятичными строками; нет r9/default250, автоматического налогового процента или распределения месяца по дням. Неизвестные неподдерживаемые поля/сопоставления не удаляются молча при чтении.

Сохранение требует явной галочки, выбранного магазина и исходной ревизии. Изменение данных сбрасывает галочку. После подтверждения появляется номер сохранённой версии. Отзыв — отдельное явно подтверждаемое действие. Сохранение параметров само по себе отчёт не запускает.

При потере ответа браузер сохраняет только непрозрачный номер команды, магазин, action, revision и deadline — не денежные черновики, session token или ключи. До проверки исходной команды новое изменение заблокировано. Status возвращает первоначальный эффект либо NOT_FOUND с временем сервера. Истёкшая неизвестная команда не может быть принята позднее. Web Lock и expected_revision защищают от двух вкладок; отказ browser storage останавливает отправку до POST.

BFF сохраняет прежние Host/Origin/session проверки, запрещает неизвестные actions/поля и duplicate JSON keys. Он не устанавливает confirmed=true за пользователя и не позволяет браузеру выдавать execution ticket.

## Защищённая проверка прав — реализована, пока не включена для production jobs

Платформа может выдать подписанный короткий ticket, привязанный к среде/product/session UUID/tenant/store/period/input hash. Runtime не получает browser session token и пароль PostgreSQL. Отдельный read-only endpoint проверяет свой сервисный ключ, ограниченный body и каждый раз перечитывает актуальные session/approval/store/credential/access revisions. Подпись не заменяет текущие права.

Клиент использует прежний bounded shared HTTP, фиксированный loopback URL/path, ограниченный срок, без произвольных URL и автоповторов. Ответ связан с новым request_id и HMAC; старый или неподписанный ответ не принимается. В тесте пройден полный Worker с настоящими HTTP-вызовами current-verifier и отказом после отзыва. Это ещё не установка всего маршрута platform→job admission→marketplace.
