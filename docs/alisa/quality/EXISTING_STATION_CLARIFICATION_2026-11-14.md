## Работа запроса

1. Прежний webhook проверяет действующий legacy access token. Station выбирает
   сохранённого владельца по account/application и сохраняет квитанцию обращения.
2. Native получает через отдельный закрытый Unix endpoint только ссылку на эту
   квитанцию. Endpoint принимает лишь UID существующей службы alice-market;
   исходный voice ingress сохраняет прежний закрытый режим доступа.
3. Модель выбора использует общий каталог шаблонов. Если обязательного условия
   не хватает, возвращает короткий вопрос; API маркетплейса пока не вызывается.
4. Ответ пользователя продолжает тот же native job. Исходные вопрос, календарь,
   часовой пояс, магазины и каталог остаются закреплены. После обрыва повтор
   с прежними request/message/body подтверждает прежнюю операцию.
5. Перед продолжением, исполнением и выдачей проверяются текущий токен,
   сохранённая связь владельца и native scope. Refresh не заменяет access.
   Отмена относится к конкретной беседе; общий job останавливается после
   последнего читателя. Вопрос имеет прежний короткий TTL и максимум 4 уточнения.
6. Документы сохраняет прежний общий архиватор по использованному шаблону
   на 48 часов. Уточняющий вопрос документом не становится. Новые шаблоны
   подключаются через каталог, отдельного списка бизнес-фраз здесь нет.

Секретные bearer-токены в native/model payload не передаются. Station хранит
минимальный proof в существующих квитанциях, без продления их часового срока.
Immutable authorization view публикуется после успешного сохранения; изменённый
view инвалидируется перед записью. Неудачная запись и её точный повтор не
восстанавливают отозванную связь и не создают второй расчёт. Read-only authority
не захватывает блокировки, удерживаемые при обратном запросе статуса.

Frozen `rt_job_r02` и `runtime_task_v1.schema.json` не изменены. Совместимость
реализована отдельным overlay. Схема task SHA256 остаётся
`08b4b6c708c5ae1d5387dbd593fde7ea40c9f671efdad8b9aacbcab9bd683d34`.
