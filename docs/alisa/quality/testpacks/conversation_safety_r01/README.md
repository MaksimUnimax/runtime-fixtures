## Как проводить и записывать

Начать с `docs/alisa/quality/README.md`; новый run — `quality/inbox/<UTC-дата>-TESTER-<8hex>/`. Точную версию установить по manifest/ExecStart; общий заголовок «Матрица 0.10, базовый пакет 1» недостаточен.

A/B должны иметь действительно разные session_id одного аккаунта. Две вкладки не доказывают две беседы. Записать безопасные хеши session_id; полный Request, access_token, cookies и ключи не сохранять в Git. Для каждого сообщения: запрос, полный безопасный ответ либо закрытая evidence-ссылка с hash, tts при наличии, UTC начала/конца, время первого ответа, наблюдения READY и дочитывания страниц отдельно. Неизмеренное — null, не ноль. «Принято» не означает готовый отчёт.

Рабочие данные, часы, роли и квоты не менять ради PASS. Для отмены требуется ещё QUEUED/RUNNING: если задание успело READY — SKIP_TIMING, не PASS. Повтор фразы с новым message_id не является повторной доставкой прежнего сообщения. Для недоступного механизма replay — SKIP_PREREQUISITE. Restart только в согласованном окне с исполнителем и при отсутствии посторонних активных работ.

Перед пятидневным отчётом сверить текущий общий бюджет начислений и последующих стадий. При нехватке — SKIP_QUOTA или только проверка плана на временной БД. Не запускать месяц или «обнови» ради протокола; UNKNOWN не повторять автоматически. Готовый безопасный отчёт для чтения использовать повторно в рамках точного кэша, без склейки чужих старых данных.

## Что считать доказательством

Фактические ответы и времена не заполнять из авторского smoke. Для CS10/CS11 числовой PASS требует независимого источника/алгоритма и совпадения оси, периода, магазина и валюты. Для изоляции нужен explicit job/session match и последовательность страниц; один HTTP200 этого не доказывает. Общий итог может быть PARTIAL при выполненном диалоге, но непроверенных числах.

Сохранённый авторский smoke 09:20 UTC: один полный отчёт текущих цен, один HTTP200, shared reader 1,1,2,2 и после restart3,3; прочитаны первые три страницы из14, не все14. Офлайн:1035/57/70/78 плюс JSON-only. Эти доказательства не превращаются в независимый VERIFIED.
