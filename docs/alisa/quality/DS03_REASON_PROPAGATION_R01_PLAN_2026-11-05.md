## Адресное решение

1. Сначала сохранить точный failing regression с исходной искусственной ценой1e-10000, реальным temporary Repository/Engine/Worker, без liveDB/HTTP. Проверять не только FAILED, но и точный NUMBER_RANGE, result=None, одну запись вызова, русскую причину/next_action, отсутствие повторного HTTP и сохранение UNKNOWN для неизвестного сетевого исхода.
2. В общих _read/_guard сохранять только явный безопасный числовой код NUMBER_RANGE; остальные ошибки структуры/привязки продолжают маппироваться в предусмотренный схемой код. Не отражать raw exception/body/path в ответе и не ослаблять guard.
3. В JSON-каталоге объяснений добавить NUMBER_RANGE и TABLE_RESPONSE_SCHEMA как известные классы отказа проверки входных данных. Не утверждать внутреннюю причину на стороне площадки; не печатать исходное число. Тестировать обе формы: числовая граница и настоящий структурный дефект.
4. Отдельный immutable release 20261105-v010-number-reason-r1, не смешивать с C-UE01. Сохранить все1240 прежних проверок и добавить точный regression. Новый комплект и manifest после clean extraction. Установка только после совпадения active base/config, собственного lock, отсутствия активных заданий/ожидающих уточнений и успешной полной проверки. Новых миграций/допусков/бизнес-HTTP не требуется.
5. После установки безопасный no-marketplace gateway smoke, точный тест искусственного ответа на установленном исходнике; публичный статус READY_FOR_RETEST, не независимый VERIFIED. Ответ исполнителя рядом с исходным tester inbox, короткий retest-пакет с пустыми результатами.
