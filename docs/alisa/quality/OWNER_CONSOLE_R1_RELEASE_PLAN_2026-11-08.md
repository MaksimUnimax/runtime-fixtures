# OWNER-CONSOLE-R1 — ограниченная поставка формы параметров

Команда владельца: продолжать подключение формы и защищённой проверки; необходимые действия владельца описать конкретно с рабочими ссылками перед «Следующим шагом».

Планируется включить только ввод/подтверждение параметров владельца на действующем alisa.octoport.ru. Новая голосовая C-UE01 и штатный клиентский RuntimePort автоматически не включаются.

## Область изменения

Новый неизменяемый release объединяет сохранённую текущую web/identity базу da73 с точным web build и source owner_data. Изменяются только указатели web-current и site-current (platform), feature flags owner-data в их собственных env. Identity/admin/runtime-процессы не переключаются, MFA/пароль/email/login/session implementation не меняется.

Две новые таблицы owner_data создаются штатной additive Django migration. До неё — частная согласованная backup платформенной БД, migration plan и проверка свободного места. Никакие реальные себестоимости, налоги, расходы, пользователи, магазины или keys не создаются миграцией.

Роль runtime должна сохранить ограниченные права; требуются права только на новые бизнес-таблицы. Прежние append-only audit/grants ограничения остаются. Ни market runtime, ни браузер не получают DB credentials.

ALISA_OWNER_DATA_ENABLED=1 включает форму и внутренний owner API. ALISA_OWNER_RUNTIME_ENABLED остаётся0 при данном выпуске: RPC-код и подписанный ticket проверены отдельно, но production job-admission/credential routing ещё не принят. Не выдавать доступность формы за готовый голосовой отчёт.

## Gates

Проверены точный Node24.22.1, typecheck и production build.39 model/strictJSON checks и18 настоящих Chromium+Next BFF сценариев прошли с искусственным platform ответом.85 PostgreSQL/source/recovery/loopback-RPC checks прошли; полный матричный повтор выполняется отдельно до активации. Авторские результаты не являются независимым verdict.

После установки: manifests всех затронутых компонентов, schema/role privileges, readiness, публичные HTTPS ссылки, анонимный redirect к login и отсутствие доступа к owner/API без сессии, отсутствие изменений identity/admin/runtime PID. Никакое чтение/запись реальных owner facts для smoke не выполняется и вход владельца не имитируется.

## Возврат кода

Сохранить предыдущие web/site pointers и частные env файлы. При неуспешной готовности вернуть только эти указатели/flags и перезапустить только свои web/platform службы. Additive таблицы не удалять и backup поверх бизнес-данных автоматически не восстанавливать. Не очищать чужие worktrees, Business Bridge или реальные данные ради места.

До подтверждённого readback не направлять пользователя на новую страницу как на работающую. После — ссылка /app/owner-inputs, выбор магазина, ввод SKU/стоимости/дат и явное сохранение версии. Точные суммы определяет владелец, не пример r9 и не исполнитель.
