# Обязательная автоозвучка на Станции — 8 ноября 2026

> Уточнение владельца и исследования: пользователь не должен вручную создавать сценарии. Публичный IoT API не предоставляет их создание; найденный автоматический путь использует внутренний Quasar API и пока не принят на нашей колонке. Приветствие — только «Привет, {имя из профиля сайта}», справка — по запросу. Полный путь и обязательные ограничения: [STATION_END_TO_END_CONTRACT_2026-11-08.md](STATION_END_TO_END_CONTRACT_2026-11-08.md). Прежняя ручная инструкция ниже — диагностический опыт, не целевой onboarding.

Прямое уточнение владельца: после одного вопроса готовый ответ должен прозвучать на выбранной колонке автоматически. Дополнительная реплика пользователя для проверки готовности не является целевым интерфейсом. Этот документ уточняет действующий roadmap; исторический v0.5 сохраняется как снимок.

## Почему сейчас работает иначе

В установленном voice webhook `/opt/alice-lab/releases/20261103-market-dialogue-r4/alice_lab.py:115` пустая команда и справка возвращают текст с ручным чтением. В установленном `alisa-runtime-06f3c053e7719290/engine.py` сохраняются такие же подсказки для READY/QUEUED/RUNNING. Это реальная текущая реализация.

[Исходный план от 3 ноября](../runtime/v0.9/SMART_HOME_AUTO_DELIVERY_REVIEW_2026-11-03.md) уже описывал server→IoT scenario→Station→новый skill request. Ручная команда там названа резервом/отладкой, а аппаратная проверка оставлена NOT VERIFIED. В более позднем [v0.5 S18](../service-platform/v0.5/ROADMAP.md) автоозвучка была отложена как отдельное исследование. То есть требование сохранили в документах, но не довели до поставленного голосового пути.

Обычный навык отвечает в существующем запросе; бюджет webhook 4,5 секунды не позволяет ждать длинный расчёт произвольно долго. Этот предел объясняет отдельный worker, но не заменяет отсутствующий канал автоматической доставки.

## Как должен идти ответ

1. Пользователь задаёт вопрос один раз. Сервер сохраняет задание и кратко подтверждает приём.
2. Worker заканчивает расчёт и сохраняет READY и событие доставки для конкретного задания.
3. По отдельному пользовательскому IoT-разрешению сервер запускает заранее выбранный сценарий.
4. Действие сценария обращается к нашему навыку фиксированной фразой. Само действие не содержит финансовых сумм.
5. Новый запрос навыка проверяет пользователя, разрешённый канал, актуальность доступа и конкретное ожидающее задание, затем читает сохранённую сводку. Маркетплейсы/LLM повторно не вызываются.
6. Колонка озвучивает сводку без дополнительной речи пользователя.

Документированный API запуска сценария принимает ID сценария, а не произвольный динамический текст. Поэтому объявление «ответ готов» с последующим ручным запросом не удовлетворяет требованию: нужно проверить именно переход в навык и чтение готового ответа.

Автоозвучка теперь обязательна для приёмки этого голосового пути. Её нельзя оставлять необязательным будущим улучшением. Начальный опыт со сценарием можно провести сейчас; завершённая поставка зависит от последующих пунктов таблицы.

Отдельный delivery record должен сохранять область прав и конкретное задание. Нельзя ради нового skill session отключать существующую изоляцию бесед. Для нескольких готовых заданий нужен явный порядок в разрешённом канале. Quiet hours следует проверять на сервере: ручные/внешние запуски сценария могут обходить отдельные условия его расписания.

Токен account-linking навыка не является токеном API умного дома. IoT-права запрашиваются отдельным пользовательским согласием. В чат секреты не пересылаются.

## Первый доступный аппаратный тест

В приложении «Дом с Алисой»:
1. Создать сценарий «Проверка Октопорта».
2. Если требуется условие, выбрать «Фраза» и задать «проверка октопорта».
3. В «Тогда» выбрать свою колонку и «Ответить на вопрос или выполнить команду» (в некоторых версиях — «Произвольное действие»).
4. Ввести: **«Спроси Октопорт маркет проверка связи»**.
5. Сохранить и нажать кнопку запуска сценария в приложении. Ничего колонке не говорить.
6. Ожидаемый ответ существующего обработчика: **«Связь с учебным сервером работает. Контрольное число сто двадцать три.»**

Это проверка сценарий→приватный навык на реальном устройстве. Она ещё не проверяет серверный POST, IoT OAuth, job READY или выдачу финансовых данных. Переход и сохранение account-linking контекста необходимо наблюдать на конкретном устройстве; документация не заменяет этот опыт.

Если слышен только общий ответ Алисы, навык не найден или колонка молчит, записать исход дословно. При затруднении сначала отдельный сценарий «Прочитать текст вслух» с безопасной фиксированной фразой позволит отличить проблему запуска колонки от перехода в навык.

Приветствие и справку следует разделить и вынести в речевые настройки: короткое вступление, примеры только реально работающих запросов, отсутствие ручного опроса готовности.
