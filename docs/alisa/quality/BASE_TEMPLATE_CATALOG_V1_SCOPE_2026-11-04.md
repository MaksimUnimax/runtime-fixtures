# Базовые шаблоны v1 — перечень для согласования

04.11.2026. **PROPOSED_FOR_OWNER_AGREEMENT. Не опубликованный исполняемый каталог.** Поручение: сначала согласовать простые переиспользуемые шаблоны, затем реализовать их и строить составные. Никакие записи здесь не являются разрешением на новые API, установкой или приёмкой функции. Рабочая матрица, platform-файлы и реестр статусов тестера не изменялись.

## Вывод и два уточнения

Порядок «простые → составные» правильный и соответствует ADR-005/006. Базовый блок отдаёт типизированные данные с осью времени, областью, валютой и детализацией, а не только текст Алисы. Составной рецепт ссылается на определения блоков, разворачивается общим компилятором и не парсит текст другого отчёта. Одновременно с первыми блоками нужны 2–3 составных контрольных примера: это тест совместимости, а не преждевременная разработка всей сложной аналитики.

Три слоя: декларативный API-контракт → семантические базовые блоки → формулы/группировки/готовые отчёты. Сумма, отношение, группировка, сравнение, ranking и квалифицированный join — общие операции, не обработчики конкретных фраз. ДРР/средняя цена/ценовой порог не относятся к исходным данным. Один блок может возвращать несколько совместимых полей, например количество и сумму заказанных товаров.

| B12 | Расход на рекламу | Основной расход и квалифицированные компоненты финансирования | Ozon/WB; бонусы/предоплата не прибавляются повторно, пополнение не расход |
| B13 | Рекламные исходные счётчики | Показы, клики, рекламно-атрибутированные заказы/суммы с окном атрибуции | Новый блок; не входит в текущие 42 scalar metrics |
| B14 | Активность карточки | Переходы и добавления в корзину | WB есть; не уникальные покупатели по предположению, Ozon требует квалификации |
| B15 | Остатки/резервы/товары в пути | Количество по состоянию/складу/схеме, момент снимка | Общие остатки есть; FBS/резервы в registry — Ozon, transit — WB; present/reserved автоматически не вычитать |
| B16 | Текущие цены предложения | Квалифицированные цены и условия скидки сейчас | Новый блок; не исторический чек и не обещание доступности любой персональной цены по карте |

B06 — параметризованная группа простых статей, не девять Python-обработчиков. Если источник даёт только объединённую логистику, разбивку не выдумывать. «Все услуги» — только контрольный итог. Общая сумма расходов требует непересекающейся классификации, включая рекламу, чтобы не вычесть одну сумму дважды.

B05: по исходным CASE sale_price — сумма строки, seller_price — цена единицы; SUM(sale_price)/SUM(quantity) — взвешенная средняя. Она не доказывает цену каждой единицы многотоварной строки или кассовый чек. B16 — текущая цена, не замена B05.

## Из чего соберём сложные отчёты

- ДРР по заказам = B12/B01 ×100. Период, scope, валюта совпадают; SKU-ДРР запрещён без обеих сторон по SKU.
- Средняя стоимость заказанного товара = сумма B01 / количество B01; это не средний чек без числа заказов.
- Средняя цена реализации = суммы строк B05 / количества B05; не среднее средних.
- Доля выкупленного среди заказанного = B04/B01 одной когорты. Официальный процент выкупа WB имеет другую базу: выкупы/(выкупы+отмены). Названия формул различаются.
- Доля хранения/логистики = выбранные статьи B06 / явная финансовая база B08; не неопределённый «оборот».
- Способы оплаты = B05 + S02 через квалифицированные ключи без размножения строк; unknown/unmatched видимы.
- Топ/динамика = выбранный B01/B02/B05 + общие group/sum/sort/top/series.
- Год к году = один выбранный показатель на два сопоставимых завершённых периода, без смешения осей.
- Ценовые диапазоны = B05 + общий статистический оператор; не причинный вывод.
- Маржинальный результат = выбранная признанная база B05/B08 + B07 − непересекающиеся B06/B12 − S03. Не называть чистой прибылью без всех затрат и налогов.

Составные рецепты могут ссылаться на другие составные. Разворачивается один граф с проверкой циклов/единиц/даты/полноты. Общие совместимые выборки внутри одного задания не дублируются. Переиспользуется ОПРЕДЕЛЕНИЕ шаблона; пересекающиеся куски старых отчётов не склеиваются. Правило владельца exact-only для готового целого задания сохраняется.

## Обязательный контракт и план

Каждый базовый блок: ID/version/meaning; grain/axes/timezone; единицы/валюта; scope; доступные поля/фильтры/разрезы; source/version; completeness/as_of; null/zero/sign; пересечение расходов; права/квоты/TTL; independent synthetic gold; негативные проверки; ссылки на квалификацию. Возвращать минимально достаточную структуру и итог; не создавать бессрочное хранилище raw API.

После согласования: A — переиспользовать имеющиеся источники и оформить простой каталог, не переписывать работающие механизмы. B — первым новым источником B05/SRC-OZON-ACCRUAL; затем исходные CASE цены и дневные количества, retest OZCP-001/002/003/005. C — S02/оплата, B13/рекламная статистика, B16/текущие цены, S03/себестоимость отдельными пакетами. Ozon события исследуются отдельно и не блокируют WB/прочие блоки.

В ходе A/B три сквозных проверки композиции: ДРР, quantity>1 и средняя цена реализации, доля двух расходов. Закончить всю библиотеку сложных отчётов заранее не требуется. Тестер ведёт gold/negative/retest через quality/inbox; платформа не меняется этим исполнителем.

RT-CAT-R01 сейчас offline и поддерживает скалярные slots; template-ID интерфейс произвольных таблиц/SKU/сравнения не появляется от добавления записей. Его расширение — один общий версионированный контракт с приёмкой, не Python под каждый шаблон.
