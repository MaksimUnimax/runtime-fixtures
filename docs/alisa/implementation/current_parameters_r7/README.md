## Реализованные компоненты

`parameter_dependency_catalog.json` — декларативный профиль `unit_economics.ozon.v1`: какие коэффициенты требуются формульным переменным, где искать эффективное значение и в какой области собирать отсутствующее. Сейчас два слота: loss_rate и delivery_mean. Это профиль зависимостей, **не новый зарегистрированный live-шаблон и не полная формула прибыли**. Никаких конкретных чисел магазина/дублирующихся расчётных скриптов здесь нет.

`parameter_dependencies.py` — общий чистый binder. Он получает согласованные чтения текущих значений, формирует значения переменных в памяти и отдельный список недостающих producer-зависимостей. Не вызывает HTTP, модель, очередь, запись или новый сервис.

`parameter_dependency_service.py` — использование binder через прежние проверки владельца/магазина/SKU и owner_data. Каждый переданный SKU proof проверяется ДО объединения одинаковых чтений. Чужой магазин/площадка, отозванная сессия и подделанный повторный proof не могут скрыться за первым корректным потребителем.

## Проверенные правила

- Заполненное число, включая0 и давнюю дату, применяется без сбора. Сохранённый коэффициент за полгода не возвращается сам к годовому.
- Индивидуальный SKU приоритетен, иначе общее значение используется без копирования в отдельные строки.
- При отсутствии общих коэффициентов77SKU дают только2общих producer-зависимости, не154сборки. Разные магазины не объединяются.
- Ожидаемая ревизия первичного заполнения берётся из реальной целевой общей записи, не из ревизии SKU-исключения/INHERIT.
- Дневной период отчёта не попадает в период сбора коэффициента. Год default; разные слоты могут явно задавать свои периоды. Конфликт двух периодов для одной сохраняемой переменной отклоняется, а не разрешается произвольно.
- Подтверждённая короткая история поддерживается существующим контрактом только для default; неподтверждённая или скрыто сокращённая явная история не принимается. Само получение live-доказательства короткой истории здесь не реализуется.
- Первичный план содержит только `fill_missing`, а не `replace_calculated`. Он явно отмечен `execution_authorized=false`: наличие dependency не является допуском к записи. Исполнение должно пройти существующий job/authority.
- Если во время сбора пользователь вручную заполнил число, существующая atomic-fill не перезаписывает его; повторная привязка читает актуальное значение.
- Перед выдачей отчёта проверяются текущие ревизии. Изменение требует повторно прочитать переменные и пересчитать итог по уже полученным данным маркетплейса, а не заново собирать год.
- При поздней повторной привязке сохраняется исходная дата, от которой был запрошен defaultгод. Переход через полночь не сдвигает период задания. Смена определения профиля требует явной обработки совместимости, не незаметной замены графа.

## Без истории чисел

`ResolvedParameters` не сериализуется как JSON целиком. Текущие значения и паспорт доступны только в памяти для формулы/объяснения. `checkpoint()` возвращает технические pins, связи слотов, исходную дату планирования и запросы НОВЫХ producer-заданий. Старые числа, даты их прошлой сборки, исходные числители/знаменатели, SKU-proof и сессия туда не попадают.

Подписи к ответу показывают происхождение/manual/calculated, фактический период и даты текущих использованных значений. Ручному числу не выдумывается дата сбора. Сам binder не сохраняет отчёт или snapshot, не создаёт таблицу истории.

## Граница готовности

Готовы декларативное разрешение зависимостей, типизированные входы формулы, план только отсутствующих значений, authenticated readset и проверка/rebind перед публикацией. Эти части реально проверены вместе с PostgreSQL.

**Ещё не подключено:** вызов resolver из зарегистрированного составного native-шаблона, передача разрешения на начальный fill_missing через существующий job/private RPC и возобновление того же экономического отчёта после готовности зависимостей. Не добавлена/не придумана полная финансовая формула, включая налоги/эквайринг/себестоимость: её источники и семантика должны быть отдельной квалифицированной частью шаблона. Это не завершение всей юнит-экономики.

Установленные88шаблонов, их каталоги, pin, схемы авторизации, флаги, БД и код liveне менялись. Нативный guard PARAMETER_DEPENDENCY_BINDING_REQUIRED пока не снят. Нет миграций, новых маршрутов или действий за пользователя.
