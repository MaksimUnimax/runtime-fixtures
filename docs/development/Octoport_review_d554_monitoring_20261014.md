# Исправление замечаний ревью d5549e9e: мониторинг

Основание: отчёт по `d5549e9e52e84fa887c8ded1e8e423faff23f85e`, замечания 6, 7, 8; прямая передача владельцем работы с ревью отдельному исполнителю 14.10.2026 04:58 МСК. База изменения: `0374012512cf9cc7640a0583a107a3f6a37dd9d4`.

## Изменение поведения

- При отказе чтения/сохранения результата мониторинга обе ветки фоновой задачи обработаны. Периодический tick тоже перехватывает rejection. Ожидающий caller получает отказ; диагностический callback получает только безопасные code/lane. Чужая durable lease не снимается, успех не выдумывается, runner повторно ради восстановления не выполняется.
- Telegram подтверждает прогресс всей raw-страницы, включая неподдерживаемые updates. Сервис применяет nextOffset после обработанного пакета, сохраняя монотонность и прежний per-update запрет повторного выполнения при неоднозначном handler failure. Пустой mapped список больше не блокирует следующие команды; авторизация сохранена.
- Семейный retry budget применяется один раз за законченный acquisition pass. 13 документов WB получают те же два ограниченных retry-прохода, что один документ. Частичный успех не сбрасывает failure episode. HTTP 429 сохраняет один повтор и максимальный Retry-After с прежним ограничением; authority blocker не создаёт автоматический повтор.
