# Работа человека и рабочих диалогов

При переносе используется существующий START соответствующей роли; постоянный PROMPT остаётся договором на проект.

Каждый активный A/B/C сначала восстанавливает checkpoint, исход последнего вызова, процессы и Git/WIP. Затем продолжает разрешённый незавершённый результат; по его проверенному окончании выбирает следующий доступный результат общего SPEC/PLAN. Ожидание ручного тестирования пакета не останавливает независимую разработку. Нет обязательных queue-add, claim, регистрации и программной приёмки.

Controller лично проверяет причины простоя и устраняет доступные в своём scope; после исправления проверяет исходную границу и фактическое продвижение. Неактивный диалог не исполняется. Нового серверного исполнителя нет.

OPERATOR — отдельный диалог для выдачи готовых проверенных пакетов и приёма замечаний. Текущий Тестер R3 продолжает свой scope; его Chromium, профиль и активные правки сохраняются.

Правила: [WORK_METHOD.md](WORK_METHOD.md), [PROTOCOL.md](PROTOCOL.md), [OPERATOR_TESTING_POLICY.md](OPERATOR_TESTING_POLICY.md). WIP, один автор, история, права live, адресные STOP и продуктовые проверки сохраняются.
