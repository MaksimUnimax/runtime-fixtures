# Жизненный цикл временных рабочих копий Octoport

Основание: прямое поручение владельца 2026-10-01 — не оставлять ненужные копии после задач и review. Действует для новых временных копий A/B/C и контроллера. Не меняет STOP, независимое review, exact-head CI, безопасность и ownership.
Это операционное правило для исполнителей, не установленный автоматический запрет или daemon.

## До создания
1. Зафиксировать владельца, task/review ID, назначение, exact base/HEAD, потребителя и условие окончания временной копии.
2. Не создавать полный checkout ради повторного чтения документов, если достаточно доступного read-only источника. Для отдельного review сохраняется независимый контекст; повторно использовать уже освобождённую чистую копию допустимо только с проверкой exact HEAD и отсутствия чужого потребителя.
3. Проверить свободный диск и ожидаемый размер. Учесть жёсткие ссылки: сумма отдельных du не равна освобождаемым блокам. Не устанавливать зависимости в docs-only review без конкретной необходимости.

## После завершения задачи или review
4. Автор обязан завершить жизненный цикл своей временной копии на безопасной границе, а не оставлять её бессрочно. Сохранить exact commit/tree и ветку либо сохранённый локальный ref с явно сохранённым сроком удержания либо remote ref с подтверждённым удержанием; повторно сверить точные OID перед удалением. Одна текущая ссылка на изменяемую remote branch недостаточна.
5. Инвентаризировать tracked, untracked и ignored. Уникальные результаты, патчи, тестовые доказательства и нужные входы сохранить вне удаляемого дерева в разрешённом постоянном месте, сохранить прежние ограничения доступа, сверить хеши и фактическое содержимое/readback, обновить ссылки потребителей. Наличие ветки не сохраняет untracked/ignored файлы.
6. Перед созданием/повторным использованием копии и перед её очисткой использовать общий существующий controllers/coordination.lock: под ним запретить запуск новых потребителей точного target на время заключительной проверки и удаления. Если все потребители не соблюдают эту границу или исключение гонки не доказано, KEEP. Канонизировать зарегистрированный путь и непосредственно перед удалением повторно проверить: Git clean; нет незавершённых Git-операций и worktree lock; нет активного процесса cwd/open fd/mmap, job, review, другой задачи или ожидающего потребителя этой копии. При неполной проверке не удалять.
7. Удалять только собственную зарегистрированную временную копию завершённой работы штатным git worktree remove без force; при отказе остановиться и сохранить копию. Если мешают ignored восстановимые зависимости/сборки, сначала проверить и удалить только их точные пути в этой копии; неизвестное содержимое не трогать. Не применять общую рекурсивную очистку родительского каталога.
8. Не удалять ветки/refs, канонические рабочие копии A/B/C, профили, БД/тома, credentials, immutable releases, архивы выдачи, intake, логи и evidence. Если внутри временного дерева присутствуют такие защищённые данные, вся копия получает KEEP; обычная процедура выше не разрешает их удаление даже после копирования. Это не относится к отслеживаемым исходникам, которые лишь описывают форматы профилей/логов/БД. Канонические копии определять по точным зарегистрированным путям, а не по букве роли. Не следовать symlink за границы копии. Уникальные либо невосстановимые данные требуют отдельного подтверждения владельца.
9. BLOCKED/WIP, неизвестная зависимость, активный потребитель или dirty — KEEP с причиной, ответственным и следующим шагом. Возраст, размер, PASS или DONE сами по себе не доказывают ненужность.
10. Сохранить квитанцию: точные пути, task/review, HEAD/ref, проверки потребителей и сохранённых артефактов, удалено/оставлено, свободное место до/после. Проверить отсутствие удалённой копии в git worktree list и сохранность refs/evidence. Учитывать параллельную запись при оценке эффекта.
11. Если копия нужна дальше, назвать конкретного потребителя и условие освобождения. Новый раунд review не освобождает предыдущую копию автоматически; после завершения её потребителей применить пункты 4–10.

## Ранее накопленные копии
12. Для исторических копий сначала отдельный точный список, объём с учётом hardlinks, сохранность refs и уникальных файлов, завершение потребителей; затем отдельное подтверждение владельца на этот перечень. Это правило не разрешает массовую очистку накопленных worktrees, Docker volumes или кэшей.
13. Подтверждённое ранее удаление десяти node_modules не является разрешением удалить их родительские worktrees или любые другие файлы.
