## Изменение продукта

- Вместо безусловного `roles[0]` пользователь явно выбирает роль для grant/revoke. Доступны четыре роли действующего HTTP API.
- Нельзя назначить уже имеющуюся роль или снять отсутствующую. Последнее слово остаётся за серверными проверками.
- Подтверждение создания показывает user ID и initial role; grant/revoke — principal и роль. Изменение выбранной цели до отправки сбрасывает прежние reason/confirmation.
- `creating`/`busy` сохраняются в стабильном родителе. Пока POST не завершён, выбор цели и соседние операции заблокированы; optional `Mutation.onBusyChange` и проверка `disabled` сохраняют это правило и на Confirm/submit.
- Передаётся исходная `expectedRevision`. Stale/conflict не воспроизводят операцию автоматически; unauthorized/forbidden обновляют доступ. Backend auth, CSRF, last-owner protection и транзакции не менялись.
- Отдельная конфигурация UI-теста поднимает только свою админку: без API harness, Portal, global DB setup/reset, общей БД или серверного профиля R3. Общая конфигурация server e2e не изменялась.
