# Подключение Тестера-2 к существующему порядку

Основание — прямое поручение владельца 29.10.2026. Действующий договор новой роли: [PROMPT_TESTER_2.md](PROMPT_TESTER_2.md); запуск: [START_TESTER_2.md](START_TESTER_2.md). Это самостоятельное адресное дополнение. Старые ограничения «единственный тестер» и «не создавать новую роль» перекрываются только для разрешённого TESTER_2.

## Что уже разрешено

Параллельное доведение одного свободного утверждённого блока Тестером-2 с полной ответственностью за свой результат. OPERATOR остаётся Тестером-1. Существующие задачи, авторы, права live/DB, независимое review и CI сохраняются. Роль постоянная, исполнение временное при доступном ресурсе Astra; пауза, возобновление и передача OPERATOR описаны в договоре.

## Общие документы: сохраняемый автор

На момент подключения PR272 `95b72c9c9d2d1f4479682f997369d64f9632bfa5` содержит ещё не интегрированный комплект общих правил, включая отмену ожидания ownerAccepted. Его 17 файлов не перезаписываются новым автором. Этот документ содержит точный добавочный материал для их существующего автора либо согласованного преемника. Не считать эти входные ссылки уже опубликованными в main до обычной интеграции и readback.

### WORK_METHOD.md и PROMPT_OPERATOR.md

OPERATOR — основной Тестер-1; TESTER_2 — дополнительный тестер для отдельного свободного блока. Каждый ведёт один блок, сохраняются технические зависимости и независимость тестовых сред. После технического завершения переходить дальше без ожидания ручной приёмки. Тестер-1 после собственного блока может принять безопасно сохранённую работу Тестера-2 по разделу передачи PROMPT_TESTER_2.md. Не перезаписывать его текущую задачу.

### PROTOCOL.md и OWNER_BLOCK_TESTER_WORKFLOW.md

Для TESTER_2 используется собственный checkpoint, а не чужие поля current_personal_implementation. При паузе сохранять код, результаты, незавершённые операции и следующий шаг. Принятие OPERATOR — атомарное обновление владельца исходной записи после проверки отсутствия второй активной записи/операции. Статус паузы не является готовностью продукта. `ownerAccepted` не возвращать как технический gate.

### OWNERSHIP.json

Добавить TESTER_2 с отдельной фактической рабочей копией/веткой из его checkpoint. Разрешённый scope определяется выбранным блоком; постоянной монополии на admin/server/extension нет. Исключения `apps/site/**`, `tests/regression/imported/**`, чужой активный код и отдельные live/DB полномочия сохраняются. Это описание роли, не новый программный допуск.

### Серверные копии и PROMPT_DOT_ASSISTANT.md

Сохранить соответствующие более новые серверные указания. Добавить ссылку на договор, checkpoint и отдельный scope Тестера-2; не создавать расписание и не менять модели других исполнителей. Текущий thread ID получить из фактического диалога, не выдумывать. Не утверждать, что dot получил документ, до подтверждения.

## Начальный самостоятельный участок

Для воспроизводимой изолированной проверки добавлена собственная `tests/e2e/server/admin-principal-roles.playwright.config.ts`. Она запускает только свою админку и browser UI tests с синтетическим API, без reset БД или запуска API/portal. Общая конфигурация server e2e не изменяется.

OWNER_BLOCK B14 «Админка: пользователи, роли и журнал»; первый результат — выбор административных ролей, принимаемых действующим HTTP API, и проверка корректного grant/revoke при текущей ревизии. Изменяемые продуктовые пути: `apps/admin/app/admin-ui.tsx` (Principals и узкий optional busy/disabled-контракт Mutation для защиты этих форм), собственный helper/test `apps/admin/lib/admin-principal-roles.*`, `tests/e2e/server/admin-principal-roles.spec.ts`.
