# Приоритетные задания

Канонический рабочий путь: /root/octoport-control/controller-notices/PRIORITY_TASKS.md.
Назначение: приоритетные задания dot действующему Контроллеру по результатам собственных аудитов dot; получение и фактический ответ Контроллера записываются здесь.
Прежние обязанности Контроллера не заменяются. Это рабочий документ, не программная очередь, не допуск к работе и не восстановление отменённого реестра ошибок.
Состояние документа: версия 1; создан 15.10.2026. Пустой список не доказывает отсутствие проектных проблем.
GitHub-копия служит опубликованным шаблоном/копией порядка; текущее исполнение определяется серверным документом. Копии нельзя редактировать как два независимых источника состояния.

## Порядок
1. dot проверяет актуальность проблемы, уже открытые задания, действующего автора и существующие результаты. Затем добавляет приоритетное задание с уникальным постоянным ID и версией. Повтор той же открытой проблемы дополняет её пункт, а не создаёт дубль.
2. Контроллер читает документ при запуске/возобновлении, на безопасных границах этапов, перед выбором следующей задачи и перед итогом. Приоритет: сначала действующие адресные команды владельца и безопасность, затем доступные срочные задания dot, затем прежняя основная работа.
3. Контроллер подтверждает получение конкретной версии. Перед действием проверяет исход последней операции и одного автора. Получение не означает выполнение; статус и таймер не доказывают прогресс.
4. После исполнения Контроллер заполняет результат и evidence в том же пункте. dot проверяет результат в отдельном поле. До проверки dot Контроллер продолжает независимую разрешённую работу.
5. Если критерии не выполнены, dot возвращает тот же пункт на доработку с причиной; выполненные операции не повторяются вслепую. Если закрытая проблема действительно возникла снова, новое задание ссылается на прежний ID и новое доказательство.
6. Изменение требований получает новую версию; Контроллер подтверждает её перед действиями по новым требованиям. Прежний результат остаётся связан со своей версией, нельзя незаметно подменить предмет приёмки.
7. После исполнения или фиксации конкретного внешнего блока Контроллер возвращается к сохранённому разрешённому этапу основной работы. Невыполненный остаток остаётся открытым.
8. Явные запреты, STOP, чужой WIP, Тестер/R3, live/DB/security и обязательные подтверждения сохраняются. Задание dot не расширяет полномочий.

## Формат одного пункта
- ID; версия задания; создано UTC; последнее содержательное обновление UTC; приоритет; адресат.
- Постановка dot: проблема, первичные данные, причина либо UNKNOWN и недостающий источник, требуемое действие, scope/ограничения, критерии завершения, зависимости, ссылка на исходное поручение при наличии.
- Точка возврата: существующий checkpoint/этап основной работы и ближайший незавершённый разрешённый шаг.
- Ответ Контроллера: принятая версия; ПРОЧИТАНО / В РАБОТЕ / БЛОК / ВЫПОЛНЕНО; время; что сделано; точные результаты; ссылки на evidence; исход повторной проверки; остаток.
- Для БЛОК: точная операция, полный первичный ответ/аргументы/время без секретов, установленная причина либо UNKNOWN, выполненная диагностика, ответственный, допустимое следующее действие и условие возврата.
- Проверка dot: проверенная версия результата; ПРОВЕРЕНО / ДОРАБОТКА; доказательства и причина вердикта.
- ВЫПОЛНЕНО не означает PRODUCTION, если критерий задания не включал соответствующую принятую проверку. Запрос на review не равен verdict.

## Целостность записи
dot изменяет постановку и своё поле проверки; Контроллер — свой ответ и результат. Каждый сохраняет чужие поля.
Используется предусмотренная PROTOCOL короткая защищённая запись: под защитой перечитать актуальную версию, проверить ожидаемый исходный блок, изменить только свой блок, записать и освободить защиту; затем readback. Защиту не держать во время тестов, сети и ожидания.
Не перезаписывать весь документ устаревшей копией. При конфликте версии перечитать и согласовать изменения. Одного readback недостаточно для доказательства защиты от гонки; если защищённая запись недоступна, не выполнять небезопасную полную перезапись и сохранить точный остаток в существующем checkpoint.
Ни отметка «В РАБОТЕ», ни истечение времени не разрешают второму автору перехватить задачу; сначала проверяется фактический исход.

## Хранение 7 суток
При штатном обновлении удалить из этого документа историю, чьи собственные timestamps старше текущего UTC минус 7 суток. Проверка старой записи не обновляет дату её результата и не продлевает хранение истории.
Для старого незакрытого задания сначала оставить компактный актуальный остаток с тем же ID, исходной датой, принятой версией требований, фактическим состоянием, ответственным, критерием завершения и ссылками на первичные результаты; старую подробную историю убрать. Возраст задания не отменяет невыполненную работу.
Для завершённого старого задания удалить его историю из этого документа; результаты остаются в существующих продуктовых checkpoint/evidence/Git. Перед новым назначением сверить их, чтобы не повторить завершённое. Нового архива/реестра и фоновой очистки не создавать.
Удаление здесь не распространяется на исходники, WIP, evidence и другие документы. Сохранять обычную восстановимость изменений; необратимое удаление вне документа не поручено.
