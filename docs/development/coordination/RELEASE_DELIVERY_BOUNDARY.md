# Стабильная граница выдачи и непрерываемая приёмка main

Основание: ORG-001/002/003 и аудит L2 2026-09-29. Контроллер вправе исправлять организацию в согласованном roadmap; C сохраняет единоличную интеграцию и разрешённые live операции.

## Две отдельные проверки
C00 отвечает на вопрос о состоянии текущего remote main. Выдача отвечает на вопрос о конкретном принятом исходнике, неизменном пакете и целевом окружении.
Для выдачи C записывает точный source/tree/package hash, operator/deployment identity и IDs всех пяти успешных push-проверок именно выбранного main SHA.
Новое изменение сайта/отчёта не перепривязывает уже принятый пакет автоматически к новому main. Не переименовывать отменённый/неполный CI в PASS и не переносить branch PASS на main.
Перед применением C читает последующие изменения и текущие значимые регрессии. Изменение кода, правил безопасности, инфраструктуры или входов, затрагивающее выбранный путь, требует конкретной оценки и необходимых новых проверок. UNKNOWN блокирует только зависимое действие.
Обнаруженная опасная регрессия нужного контракта не скрывается ссылкой на старый зелёный SHA. Live bootstrap/совместимость/права проверяются в целевом окружении по прежним правилам.

## Жизненный цикл CI
Все существующие jobs, triggers, required names и проверки сохраняются.
На main concurrency identity включает точный commit SHA: более новый push не отменяет начатую/ожидающую приёмку другого принятого commit. Повтор одного SHA может заменить предыдущую попытку; gate всегда читает последний результат.
В рабочих ветках/PR сохраняется отмена устаревшей попытки по ref. Coordination workflow не имеет cancellation group и не требует правки.
Основание GitHub: https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency
Это устраняет конкретный механизм потери приёмки. Выбор suite по области и безопасное переиспользование результатов — отдельные незакрытые ORG-001/002; эта правка не обещает сокращения количества всех запусков.
Применение подтверждается интеграцией C и настоящим main push: следующий push другого SHA не отменяет предыдущий из-за общей группы. До этого статус IMPLEMENTED_NOT_APPLIED.

## Независимая работа и завершение аудита
Порядок интеграции C не является запретом B/A писать уже согласованную независимую часть. Исходник будущей миграции и disposable proof отделены от текущего выпуска и live DB.
Контроллер в конце каждого аудита под коротким controllers/coordination.lock обновляет свой last_audit/last_observed_main и дополняет decisions.jsonl, затем читает обратно. Поздний STOP и операционные задачи чужого участника не менять.
Отклонение одного широкого вызова не доказывает запрета всего интерфейса. Сначала установить точный отказ; действительный safety reject не обходить. Разрешённые ограниченные операции выполнять штатным интерфейсом.
Перед ответом владельцу сопоставить отчёт с общей базой: организация, новые ошибки, реально исправленное, повторы с причинами, оставшееся. Проверять смысл и evidence, а не наличие пяти заголовков.
