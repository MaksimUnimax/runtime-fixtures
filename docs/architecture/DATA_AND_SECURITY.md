# Данные, хранение и безопасность

## Размещение

|---|---|---|---|
| Ключи Ozon/WB | По accountId/storeId/credentialRevision | Нет постоянного хранения; только согласованный шифрованный relay | Запрещена |
| Account/device sessions | Привилегированное хранилище; доступны только своему аккаунту | Хеши/сессии по принятой auth-модели | Запрещена |

## TTL и очистка

Бизнес-payload получает createdAt и expiresAt=createdAt+1 час при сохранении. Повтор доставки не продлевает срок.
Час применяется ко всем копиям payload: IndexedDB, chunks, промежуточным файлам и локальным очередям. Удаление blob освобождает связанные metadata/URL.
Просроченное содержимое не читается даже если физическая очистка ещё не выполнилась. Браузер может спать: фактическое удаление происходит на следующем доступном пробуждении/старте, а не гарантированно по настенным часам.
При нехватке места сообщать локальную ошибку, не выдавать несуществующую ссылку и не повторять API скрыто.

Opaque provider references имеют собственные документированные сроки; это не повод хранить весь отчёт дольше.
Краткий query cache хранит только явно разрешённые provider policy данные и не превышает час для бизнес-payload. 60 секунд ограничения запроса и один час файлового буфера — разные величины.
Маркеры завершённых действий могут жить дольше часа в ограниченном объёме без содержимого ответа; при удалении старых маркеров baseline должен исключать повторное исполнение старой истории.

## Защита локальных ключей

Ключи не помещаются в storage.sync, page localStorage, DOM, URL, content-script сообщения, export диагностики или общую телеметрию.
Worker проверяет отправителя, tab/origin/conversation/account и generation на входе и после await. Недоверенная страница не выбирает произвольный storeId для запроса.
Шифрование локального хранилища ключом, лежащим рядом, не объявляется защитой от владельца профиля/вредоносного ПО. Главные границы: browser isolation, минимальные разрешения и недоступность странице.
При выходе секреты сохраняются только по выбору пользователя; фоновые исполнение и перенос этого аккаунта прекращаются. Следующий пользователь расширения не видит оставшиеся магазины.

## Экспорт и relay

Экспорт: версия формата, список магазинов, типы credentials, контроль целостности; защищён паролем через стандартную библиотечную криптографию/проверенные WebCrypto primitives, без собственной криптосхемы.
Формат включает соль/KDF параметры/nonce/authentication tag. Один checksum не обеспечивает секретность.
Пароль вводится отдельно и не отправляется серверу. Импорт лимитирует размер/сложность, отвергает неизвестные поля с исполняемым смыслом, проверяет целостность до записи.
Старые форматы принимаются только явно описанными адаптерами. Неизвестный формат не конвертируется эвристически.

Relay: получатель создаёт краткоживущую криптографическую пару, запрос связывается с accountId/recipientDeviceId/requestId/expiry. Источник отвечает только тому же авторизованному аккаунту, после зарегистрированного согласия получателя.
Payload шифруется для получателя, не расшифровывается сервером, не попадает в БД, durable queue, логи, tracing, crash dump или резервные копии. Передача может использовать короткий активный канал и ограниченную память relay.
Запрос на перенос и безопасные статусы могут сохраняться без ключей. Падение relay теряет пакет; повтор возможен только пока активен источник и согласие.
Серверный транспорт с шифрованным payload не считается «ключи сохранены на сервере», но пользователь прямо уведомляется о прохождении через сервер. Подробности потока — [SYNC](SYNC.md).

## Авторизация и конфигурация

Подписанный bootstrap проверяется вместе с точной схемой, контекстом, сроком и локальным allowlist.
Удалённый профиль выбирает встроенные стратегии и ограниченные параметры; не добавляет JS, произвольные URL, заголовки или новые права.
Команда разрешена пересечением локальной возможности, доступа аккаунта, прав магазина и применимой политики.
Онлайн-отзыв не подменяется старым разрешающим cache. При настоящей недоступности используется последний допустимый подписанный snapshot до offlineGraceUntil без локального продления.

## Логи и retention сервера

Схемы событий имеют allowlist; произвольное поле body/payload запрещено. Уровень debug не открывает секреты.
Технические значения по умолчанию: сырые безопасные диагностические события 14 дней; административный audit 90 дней; агрегаты беты 90 дней, затем пересмотр по фактической потребности.
Это проектная политика, не утверждение юридической достаточности. Удаление аккаунта удаляет/обезличивает связанные данные по отдельной проверяемой процедуре; резервные копии доживают свой ограниченный цикл и не применяются как действующий каталог.
Секреты production находятся в окружении/secret store выбранного хостинга, не в Git и не в документации.
