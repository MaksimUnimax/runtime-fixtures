## 1. P2 — недоступный первый DNS-адрес блокирует доступный официальный источник

Место: [`tooling/api-watch/src/acquire.ts:132–133`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/tooling/api-watch/src/acquire.ts#L132), связанный [`Agent lookup:162–170`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/tooling/api-watch/src/acquire.ts#L162).

### Причина и последствие

`selectVerifiedOfficialAddress` проверяет все DNS-ответы, затем возвращает только `values[0]`. Новый `HttpsAgent` отключает `autoSelectFamily`, а lookup отдаёт лишь этот один адрес даже при `options.all`. Если первый разрешённый адрес не отвечает либо его семейство недоступно из текущей сети, доступные разрешённые альтернативы не используются. Acquisition возвращает `SOURCE_TEMPORARILY_UNAVAILABLE`, хотя тот же документ доступен через следующий проверенный адрес. Повтор с тем же порядком DNS-ответов снова выбирает первый адрес.

Выбор одного адреса введён текущей дельтой. Проверка публичности адресов сама по себе не требует отказа от перехода к другим адресам из того же проверенного DNS-набора.

### Подтверждение

Независимая проверка вызывает настоящий `acquireOfficialSource` без `input.fetcher`. DNS-резолвер в тесте возвращает два синтетических публичных ответа; собственный транспортный адаптер переводит соединения исключительно на свежий локальный TLS-сервер. Первый IPv6-путь не имеет слушателя, второй IPv4-путь работает. Использованы настоящий Node HTTPS, Agent, socket lifecycle и TLS-проверка исходного hostname с тестовым CA. Соединений с внешними адресами нет.

```json
{"kind":"SOURCE_TEMPORARILY_UNAVAILABLE","validatedAddressCount":2,"attemptedCount":1}
```

Регрессия, ожидающая получение документа через доступную альтернативу, падает. Контроль с тем же порядком адресов и стандартным Node family fallback проходит. Также проходят обычная загрузка и отрицательная проверка сертификата другого hostname. Отдельный транспортный мок повторяет результат выбора одного адреса.

### Рекомендация

Сохранять проверенный набор адресов и пробовать его доступные элементы в пределах общего deadline. Каждое соединение должно использовать адрес из этого набора, сохраняя проверку сертификата исходного hostname и отдельную проверку каждого redirect hop. Одного включения `autoSelectFamily` недостаточно, пока lookup возвращает единственный адрес. Добавить регрессию первого недоступного адреса с доступной альтернативой.

## 2. P2 — ранний отказ acquisition оставляет HTTPS-соединение без deadline

Место: [`tooling/api-watch/src/acquire.ts:193–210`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/tooling/api-watch/src/acquire.ts#L193), связанная [`ветка 429/5xx:497–510`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/tooling/api-watch/src/acquire.ts#L497).

### Причина и последствие

Новый transport создаёт отдельный Agent для каждого запроса и уничтожает его при `incoming.close` либо ошибке request. Ответ передаётся через `Readable.toWeb(incoming)`. После заголовков `429`/`5xx` acquisition снимает общий таймер и возвращает failure, не отменяя body и не abort-ая запрос.

Если сервер оставляет body незавершённым, `incoming.close` не наступает, а таймер уже снят. Запрос логически завершён, но его socket/Agent остаётся открыт за пределами установленного deadline. Повторные проходы могут накапливать такие соединения и расходовать ресурсы процесса. Аналогичные ранние выходы без освобождения body есть у access-control статусов и отклонённых redirect; непосредственно воспроизведена ветка `429`.

Ветки раннего возврата существовали и до этой дельты. Это вновь подтверждённое замечание к их совместной работе с новым transport; отчёт не приписывает появление самой ветки `429` последнему коммиту.

### Подтверждение

Свежий собственный TLS-сервер отправляет заголовки `429` и держит response открытым. Вызов настоящего acquisition возвращается; спустя 100 мс после возврата при deadline 50 мс соединение остаётся открытым с обеих сторон:

```json
{"kind":"SOURCE_TEMPORARILY_UNAVAILABLE","deadlineMs":50,"waitedAfterResultMs":100,"openClientSockets":1,"openServerSockets":1,"agentDestroyCalls":0}
```

Регрессия, ожидающая освобождения соединения, падает. Контрольный незавершённый ответ `200` корректно прерывается общим deadline и закрывает socket. Транспортный мок отдельно подтверждает отсутствие cancel/destroy после раннего `429`. Каждый тест принудительно закрывает только собственные Agent/socket/server после измерения.

### Рекомендация

Гарантировать освобождение текущего body/request на каждом раннем выходе, включая ошибку redirect, отказ по статусу и отказ по объявленному размеру. Снимать deadline после освобождения транспорта. Добавить проверки незавершённых ответов с ранним отказом и обычного успешного чтения.

PostgreSQL [`markSourceSeen:199–222`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/packages/server/db/src/credential-transfer-repository.ts#L199) возвращает запрос в `SOURCE_SEEN`; [`markDelivered:242–249`](https://github.com/MaksimUnimax/runtime-fixtures/blob/2d640ce704ed16b8ed6070bfb4eca5af854d8365/packages/server/db/src/credential-transfer-repository.ts#L242) из этого состояния пакет не выдаёт.

Повторная проверка использует заново собранный worker, настоящие decrypt/import/client handlers и PostgreSQL service/repository. Очищается только память собственного relay и создаётся новый service с той же базой:

```json
{"beforePhase":"IMPORTED_PENDING_ACK","beforeResult":"IMPORTED","afterRecordCount":0,"popupImportState":"PENDING","serverState":"DELIVERED_TO_RECIPIENT","storesUnchanged":true}
```

Удаляется recipient record с сохранённым результатом, а UI теряет факт уже выполненного импорта. Импортированные ключи магазинов остаются на месте; их удаление или повторный импорт этим сценарием не установлены. Контроль потерянного ответа после настоящего ACK commit проходит: readback `COMPLETED` сохраняет `ACKED_RESULT` и показывает `IMPORTED`.

Рекомендация: сохранять durable import result при восстанавливаемой потере relay и отделять её от терминального replay. Предусмотреть восстановление с сохранением привязок account/device/request/packet и запрета повторного импорта; не объявлять успешный ACK без достаточного подтверждения.
