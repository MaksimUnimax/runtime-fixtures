# Octoport Harness: API, матрица и плагины

Рабочий адрес: **https://alisa.octoport.ru/harness/**.

Harness `0.2.2-rc.1` использует действующий серверный DeepSeek API key. Вход выполняется через существующий аккаунт Octoport; у каждого пользователя свои чаты, доступные магазины и настройки плагинов. Фронтенд следует установленному Harness: его дизайн-токены, боковая панель 280 px, колонка переписки 748 px, поле ввода, светлая и тёмная темы. Это интерфейс над авторизованным BFF, а не публикация общего native Host-owner UI.

## Исполнение запроса

```text
чат → постоянно включённый диспетчер плагинов
    → локальная команда установленного плагина
    или
    → matrix → исходный DeepSeek selector → шаблон → API магазина
             → проверенный обработчик → короткий ответ + подробности → история Harness
```

Фильтр, каталог из 90 шаблонов, валидация параметров, кэширование и расчёты используют проверенное ядро Алисы. Входной selector сохраняет свой Chat Completions transport и стабильный префикс. Перед ним нет отдельного LLM-диспетчера. После обработчика нет финального model answer: готовый текст поступает в Harness напрямую.

Голосовой канал Алисы, браузерная диктовка, синтез речи и голосовое «Скажите: дальше» в интерфейсе Harness не используются. По умолчанию показан короткий результат с периодом и необходимой оговоркой; детали и защищённая ссылка на полный отчёт выдаются отдельно. Сводная ДРР считается из сумм исходных величин, изменение долей сохраняет процентные пункты, неизвестная стоимость не превращается в ноль.

## Плагины

| ID | Назначение | Область |
| --- | --- | --- |
| `plugin-manager` | Список, включение и вызов зарегистрированных возможностей | Всегда включён |
| `matrix` | Матрица и обработчики магазинов | По умолчанию включён; настройка аккаунта или чата |
| `dev-meter` | Токены и оценка рублей по фактическим квитанциям | Только явно разрешённые разработчики |

Примеры команд:

```text
покажи плагины
включи плагин матрица
отключи плагин matrix
включи счётчик токенов
покажи расход
/plugins account enable dev-meter
/plugin dev-meter requests {"limit":20}
```

Команда без `account` меняет текущий чат. Установка нового кода — отдельная операция выпуска. Модуль добавляется в `engine/plugins/installed/<id>/` с манифестом, псевдонимами, действиями и хешем кода; диспетчер обнаруживает его автоматически. Код диспетчера для каждого плагина не переписывается. Плагины реализованы через настоящий Cordis Service и `ctx.plugin()` установленного Harness. Общий native profile manager не выставлен пользователям, потому что его операции меняют профиль всех сессий.

Полный контракт, пример модуля и границы расширения: [engine/PLUGINS.md](engine/PLUGINS.md). Схема пользователей, магазинов и разрешений: [MULTIUSER.md](MULTIUSER.md).

## Счётчик разработки

На сервере проверяется точная пара customer/tenant из текущей сессии по закрытому allowlist. Роль владельца обычного клиентского аккаунта не даёт доступ к счётчику. Разрешённый пользователь видит расход под ответом и в разделе «Расход запросов»; остальные не получают служебные расходы через API или историю.

В квитанции сохраняются входные/выходные токены, cache hit/miss, число вызовов, повторные попытки, тариф и курс на момент отправки. Рубли являются оценкой, а не банковским списанием. Новые запросы используют датированный снимок курса из `backend/pricing.json`; прошлые квитанции не переоцениваются. Если usage или цена неизвестны, итог остаётся неизвестным, а известная часть показывается отдельно. Локальные команды диспетчера имеют нулевой расход модели.

## Компоненты

| Каталог | Назначение |
| --- | --- |
| `engine/` | Настоящий Harness AgentLoop, Cordis-плагины, scoped preferences, история и идемпотентность |
| `backend/` | Авторизация, привязка запроса к владельцу, матрица и обработчики, разрешения разработчика, квитанции расхода |
| `static/` | Интерфейс по референсу Harness, управление плагинами, короткие ответы и счётчик |
| `deploy/` | Службы, nginx и защита от повторного исполнения через native очередь Алисы |
| `tests/` | Синтетические браузерные проверки и проверки расчётного вывода |

Engine слушает `127.0.0.1:18132`, gateway — `127.0.0.1:18131`. Внешний nginx публикует только `/harness/`. Сервисы Алисы продолжают использовать свою очередь.

## Ключ и авторизация

DeepSeek API key читается через systemd `LoadCredential` из существующего файла `/var/lib/alice-lab/secrets/deepseek.key`; значение не попадает в Git, браузер, диалоги или отчёты. Пользователь не вводит API key. Штатная `__Host-alisa_session` проверяется при каждом запросе; ключ модели не заменяет авторизацию.

`/harness/login` ведёт на штатный вход и возвращает в фиксированный адрес чата через обычный `/app` callback. Маркер возврата не предоставляет доступ. Browser payload, prompt и plugin alias не могут задать чужой actor/tenant или получить доступ к чужим магазинам.

Для расчётов с коэффициентами создаются настоящие WEB Query metadata receipts с штатным подтверждением пользователя. Marker `harness_runtime_v1` отделяет их от обычной истории и очереди Алисы. Проверка owner, TTL и principal сохраняется; схема БД не меняется. Этот guard нужен и при откате, пока существуют живые Harness receipts.

`request_id` защищает от повторного исполнения после двойного клика и потери ответа. Неизвестный исход не запускает автоматический повтор. Незавершённые jobs после перезапуска становятся interrupted; новая явная реплика получает новый идентификатор. Готовая история доступна после нового входа. Смена настроек плагина влияет на будущие запросы; уже принятый запрос хранит свой снимок включённых возможностей.

## Проверки и эксплуатация

Тесты engine выполняются на установленном точном Harness без пропусков. Python-проверки используют проверенное ядро Алисы. Браузерные проверки работают с синтетическими аккаунтами и отдельным Chromium, без действующих browser profiles. Они проверяют двойную отправку, смену чата и выход во время ответа, детали, состояние плагинов, доступ к счётчику и мобильную компоновку.

Fixture pipeline не подтверждает реальные данные магазина. Итоги конкретной установки, commit и хеши фиксируются в [DEPLOYMENT.md](DEPLOYMENT.md). Порядок обновления и отката — [deploy/OPERATIONS.md](deploy/OPERATIONS.md). Исходные платформенные пути фиксируются на проверенном release; изменение ключа или systemd credential требует перезапуска соответствующего Harness сервиса.
