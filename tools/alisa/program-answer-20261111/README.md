# Ответы через официальный Harness по порогу размера

Версия `alisa-program-answer-r1-20261111`, поверх фактически работающей `alisa-query-insights-r1-20261110`.

В `model_program.MIN_CHARACTERS` задан единственный порог:10000 символов полного исходного JSON до упаковки. Ниже используется прежний прямой ответ модели; от порога — полный неизменяемый файл и официальный DeepSeek Harness0.2.1rc2. Маршрут и промпты фиксируются в состоянии задания перед первым итоговым обращением. Шаблоны, поля показателей и формулы сервер для маршрутизации не разбирает. Содержание выбранного шаблона передаётся вместе с полными данными.

Модель сама читает файл, пишет и исправляет программу через run_code и формирует окончательный ответ. Сервер исполняет программу; итоговый текст остаётся текстом модели. Дополнительного модельного классификатора, формата голосового ответа и числовых/лексических фильтров нет. Правильность произвольных вычислений модели не гарантируется одним лишь исполнением программы.

Исполнитель запускается через закрытый Unix-сокет, доступный только UID службы ядра. У задания своя рабочая папка, отдельный непривилегированный UID и файловое окружение. Доступны readonly /usr и зафиксированные runtime-файлы, текущая рабочая папка и ограниченный /tmp. Ключи API и остальные задания в окружение не монтируются. Сеть UID исполнителя допускает только127.0.0.1:33193. Брокер не хранит ключа DeepSeek: все реальные HTTP-вызовы выполняет существующий транспорт ядра.

Каждый внутренний вызов проходит Worker._call, стандартную авторизацию, резервирование, отметку фактической отправки и семидневный журнал calls. Конечная usage Messages преобразуется в имеющуюся форму счётчиков; cache-read прибавляется к некэшированному входу ровно один раз, reasoning повторно не прибавляется. Частичная/неизвестная usage не считается нулевой стоимостью. Отмена и потеря аренды прекращают исполнение; heartbeat продлевает аренду только действующему владельцу. Неизвестный сетевой исход не повторяется. Полученные429/503 обрабатывает существующий request_recovery;429 ждёт20с либо больший Retry-After и повторяет тот же payload. Собственных token/call/daily-квот не введено. Исполнитель не делает автоматический дорогой переход к прямому чтению при сбое.

Для нативного SDK удалена его подстановка max_tokens; запрос идёт с настройками выхода провайдера. Изоляционные ограничения памяти/CPU/локального исполнения сохраняются. Обычное завершение удаляет файл, программу и сессию сразу. Отменённый процесс останавливается и очищается. Оставшиеся после аварий неактивные папки старше часа проверяет timer каждые15минут; активная папка не удаляется. Это отдельный срок от семидневного учёта вызовов.

В существующий answer_prompt админки добавляется:

> Кратко ответь только на вопрос пользователя. Оставь лишь запрошенные сведения. Не озвучивай ход вычислений, технические подробности и пути файлов. Не добавляй причины и объяснения, которых нет в полученных данных.

Требование писать числа словами сохраняется. request_planning_prompt и пустой answer_extra_instruction сохраняются. Пользователь продолжает редактировать эти три настройки в прежней админке.

Проверки: полный набор1951/1951; нативный mock-контур normal/429/unknown/cancel с реальным Worker и журналом;429 повторён через20,016с,3 попытки против2 обычных. Проверка выполнена также под теми же основными systemd-ограничениями, что у ядра. Проверены9999/10000, сохранение маршрута/промпта на повторе, неполная SSE-квитанция и отсутствие её автоматического повтора.

Один реальный ответ модели на синтетическом документе19117 символов дал правильные3086,26₽ короткой фразой словами:4 внутренних вызова,0,1393621786584₽. Это проверка этапа ответа; выбор шаблона и маркетплейсы повторно не оплачивались. Колонка не вызывалась, голосовая приёмка не объявлена.

Подготовка: `prepare.py` создаёт кандидата и отдельный socket-исполнитель. Проверки `qa_program_smoke.py` и `test_program_answers.py` используют синтетические данные. Активация: `activate.py PUBLISHED_PATCH_COMMIT`, с новым манифестом `program_package.py`, штатными runtime_versions_sync и runtime-policy-guard, без обхода защит. Перед остановкой и после неё проверяется очередь; копия текущего release сравнивается с исходником. На ошибке запуска восстанавливаются исходный deployment descriptor и answer-settings.json. Первая установка действительно была отклонена старым манифестом и автоматически откатилась; повтор допускается после подготовки полного нового манифеста.

Оригинальные шаблоны, матрицы, доступы, маркетплейс-обработчики и доставка не меняются этим патчем. Для следующих изменений ядра исходной должна быть уже установленная версия с этим маршрутом. Голосовые тесты остаются остановленными до команды владельца.
