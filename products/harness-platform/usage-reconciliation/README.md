# Сверка оценочной стоимости вызовов модели

Утилита отвечает на вопрос «какую часть оценочных расходов можно подтвердить по журналу шлюза?». Она объединяет начало и завершение попытки, пересчитывает сумму по таблице тарифов и показывает, по каким причинам общий итог нельзя вывести. Это самостоятельная часть этапа 4 дорожной карты Harness. Она работает на копии журнала, которой можно пользоваться и после остановки сервиса.

## Запуск за минуту

Нужен Python 3.10 или новее. Из этого каталога выполните

```sh
python3 reconcile.py example.jsonl --tariffs tariffs.json
```

В примере есть начало одной попытки и два одинаковых сообщения о завершении. Получатся `unique_attempts=1`, `duplicate_events=1`, `total_usd="0.000038814"` и `total_rub="0.00310512"`. Числа синтетические. Для проверки своей выгрузки укажите путь к снимку JSONL вместо `example.jsonl`. Берите один согласованный снимок, который охватывает обе фазы нужных попыток. При разрезании файла по полуночи попытка может начаться в предыдущем дне. Дата файла сама по себе не определяет отчётный период.

## Что означает результат

| Поле | Как читать |
| --- | --- |
| `basis` | `conservative_peak_estimate` означает расчёт по пиковым ставкам тарифа. Фактический счёт провайдера и списание с кошелька клиента сверяются по другим источникам. |
| `unique_attempts` и `duplicate_events` | Число разных идентификаторов попыток и число повторно прочитанных экземпляров одного события. Новая попытка после ошибки получает собственный ID. |
| `verified_usd_attempts` и `verified_rub_attempts` | Число попыток, для которых удалось подтвердить сумму в соответствующей валюте. |
| `known_usd` и `known_rub` | Сумма проверенных вкладов отдельно для каждой валюты. При нулевом числе проверенных попыток подытог равен строке `"0"`. |
| `total_usd` и `total_rub` | Полная сумма по непустому снимку, если подтверждены все попытки для этой валюты. В остальных случаях поле содержит `null`. |
| `issues` | Счётчики причин. Для каждой неполной попытки показывается первая причина в порядке проверок. Пустая выгрузка получает причину `empty_journal`. |

Денежные значения возвращаются десятичными строками. При полном успехе процесс завершается с кодом **0**. При неполной сверке код **1** сопровождается JSON с известными суммами и причинами. Код **2** означает ошибку входных данных или чтения, JSON-отчёт в этом случае не выдаётся. Ошибка JSONL указывает номер строки. В сообщениях и отчёте отсутствуют содержимое событий и идентификаторы сессий.

## Правила сверки

1. Формат журнала — `harness-lab-model-attempt/v1`, по одному JSON-объекту в строке. Каждому `attempt_id` соответствует пара `admitted` и `finished`. Порядок строк произвольный. Перестановка полей и эквивалентная запись JSON-числа сохраняют равенство событий. Разные варианты одной фазы, расхождение метаданных между фазами, отсутствие начала или конца делают обе суммы неизвестными.
2. Подтверждение расхода требует завершения `completed` с HTTP 2xx и четырёх целочисленных счётчиков. Учитывается отдельно обычный вход, чтение из кеша и выход. В версии шлюза v1 нет ставки за создание кеша. Ненулевой счётчик создания, частичные данные и ошибки оставляют сумму попытки неизвестной. Полная попытка с четырьмя нулями даёт подтверждённый ноль.
3. Версия берётся из котировки, модель — из ответа провайдера. При отсутствии имени в ответе используется запрошенная модель. Пара версия/модель должна присутствовать в отдельном манифесте. Ставки котировки сравниваются с манифестом до расчёта. Тариф в этом каталоге воспроизводит версию `deepseek-2026-11-18-peak-cap` из `integrations/harness-native-lab/gateway/server.mjs` на коммите `3c435746aaeeeef5d8b47c75332328d519b764a4`. Новый тариф получает новую версию в манифесте.
4. Сумма в USD равна сумме трёх произведений «число токенов × ставка за миллион», делённой на миллион. RUB рассчитывается по положительному курсу из той же записи. Источник для проверки самого валютного курса потребуется отдельно. Десятичный расчёт сверяется с котировкой шлюза с относительным допуском `2e-15` на округление JavaScript. Для нулевой суммы сравнение точное.
5. При отсутствии курса или расхождении только в RUB подтверждённый USD сохраняется. При несовпадении USD обе общие суммы становятся неизвестными. Событие со спорной суммой не увеличивает соответствующий подытог.

Записи целиком индексируются в памяти по попыткам, одинаковые варианты фаз учитываются по отпечатку. Время и память зависят от размера снимка. Формат шлюза v1 предназначен для лаборатории одного владельца. Привязка расхода к клиенту и пользовательской операции потребует доверенных идентификаторов от сервиса.

## Приёмка

Из каталога компонента запустите

```sh
python3 -B -m unittest discover -s . -p 'test_*.py' -v
```

В полном репозитории дополнительно запустите из корня

```sh
node --test products/harness-platform/usage-reconciliation/test_gateway.mjs
```

Для второй проверки нужен Node.js 22+ и Python. Тест поднимает штатный шлюз и имитатор провайдера на временных портах localhost, делает запрос, передаёт фактический журнал в утилиту, затем повторно добавляет финальную запись и сверяет обе суммы. Все данные тестовые.

Следующий шаг для продуктовой интеграции — привязать попытки к доверенным идентификаторам клиента и операции в журнале шлюза. Тогда эту сверку можно применять отдельно к ручному запросу или запуску поручения и сравнивать её результат с расходом, показанным в приложении.
