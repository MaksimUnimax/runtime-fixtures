# Архивный отчёт в чате Harness

Плагин `report_archive.plugin` предоставляет чату один инструмент чтения — `marketplace_daily_archive`. Пользователь указывает дату. Сервер определяет рабочее пространство по сессии и проверяет право на плагин и его включение в чате. Плагин читает сохранённые снимки Ozon и WB за выбранный день.

## Запуск приёмки

Из каталога `products/harness-platform` подготовьте Python и закреплённый пакет Harness по [инструкции аккаунтов](../../docs/ACCOUNT_CHATS.md). Для следующих команд требуется `HARNESS_NODE_MODULES` с абсолютным путём к установленному пакету.

```sh
python -m unittest discover -s tests -p 'test_*archive*.py' -v
```

Для проверки собственного суточного ZIP передайте путь и дату архива. Команда создаёт временный аккаунт, входит, открывает чат и отправляет вопрос через `POST /api/chats/{id}/turns`. После перезапуска сервиса повторно читает сохранённый ответ через `GET /api/chats/{id}/messages`. Нормализованный JSON из реплики ассистента возвращается на stdout. Выберите для результата приватный каталог.

```sh
python -m acceptance.archive_chat.check "$DAILY_ARCHIVE" "$REPORT_DATE" > "$PRIVATE_RESULT"
```

Проверка по [поштучным ведомостям из PR №473](https://github.com/MaksimUnimax/runtime-fixtures/pull/473) принимает этот JSON через `--actual`. Из рабочей копии с утилитой сверки выполните команду ниже, указав абсолютные пути.

```sh
python acceptance/marketplace_reports/replay.py "$DAILY_ARCHIVE" --actual "$PRIVATE_RESULT"
```

## Путь данных

| Участок | Что выполняется |
| --- | --- |
| Архив Ozon | Количество, оборот и расчётные остатки берутся из снимка `UNIT_ECONOMICS.json` версии `ozon-paired-statistics/v1`. Расход на рекламу берётся из `advertising_totals`. |
| Архив WB | В датированном JSON версии `wb-formula-semantics-r16` используются показатели заказов, парный расчёт остатков и списанная реклама. Оперативная реклама, разница и охват кампаний возвращаются отдельными полями. |
| Сводный итог | Суммы по обеим площадкам складываются до округления. ДРР вычисляется по суммарному исходному обороту. При нулевом обороте процент имеет значение `null`. |
| Чат | В режиме приёмки тестовая модель извлекает одну дату в формате YYYY-MM-DD и выбирает инструмент архивного отчёта из доступных в чате. Нативный агент выполняет MCP-вызов. Адаптер проверяет связь вызова с его результатом и сверяет с ним финальный ответ. |

В автономном экземпляре API используется каталог `<абсолютный путь базы>.reports/<sha256(workspace_id)>/<YYYY-MM-DD>.zip`. Функция `report_archive.plugin.archive_path` формирует этот путь из доверенного пространства. Архивы размещает оператор. Для запуска плагина через отдельный MCP-процесс корень также задаётся абсолютным путём в `HARNESS_REPORT_ARCHIVE_ROOT`. В тестовой конфигурации `HARNESS_OFFLINE_MODEL=1` имя `HARNESS_OFFLINE_ADAPTER=archive_chat` выбирает установленный адаптер приёмки. При обычной настройке без этого параметра действует штатный тестовый ответ проекта.

В архиве должен быть ровно один подходящий снимок каждой площадки за указанную дату. Отсутствие снимка, неоднозначность или несовместимая версия дают ошибку. Достоверность выгрузки и свежесть проверяются при сборе. Этот прогон использует архивный источник и детерминированную тестовую модель. Проверка живых API площадок, выбора инструментов внешней моделью и действий через экраны веб-клиента относится к отдельной приёмке.
