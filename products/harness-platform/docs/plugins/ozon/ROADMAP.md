### Проверка на Seller API

Каталог и оба коэффициента за один завершённый день проверены на действующем подключении Seller API. Расчёты выполнены отдельно для всего магазина и для одного товара, с реальной моделью через шлюз Octoport. Значения в рабочем кабинете владельца не изменялись. Числа из отчётов магазина и длительность каждой операции переданы владельцу в чате.

Первый запрос потерь товара остановился на выборе источника моделью. Повторный запуск дал подтверждённый результат. Первоначальный HTTP-код не зафиксирован. Для последующих обращений в служебный журнал выводятся статус ответа шлюза либо класс ошибки соединения. При ограничении частоты Seller API матрица продолжила выполнение после ожидания.

Сквозная проверка обычного чата прошла через рабочую модель, общую матрицу и сохранённые тестовые значения. На 20 заказанных единиц при потерях 10% и доставке 25 ₽/шт. чат вернул 18 оставшихся единиц и 500 ₽ доставки.

При проверке года в историческом формате начислений обнаружено дополнительное числовое поле скорости доставки. Обработчик сохраняет его в контрольной сумме исходной записи и считает расходы по подписанным денежным компонентам. Старый и новый форматы прошли проверку на одинаковых денежных данных. При временном сбое локальной программы проверки запроса повторяется только построение запроса до первого обращения к площадке.
