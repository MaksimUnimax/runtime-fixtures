# Личные отчёты Октопорта в Telegram

## Что получает клиент

Клиент подключает свой Telegram к аккаунту Октопорта один раз. Для каждого выбранного диалога бот присылает итоговые ответы по новым успешно сформированным отчётам Ozon и WB. Сообщение приходит и при закрытом браузере. Приложение продолжает считать отчёт в исходном чате. Плагин отвечает за доставку уже готового результата.

1. Войдите в Октопорт и установите «Документы → Отчёты в Telegram» в каталоге «Плагины». Откройте нужный чат. В разделе «Установленные плагины» выберите «… → Подключить» у этого плагина.
2. Откройте настройки плагина и нажмите «Подключить Telegram для отчётов этого чата». Подтвердите нужную учётную запись на стороне Telegram и разрешите боту писать вам.
3. Бот пришлёт короткое проверочное сообщение. После подтверждения доставки вернитесь по кнопке в свой чат. Первый новый готовый отчёт поступит в Telegram автоматически.
4. В другом диалоге подключите уже установленный плагин и нажмите «Получать новые отчёты этого чата». Доступ можно остановить для одного чата или отключить Telegram для всего аккаунта.

От клиента требуется доступ к своему авторизованному аккаунту Telegram. В зависимости от устройства Telegram может попросить подтвердить вход. Октопорт получает числовой идентификатор из подписанного ответа Telegram. Пользователю не надо искать свой ID, сообщать Октопорту номер телефона, передавать секреты бота или нажимать Start в личном чате.

## Почему выбран Telegram Login

| Вариант | Действие клиента | Возможности |
|---|---|---|
| Telegram Login с разрешением на сообщения | Подтвердить подключение со страницы Октопорта | Основной реализованный сценарий. Бот может отправлять личные сообщения после согласия. |
| Ссылка на бота с одноразовым параметром start | Открыть бота и запустить его | Возможный резервный сценарий. Потребует обработчика входящих обновлений и подтверждения связи с аккаунтом Октопорта. |
| Ввод ID или @username | Ввести идентификатор | Сам по себе идентификатор не подтверждает владельца и не даёт боту разрешения на первое личное сообщение. |
| Упоминание гостевого бота в чате | Упомянуть бота | Telegram даёт ответить на конкретный вызов. Для подписки на будущие личные отчёты нужен отдельный допуск. |

## Подключение бота оператором

Один бот Октопорта обслуживает подписавшихся клиентов. Для каждого клиента хранится собственный приватный получатель. Для пилота подходит отдельный бот для отчётов. Подключение существующего бота возможно с согласия его владельца. Модуль выполняет исходящие запросы Bot API и не переключает webhook или getUpdates.

1. В [@BotFather](https://t.me/BotFather) выберите бота, откройте **Login Widget** и зарегистрируйте два разрешённых адреса — `https://octoport.ru` и `https://octoport.ru/telegram/return`. Оставьте подпись RS256. Telegram выдаёт для входа отдельный **Client Secret**. У того же бота есть **Bot Token** для отправки сообщений.
2. Настройте маршрут по инструкции ниже и выполните на сервере приложения `sudo /usr/local/sbin/octoport-telegram-setup`. Введите Bot Token в скрытом приглашении. Команда вызовет `getMe` через выбранный роутер и покажет подтверждённое @имя. Затем введите Client Secret. Команда получает числовой ID из токена и атомарно записывает данные в `/etc/credstore/octoport-telegram.json` с правами 0600. Секрет входа проверяется при обмене кода после согласия пользователя.
3. В удобный момент после завершения активных запросов и задач плагинов перезапустите `harness-prod.service`. Служба получает отдельную учётную запись systemd через `ImportCredential=octoport-telegram.json`. При замене только сетевого узла этот шаг не требуется. Для отдельного стенда приложение также поддерживает `HARNESS_TELEGRAM_CONFIG_FILE` и `LoadCredential` с явно заданным файлом.
4. На обоих HTTPS-прокси отключите access log в точном маршруте `/telegram/return`. Этот URL получает одноразовый код авторизации. Приложение возвращает `Referrer-Policy: no-referrer` и убирает код из адресной строки. Для проверки откройте страницу возврата без параметров — она должна сообщить об отмене подключения и предложить вернуться в Октопорт.
5. Проверьте полный сценарий ниже с владельцем тестового аккаунта. Одобрение подключения требуется от самого получателя.

## Рабочий маршрут и смена серверов

Роль **сервера приложения** — хранить ключи бота, подтверждённого получателя, подписки на диалоги и очередь отчётов. Роль **роутера Telegram** — принимать CONNECT от разрешённых серверов Октопорта только к `oauth.telegram.org:443` и `api.telegram.org:443`. TLS устанавливает само приложение и проверяет сертификат Telegram. Ответ возвращается по тому же соединению. Публичная страница входа открывается в браузере клиента напрямую. Маршрут и службы принадлежат плагину Telegram.

| Что меняет оператор | Где и что указать | Как применить |
|---|---|---|
| IP, DNS-имя или порт роутера | На сервере приложения в `/etc/harness-prod/telegram-route.env` задайте `TELEGRAM_ROUTER=имя-или-IP:порт` | Перезапустите только `octoport-telegram-route.service`. Проверьте оба адреса Telegram по инструкции ниже |
| IP сервера приложения | На роутере в `/etc/octoport-telegram-router/route.env` измените `TELEGRAM_APP_SOURCES`. Используйте исходящий IP, который видит роутер после NAT. Несколько отдельных адресов указываются через пробел в двойных кавычках | Перезапустите `octoport-telegram-router.service`. При переезде сначала разрешите оба источника, проверьте доступ с нового и затем удалите старый |
| Интерфейс или порт прослушивания | Там же задайте `TELEGRAM_LISTEN=локальный-IP:порт` | Перезапустите службу роутера. При смене опубликованного адреса обновите и `TELEGRAM_ROUTER` на стороне приложения |
| Только локальный порт приложения | На приложении сокет слушает `127.0.0.1:18765`. При конфликте выберите свободный порт в override для `ListenStream` (сначала очистите старое значение) и в `/etc/harness-prod/telegram-connect-port` | Выполните `daemon-reload`, перезапустите локальную службу и сокет, обновите `connect_proxy_port` в закрытой конфигурации и перезапустите приложение |

Для смены роутера сначала подготовьте новый узел с разрешением для действующего приложения. Перед переключением дождитесь завершения активных отправок. Запишите прежнее значение `TELEGRAM_ROUTER`. После переключения выполните обе сетевые проверки и проверьте один согласованный отчёт. Для отката верните прежнее значение и перезапустите только локальную службу маршрута. При недоступном роутере подключения через настроенный порт завершаются ошибкой. Приложение сохраняет учётную запись и подписки. Перенос самого сервера приложения требует штатного переноса состояния и секретов Октопорта. Смена только IP или транспорта повторного согласия клиента не требует.

### Установка на другом узле

Шаблоны находятся в [deploy/telegram](../../../deploy/telegram). Для роутера используется Apache 2.4 с модулями `mpm_event`, `authz_core`, `authz_host`, `proxy` и `proxy_connect`. На сервере приложения используется штатный `systemd-socket-proxyd`. Параметры ниже задаёт оператор конкретной установки. Команды выполняются из каталога шаблонов с правами root на соответствующем узле.

**На роутере.** Создайте каталог `/etc/octoport-telegram-router/empty` с правами 0755. Установите `telegram.conf` в `/etc/octoport-telegram-router/`, а `octoport-telegram-router.service` — в `/etc/systemd/system/`. Запишите `TELEGRAM_LISTEN` и `TELEGRAM_APP_SOURCES` в `/etc/octoport-telegram-router/route.env` с правами 0600. Ограничьте список исходящими адресами серверов приложения. Затем запустите службу.

```sh
systemctl daemon-reload
systemctl enable --now octoport-telegram-router.service
```

**На сервере приложения.** Установите `octoport-telegram-route.socket` и `octoport-telegram-route.service` в `/etc/systemd/system/`. Установите `telegram-reports.conf` в `/etc/systemd/system/harness-prod.service.d/`, а `setup.py` — как `/usr/local/sbin/octoport-telegram-setup` с правами 0700. Запишите `TELEGRAM_ROUTER` в `/etc/harness-prod/telegram-route.env` с правами 0600 и число `18765` в `/etc/harness-prod/telegram-connect-port`. Активируйте локальный сокет.

```sh
systemctl daemon-reload
systemctl enable --now octoport-telegram-route.socket
```

**Проверка с сервера приложения.** В обеих командах используйте фактический локальный порт. Первая возвращает JSON с открытыми ключами Telegram, вторая показывает ответ узла Bot API. Для чужого назначения и источника вне списка роутер должен вернуть CONNECT 403. Проверка доступа к API не отправляет сообщений клиентам.

```sh
curl --noproxy '' --proxy http://127.0.0.1:18765 --max-time 10 -fsS https://oauth.telegram.org/.well-known/jwks.json
curl --noproxy '' --proxy http://127.0.0.1:18765 --max-time 10 -sS -o /dev/null -w 'CONNECT %{http_connect}, HTTP %{http_code}\n' https://api.telegram.org/
```

## Контракт доставки

- Получатель принадлежит одному workspace и одному боту. Подмена адресата через форму или запрос модели не предусмотрена. При замене аккаунта Telegram сначала отключают прежнюю привязку. Для старых подписок требуется новое согласие.
- Подписка начинается с текущей позиции в серверном журнале чата. После перезапуска курсор сохраняется. Удаление чата или отключение плагина удаляет его подписку. Удаление плагина из аккаунта также удаляет привязку Telegram. Сообщение, уже переданное в Telegram до отключения, может дойти.
- Для отправки нужны завершённый ход, настоящий вызов инструмента маркетплейсов, его успешный результат с данными и последующий итоговый текст ассистента. Одного вопроса со словом «отчёт» недостаточно. Для отправки используется только финальный текст отчёта. Служебные аргументы, промежуточные ответы инструмента и обычные реплики остаются в Октопорте. Если проверка обнаружила в итоговом тексте распознаваемый ключ, доставка этого ответа пропускается.
- Короткий отчёт приходит личным сообщением. Для текста, превышающего 4096 единиц UTF-16, бот отправляет один UTF-8 файл `octoport-report.txt`. Текст отправляется без интерпретации HTML или Markdown, предпросмотр внешних ссылок в сообщении выключен. Получение message_id подтверждает принятие Telegram. Отметку прочтения клиента Bot API здесь не предоставляет.
- Опрос работает внутри существующей службы. В обычном режиме новые отчёты проверяются примерно раз в 12 секунд. Время может увеличиваться из-за нагрузки, сети и ограничений Telegram. При подтверждённом 429 сохраняются позиция и retry_after. Если результат HTTP-вызова неизвестен, автоматическая повторная отправка этого отчёта прекращается. В настройках клиент может продолжить со следующего отчёта, сохранив очередь более поздних. После блокировки бота нужно заново разрешить доставку.
- На сайте Code Flow использует одноразовый state, PKCE S256, nonce, сессию Октопорта, срок привязки и повторную проверку текущего чата. ID Token проверяется по ключам Telegram, issuer, audience и сроку действия. Адресатом служит отдельный числовой claim `id` из профиля. Scope `telegram:bot_access` запрашивает право писать, `phone` не запрашивается. Нейтральное сообщение проверяет возможность доставки до подписки на данные магазина.

## Приёмка и дальнейшая работа

Автоматические сценарии находятся в `tests/test_telegram_reports.py` и `tests/browser/test_telegram_browser.py`. Они используют временные данные и тестовые ответы Telegram. Проверяются PKCE и подписанный ID Token, изоляция получателя, повтор и отмена привязки, прежние отчёты, длинные сообщения, 429, неопределённый результат и возобновление. Chromium проходит обычный каталог, настройки, возврат с другого сайта и остановку доставки.

Для боевой приёмки используйте отдельный аккаунт Октопорта и согласованный Telegram. Проверьте согласие без Start, первое нейтральное сообщение, один новый отчёт выбранного чата и источник в Октопорте. Затем проверьте второй диалог с выключенной подпиской и отключение доставки. Фактическую доставку проверяет получатель в своём Telegram.

В первой версии отчёт можно запросить обычным способом в чате. Планировщик ежедневных и еженедельных отчётов — следующий этап. Для него нужно выбрать отчёт и магазин, часовой пояс, время и дни доставки. Формирование отчёта остаётся у таймера и матрицы, а отправку готового результата выполняет этот плагин. Отдельная задача — прикладывать подготовленные исходным плагином PDF/XLSX.

### Фактическая проверка 21 ноября 2026 года

Первая установка использует Alisa как сервер приложения и Easyscript как роутер Telegram. Параметры этой установки — `TELEGRAM_ROUTER=78.17.68.165:19443`, `TELEGRAM_LISTEN=78.17.68.165:19443`, `TELEGRAM_APP_SOURCES=185.219.43.9/32`. Они хранятся в конфигурации развёртывания. С Alisa через локальный сокет получены публичные ключи Telegram и ответ Bot API. На запрещённое назначение и на запрос с другого исходящего адреса роутер вернул 403. Сайт Октопорта отдал страницу возврата и её скрипт с HTTP 200. Проверка доставки личного сообщения требует настройки Login Widget и согласия получателя.
