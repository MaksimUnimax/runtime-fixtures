# Фильтр плагинов

Техническое задание для Октопорта от 23 ноября 2026 года.

## Цель

Октопус понимает задачу из обычного сообщения, находит подходящие возможности в актуальном каталоге и учитывает их состояние у пользователя. Сервер открывает только инструменты, выбранные для выполнения текущей задачи.

## Обязательные требования

| Код | Требование |
|---|---|
| Ф1 | Каталог включает все опубликованные плагины и интеграции, доступные пользователю для подключения. В него входят неустановленные плагины, установленные плагины и интеграции без подключения аккаунта. Состав берётся из реестров продукта. Добавление, переименование, обновление и снятие с публикации отражаются со следующего сообщения в новом и уже открытом чате. |
| Ф2 | Карточка реестра хранит название, назначение, доступные операции, зависимости каждой операции, необходимые права и шаги настройки со ссылкой на действующий экран. Рекламные операции Ozon требуют Performance API. Продажи Ozon требуют Seller API. Доставка в Telegram требует подтверждённой интеграции при выборе этого канала. |
| Ф3 | Сервер отдельно определяет установку плагина в аккаунте, его включение в текущем чате, сохранённые интеграции, привязку выбранного магазина к чату и подтверждённые права на операцию. Сервер открывает рабочий инструмент только в пределах этих прав. Исполнитель повторно проверяет магазин, права и параметры перед обращением к площадке. Сведения о чужих аккаунтах и ключи исключаются из ответов справки и запросов к модели. |
| Ф4 | Смысл запроса определяет текущая модель в обычном обращении. На старте модель получает краткий каталог, справку и указатель доступных действий. Справка показывает состояние и только нужные шаги. Для исполнения модель запрашивает конкретное действие. Разрешение действует до конца хода. При восстановлении незавершённого хода сохраняются успешно открытые и всё ещё доступные действия. |
| Ф5 | Для обычной реплики, справки, настройки или пересказа без необходимости API в каждом фактически отправленном запросе к модели содержится 0 шаблонов Ozon и 0 шаблонов WB. Учитываются история, описания, результаты инструментов, идентификаторы и схемы. При запросе реальных данных передаются только подходящие действия, шаблоны и параметры для разрешённых магазинов. |
| Ф6 | При двусмысленности Октопус задаёт вопрос о недостающем параметре. Просьба «мне нужно чтобы ты отслеживал рекламу» позволяет распознать фоновое наблюдение без слова «таймер». Если «Таймер» доступен к установке, Октопус предлагает его установить. Если он установлен и выключен в чате, Октопус предлагает включить его здесь. Уже включённые плагины площадок и привязки магазинов учитываются отдельно. Уточняются площадка, показатели, частота и канал доставки, если они неизвестны. При подтверждённом расписании состояние сообщает исполнитель. |
| Ф7 | Фильтр работает в общем слое Harness для прямого DeepSeek и OpenRouter, в новых и существующих чатах. Гостю доступна публичная справка. Публичный каталог кэшируется по версии реестра. Частное состояние читается для текущего аккаунта и чата. При росте каталога краткий указатель укладывается в бюджет. Полный список открывается по запросу. |
| Ф8 | Поддерживается добавление нового модуля и действия через реестр. Отбор повторно использует контракты и проверку доступа модулей. Общий фильтр применяется к новым действиям без ручного перечисления их названий и шаблонов. |
| Ф9 | На «Что ты умеешь?» и «Какие есть плагины?» гостевой скрипт возвращает из базы название и описание каждого опубликованного плагина. По названию показывает карточку, по запросу об интеграциях показывает подключения отдельно. Модель и внешние API не вызываются, расход токенов и монет равен нулю. |
| Ф10 | В разделе «Администрирование → Плагины» администратор может убрать плагин из каталога установки и вернуть его. Снятие сразу закрывает новые установки, в том числе автоматические при подключении магазина. Ранее установленные экземпляры сохраняют настройки и доступ в своих чатах. |

## Критерии приёмки

| № | Сценарий | Проверяемый результат |
|---|---|---|
| 1 | Чистый аккаунт, существующий чат и гостевая справка. Опубликовать, переименовать и снять тестовый плагин и интеграцию. | Список совпадает с реестром. Опубликованная позиция видна до установки и до подключения. Изменения видны со следующего сообщения. |
| 2 | Ozon и WB включены, магазины сохранены, доступ текущего чата выключен. У одного Ozon только Seller API. | Октопус сообщает реальные статусы. Для сохранённого магазина предлагает «Доступ в этом диалоге». Для рекламы Ozon указывает недостающий Performance API. Другой чат сохраняет собственные привязки. После отзыва доступа чтение запрещено. |
| 3 | «Мне нужно чтобы ты отслеживал рекламу». Повторить для неустановленного, установленного выключенного и активного «Таймера». | В каждом случае Октопус знает о «Таймере», сообщает применимый шаг и уточняет неизвестные параметры. При варианте только в чат Telegram не требуется. При варианте в Telegram проверяется действующая привязка. Публикация расписания требует штатного подтверждения. |
| 4 | Оба магазина подключены. Спросить «Что такое ДРР?», «Как подключить Telegram?», «Как подключить Ozon и WB?». Сразу после отчёта попросить «Сократи ответ». | В сериализованном запросе каждого вызова модели 0 шаблонов каждой площадки. Ответы сохраняют доступные подтверждённые сведения. |
| 5 | В том же чате запросить вчерашние продажи по WB и Ozon, затем сменить период. Включить неоднозначный вопрос без показателя. | Контрольные суммы по обеим площадкам совпадают с источниками. При смене периода сохраняются ранее выбранные показатель и магазины. При неизвестном показателе Октопус его уточняет. |
| 6 | Зарегистрировать новое рабочее действие. Попробовать выполнить его до и после открытия и в следующем ходе. | До открытия схема закрыта, прямой вызов отклоняется. Открытие допускает вызов с нужными правами. Следующий ход снова начинает с закрытой схемой. |
| 7 | Повторить сценарии на прямом DeepSeek и OpenRouter со старым и новым чатом. Сравнить у одинаковых задач число вызовов, входные токены, время и списания. | Оба маршрута соблюдают правила отбора. Результаты публикуются с точной версией. Экономия подтверждается фактическими запросами и квитанциями, а целевой бюджет блока краткой справки и настройки на 8 и 128 контрольных карточках составляет до 400 токенов по контрольному токенизатору. |
| 8 | Вопросы гостя о возможностях, каталоге и одном плагине. | Названия и описания совпадают с записями базы. Обращений к модели и внешним API, токенов и списаний — 0. |
| 9 | Администратор снимает и возвращает один плагин. Повторить запросы в открытом гостевом и пользовательском чате, запросить новую установку, перезапустить сервис. | Видимость и возможность установки соответствуют решению. Для обычного пользователя изменение публикации запрещено. У прежнего владельца остаётся доступ к установленному экземпляру. |

Приёмка фиксирует точную версию релиза, сценарий, фактический результат и доказательство. Сценарии с данными площадок проходят на тестовых аккаунтах и магазинах. Проверка расходов выполняется парно на одинаковых входных условиях.
