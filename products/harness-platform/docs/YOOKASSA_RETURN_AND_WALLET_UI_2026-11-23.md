# Octoport · Возврат из ЮKassa и оформление кошелька — 23 ноября 2026

## Причина гостевого экрана после оплаты

На `https://octoport.ru/` аутентификация использует защищённую cookie `__Host-harness_session` с `SameSite=Strict`. При переходе с `yoomoney.ru` после оплаты первоначальный GET `/?account=wallet` приходит **без** этой cookie, хотя сессия действительна и продолжает храниться в браузере. Исходный server renderer показывает гостевой режим. Это ошибка интеграции возврата, не доказательство потери платежа или логина.

**Исправление без ослабления SameSite:**

1. `platform_core/web_ui.py`: если GET `/?account=wallet` не содержит действительной member cookie, отдаёт минимальную cookie-neutral переходную страницу вместо guest-shell; для `/?account=wallet&resume=1` без сессии показывает обычный login panel и сообщение, что повторная оплата не требуется. С действительной cookie сразу показывает member-shell.
2. `/payment/return` — отдельный cookie-neutral маршрут (HTTP 200, no-store) для платежных переходов.
3. `native/web/payment-return.js` — скрипт, обслуживаемый с собственного домена, выполняет `window.location.replace('/?account=wallet&resume=1')`. Вторая навигация инициирована уже документом Octoport, и `SameSite=Strict` cookie приходит как положено.
4. `tests/test_web_ui.py` — проверяет первый guest-safe ответ, переходный скрипт, отсутствие новой cookie, fallback на login при истёкшей сессии, успешную member navigation при действительной cookie и сохранение `SameSite=Strict`.

**Тест настоящим Chromium:** в изолированном профиле использована только синтетическая cookie `__Host-octo-return-qa` с `SameSite=Strict` (ни одного настоящего ключа/логина). Навигация с локального стороннего origin на `https://octoport.ru/?account=wallet`:
- Первый URL `/?account=wallet`: синтетическая Strict cookie **не передана**.
- Второй URL `/?account=wallet&resume=1`: Strict cookie **передана**.
- Результат `EXTERNAL_RETURN_STRICT_COOKIE_RESTORED_PASS`.
