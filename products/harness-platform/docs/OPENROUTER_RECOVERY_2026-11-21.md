## Что происходит при остановке

После ответа OpenRouter 429 Octoport сохраняет в закрытой базе чата срок следующей попытки, отправленные параметры, состояние инструментов и привязку к исходной сессии. Для изображения сохраняются модель, описание, количество и согласованный тариф. Ядро ОС освобождает блокировку при завершении процесса. Новый процесс проверяет владельца чата, сессию, текущие подключения и права на платную операцию. Ожидание принадлежит одному обработчику. Уже записанный запрос в истории возвращается клиенту повторно без запроса к модели.

Перед повторной отправкой обработчик атомарно снимает отметку подтверждённого отказа. Если сервис остановлен после этой точки и подтверждения от провайдера нет, операция переходит на сверку. Это сохраняет однократность расходов при неопределённом исходе. Изображение и квитанция из одного ответа сохраняются одной транзакцией. Если окончательный ответ модели прервался, готовое вложение доступно владельцу в исходном чате. Если несколько инструментов запущены одновременно и результат соседнего инструмента неизвестен, автоматическое продолжение текста останавливается, готовое изображение доступно отдельно.

| Проверка восстановления | Подтверждённый результат |
|---|---|
| Процесс остановлен на первом отказе текстовой модели. Два экземпляра начинают с одной базой | Один повтор с исходными параметрами, одна пара «вопрос — ответ» в истории |
| Во время ожидания истекла блокировка чата, другой процесс отправил новый вопрос | Незавершённая операция сохранила порядок. Конкурирующий запрос получил 409 |
| Пользователь вышел из аккаунта во время простоя | После запуска нового обращения к провайдеру нет, резерв отклонённой попытки освобождён |
| Генератор уже создал изображение, текстовая модель вернула 429 при продолжении | Продолжение получило первоначальный результат инструмента, генератор выполнился один раз |
| Пользователь вышел после готового изображения | После повторного входа владелец открыл изображение. Чужой аккаунт получил 404 |
| Генератор вернул 429, основная модель OpenRouter, стартовали два экземпляра | Две отправки генератору с одинаковым телом, из них один отказ и одна успешная. В кошельке одна платная попытка изображения |
| Генератор OpenRouter вернул 429 при основной модели DeepSeek | После запуска DeepSeek получил результат инструмента, завершил ответ, в истории появилась картинка. Сохранена одна платная попытка генератора |
| Процесс остановлен после приёма запроса генератором до получения квитанции | При повторной отправке того же сообщения клиент получил статус сверки. Второго обращения к генератору не было |

В этих восьми тестах настоящий процесс приложения и дочерний Harness завершаются сигналом SIGKILL. Ответы провайдеров контролирует тестовый сервер. Проверка в Chromium отдельно подтверждает, что владелец видит ссылку на готовое вложение только в исходном чате.

## Администрирование и зависимости

Админка показывает время получения каталога, последней успешной генерации, последней проверки и её результат для текущего ключа. Диагностика различает отклонённый ключ, недоступную модель, нехватку средств у провайдера и ошибку соединения. При исчерпании локальных текстовых слотов обслуживается самый ранний запрос из рабочих пространств, которым доступен слот. Тест порядка выполнялся внутри одного процесса приложения.

Для выпуска подготовлено отдельное окружение Node и Python. Версии зафиксированы в lock-файле npm и ограничениях pip. Проверены совместимость MCP через stdio, установка полным `npm ci`, целостность зависимостей Python через `pip check`, обновление схем на существующей базе и фактический состав установленного окружения. Проверка OSV по 621 пакету показала 0 совпадений. Это результат проверки на дату выпуска.

## Ограничения и эксплуатация

Потолок цены текстовой модели передаётся провайдеру. Для выделенного API изображений в проверенной схеме OpenRouter отсутствует эквивалентный параметр. Защита кошелька ограничивает списание резервом, новая отправка требует свежего тарифа. Расхождение с внешней квитанцией выше резерва требует сверки оператором.

На системном разделе Easyscript при проверке оставалось 841–899 МиБ. Свободного пространства для расширения раздела внутри текущего диска нет. Крупные рабочие копии, журналы и архивы других задач сохранены. Для увеличения оплачиваемого диска требуется решение владельца.
