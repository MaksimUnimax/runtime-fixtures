# Разработка и подключение модуля

Точка входа — доверенная композиция, которую выбирает оператор сборки. Это установленный Python-модуль с коллекцией `PLUGINS`. Пустая композиция является штатным режимом. CLI принимает имя модуля в `--composition` только на локальной границе администрирования. Модель получает лишь названия доступных ей инструментов и их схемы.

## Первый модуль

Скопируйте структуру примера из `examples/reference_plugin.py` в корне продукта в свой пакет и экспортируйте его декларации в композиции. Начните со стабильных ID, описания доступных данных, подходящих параметров и обработчика. Исходный пример не загружается по умолчанию.

```python
from platform_core.catalog import Capability, Plugin

def convert_distance(scope, arguments):
    return {"metres": arguments["kilometres"] * 1000}

PLUGINS = (
    Plugin(
        id="distance", version="1.0.0", capabilities=(
            Capability(
                name="distance_to_metres",
                description="Перевести указанное число километров в метры.",
                input_schema={
                    "type": "object",
                    "properties": {"kilometres": {"type": "number", "minimum": 0}},
                    "required": ["kilometres"],
                    "additionalProperties": False,
                },
                handler=convert_distance,
            ),
        ),
    ),
)
```

Сохраните пример как `distance_plugin.py` в локальном каталоге запуска. Выполните шаги README с композицией `distance_plugin`, выдайте право и включите модуль `distance` в выбранном чате. Вызов `distance_to_metres` с `{"kilometres": 2.5}` вернёт `{"metres": 2500.0}`. Можно объединить несколько пакетов в одной композиции: импортируйте их списки и присвойте `PLUGINS = (*first_plugins, *second_plugins)`.

## Контракт v1

| Поле | Условие |
| --- | --- |
| Plugin.id / version | Уникальное имя пакета и строковая версия выпуска |
| Plugin.manifest_version | Поддерживается версия 1. Неизвестная версия отклоняется перед запуском |
| Capability.name | Уникальное во всей композиции MCP-имя, до 128 букв ASCII, цифр и символов нижнего подчёркивания, точки или дефиса |
| description / input_schema | Непустое описание и JSON Schema Draft 2020-12 с корневым типом object. Контракт v1 использует встроенные схемы без ссылок. Проверка схемы происходит при загрузке, проверка входа — до вызова обработчика |
| effect / handler | Для v1 поддерживается read. Синхронный доверенный обработчик принимает Scope и словарь аргументов, возвращает конечное значение JSON. Обработчик чтения соблюдает отсутствие внешних изменений |
| Ответ | CLI возвращает сам результат. MCP отдаёт объект `{"result": ...}` в structuredContent и текстовом блоке. Неизвестные и недоступные инструменты получают одинаковый внешний ответ |

В своём модуле используйте Scope, полученный от платформы. Если параметр обозначает объект хранения, модуль запрашивает его в пределах разрешённого кабинета. Запись, платежи и внешние изменения потребуют отдельного контракта исполнения. Секретные значения не входят в схемы результатов и переписку. Для проверки нового модуля нужны успешный пример, неверный параметр, попытка вызова при отключённом модуле и подтверждение совпадения с источником данных.

## Подключение к штатному Harness

`native/platform-mcp.mjs` предоставляет фабрику записи для заявленного в upstream клиента и функцию монтирования в область Cordis. После получения реальной identity сервер собирает объект запуска. Пути к Python, каталогу пакета, его БД и модуль композиции берутся из конфигурации установки. Та же связка actor/workspace/chat должна быть заранее создана сервером.

```javascript
import { platformMcpEntry } from './native/platform-mcp.mjs';

const entry = platformMcpEntry({
  pythonExecutable, productDirectory, databasePath, compositionModule,
  scope: { actorId, workspaceId, chatId },
});
```

Добавьте запись в приватную композицию агента данного чата. В ней инструменты адаптирует официальный MCP-клиент Harness. Имена на стороне модели может нормализовать и сокращать upstream. Никогда не полагайтесь на построение имени модели из сырых идентификаторов. В разделе [приёмки](ACCEPTANCE.md) отдельно зафиксированы проверки SDK, адаптера и граница фактической проверки установленного native runtime.

Базовая документация закреплённого upstream: [клиент MCP](https://github.com/deepseek-ai/deepseek-harness/tree/66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db/packages/mcp/mcp-client). Для будущего плагина поручений сначала оцените [штатное расширение расписаний](https://github.com/deepseek-ai/deepseek-harness/tree/66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db/packages/schedule/tool-schedule) на изоляцию кабинетов и связь доставки с фактическим исходом исполнения.


## Подключения аккаунта

Дескрипторы в platform_core/integrations.py задают поля и операции. Ozon принимает Client-Id / Api-Key продавца и отдельную пару Performance. Wildberries принимает API-токен статистики. Для семантики используется OAuth Яндекс Вордстата с одобренным доступом. Пользователь выбирает название магазина, сохраняет данные и может проверить соединение. Повторное сохранение с теми же сервисом и названием обновляет ключи. У Ozon можно обновить одну пару отдельно.

Пример ввода в чате — «Подключи Ozon, название: Мой магазин, client_id: …, api_key: …». При вставке распознанных реквизитов открывается закрытая форма. При отправке полностью набранной команды обработчик сохраняет подключение и показывает подтверждение. Команда «Подключи Wildberries» сразу открывает ввод токена. Проверка и сбор семантики выполняются через фиксированные HTTPS-адреса адаптера. Состояние «Сохранено» означает успешную зашифрованную запись. «Связь подтверждена» требует ответа официального API. Секреты из списка подключений не возвращаются.

Новый сервис можно добавить дескриптором, обработчиком доступа и тестом. Для будущей заявки «подключи Яндекс Маркет» агент сможет найти официальную документацию и предложить черновик схемы для конкретного аккаунта. Активация требует проверки домена, способа аутентификации и безвредного запроса. В первом выпуске исполняются три проверенных схемы. Регистрация магазина сама по себе не добавляет отчёты о продажах.
