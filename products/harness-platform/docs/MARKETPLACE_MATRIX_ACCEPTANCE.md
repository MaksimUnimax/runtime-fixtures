# Приёмка матрицы Ozon и Wildberries в чате

## Прогон

1. Сохранить ревизию сборки и список шаблонов из каталога. В отдельном тестовом диалоге выбрать магазины в настройках плагинов. Зафиксировать, какие шаблоны агент действительно получил с этими подключениями.
2. Для каждого простого шаблона отправить обычный вопрос продавца. Указать магазин и период, если они нужны для получения показателя. Для составного сценария запросить несколько показателей или сравнение площадок одним сообщением. Отдельно проверить короткое продолжение предыдущей реплики.
3. Для каждого хода сохранить исходный вопрос, полный ответ, время отправки и ответа, длительность, входные токены, кэш, выходные токены, итоговое количество, стоимость в рублях и списанные монеты. Привязать запись к событию этого хода в журнале инструмента. Переписку, реквизиты кабинета и показатели конкретного продавца хранить в закрытой таблице приёмки.
4. Отмечать отдельно доступность для выбора, фактический выбор агентом, результат исполнения и проверку бизнес-ответа. Для денег проверить валюту и состав суммы. Для продаж указать, использовалась дата заказа, выкупа или начисления. В сравнении площадок проверить одинаковое определение показателя. Если сверка с данными кабинета ещё не выполнена, оставить её открытой.
5. В составном вопросе проверить результат каждого компонента. При частичном результате сохранить полученные значения и назвать недостающие. Если журнал содержит только общий статус, отдельные компоненты требуют проверки. При разрыве связи проверить историю хода и квитанцию до повтора.

## Разбор и повтор

Если агент выбрал неверный шаблон, проверить назначение шаблона и описание доступных параметров в меню. Если выбор верный, проследить запрос до площадки, декодирование ответа и расчёт. Ошибку представления исправлять в инструкции к ответу. При временном ограничении запрос повторяется с учётом срока, который вернула площадка, и оставшегося времени хода. Независимые части составного вопроса можно продолжить.

Сохранить исходный неудачный прогон. После исправления повторить тот же вопрос с теми же магазинами и периодом, добавить переформулировку и связать результаты с версией изменения. Прямой вызов обработчика помогает проверить расчёт. Сквозную приёмку закрывает повтор через чат с зафиксированным выбором, результатом и квитанцией.

## Повторная проверка денежных формул и ошибок площадки

- Запросить ДРР, сумму заказов и расход на рекламу. Проверить исходные значения, которые матрица передала агенту по этому магазину и периоду. Округлённый процент в ответе должен совпасть с отношением этих сумм. Восстановление оборота из округлённого процента считать ошибкой.
- Для суммы хранения и логистики, а затем для их доли в финансовых продажах сверить обе статьи и знаменатель. При отказе проверить, запросил ли обработчик валюту нужного магазина до компиляции денежной формулы.
- Для ожидающего отчёта сверить последний ответ именно того источника, который поставил вызов в очередь. Время следующей попытки встречается и при серверной ошибке площадки, и при ограничении частоты. Проверять эти случаи отдельно.
- Проверить выбор шаблонов при двух подключениях, когда нужный отчёт доступен только на одной площадке. В составном вопросе сохранить запрошенный магазин для каждого показателя.
- Для предварительного расчёта коэффициента зафиксировать создание отчёта, ожидание готовности и результат чтения. Если время хода истекло, сохранить видимое сообщение, время окончания и подтверждённое списание из журнала, даже когда финальный ответ в чате отсутствует.

### Ожидание после HTTP 429

Время ожидания, заданное площадкой после HTTP 429, приостанавливает таймер хода. Матрица повторяет тот же вызов в рамках исходной операции. Сообщение в чате показывает ход ожидания. Повтор проверяет доступ к чату и магазину, а учёт модели остаётся привязан к исходному идентификатору.
На изолированном стенде с установленным Harness поставщик вернул HTTP 429 с Retry-After 125 секунд. Сквозной прогон завершился за 132,8 секунды. Повтор отправки с исходным идентификатором вернул сохранённый ответ. В журнале осталось два вызова модели, выбор отчёта и итоговый ответ.

## Перепроверка 21 ноября 2026 года

Шесть шаблонов ранее останавливались при проверке доступности. В Octoport подключены разрешённые источники рекламы Ozon и WB и предварительные расчёты прогнозов Ozon. Шаблоны по-прежнему доступны только по подходящим подключённым ключам. Расчёт в чате не записывает коэффициенты магазина.

- Wildberries вернул фактические выкупы и возвраты. При повторе возвратов штатный исходящий запрос продолжился после HTTP 429.
- Рекламный отчёт Ozon подтвердил расход 4 272,80 ₽ за 19.11.2026. В выборке WB статистика получена для 18 из 21 активной кампании и 18 из 430 поддерживаемых. Пропуски оставлены неизвестными.
- Для длинных выгрузок окно выполнения продлевается при проверенном прогрессе. Доля потерь Ozon за 01.10.2026 рассчитана за 178,568 с. Прогноз доставки за тот же день завершился за 478,196 с после повторов ограничения площадки.
- Полный прогноз экономики Ozon за 19.11.2026 завершён за 99,174 с. Проверка 01.10.2026 завершилась по тайм-ауту на длинной сверке начислений за 745,511 с. Эти два результата относятся к разным периодам.
- Модель получает подсказки формул вместе с ответом выбранного шаблона. Для прогнозов отдельно показываются периоды и значения коэффициентов, для полной экономики и основание себестоимости. Контрольные значения конкретного магазина берутся из реестра статистики владельца.
- Прогон выполнен через обработчик с действующим подключением. Вызовов модели для перепроверки не было.

## Коэффициенты и нормативы «Кровь и Песок»

Источник — ветка «статистика» репозитория `MaksimUnimax/blood_sand`, редакция `agreed-statistics-r16`. Числа ниже относятся к одному магазину. В чатах Octoport подключены самостоятельные предварительные расчёты двух коэффициентов Ozon. Правила WB здесь служат основанием для обсуждения переноса.

| Ozon | Прямая и последняя доставка | (719 098,18 + 72 786,15) ₽ / 7 793 исходно заказанные единицы = 101,6148 ₽/шт. | 01.11.2025–31.10.2026 |

В прогнозе WB исходное количество умножается на годовую ставку прямой доставки. Резерв обратной доставки равен исходному количеству × доле потерь × стоимости обратного события. Комиссия при отсутствии исходного финансового факта равна текущей официальной ставке категории и схемы плюс утверждённая поправка. Годовая поправка пересчитывается по команде владельца. Для Ozon обратная доставка берётся по актуальному тарифу SKU и схемы.

Ожидаемые оставшиеся единицы равны исходному количеству N × (1 − доля потерь). В двух денежных сценариях основной делитель — N. Доля потерь применяется к обороту, исходной комиссии и себестоимости. Реклама и прямые доставки рассчитываются на исходной базе. Себестоимость 250 ₽ — указанное владельцем значение его магазина.

Длинный повтор за 01.10.2026. Ускорена сверка страниц за счёт повторного использования проверенных параметров одинакового запроса, с прежней проверкой полномочий и данных. Получены 52 ответа по начислениям и оба отчёта о реализации. Оставшийся отказ связан с отсутствующей котировкой товара или схемы доставки в текущем каталоге Ozon. Для 31.10.2026 выявлена другая причина. Код 38 в справочнике самого Ozon означает материалы для упаковки. Методика прогноза пока не определяет место этого начисления в расходах. Оба ограничения показываются в чате обычным текстом.

### Контроль охвата рекламных кампаний WB

Запросить одним сообщением детализацию активных кампаний, их итог и отчёт по всем поддерживаемым статусам за тот же день. Детализация и итог активных кампаний используют текущий статус 9. Расширенный отчёт оставляет группы 7 (завершены), 9 (активны) и 11 (на паузе) раздельными и показывает статус каждой строки. Кампании со статусом 4 (готовы к запуску) считаются отдельно в списке кампаний.

Архив до начала периода определяется по статусу 7 и дате последнего изменения WB в московском часовом поясе. Такие кампании выводятся отдельной строкой в разбивке охвата. Расширенный отчёт сохраняет строки статистики по любым поддерживаемым статусам, которые вернул WB. Статус относится к моменту запроса, метрики — к запрошенному периоду. Подтверждённая нулевая строка входит в охват. Кампании со списаниями проверяются отдельно по финансовому журналу. [Статусы и список кампаний WB](https://dev.wildberries.cn/docs/openapi/promotion)

На изолированном прогоне активный отчёт запросил два ID, исключив кампанию на паузе. Расширенный отчёт сохранил нулевую строку по кампании, которая уже была завершена до начала периода. Контроль включил завершение в полночь по Москве, чтобы не отнести эту кампанию к архиву до периода. Проверка проходит через компилятор, штатный декодер и ответ инструмента с подменой внешних ответов WB.

### Материалы для упаковки Ozon

В полном прогнозе материалы для упаковки Seller API `PackageCost` (тип 38) и услуга упаковки `PackingFee` (тип 39) учитываются отдельными строками. Матрица сверяет дебеты и корректировки между начислениями по отправлениям и начислениями по дням. Сумма по отправлению без SKU распределяется по исходным заказанным единицам. В обоих вариантах прогноза каждая статья имеет один и тот же размер и вычитается один раз.

В контрольном примере материалы стоили 10 ₽ после корректировки дебета 12 ₽ на 2 ₽. Услуга стоила 2 ₽ после корректировки дебета 3 ₽ на 1 ₽. На исходно заказанную единицу приходится 2,50 ₽ за материалы и 0,50 ₽ за услугу. В обоих сценариях общий расход вырос на 12 ₽, остаток уменьшился на 12 ₽. Расход типа 93 сохранён в прежней статье. При отсутствующей корректировке в одном из источников и при неизвестном типе начисления расчёт останавливается.

### Котировки для исходных заказов Ozon

При повторе 22 ноября общая выгрузка цен пропустила архивный SKU из исходных заказов. Seller API вернул карточку по точному SKU и действующую котировку по её product_id. Прогноз запрашивает карточки по SKU из исходных заказов и котировки по сопоставленным product_id. У каждого запроса проверяются область магазина, полнота ответа и соответствие всех идентификаторов. Если точная котировка отсутствует, полный прогноз останавливается.

При проверке объёма ответа с котировками принимаются поля `total_items` и `total` в переходный период Ozon. Если метод вернул оба поля, значения должны совпасть. В живом запросе Ozon вернул курсор даже после получения всех запрошенных котировок. Для запроса по точному списку полноту подтверждает совпадение всех ID и количества строк. Контрольный тест принимает котировку архивного SKU для FBO и отклоняет пустой ответ и сопоставление с другим SKU. [Изменение Seller API](https://dev.ozon.ru/news/801-Otkaz-ot-polia-total-v-metodakh-Seller-API/)

## Дополнительные read-only шаблоны

Карточка дополнительного шаблона в `platform_core/marketplace_matrix/read_templates.json` задаёт ID, профиль доступа, HTTP-метод, точный путь, назначение для поиска, версию источника, форму параметров и состояние. Используйте идентификаторы с площадки или из исходного вопроса. Проверяйте, что запросы с явным ID из другого магазина, неизвестным полем или неподтверждённым курсором отклоняются. Методы формирования файла, защищённые ответы и методы с отдельной авторизацией требуют собственной проверенной цепочки от запроса до выдачи результата владельцу.

Штатный чат открывает дополнительные карточки через `marketplace_read`. Для проверки отправьте вопрос без технического названия метода и отдельно запрос с точным методом. В обоих случаях сверьте выбранный ID, профиль ключа, URL без секретов и сопоставление полей с ответом API. Проверьте пустой ответ и ответ с большим количеством строк. Если в инструменте указаны пропуски, ответ чата должен описать доступную выборку и границы её полноты. Отдельно проверьте, что запрос без связанного магазина и запрос из другого чата отклоняются до HTTP-вызова.

В журнале отдельная строка на каждый прогон. Укажите режим, ревизию, шаблон, исходный вопрос, полный ответ, результат сверки, сквозное время, сумму из квитанции и её ID. Локальным тестам присваивается свой режим. Их измерения и ответы фикстур не закрывают строки сквозной приёмки. Сохраняйте текст прогона с данными продавца в закрытом журнале.

При возврате к сохранённому снимку матрицы восстановите байты каталога по его SHA-256, сопоставьте экспорт ID с выбранной ревизией и повторно проверьте наличие шаблонов через каталог чата. Восстанавливайте изменения каталога и его регистрации из соответствующей ревизии. Снимок содержит только данные шаблонов.
