# OpenRouter в Octoport

Техническое задание и дорожная карта от 21 ноября 2026 года. На этом этапе обследованы три сервера и подготовлен документ. Развёртывание и сквозная приёмка запланированы отдельно. Под «Алисой» здесь понимается сервер, на котором работает продовый веб-чат Octoport.

## Задача

Дать чату Octoport стабильный маршрут к выбранной пользователем модели OpenRouter. Алиса владеет настройками, ключом, диалогом, вызовами инструментов и списанием монет. Easyscript обеспечивает сетевой выход к OpenRouter. Второй экземпляр прокси на Easyscript обслуживает прод независимо от экспериментов со стендовым хабом.

**Путь запроса и ответа:** Алиса → выделенный прокси на Easyscript → OpenRouter → тот же прокси на Easyscript → Алиса → чат пользователя. Стенд 80 участвует в разработке, а прод работает при выключенном стенде.

## Как будет работать прод

Заданный владельцем результат — отдельный продовый роутер на Easyscript и перенос функций OpenRouter в настройки и админку Алисы. Ниже описан предлагаемый способ реализации, включая порядок выбора модели, защиту бесплатного тарифа и восстановление после сбоя. Эти изменения ещё не установлены.

1. **Сеть.** На Easyscript поднять отдельный экземпляр по образцу действующего CONNECT-прокси. Выделить ему службу, конфигурацию, порт и журнал. Свободный порт проверить при установке. Разрешить вход с подтверждённого исходящего адреса Алисы и назначение только `openrouter.ai:443`. Адрес сервера Алиса — 185.219.43.9. Перед заполнением списка разрешённых источников сверить фактический адрес тестового соединения, наблюдаемый на Easyscript, с учётом возможного NAT. Установить запрет по умолчанию для остальных источников, назначений и методов. Приложение Алисы само устанавливает TLS с OpenRouter внутри туннеля и проверяет сертификат. Easyscript пересылает байты в обе стороны. Использовать уже сохранённый на Алисе ключ и существующую форму его замены.
2. **Клиент на Алисе.** Выделить HTTP-клиент именно для OpenRouter, явно передать адрес нового прокси. Каталог для ключа (`GET /api/v1/models/user`), генерация (`POST /api/v1/chat/completions`) и сверка (`GET /api/v1/generation?id=…`) используют один маршрут. Отсутствующая или ошибочная настройка делает недоступным маршрут OpenRouter. Чат, настройки и прямой DeepSeek при этом открываются. Автоматический прямой выход к OpenRouter при отказе прокси исключить.
3. **Кто выбирает модель.** В качестве правила для общего значения предлагается явный выбор пользователя выше настройки администратора. Рабочие пространства без индивидуального выбора берут общий провайдер, модель и уровень рассуждения со следующего сообщения. В настройках нужна команда «Использовать по умолчанию». Сохранённый явный выбор, включая прямой DeepSeek, должен пережить обновление. Начатая операция использует тот же маршрут на всех модельных вызовах. Уровни рассуждения показывать по подтверждённым возможностям модели. Если настройка недоступна, интерфейс это объясняет, а клиент опускает соответствующий параметр.
4. **Чат и инструменты.** Алиса отправляет сообщения и описание доступных инструментов. Части потокового ответа поступают обратно через Easyscript. Вызов инструмента принимает агент на Алисе и выполняет его с действующими правами пользователя и чата. Результат передаётся выбранной модели для следующего шага. Ключи магазинов остаются в интеграциях Алисы. Для гостевого FAQ сохраняется действующий сценарий. [Потоковый ответ OpenRouter](https://openrouter.ai/docs/api-reference/streaming).
5. **Стоимость.** Каталог для ключа определяет доступные модели. Для платной операции действуют права, резерв, курс и расчёт по фактической стоимости OpenRouter. Для бесплатной проверять все заявленные ставки и запрашивать нулевой потолок цены. После исчезновения нулевого тарифа остановить новую бесплатную генерацию и предложить другой выбор. Положительная квитанция по согласованному нулевому тарифу требует сверки оператором и не создаёт списания пользователю. Токены кэша входят во входные токены провайдера, их нельзя прибавлять к полному входу второй раз. Сохранять ID генерации для восстановления пропущенной квитанции. [Метаданные генерации OpenRouter](https://openrouter.ai/docs/api/api-reference/generations/get-generation).
6. **Сбои и повтор.** Различать отказ соединения с Easyscript, отказ ключа, исчерпание средств, временный лимит и обрыв после принятия запроса. Для подтверждённого 429 до генерации продолжать ту же операцию после указанной провайдером паузы, показывая ожидание и позволяя отменить. Длительное ожидание переносить в возобновляемое состояние. На обследованном стенде для бесплатной модели есть ответ пользователю «Попробуйте позже», полноценное возобновление для OpenRouter предстоит реализовать. При неоднозначном обрыве восстанавливать квитанцию по известному ID и результат операции, если он сохранён. Без подтверждения исхода помечать операцию на сверку. Автоматический повтор уже выполненного инструментального действия или дублирующий платный запрос недопустим.
7. **Сведения для оператора.** В админке различать «ключ сохранён», «каталог получен» и «генерация прошла». Показывать время последней проверки, результат и краткую причину сбоя. В чате давать понятное действие, например «Модель временно занята, повторим запрос». Журналу достаточно номера операции, этапа, кода отказа и времени. Текст диалога и значения ключей в сетевой журнал не записывать.
