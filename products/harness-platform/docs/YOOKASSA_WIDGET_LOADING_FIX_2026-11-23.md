# Octoport · Зависшая загрузка встроенного виджета ЮKassa — исправление 23.11.2026

## Симптом

После создания боевого неоплаченного заказа на 1,30 ₽ внутри окна «Пополнить баланс» появлялись бесконечный индикатор загрузки в iframe ЮKassa и надпись «Загружаем защищённую форму…». При этом checkout backend создал и сохранил `confirmation_token`, а сам заказ оставался `pending`. Причина задержки находится в инициализации или загрузке клиентского виджета, **не в начислении монет**.

## Проверенные программные дефекты

1. Код на сайте создавал `new YooMoneyCheckoutWidget({...})` **без обязательного `return_url`**, хотя официальная документация ЮKassa указывает его как обязательный. Исправлено передачей `https://octoport.ru/payment/return`.
2. `await widget.render(...)` ожидал бесконечно при зависании/отсутствии ответа внешнего iframe. Никакого механизма тайм-аута, сообщения пользователю и перезапуска на том же заказе не существовало.
3. JS SDK загружался лишь после нажатия оплаты, что добавляло к времени открытия ещё один сетевой этап.
4. В разрешениях `connect-src` для пользовательского checkout-страницы отсутствовал `https://kassa.yandex.ru`, используемый официальным клиентом ЮKassa. Админка и общая безопасность сайта не расширялись.

**Граница доказательств:** эти дефекты подтверждены исходным кодом. Реальную сетевую ошибку внутри iframe на устройстве владельца без его браузерного журнала установить нельзя. Поэтому не утверждать, что каждый из дефектов был единственной причиной его конкретного зависания.

## Изменение

- Форма предварительно загружает официальный JS при открытии окна (без создания платежа).
- Загрузка JS ограничена 8 секундами, загрузка виджета `render()` — 11 секундами. Через 3,5 секунды пользователь видит предупреждение о медленном ответе ЮKassa.
- Если виджет не открылся, его DOM очищается, место пустого iframe скрывается и появляется кнопка «Повторить загрузку».
- Повтор использует **тот же `confirmation_token`, тот же `request_key` и не создаёт новый заказ**.
- В `error_callback` виджета показывается сообщение об ошибке. Консоль сообщает только категорию `widget_*` и длительность; платежные токены, ключи, ФИО, email, карта и полные provider URL не логируются.
- В CSP пользовательского shell добавлен `https://kassa.yandex.ru` для исходящих запросов виджета; административные страницы и глобальная политика сессии `SameSite=Strict` без изменений.
- Патч к фактически установленной кодовой базе: [YOOKASSA_WIDGET_LOADING_FIX_2026-11-23.patch](YOOKASSA_WIDGET_LOADING_FIX_2026-11-23.patch). Не применять автоматически к устаревшему `main`.

## Проверка

- Прогон: `tests.test_checkout`, `tests.test_web_ui`, `tests.test_account_access` — **21/21 PASS** на отдельной копии текущего релиза.
- Дополнительный статический тест — **1/1 PASS** (наличие `return_url`, 8/11-секундных тайм-аутов, кнопки повтора и разрешения CSP).
- Реальный headless Chromium с *синтетической* YooKassa-функцией: первый `render()` намеренно никогда не завершался. Через 11 секунд форма показала ошибку и кнопку повтора. Повтор вызвал `render()` во второй раз **на том же токене** без нового POST на создание платежа. Тест `MOCKED_TIMEOUT_RECOVERY_PASS`, ошибок JavaScript не было.
- Отдельная диагностика доступности SDK на опубликованном сайте (только заведомо тестовый недействительный токен, никакой оплаты): внешний JS загрузился за 1 081 мс, iframe `render()` — за 888 мс, ошибок сетевой загрузки нет. **Это не проверка работы настоящего платежа**.
- Реальные API `POST /api/coins/checkout` в тесте Chromium не вызывались (локальная синтетическая заглушка).
- Установлено на сервер: `/opt/harness-prod/releases/yookassa-embedded-loader-fix-20261123-f8bc772`. Сервис `harness-prod.service` активен.
- Smoke: `/`, `/about/`, `/payment/return`, `/ui-assets/project/checkout.js`, `/api/coins/quote` — HTTP 200; анонимная попытка начать платёж — 401.
- Перед/после: **один старый успешный платёж**, **один незавершённый**, ровно **одно начисление / 1 монета**, база `quick_check=ok`. Новых платежей и списаний не создавалось.

## Ручная приёмка владельцем

В уже авторизованном браузере обновить `https://octoport.ru/?coins=1#buy-coins` с очисткой кэша страницы (например Ctrl+Shift+R), открыть «Пополнить баланс» и нажать «Продолжить к оплате». Текущий pending заказ можно повторно открыть, **ничего оплачивать повторно не нужно**. Ожидается быстрая встроенная форма или, если сеть ЮKassa по-прежнему не отвечает, предупреждение через 3,5 сек и диагностическая ошибка с кнопкой повтора не позднее ~11–19 сек (в зависимости от того, что зависло: JS или iframe).

Не считать **реальную** загрузку ранее созданного токена в браузере владельца доказанной, пока владелец не проверит сам. Если ошибка сохраняется, запросить только сообщение/код ошибки и сетевые домены из DevTools без токенов/cookies, а не проводить новые платежи.

**Режим:** только боевой пилот администратора на 1 монету; общий запуск отключён. Фискальная процедура зачёта предоплаты требует отдельной приёмки.
