# Интеграция Telegram

## Подключение клиента

1. Войдите в Октопорт. В «Настройки → Интеграции» откройте список «Сервис» рядом с Ozon и Wildberries, выберите Telegram и нажмите «Подключить Telegram». Можно подключиться до установки любого плагина.
2. Выберите свой аккаунт в Telegram и разрешите боту писать вам. Октопорт сверяет подпись Telegram, отправляет проверочное сообщение и сохраняет подтверждённого получателя за вашим аккаунтом. При необходимости номер телефона вводится в форме Telegram. Вручную указывать ID или нажимать Start в чате с ботом не требуется.
3. Вернитесь в Октопорт. Подключение доступно в существующих и будущих диалогах этого аккаунта. Какие сообщения отправлять, определяют настройки каждого плагина.
4. Чтобы отозвать доступ у всех плагинов, в «Интеграциях» нажмите «Отключить Telegram для всех плагинов». При новом подключении подписки на отчёты включаются заново.

## Зависимости плагинов

| Компонент | За что отвечает |
|---|---|
| Интеграция Telegram | Авторизует клиента, подтверждает личный чат, хранит связь с аккаунтом и доставляет сообщение через бота. |
| Тестовый плагин «Отчёты в Telegram» | Читает новые готовые отчёты WB и Ozon из выбранного диалога и передаёт текст общей интеграции. |
| Будущий плагин-таймер | Хранит расписание, часовой пояс и выбранные источники. По расписанию собирает данные с предоставленным доступом и передаёт готовый результат той же интеграции. |

**Для тестирования отчётов.** Установите «Документы → Отчёты в Telegram» из каталога плагинов и подключите его в выбранном чате. Если Telegram уже связан, нажмите «Получать новые отчёты этого чата». Если связи нет, плагин показывает «Добавьте интеграцию Telegram в разделе „Интеграции“» и кнопку перехода в этот раздел. Удаление плагина сохраняет интеграцию для других потребителей. Подключение Telegram само по себе не даёт доступ к магазину и не включает рассылки.

**Для разработчика.** Серверный потребитель вызывает `await state.telegram.send(workspace_id, text)`. Берите `workspace_id` из проверенной области доступа текущего задания. Плагин проверяет собственное разрешение на отправку и права на источники. Интеграция сама определяет получателя этого аккаунта и возвращает `message_id` при подтверждённой отправке. При отсутствии привязки возвращается `DeliveryError("disconnected")`. Ошибки `blocked`, `limited`, `rejected` и `unknown` обрабатывает потребитель. После `unknown` повторная отправка может создать дубликат. Токен бота и Telegram ID не передаются плагинам или модели.

## Почему выбран Telegram Login

| Вариант | Действие клиента | Возможности |
|---|---|---|
| Telegram Login с разрешением на сообщения | Подтвердить подключение со страницы Октопорта | Основной реализованный сценарий. Бот может отправлять личные сообщения после согласия. |
| Ссылка на бота с одноразовым параметром start | Открыть бота и запустить его | Возможный резервный сценарий. Потребует обработчика входящих обновлений и подтверждения связи с аккаунтом Октопорта. |
| Ввод ID или @username | Ввести идентификатор | Сам по себе идентификатор не подтверждает владельца и не даёт боту разрешения на первое личное сообщение. |
| Упоминание гостевого бота в чате | Упомянуть бота | Telegram даёт ответить на конкретный вызов. Для подписки на будущие личные отчёты нужен отдельный допуск. |

## Подключение бота оператором

Один бот Октопорта обслуживает подписавшихся клиентов. Для каждого клиента хранится собственный приватный получатель. Для пилота подходит отдельный бот для отчётов. Подключение существующего бота возможно с согласия его владельца. Модуль выполняет исходящие запросы Bot API и не переключает webhook или getUpdates.

1. В [@BotFather](https://t.me/BotFather) выберите бота и откройте **Login Widget**. В единственном поле домена укажите `octoport.ru`. Для `@Octoport_bot` Telegram уже принимает этот домен. Адрес возврата `https://octoport.ru/telegram/return` подставляет сам Октопорт.
2. Настройте сетевой маршрут по инструкции ниже. На сервере приложения выполните `sudo /usr/local/sbin/octoport-telegram-setup` и в скрытом приглашении введите **Bot Token** из BotFather. Команда сверит ID и имя бота методом `getMe` через выбранный роутер и сохранит конфигурацию `auth_mode=widget` в `/etc/credstore/octoport-telegram.json` с правами 0600. В этом режиме достаточно одного токена. Из него сервис выводит ключ для проверки подписи Telegram. Если токен был раскрыт в переписке, перевыпустите его в BotFather перед включением личных отчётов.
3. В удобный момент после завершения активных запросов и задач плагинов перезапустите `harness-prod.service`. systemd передаёт службе закрытую конфигурацию через `ImportCredential=octoport-telegram.json`. При замене только сетевого узла этот шаг не требуется. Для отдельного стенда приложение также поддерживает `HARNESS_TELEGRAM_CONFIG_FILE` и `LoadCredential` с явно заданным файлом.
4. На обоих HTTPS-прокси отключите access log в точном маршруте `/telegram/return`. Страница обрабатывает подписанный профиль Telegram и одноразовое состояние запроса. Приложение возвращает `Referrer-Policy: no-referrer` и убирает код из адресной строки. Для проверки откройте страницу возврата без параметров — она должна сообщить об отмене подключения и предложить вернуться в Октопорт.
5. Проверьте полный сценарий ниже с владельцем тестового аккаунта. Одобрение подключения требуется от самого получателя.

## Рабочий маршрут и смена серверов

Роль **сервера приложения** — хранить ключи бота, подтверждённого получателя, подписки на диалоги и очередь отчётов. Роль **роутера Telegram** — принимать CONNECT от разрешённых серверов Октопорта только к `oauth.telegram.org:443` и `api.telegram.org:443`. TLS устанавливает само приложение и проверяет сертификат Telegram. Ответ возвращается по тому же соединению. Публичная страница входа открывается в браузере клиента напрямую. Маршрут и службы используются общей интеграцией Telegram.

| Что меняет оператор | Где и что указать | Как применить |
|---|---|---|
| IP, DNS-имя или порт роутера | На сервере приложения в `/etc/harness-prod/telegram-route.env` задайте `TELEGRAM_ROUTER=имя-или-IP:порт` | Перезапустите только `octoport-telegram-route.service`. Проверьте оба адреса Telegram по инструкции ниже |
| IP сервера приложения | На роутере в `/etc/octoport-telegram-router/route.env` измените `TELEGRAM_APP_SOURCES`. Используйте исходящий IP, который видит роутер после NAT. Несколько отдельных адресов указываются через пробел в двойных кавычках | Перезапустите `octoport-telegram-router.service`. При переезде сначала разрешите оба источника, проверьте доступ с нового и затем удалите старый |
| Интерфейс или порт прослушивания | Там же задайте `TELEGRAM_LISTEN=локальный-IP:порт` | Перезапустите службу роутера. При смене опубликованного адреса обновите и `TELEGRAM_ROUTER` на стороне приложения |
| Только локальный порт приложения | На приложении сокет слушает `127.0.0.1:18765`. При конфликте выберите свободный порт в override для `ListenStream` (сначала очистите старое значение) и в `/etc/harness-prod/telegram-connect-port` | Выполните `daemon-reload`, перезапустите локальную службу и сокет, обновите `connect_proxy_port` в закрытой конфигурации и перезапустите приложение |

Для смены роутера сначала подготовьте новый узел с разрешением для действующего приложения. Перед переключением дождитесь завершения активных отправок. Запишите прежнее значение `TELEGRAM_ROUTER`. После переключения выполните обе сетевые проверки и проверьте один согласованный отчёт. Для отката верните прежнее значение и перезапустите только локальную службу маршрута. При недоступном роутере подключения через настроенный порт завершаются ошибкой. Приложение сохраняет учётную запись и подписки. Перенос самого сервера приложения требует штатного переноса состояния и секретов Октопорта. Смена только IP или транспорта повторного согласия клиента не требует.

### Установка на другом узле

Шаблоны находятся в [deploy/telegram](../../../deploy/telegram). Для роутера используется Apache 2.4 с модулями `mpm_event`, `authz_core`, `authz_host`, `proxy` и `proxy_connect`. На сервере приложения используется штатный `systemd-socket-proxyd`. Параметры ниже задаёт оператор конкретной установки. Команды выполняются из каталога шаблонов с правами root на соответствующем узле.

**На роутере.** Создайте каталог `/etc/octoport-telegram-router/empty` с правами 0755. Установите `telegram.conf` в `/etc/octoport-telegram-router/`, а `octoport-telegram-router.service` — в `/etc/systemd/system/`. Запишите `TELEGRAM_LISTEN` и `TELEGRAM_APP_SOURCES` в `/etc/octoport-telegram-router/route.env` с правами 0600. Ограничьте список исходящими адресами серверов приложения. Затем запустите службу.

```sh
systemctl daemon-reload
systemctl enable --now octoport-telegram-router.service
```

**На сервере приложения.** Установите `octoport-telegram-route.socket` и `octoport-telegram-route.service` в `/etc/systemd/system/`. Установите `telegram-reports.conf` в `/etc/systemd/system/harness-prod.service.d/`, а `setup.py` — как `/usr/local/sbin/octoport-telegram-setup` с правами 0700. Запишите `TELEGRAM_ROUTER` в `/etc/harness-prod/telegram-route.env` с правами 0600 и число `18765` в `/etc/harness-prod/telegram-connect-port`. Активируйте локальный сокет.

```sh
systemctl daemon-reload
systemctl enable --now octoport-telegram-route.socket
```

**Проверка с сервера приложения.** В обеих командах используйте фактический локальный порт. Первая возвращает JSON с открытыми ключами Telegram, вторая показывает ответ узла Bot API. Для чужого назначения и источника вне списка роутер должен вернуть CONNECT 403. Проверка доступа к API не отправляет сообщений клиентам.

```sh
curl --noproxy '' --proxy http://127.0.0.1:18765 --max-time 10 -fsS https://oauth.telegram.org/.well-known/jwks.json
curl --noproxy '' --proxy http://127.0.0.1:18765 --max-time 10 -sS -o /dev/null -w 'CONNECT %{http_connect}, HTTP %{http_code}\n' https://api.telegram.org/
```

## Контракт доставки

- Получатель принадлежит одному workspace и одному боту. Подмена адресата через форму или запрос модели не предусмотрена. При замене аккаунта Telegram сначала отключают прежнюю привязку. Для старых подписок требуется новое согласие.
- Подписка начинается с текущей позиции в серверном журнале чата. После перезапуска курсор сохраняется. Удаление чата или отключение плагина удаляет его подписку. Удаление плагина сохраняет привязку Telegram. Отключение интеграции удаляет подписки всех чатов этого аккаунта. Сообщение, уже переданное в Telegram до отключения, может дойти.
- Для отправки нужны завершённый ход, настоящий вызов инструмента маркетплейсов, его успешный результат с данными и последующий итоговый текст ассистента. Одного вопроса со словом «отчёт» недостаточно. Для отправки используется только финальный текст отчёта. Служебные аргументы, промежуточные ответы инструмента и обычные реплики остаются в Октопорте. Если проверка обнаружила в итоговом тексте распознаваемый ключ, доставка этого ответа пропускается.
- Короткий отчёт приходит личным сообщением. Для текста, превышающего 4096 единиц UTF-16, бот отправляет один UTF-8 файл `octoport-report.txt`. Текст отправляется без интерпретации HTML или Markdown, предпросмотр внешних ссылок в сообщении выключен. Получение message_id подтверждает принятие Telegram. Отметку прочтения клиента Bot API здесь не предоставляет.
- Опрос работает внутри существующей службы. В обычном режиме новые отчёты проверяются примерно раз в 12 секунд. Время может увеличиваться из-за нагрузки, сети и ограничений Telegram. При подтверждённом 429 сохраняются позиция и retry_after. Если результат HTTP-вызова неизвестен, автоматическая повторная отправка этого отчёта прекращается. В настройках клиент может продолжить со следующего отчёта, сохранив очередь более поздних. После блокировки бота нужно заново разрешить доставку.
- Нажатие кнопки создаёт одноразовое состояние, привязанное к сессии Октопорта, аккаунту и боту. Октопорт открывает отдельную страницу с официальным скриптом Telegram. Атрибут `data-telegram-login` содержит проверенное имя бота, `data-request-access="write"` запрашивает разрешение писать, `data-auth-url` задаёт адрес возврата с состоянием запроса. Скрипт загружается только при подключении Telegram. На форме Telegram пользователь подтверждает свой аккаунт и разрешает сообщения. Если Telegram запрашивает номер, он вводится на стороне Telegram. Октопорт сверяет HMAC-SHA-256 подписанного профиля и время `auth_date`, отклоняет повторно использованное подтверждение и использует подписанный числовой `id` как получателя. Интеграция сохраняет привязку после принятия проверочного сообщения Telegram.
- Ранее настроенные установки OIDC с `client_secret` сохраняют прежний Code Flow с PKCE, nonce и проверкой ID Token. Новый установщик выбирает доменный виджет явно.

## Приёмка и дальнейшая работа

Автоматические сценарии находятся в `tests/test_telegram_reports.py` и `tests/browser/test_telegram_browser.py`. Они используют временные данные и тестовые ответы Telegram. Проверяются подпись виджета, срок действия, однократность подтверждения, PKCE и подписанный ID Token, изоляция получателя, повтор и отмена привязки, прежние отчёты, длинные сообщения, 429, неопределённый результат и возобновление. Chromium проходит обычный каталог, настройки, возврат с другого сайта и остановку доставки.

Для боевой приёмки используйте отдельный аккаунт Октопорта и согласованный Telegram. Проверьте согласие без Start, первое нейтральное сообщение, один новый отчёт выбранного чата и источник в Октопорте. Затем проверьте второй диалог с выключенной подпиской и отключение доставки. Фактическую доставку проверяет получатель в своём Telegram.

В первой версии отчёт можно запросить обычным способом в чате. Планировщик ежедневных и еженедельных отчётов — следующий этап. Для него нужно выбрать отчёт и магазин, часовой пояс, время и дни доставки. Формирование отчёта остаётся у таймера и матрицы, а отправку готового результата выполняет общая интеграция Telegram. Отдельная задача — прикладывать подготовленные исходным плагином PDF/XLSX.

### Фактическая проверка 21 ноября 2026 года

Первая установка использует Alisa как сервер приложения и Easyscript как роутер Telegram. Параметры этой установки — `TELEGRAM_ROUTER=78.17.68.165:19443`, `TELEGRAM_LISTEN=78.17.68.165:19443`, `TELEGRAM_APP_SOURCES=185.219.43.9/32`. Они хранятся в конфигурации развёртывания. С Alisa через локальный сокет получены публичные ключи Telegram и ответ Bot API. На запрещённое назначение и на запрос с другого исходящего адреса роутер вернул 403. Сайт Октопорта отдал страницу возврата и её скрипт с HTTP 200. Telegram открыл для домена форму входа с именем Octoport. Реальная доставка личного сообщения требует рабочего Bot Token и подтверждения получателя.
