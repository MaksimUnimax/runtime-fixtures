База source-diff: [YOOKASSA_EMBEDDED_2026-11-23.patch](YOOKASSA_EMBEDDED_2026-11-23.patch). Патч применим к указанному установленному source baseline, НЕ к произвольному commit из `main`.

Изменено только:
- `platform_core/checkout.py`: новые платежи `confirmation.type=embedded` / `confirmation_token`, авторизация владельца, повторное использование подтверждения, старые `redirect` платежи остаются совместимыми, серверная проверка статуса и однократное зачисление сохраняются;
- `platform_core/coins.py`: новая вспомогательная таблица `coin_checkout_widgets` для токена незавершённого заказа, без `ALTER TABLE` существующих финансовых записей;
- `platform_core/native_web.py`: CSP только пользовательского shell разрешает официальные скрипты, iframe и сетевые адреса виджета; `frame-src` отделён от `form-action` отдельной точкой с запятой; политика админки не расширена;
- `native/web/checkout.js`: оплата внутри того же `dialog`, отдельная загрузка официального скрипта, события завершения, ручная проверка и сохранение idempotency key; после подтверждения нет полной перезагрузки чата;
- `native/web/checkout.css`: окно и внутренний контейнер в цветах и типографике Octoport, светлая/тёмная темы, узкие экраны;
- `native/web/account.js`: событие `octo-wallet-refresh`, чтобы обновлять баланс после оплаты без перезагрузки чата;
- `tests/test_checkout.py`: проверки создания embedded-платежа, повторного использования токена, отсутствующего токена при GET, защиты от двойного начисления и CSP.

Включение боевого пилота **не расширялось**: `YOOKASSA_PILOT_ONLY=1`, `YOOKASSA_PAYMENTS_ENABLED=1`. Платёж может инициировать только администратор, только на 1 монету за 1,30 ₽. Остальным операция отклоняется сервером, даже при прямом обращении.

## Ручная приёмка владельца — следующий шаг

1. Войти администратором в [Octoport](https://octoport.ru/?coins=1#buy-coins).
2. Нажать `Купить монеты` / `Оплатить` для одной монеты. Ожидается встроенная форма ЮKassa внутри окна Octoport, **без перехода на отдельную страницу ЮMoney**.
3. Оценить светлую/тёмную тему, ширину, контраст, СБП, мобильный экран. Оплата не обязательна для проверки дизайна; создание pending-платежа не списывает деньги само по себе.
4. Для сквозного теста пользователь самостоятельно подтверждает НОВЫЙ платёж в банке; после этого проверяем чек, уведомление и однократное пополнение.
5. Если форма не появилась: открыть консоль браузера, передать ошибку CSP/виджета, без передачи `confirmation_token`, cookies или секретов.

**Не объявлять пройденным реальный браузерный E2E встроенной формы без этой ручной проверки.** Полный коммерческий запуск для всех пользователей остаётся отдельной приёмкой с юридически корректным зачётом предоплаты при фактическом расходовании монет.
