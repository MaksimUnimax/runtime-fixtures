# Работа оператора хаба

Откройте «Администрирование → Хаб моделей». «Требуются ключи» показывает модели, для которых в хабе ещё нет ключа ни одного известного прямого поставщика. Варианты для одной модели взаимозаменяемы на этапе регистрации. Новая неизвестная модель появляется в кандидатах для исследования.

Выберите поставщика, укажите узнаваемую метку и введите секрет. Повторная запись под той же меткой заменяет ключ. Секрет шифруется на сервере существующим хранилищем установки. В списке остаются только поставщик и метка. Статус «Ключ сохранён» подтверждает сохранение. Для допуска к клиентскому трафику нужна отдельная прямая проверка.

Каталог обновляется службой octoport-hub-catalog каждые 15 минут. Кнопка «Обновить показания» перечитывает состояние сервера. При отказе каталога на экране остаются последний успешный снимок, время попытки и причина сбоя.

Исследователь запускается командой `python -m platform_core.hub_research --database <путь-к-БД-хаба>` из каталога продукта. Он передаёт второй серверной авторизации Codex до четырёх публичных ID за запуск. Источники перепроверяются через семь дней. При сбое последняя успешная проверка сохраняется. Вывод исследователя носит справочный характер. Он не может изменить цену, разрешить маршрут, получить ключ из формы или выполнить запрос маркетплейса.

Обе команды и веб-приложение должны использовать одну базу. В поставляемых unit-файлах это /var/lib/octoport-model-hub/model-hub.sqlite3. Для веб-службы задайте HARNESS_MODEL_HUB_DATABASE с этим путём и StateDirectory=octoport-model-hub дополнительно к существующему каталогу состояния. По умолчанию тестовое приложение ищет базу рядом с базой аккаунтов. Таймер исследования запускается каждые 30 минут. Команда каталога выполняется от пользователя приложения. При запуске исследователя с правами владельца профиля файл базы должен быть предварительно создан сервисным пользователем. Профиль codex2 уже авторизован на узле 80. При недоступной авторизации проверять статус штатной командой `codex2 login status`.

Приёмка прямых адаптеров, статистики ключей и автоматического переключения описана в [дорожной карте](ROADMAP.md).

## Прямые вызовы чата и матрицы

На стенде включается HARNESS_HUB_INFERENCE=1. Реестр маршрутов читается из deploy/model-hub/direct-routes.json или пути HARNESS_HUB_ROUTES_FILE. Общий HTTP-клиент идёт через настраиваемый роутер. Для нового API добавьте разрешённый домен на роутере. Для Google нужен также aistudio.google.com для чтения опубликованного тарифа. Смена адреса сервера меняет только конфигурацию установки.

Таймер octoport-hub-health проверяет очередь примерно каждые две минуты. Успешный маршрут повторно проверяется через десять минут, отказавший — по истечении его паузы. Перед каждым обращением хаб заново проверяет прямой тариф. Для Atlas проверяются все ставки точного идентификатора в /v1/models. Ответ 402 снимает маршрут с выдачи. Для Cloudflare требуется полный ответ списка подписок и подтверждённый Workers Free. При 403 на чтение подписок нужен Account Billing Read. Тариф Google Gemma проверяется по тарифной таблице Google. Пробный вызов проверяет название инструмента и аргументы, второй проверяет ответ по вымышленным данным. Рейтинг v1 начисляет до трёх баллов за один двухэтапный пример. Окна статистики в админке показывают число наблюдений, p95, наблюдаемый простой и отказы. На пилоте эти оценки предварительные.

В настройках ИИ «Хаб Octoport» показывает маршруты, прошедшие прямую проверку. Автовыбор и конкретная предпочитаемая модель применяются к чату и матрице. Публичный текст и выполнение инструмента проверяются независимо. Для публичного режима передаётся только последний текст пользователя. В остальных режимах после отказа хаб пробует другой ключ той же модели, затем доступную модель по мощности и стабильности. Если все маршруты отказали после получения данных, кнопка «Продолжить запрос» повторяет ту же операцию. Зашифрованная контрольная точка действует 24 часа с прежними правами на магазины. Стоимость режима в кошельке равна нулю.

Бесплатные проекты Google по умолчанию доступны только для публичных вопросов. Условия обработки данных для конкретного проекта проверяет администратор. Он может подтвердить применимость условий обработки Paid Services на 30 дней. Замена ключа снимает подтверждение. Включать платный биллинг для этой проверки не требуется. Для Atlas минимальное пополнение составляет 25 долларов. На пилоте с бюджетом 2 доллара и ответом 402 этот резерв недоступен.
