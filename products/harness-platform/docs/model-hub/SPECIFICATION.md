# Хаб моделей Octoport. Техническое задание

Решение владельца от 21 ноября 2026 года. Пользователь с нулём монет выбирает хаб для работы в чате и с матрицей WB/Ozon. Octoport вызывает API выбранной компании своим ключом. OpenRouter служит публичным источником новых кандидатов. Существующие подключения DeepSeek и OpenRouter управляются в основной админке.

## Каталог и оператор

1. По расписанию читать публичный каталог OpenRouter. Для чата отбирать текстовый ответ с вызовом инструментов и известными нулевыми ставками, включая дополнительные виды токенов и плату за запрос. Проверять название, идентификатор модели, фактического поставщика и возможные прямые варианты. Автор модели и хостинг могут быть разными компаниями.
2. Одна серверная авторизация Codex через существующий профиль codex2 выделена для исследования кандидатов. На вход идут публичные идентификаторы. Результат содержит ссылку на официальный источник, прямой ID модели, условия, срок акции, наличие ключа для регистрации и дату проверки. Данные от сайтов считаются данными. Обычный сбой Codex не останавливает уже проверенные маршруты.
3. Сопоставлять найденную модель с известными прямыми маршрутами и реестром ключей. Собирать максимально широкий набор независимых поставщиков. Если ключ конкретного поставщика уже сохранён, запрос на него закрывается. Другие поставщики той же модели остаются в списке задач. Исследование сохраняет отдельный результат по каждой паре модели и поставщика. Для поставщика с несколькими моделями выводить одно уведомление со списком. Предложение исследовать нового поставщика и сигнал «добавить ключ» различаются. Секрет создаёт оператор в кабинете поставщика и вводит только в защищённой форме хаба.
4. В разделе «Администрирование → Хаб моделей» показывать время последней попытки и успешного обновления, ошибки каталога, кандидатов, ключи без секретных значений, тарифы, проверки, ограничения, статистику, рейтинг и историю переключений. При ошибке каталога сохранять последний успешный снимок. Исчезновение из каталога прекращает новые уведомления по кандидату. Жизненный цикл подключённого маршрута определяется прямыми проверками.
5. Различать ключ, аккаунт поставщика, маршрут и модель. Один ключ может обслуживать несколько моделей, один аккаунт может иметь общую квоту, одна модель может работать у нескольких поставщиков. У каждого ключа есть несекретная метка. Оператор может заменить, отключить и отозвать ключ.

Решение владельца от 21 ноября. Dots Studio и Atlas Cloud исключены из предложений регистрации для проекта, включая повторное появление под другим именем после обновления каталога. Оператор видит причину в админке. Действующие ключи и проверки маршрутов сохраняются. Независимый хостинг тех же весов рассматривается отдельно.

## Независимая проверка и выбор

| Событие | Действие |
| --- | --- |
| Новая модель, акция или бесплатная квота | Проверить прямую цену и дополнительные сборы, разрешённую нагрузку, срок, обработку данных, контекст и вызов инструмента. При конечной квоте нужен режим без платного превышения. |
| Истёк срок подтверждённого тарифа, включена оплата или цена неизвестна | Немедленно снять маршрут с бесплатной выдачи. Проверку срока выполнять и при выборе маршрута. |
| Ошибка авторизации | Снять соответствующий ключ, отразить отказ в админке. Различать отзыв ключа и запрет для одной модели. |
| Исчерпана квота | Снять затронутый ключ или весь общий лимит аккаунта до разрешённого времени. Соблюдать Retry-After. |
| Тайм-аут, ошибки сервера, рост задержки | Записать причину и длительность. Временно вывести перегруженный маршрут из выдачи и выбрать следующий. После паузы проверить возврат отдельным безвредным запросом. |
| Отсутствуют пригодные маршруты | Сохранить состояние отчёта, показать причину и возможность продолжить. Платное обращение и списание монет в этом режиме исключены. |

Хаб проверяет тариф у поставщика, отдельно проверяет ответ конкретного ключа и учитывает исходы реальных вызовов. Для синтетической проверки используются вымышленные данные. Счётчики проверок и пользовательских запросов разделены. Успешный HTTP 200 сам по себе не подтверждает цену или способность вызвать инструмент.

Статистика по ключу и маршруту включает количество попыток, долю успеха, периоды недоступности и их длительность, число отказов по причинам, время восстановления, задержку p95, занятые слоты и срок сброса квоты. Для рейтинга показывать окна 24 часа и 7 дней, размер выборки и дату последней проверки. Непроверенный маршрут получает статус «Проверяется».

Сначала отбирать доступные для данного клиента маршруты с действующим бесплатным тарифом, подходящими возможностями и свободной ёмкостью. Внутри отбора первым критерием служит **мощность модели**, вторым — **стабильность ключа и маршрута**. Сильная жёлтая опережает слабую зелёную. Среди равных по мощности зелёная опережает жёлтую. Красные и непроверенные маршруты направляются на повторную проверку. Шкалу мощности калибровать по правильности выбора шаблона WB/Ozon, аргументов вызова и ответа по эталонным данным. Показывать версию оценки и размер выборки. Пороги цветов и окно для возврата откалибровать на пилоте.

Выбранную пользователем модель закрепить за операцией, включая селектор матрицы и окончательный ответ. При отказе сначала пробовать доступный ключ той же модели, затем лучшую пригодную замену. При смене модели записывать причину и продолжать с последней завершённой стадии. Уже выполненный запрос маркетплейса повторно не отправлять. На повторе пользовательской команды использовать прежний идентификатор операции.

## Приёмка владельцем

- Одинаковый снимок каталога обработан дважды, уведомление одно. Добавление ключа одной компании покрывает все сопоставленные модели. Повреждённый ответ не стирает снимок.
- Отключение OpenRouter и Codex оставляет доступной проверенную прямую модель. Прямое изменение цены и отзыв ключа вызывают переключение независимо от OpenRouter.
- При одинаковой работе чата и матрицы записаны модель, поставщик, несекретная метка ключа, этап, причина переключения и нулевая стоимость. Секреты магазинов, ключи поставщиков и данные отчёта не попадают в мониторинг.
- На тестах сильная жёлтая выигрывает у слабой зелёной, отказавшая сильная пропускается, два процесса не занимают последний слот одновременно. Потеря ответа после успешного запроса к магазину не создаёт второй запрос.
- Администратор видит хаб отдельно. Пользователь и гость не получают доступ к его ключам и статистике. В основной админке работают прежние формы DeepSeek и OpenRouter.
