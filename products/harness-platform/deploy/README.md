# Публичный выпуск Harness

В этой сборке гостевой чат использует локальную базу ответов. После регистрации доступны личные чаты, вход, выход и кошелёк. Выдача тестовых монет и просмотр себестоимости по логину доступны администратору. Образцы архивов маркетплейсов используются при проверке сборки. Новый кабинет открывает каталог подключений Ozon, Wildberries и Яндекс Вордстат. Список магазинов заполняет владелец аккаунта.

## Развёртывание

Служба `harness-prod` использует отдельные каталоги кода и состояния. Код находится в `/opt/harness-prod/releases/<revision>`, символьная ссылка `/opt/harness-prod/current` выбирает выпуск. Для нового выпуска установите зависимости Python по `requirements.txt` и закреплённый Node-рантайм с `@deepseek-ai/dsh@0.2.2-rc.1`. Служба использует их из `/opt/harness-prod/runtime/v1`. Первоначальная раскатка использует проверенную копию пакетов с сервера. Секрет реле предоставляет systemd. Реле на loopback обращается к DeepSeek. Расход и резерв считает шлюз продукта.

При первой установке создайте /etc/harness-prod с правами 0700. Запишите в новый файл /etc/harness-prod/integrations.key 32 случайных байта с правами 0600. Храните его резервную копию отдельно от базы аккаунтов. При обновлении используйте существующий ключ. Systemd передаёт его процессу службы через LoadCredential.

Базовая конфигурация сразу работает с прямым DeepSeek. Дополнительный ключ OpenRouter подключается только по решению оператора. Инструкция по включению, возврату к одному DeepSeek и сохранению истории находится в [архитектуре](../docs/ARCHITECTURE.md#отключаемый-шлюз-моделей).

Запустите службу из `harness-prod.service` после проверки конфигурации на сервере. Для публичного узла требуется сертификат имени из конфигурации nginx. Директива HTTP для ACME использует webroot `/var/www/harness-public-acme`. После установки сертификата проверьте `nginx -t` и перечитайте конфигурацию. После продления сертификата nginx должен перечитать его. Файлы базы и сессий остаются в `/var/lib/harness-prod`. Перед сменой схемы сделайте консистентный снимок состояния. Для возврата совместимой версии переключите ссылку current на предыдущую ревизию и перезапустите только службу продукта.

## Проверки владельца

1. В новом профиле откройте главную страницу `/`. Спросите «Что ты умеешь?», затем «Сколько продаж за вчера?». Первый ответ описывает сервис, второй возвращает к тематике справки.
2. В гостевом чате откройте регистрацию. Сохраните код восстановления, введите новый логин и пароль. После регистрации откроется тот же чат с перепиской.
3. Под обычным аккаунтом с нулевым балансом откройте новый чат и отправьте вопрос. Появится сообщение о нехватке монет. Вторая вкладка с открытым первым чатом сохраняет свою историю.
4. В другом профиле браузера войдите администратором. Откройте «Администрирование» (`/admin`), укажите логин обычного аккаунта, сумму 3 и основание. Нажмите «Начислить монеты». Обновите страницу обычного аккаунта и проверьте остаток.
5. Под обычным аккаунтом отправьте «Ответь одним словом: готово». После ответа в кошельке появляется списание. Запишите остаток и обновите страницу. Остаток и число списаний сохраняются.
6. Администратор вводит логин в «Логин для просмотра расходов» и нажимает «Показать расходы». В списании откройте «Расход DeepSeek». Проверьте счётчики и стоимость. Списание в монетах равно рублёвой себестоимости. При наценке покупки 20% цена монеты составляет 1,20 ₽.
7. Откройте адрес личного чата из другого обычного профиля. Сервис возвращает 404. После выхода приватная страница требует повторного входа.

## Публичные адреса и управление ключами

Основной адрес https://octoport.ru/ открывает Harness. Администрирование доступно на /admin. Раздел «О сервисе» собирается из public-info и публикуется в /about/ вместе с локальными ресурсами. Старые информационные адреса ведут к соответствующим страницам. Алиса использует отдельные виртуальные хосты. Для публикации запустите deploy/publish_info.py с каталогом исходных брендовых изображений сайта и каталогом информационных выпусков; фрагмент deploy/octoport-edge.inc входит только в HTTPS-конфигурацию корневого домена. Связь двух серверов проверяет сертификат origin.

В /admin у каждого провайдера отдельное поле ввода. Чтобы загрузить ключ через SSH, выполните с компьютера оператора:

```shell
ssh -t root@185.244.51.141 "/opt/harness-prod/runtime/v1/venv/bin/python /opt/harness-prod/current/products/harness-platform/platform_core/provider_keys.py openrouter"
```

На новом сервере сначала задайте прямой ключ тем же способом с параметром deepseek. Введите ключ в скрытом приглашении. Параметр deepseek меняет прямой ключ. После первой загрузки OpenRouter обновите страницу Harness для появления выбора ИИ.


### Оформление связанных кабинетов

В каталоге deploy/alisa-ui находятся таблицы стилей и включаемые фрагменты для действующих виртуальных хостов. Для alisa.octoport.ru, alisa-admin.octoport.ru и id.octoport.ru подключите assets.conf на уровне HTTPS-сервера и html.conf внутри действующего прокси страниц, включая обе страницы станции. Для app.octoport.ru используются portal-assets.conf и portal-html.conf. Ресурсы обслуживаются с того же домена из /var/www/octoport-ui. Опубликуйте favicon.png из native/web/octoport-icon.png и octoport-wordmark.svg из native/web. Для theme.css и portal.css сначала включите содержимое native/web/appearance.css, затем одноимённого файла из deploy/alisa-ui. Публикация /about/ объединяет стили автоматически. После nginx -t перечитайте конфигурацию. Пути API, прокси авторизации и процессы приложений сохраняют свои настройки.
