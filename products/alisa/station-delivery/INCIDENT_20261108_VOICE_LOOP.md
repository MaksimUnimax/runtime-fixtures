# Incident: Station voice callback loop, 2026-11-08

At 10:59–11:01 UTC the Quasar scenario opened the Alice skill with a full command such as `спроси октопорт маркет доставка <nonce>`. The Station ingress only recognized `доставка <nonce>`. The unrecognized full invocation went to the ordinary DeepSeek analytics route as a new question. Each resulting READY job launched another Quasar scenario, causing a loop. Thirteen new jobs were observed in approximately 90 seconds. The underlying model calls in this loop returned HTTP 200; this incident was not an HTTP 429 or a provider retry.

The automatic Station sidecar was stopped at 11:01 UTC; the analytics worker remained active. In release `station-auto-r5-voice-route`, ingress recognizes the exact full skill invocation, routes the nonce to the bound job, and returns the existing READY answer without creating an analytics job. Unbound/invalid internal commands return a direct denial. Ingress exceptions for an internal voice command fail closed with a reply, not a gateway command. The admin form explains `{remaining}` and gives an example. No user QR reauthorization or account rebinding was performed.

Verification: 29 Station unit tests passed, including the skill adapter through Station callback with an assertion that DeepSeek is never called, the full Quasar phrase, unbound command, and Unix socket failure; the 10-second ETA test passed. The service was restarted at 11:05:48 UTC and the admin page returned its expected login redirect. At 11:06:40 UTC there had been no new jobs since reactivation. A physical Station end-to-end acceptance is still required: speak one analytical request, hear initial ETA and periodic remaining-time phrase if running, then hear the exact final report once. The configured interval at verification was 25 seconds (owner setting); we did not overwrite it.

Related 429 handling in the currently active runtime `alisa-runtime-method-semantics-r1-20261108`: all Worker provider/model calls route through `_call`, which records calls, preserves provider `Retry-After`, and reschedules the same job for known HTTP 429 with increasing pause up to 900 seconds. There is no local daily quota in the active Worker path. HTTP 401/403 deny the affected source, known other errors fail the job, and unknown transport outcomes do not retry blindly. Store credential checks use a separate rate-limited status path. The Station callback loop above produced HTTP 200 model calls and was unrelated to 429.

User check: [admin settings](https://alisa-admin.octoport.ru/admin/station/) and [customer Station connection](https://alisa.octoport.ru/app/station/). Confirm the current interval and `{remaining}` help, then make one physical voice request. Do not infer physical speech from Quasar action acceptance alone.
