# RT-CHECK v1 · platform client contract

**PROPOSED, runtime-side integration required.** This is separate from report-submit and RT-JOB. Do not send this envelope to the existing gateway.sock. The product includes the client only; it does not add an analytical transport or modify Engine/SQLite.

One UTF-8 JSON line, max 32768 bytes including newline, over `/run/alice-market/store-check.sock`. Client pins server UID with SO_PEERCRED before sending credentials; runtime must pin platform UID before reading. Socket and parent are private to those services. No browser-supplied address, URL or filesystem path. Hard client deadline 3 seconds, bounded response, no redirects/HTTP in this client and no automatic retry.

Request fields are exactly `schema_version="rt_check_v1"`, `operation="check_store"`, `pins`, `credential`. Pins: `environment`, `product_id="alisa_market"`, tenant/store UUIDs, provider OZON/WB, kind SELLER/PERFORMANCE/WB, positive credential/store revisions, request UUID. Identity and tenant come from the authenticated platform session, not browser scope. Credential fields are SELLER `{client_id,api_key}`, PERFORMANCE `{client_id,client_secret}`, WB `{token}`. Secrets are transient only: no logs, metrics labels, audit, result, error text or persistence in runtime.

Response fields are exactly `schema_version`, unchanged `pins`, `result`. Non-success result is exactly `{code}` where code is AUTH_DENIED, SCOPE_MISSING, TIMEOUT, RATE_LIMITED, CHECK_UNAVAILABLE, PROVIDER_UNAVAILABLE, IDENTITY_NOT_VERIFIED or UNKNOWN_OUTCOME or PROVIDER_PLAN_REQUIRED. Success is exactly `{code:"CONNECTED",identity,capabilities:[kind]}`. Identity is a bounded canonical ASCII provider account identity, proven by an authenticated minimal provider response. A supplied Client ID, a decoded unverified JWT, a token hash, a store name or email is not proof.

Provider owner must qualify the minimal read-only endpoint/permissions/decoder and exact identity namespace before enabling this socket. Seller and Performance remain independent. Performance must prove the same canonical seller account identity before attaching to an existing Ozon store; lacking such proof returns IDENTITY_NOT_VERIFIED. No implicit matching by company name or financial report. A timeout is not an invalid key; no hidden report, matrix job or paid operation may run during setup.

The platform persists a validation claim before IPC, keeps no DB transaction open across it, and commits only against the same current customer security/store/credential revisions. A lost/expired response stays unknown. The old active key survives a failed replacement; a key for another cabinet is never promoted. Only the tenant-local verified identity participates in duplicate checks. Raw identity, secret, vault reference and fingerprints are absent from customer API projections.

Development qualification uses disposable keys and Unix fixture peers only. Full AL-S05 acceptance requires the core owner's agreed runtime endpoint and separately authorized real Ozon, WB and Performance checks. The currently installed report gateway is not evidence of RT-CHECK readiness.

Runtime-side source is prepared in docs/alisa/runtime/v0.11/rt_check_r01. It is not installed or live accepted. Seller binding is unqualified by default; Performance cannot prove the Seller link. The extra PROVIDER_PLAN_REQUIRED result describes provider HTTP402 and never initiates payment.
